Most problems show up as a tray tooltip or a dashboard banner with a specific reason. Find the message below; each entry says what the companion has observed and what to change. When in doubt, **Check reachability** (Settings → Tunnel) tells you where along the path a request stops.

## Offline versus "the web app cannot be reached"

The companion tracks two things separately and never conflates them: whether its tunnel has a connection to Cloudflare's edge, and whether the web app answers a health check.

| Banner | What it means | What to do |
|---|---|---|
| **Offline — no network** | Neither the tunnel nor the web app can be reached. | Check your network. The companion retries with backoff (2 s doubling to 5 min) and reconnects on its own. |
| **Your computer is online; the web app cannot be reached right now** | The tunnel is up but `GET /api/health` on the web app is failing — the web app is down, being deployed, or blocked between you and it. | Nothing to fix locally. The companion keeps checking every 30 seconds while disconnected and re-tests your connections as soon as the web app answers. |
| **Reconnecting… (retry in N s)** | The tunnel dropped or the computer just resumed from sleep. | Wait. After resume the companion pauses ten seconds for the network to settle before reconnecting. |
| **Suspended** | The computer is asleep or the screen is locked; the companion stopped the tunnel on purpose so the web app sees *unavailable* immediately. | Unlock or wake; it restarts the tunnel automatically. |

## Cloudflare 530 / error 1033 — no connector

Cloudflare has your hostname but no `cloudflared` is connected to the tunnel it routes to. Causes, in order of likelihood: the companion is stopped or paused; the computer is asleep or locked; the tunnel token in the companion is for a different tunnel than the one the hostname routes to (Zero Trust → Networks → Tunnels → your tunnel → **Public hostname** must list your hostname); the token was rotated in Cloudflare and not pasted into the companion. The companion escalates to **Tunnel configuration error** only when `cloudflared` itself reports an invalid or unauthorised token, a tunnel that no longer exists, or a hostname that is not routed — never while the web app is unreachable.

## Cloudflare 502 — bad gateway

The tunnel is connected but Cloudflare could not get an answer from the service configured for the hostname. Open the tunnel's **Public hostname** entry: the **Service** must be type **HTTP** (not HTTPS) and the URL must be `localhost:<port>` with the exact port shown in the companion's Settings → Tunnel (default `47831`). A 502 also appears for a few seconds while the companion restarts its server.

## 401 from the self-check

**Check reachability** sends the origin access token exactly as the web app does. A 401 means the token the companion holds is not the one the running server expects — almost always because the access token was rotated (Rotate access token, Unlink, or re-registration) while a connection in the web app still carries the old value, or because the connection's settings were edited in the web app. Run **Register this computer**: it updates every existing connection with the current token. If the web app's own connection test still fails afterwards, test again after the next check-in (default 10 minutes) or press **Test** on the connection.

## Port in use

The WebDAV port is fixed on purpose: the tunnel's public hostname points at `localhost:<port>`, so the companion cannot pick another port silently without breaking the route. When something else holds the port the companion stops with *Port 47831 is in use*. Either stop the other program, or change the port in **Settings → Tunnel** **and** update the hostname's Service URL in Cloudflare to match, then Check reachability.

## Secure storage unavailable

The companion keeps every credential in the operating system's secure store and refuses to run without it rather than write plaintext. The message names the platform:

- **Linux** — install and unlock a secret service: `gnome-keyring` (most GNOME-based desktops) or `kwallet` (KDE). A session without an unlocked keyring, or a backend that Electron reports as `basic_text`, counts as unavailable. Restart the companion afterwards.
- **Windows** — DPAPI is unavailable only in unusual profiles (roaming profile corruption, some service accounts). Sign in with a normal interactive account.
- **macOS** — the login Keychain is locked or damaged. Unlock it in Keychain Access, or repair it via Keychain First Aid.

The check runs before an enrolment code is consumed, so fixing this never costs you a code.

## Expired or invalid code

Enrolment codes last **10 minutes** and work once. *This code has expired or is not valid* means the code is old, was already used (a second click on the same link, a paste after a successful link), or belongs to a different server than the address shown. Generate a new one from **Linked devices** and make sure the server address in the companion matches the web app that issued it. A computer clock that is badly wrong can also make a fresh code look expired.

## Blocked by your administrator

Registration is subject to the admin's **User storage connections** policy because the companion signs in as a user, never as an admin. The web app returns the same `403 forbidden` for three different reasons; the companion reads the message and tells you which:

| Message | Cause | Fix |
|---|---|---|
| **User storage connections are disabled** | The policy at `/admin/documents` is `disabled` (app-managed storage only). | An admin must set it to `limited` or `unlimited`. |
| **Connection limit reached — remove an unused storage connection in the web app** | The policy is `limited` and you already have as many connections as it allows. Each shared folder is one connection. | Remove a connection you no longer use on `/settings/document-storage`, or ask an admin to raise the limit to the number of folders you share. If an old Local Connect connection for this computer exists, choose **Use existing connection** instead — updating a row is never counted. |
| **The WebDAV engine is not allowed** | An admin has not allowed `webdav` under **Engines** at `/admin/documents`. | An admin must allow it. |

See [Usage → Adding a Storage Provider](/document-management/usage/#adding-a-storage-provider) for the policy itself.

## Read-only uploads folder

*Files sent from the web app cannot be saved here* appears whenever the connection the web app uploads to is read-only — because the uploads folder was switched to read-only, the folder lost its write permission, or you opted into **read-only only**. Online uploads then fail with `403 read_only`; uploads made while you were away are staged and every delivery attempt fails until this is fixed. Choose a writable uploads folder in **Settings → Folders** (the companion checks it can write there), or fix the folder's permissions and re-test.

## Waiting uploads that could not be delivered

After each connection the companion asks the web app to deliver staged uploads, then lists any that failed as **needs attention** with the reason the web app recorded. Delivery is retried automatically on every successful check-in (default every 10 minutes) and by **Deliver waiting uploads** on the dashboard (exactly one pass); neither will succeed until the cause is fixed.

| Reason shown | What happened | Fix |
|---|---|---|
| *not found* / *provider unavailable* | The uploads folder was removed, renamed or is on a drive that is not mounted, so the companion answers 404 / 503 for it. | Restore or re-mount the folder, or choose a different uploads folder in Settings. |
| *Provider is read-only: write operations are disabled* | The uploads connection is `isReadOnly` in the web app. | See [Read-only uploads folder](#read-only-uploads-folder). |
| *Insufficient storage* (507) | The drive holding the uploads folder is full, or would drop below the 256 MB reserve the companion keeps. | Free space on that drive. |
| *Character not allowed in file names* / *Reserved file name* / *Trailing space or dot in name* (403) | The staged file's name — or a folder in its target path, such as a node-type template — contains `\ < > : " \| ? *`, a trailing dot or space, or a reserved name such as `CON`. | Rename the file in the web app (or fix the node-type template), then deliver again. |
| *Path escapes the shared folder* (403) | The target path would resolve outside the uploads folder, including through a symlink or junction. | Check the node-type template or `uploadPath`; remove links inside the uploads folder. |

Uploads that stay staged remain usable in the web app from their staging location; nothing is lost while you fix the cause.

## Quick-tunnel address changed

A quick tunnel gets a new `*.trycloudflare.com` address on every launch. The companion updates every connection's address when it reconnects, but if it could not reach the web app at that moment the connections still point at the old address and show *unavailable*. Run **Register this computer** to update them. If this keeps happening, it is a sign you have outgrown quick tunnels — create a [named tunnel](/document-management/local-connect/setup/#create-a-named-tunnel).

## Uploads over 100 MB rejected

Cloudflare rejects request bodies over **100 MB** at the edge on non-Enterprise plans, regardless of the upload limit an admin sets in Document Management (the companion itself accepts far larger files). The web app sees a `413` from Cloudflare, not from the companion. Keep files sent through the web app under 100 MB, move to a plan with a higher limit, or simply copy larger files into the shared folder directly — the web app browses them like any other.

## Other messages

| Message | Meaning |
|---|---|
| **Not linked to a web app yet** | Complete [Link this computer](/document-management/local-connect/setup/#2-link-this-computer). |
| **Access was revoked — link again** | The device was revoked from Linked devices, or its token was rejected after a fresh refresh. Generate a new code and link again; choose *Use existing connection* when registering. |
| **Could not verify sign-in, retrying** | The refresh endpoint returned a network or server error — not a revocation. Nothing to do. |
| **Choose a folder to receive uploads** | No writable uploads folder is selected (or the selected one no longer exists). |
| **cloudflared not found** | Development builds look for `cloudflared` on `PATH`; packaged builds bundle it. You can point the tunnel settings at a `cloudflared` binary of your own; it is validated (a regular local file that answers `--version`) before it is used. |
| **Tunnel not configured** | Tunnel mode is *None*. Pick Quick or Named. |
| **Development build** badge | The app is unpackaged or unsigned: updates are disabled and `cloudflared` comes from `PATH`. |

## Where the logs are

Open **Dashboard → Open log folder**. The companion writes `local-connect.log` as JSON lines (one object per line with `time`, `level`, `scope` and `msg`), rotating at 5 MB and keeping three older files (`local-connect.log.1` … `.3`), in the app's log directory under your user profile (Electron's standard location for the application, for example `%APPDATA%\Unique Local Connect\logs` on Windows, `~/Library/Logs/Unique Local Connect` on macOS and `~/.config/Unique Local Connect/logs` on Linux). Tokens are redacted before they are written, so the file is safe to share when asking for help. The dashboard's **Recent activity** panel shows the same request stream — method, folder, path, status — for the last 500 entries.

<Aside type="tip" title="Reading a request line">
`{"level":"info","scope":"app:webdav","method":"PUT","share":"Uploads","path":"/Ingested/report.pdf","status":201,"durationMs":184}` is the web app writing a file into your uploads folder under `Ingested/`. A `PROPFIND` on `/s/<id>/` every few minutes is the web app's reachability probe or the companion's own check-in, not someone browsing.
</Aside>

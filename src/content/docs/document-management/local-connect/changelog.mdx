This page documents notable changes to **Unique Local Connect**, the desktop companion for Document Management's Local Connect feature. It follows semantic versioning — **major.minor.patch** — independently of the module: a patch for fixes and small features, a minor for a new subsystem, a major for a change that needs you to re-link or re-register.

<Aside type="note" title="Versions of the pieces that must agree">
The companion is built against the Document Management integration contract traced from **v1.11.0** (ephemeral providers since v1.8.0, offline staging and delivery since v1.9.0) and the starter template's **device-token enrolment** feature. Managed tunnels need **v1.13.0**. Each entry below names the versions it was verified with.
</Aside>

## v0.3.3 <Badge text="Current" variant="success" /> <Badge text="7 September 2026" variant="note" />

**Dashboard tidy-up, an in-window Quit, and a cleanup + security audit.** Verified with Document
Management v1.14.0 in a real end-to-end run (link → register → browse → upload).

**Added**

- **Connection** and **Activity** pages in the left menu. The linked-account and address (tunnel)
  cards moved to **Connection**; the recent-activity feed moved to **Activity**. The dashboard is now
  an at-a-glance overview.
- A **Quit** button in the sidebar footer, so you can close the app from its own window rather than
  only from the tray. It shuts down the same graceful way the tray's Quit does.

**Changed**

- The connection card now shows the linked app's name (e.g. **Veradai**) to the left of the status
  badge, and drops the descriptive sentence and the "Tunnel up · reachable" line in the normal
  connected state — the card stays clean, and still explains itself when something needs attention.

**Fixed**

- **Warning highlights now show their colour.** A typo (`warninging`) meant the amber tint/border on
  warning pills, callouts and notices silently did not apply. Cosmetic, but it affected many states.

**Security & hygiene (from a cleanup + security audit)**

- The audit found **no critical or high-severity issues**; the renderer/window hardening and the
  main-process protections (path confinement, secret handling, deep-link validation, WebDAV auth)
  all hold. The changes below are defence-in-depth and housekeeping.
- **Log redaction** now also scrubs secret-bearing query parameters (e.g. a `?token=…` in a URL) and
  known token prefixes embedded in a longer string, not just whole-value tokens and `Bearer` headers.
- **CI now runs a formatting check and a dependency-vulnerability scan** (`npm audit`, high/critical),
  on every push and before a release, so drift and vulnerable dependencies are caught automatically.
- Removed dead code (about ten unused/test-only exports) and an unused dependency, and **dropped the
  bundled Playfair Display font** (no longer the default heading face), which shrinks the installer.

**Developer experience**

- Added `npm run version:patch` / `:minor` / `:major` scripts so the version is bumped by command
  rather than by hand.

## v0.3.2 <Badge text="7 September 2026" variant="note" />

**Release-readiness fixes: a packaged build can now bundle the tunnel, and the dashboard ships less
than half the code.** Nothing you interact with changes day to day; this clears the last blockers
before a signed installer.

**Fixed**

- **The bundled `cloudflared` binary is now pinned by checksum for every platform.** The six SHA-256
  values were filled from the pinned 2026.8.3 release (byte sizes cross-checked against the GitHub
  release), so packaging installs a verified tunnel binary instead of refusing an unverified one. The
  fetch script still refuses any binary whose digest does not match.
- **Auto-update points at the right place.** The GitHub release target was corrected to the companion's
  actual repository, so the updater looks where releases are published.

**Changed**

- **The dashboard bundle is less than half the size.** The renderer is now minified (it had been
  shipping readable source) and split into framework, application and on-demand setup-wizard chunks —
  roughly 769 kB down to about 316 kB of JavaScript, and the build's size warning is gone.

**Internal**

- Hardened a flaky test whose random port window could overlap the operating system's ephemeral range,
  and stopped the fetched tunnel binary from being committed to the repository.

**Verified with** Document Management v1.14.0 and the device-token enrolment feature: typecheck, lint,
537 tests, a minified production build and a headless smoke run all pass.

## v0.3.1 <Badge text="7 September 2026" variant="note" />

**The companion looks like the web app it is linked to.** It previously shipped one product's colours,
which was wrong for an app you can link to any web app built on the same platform.

**Added**

- A deliberate **brand-neutral** palette of its own, in light and dark, contrast-checked so text stays
  readable. That is what you see before linking, and whenever a web app offers no theme of its own.
- The companion now reads the web app's public theme when it links and on each reconnect, and matches
  its colours, corner rounding and spacing. Nothing you need to configure.

**Changed**

- Typography is matched in spirit rather than exactly: the web app's fonts are not bundled with the
  companion and cannot be fetched, so a bundled or system face is used instead.
- The web app's logo is read but not yet displayed.

**Security**

- A theme is treated as untrusted, because it is styling arriving from a server over the network. Only
  colour and size values are ever taken from it, everything else in the response is discarded, and a
  theme that looks wrong in any way is ignored in favour of the neutral palette rather than partly
  applied. The same check runs again when the cached copy is read back, so editing the file on disk
  cannot slip anything past it.

## v0.2.0 <Badge text="September 2026" variant="note" />

**The tunnel stops being the user's problem.** Verified against Document Management v1.13.0 and the device-token enrolment specification (starter route base `/api/v1/auth/devices/*`).

### Added

- **Managed tunnels.** The companion asks Document Management for this computer's tunnel instead of asking you for one. It sends a **machine key** — a random id it generates once and keeps in `settings.json`, not a secret and not the device token — with the loopback port it listens on, and receives a hostname and a `cloudflared` run token. The token goes straight into the OS secure store and is never shown, logged or handed to the dashboard. The request is idempotent for that machine key, so asking again returns the same tunnel and **re-points the ingress when the local port has changed**; the companion asks on every start, which makes that the repair for a moved port.
- **A refusal aimed at the right person.** When the operator has not configured Cloudflare in the module, it answers `501 tunnel_not_configured` and the companion says *Local Connect has not been finished for your organisation… Ask your administrator to complete the Local Connect setup in the web app*, on the dashboard and in the tray. No tunnel form is ever shown to a user who cannot fix it. A web app with no tunnel endpoint at all (Document Management older than v1.13.0) is told apart and reported as such.
- **Unlink deletes the tunnel.** Unlinking now asks the web app to remove this computer's tunnel and DNS record while the device token still works, so the hostname stops resolving to this computer rather than merely going quiet. It is best effort: unlinking finishes whatever the web app answers. A tunnel an operator pinned by hand is left alone.

### Changed

- **The setup wizard lost its Tunnel step.** It is now **Secure storage → Link this computer → Uploads folder → Share folders → Register → Done**, and nothing in it mentions Cloudflare. The manual hostname and token controls moved to **Settings → Address for this computer (advanced)**, collapsed and labelled *For operators. Everyday setup never needs anything here.*
- **The interface uses the same shadcn theme as the web app** — the colour, radius and type tokens are ported from the web app so the two read as one product, with the dark palette following your operating system rather than a switcher. Fonts are bundled; the dashboard fetches nothing.
- The dashboard's **Tunnel** card is read-only and reports where the address came from (*Provided by the web app*), with the self-check and **Check again** as before.

### Fixed

- **An unlinked computer no longer claims the web app is unreachable.** Before linking there is nothing to reach, so the two reachability indicators are hidden and the dashboard says *Not linked yet — there is nothing for this computer to reach until you link it.* instead of the alarming and meaningless *Tunnel down · Web app unreachable*.
- **The Link button explains itself.** Instead of sitting disabled with no reason, the line above it names the one thing still missing — secure storage, the web app address, the enrolment code, or a pairing with another web app that must be unlinked first — and reads *Ready to link.* when nothing is.

### Known constraints

- Managed tunnels need Document Management **v1.13.0** and an operator who has set `DOC_CF_API_TOKEN`, `DOC_CF_ACCOUNT_ID`, `DOC_CF_ZONE_ID` and `DOC_LOCAL_CONNECT_DOMAIN`. Until that is done this computer has no public address, and the companion says so rather than offering the user a way out.
- Revoking a device in the web app does not delete that computer's tunnel — only unlinking from the companion does. See the [roadmap](/document-management/local-connect/roadmap/#what-is-still-missing).
- Every constraint listed under v0.1.0 that is not about tunnel provisioning still applies.

## v0.1.0 <Badge text="September 2026" variant="note" />

**Initial release.** Verified against Document Management v1.11.0 and the device-token enrolment specification (starter route base `/api/v1/auth/devices/*`).

### Added

- **Tray application** for Windows (x64, arm64), macOS (universal) and Linux (AppImage, deb): start on login (opt-in), start hidden, single instance, clean shutdown that tears down the tunnel and server, and a dashboard showing connection state, shared folders, the linked account and recent activity.
- **WebDAV server** — Class 1 plus `MOVE` and `COPY` on Node's `http`, loopback-only on a fixed port (default `47831`): `PROPFIND` depth 0/1 with the properties Document Management reads, streamed `PUT` with and without `Content-Length` written to a temp file and renamed atomically, `MKCOL` with RFC semantics (`405` when the path exists, `409` when the parent does not), `GET`/`HEAD` with ranges, honest `404` for absent paths, short header and idle timeouts. Verified end to end with the same `webdav` client the module uses.
- **One connection per folder** — each share is served at `https://<hostname>/s/<share-id>/` and registered as its own `isEphemeral` row named `<Computer> · <Folder>`; the uploads folder is the default and writable, every other folder read-only with the web app's lock icon.
- **Uploads folder** created at `<Documents>/Local Connect Uploads` by the setup wizard, required before registration, with guards against removing it or making it read-only without a replacement.
- **Cloudflare Tunnel** supervision: named tunnels (token pasted, stable hostname) for everyday use and quick tunnels for development — superseded by managed tunnels in 0.2.0; automatic reconnection with backoff; the tunnel stopped on sleep or lock and restarted on resume; orphaned `cloudflared` processes cleaned up on start; the bundled binary checksum-verified at build time.
- **Reachability self-check** — while connecting, whenever the web app's test fails with the tunnel reporting ready, and on demand from the dashboard or the tunnel step, the companion fetches one of its own share roots through Cloudflare and classifies the result (DNS, no connector, wrong ingress, refused credentials, timeout). It needs serving to be running, and is not a gate on registration.
- **Linking** via the `unique-local-connect://enrol` deep link or a pasted code, with the server address confirmed by you before anything is sent (the minted link carries only the code, so the companion asks which web app it came from), origin pinning, refusal of links for a different server while linked, automatic device-token refresh, and revocation detection.
- **Unlinking** takes this computer off the tunnel, mints a new origin token and pushes it to the registered connections so the credential the module held until then is dead, and clears the sign-in from the secure store. Revoking the device itself is done in the web app under **Linked devices** — managing devices requires a web session, so a stolen device token can never disturb your other computers.
- **Registration** as an explicit step, re-using existing connections after an unlink or reinstall, with the three `403` policy refusals told apart and worded for the user.
- **Delivery of waiting uploads** — on connection the companion triggers the module's delivery pass, bounded and progress-gated, then lists anything that failed with the recorded reason; a periodic check-in (default 10 minutes) and a manual **Deliver waiting uploads** action retry.
- **Origin authentication** with a companion-minted 256-bit bearer token checked on every request, **Rotate access token** (which pushes the new token to every registered connection), and the same rotation on unlink.
- **Path confinement** for every verb and for `Destination`, applied before any disk access, with a realpath check against symlink and junction escapes.
- **Secrets in the OS secure store** (DPAPI, Keychain, libsecret/KWallet), fail-closed, verified before an enrolment code is consumed; the tunnel token passed to `cloudflared` only through its environment.
- **Structured, redacted logs** and an in-app activity feed (the last 500 events, the 100 most recent shown on the dashboard); **Open log folder** on the About screen.
- **Automatic updates** from GitHub releases in signed builds; a *development build* badge and no updates otherwise.

### Known constraints

- Requires the starter template's device-token enrolment feature to have landed and been migrated into the web app, and a durable app-wide shared default for offline staging.
- The admin policy for user storage connections must not be `disabled`; under `limited`, every shared folder counts as one connection.
- Tunnel provisioning is manual (a tunnel token and hostname pasted into the companion). **Fixed in 0.2.0** — see [Managed tunnel provisioning](/document-management/local-connect/roadmap/#managed-tunnel-provisioning).
- Cloudflare's 100 MB request-body limit on non-Enterprise plans applies to uploads through the tunnel regardless of the module's upload limit.
- Whole folders only: sub-folder exclusions are not available (hidden entries and temp files are always omitted).
- File names containing `\ < > : " | ? *`, trailing dots or spaces, or Windows reserved names are refused on every platform, including where POSIX would allow them.
- Document Management's streamed `PUT` does not wait for the companion's response, so a write the companion refuses *after* it has started reading the body can be recorded as successful by the module. The companion performs every check before reading a byte to keep that window as small as possible; the fix is module-side and tracked on the [roadmap](/document-management/local-connect/roadmap/#requests-to-the-starter-template-and-document-management).
- HTTP Basic authentication at the origin is not offered; Cloudflare Access cannot be placed in front of the hostname for the module's requests (see [Security](/document-management/local-connect/security/#origin-authentication-on-every-request)).
- No backup, replication or restore — by design.

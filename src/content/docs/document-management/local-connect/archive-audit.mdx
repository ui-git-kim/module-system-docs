A running log of **archive-readiness audits** for the **Unique Local Connect** companion app (its own repository, `dm-local-connect-companion` — `Unique Local Connect` is the user-facing product name; the repository carries the backend/module-system name). Before a working session is archived, it is audited for anything that would be lost — unfinished work, loose ends, decisions, and ideas — and the findings are recorded here so a fresh session can pick them straight up.

<Aside type="note" title="Why this page exists">
Session transcripts get archived and are then awkward to search. This page is the durable, reviewable home for "what was in that session" — decisions and their reasoning, ideas raised in passing, work left mid-flight, and anything the code and the rest of these docs do not already capture. Newest entry first. Nothing here is deleted; when an item is actually done, it is ticked and left in place for provenance.
</Aside>

## 2026-09-07 (continued) — real Veradai e2e proven, dashboard refactor, cleanup + security audit (v0.3.3)

**Verdict:** ✅ **Safe to archive** — all gates green (typecheck, lint, format:check, 532 tests, minified build, headless smoke) and pushed. One optional leg of the e2e is still open (below), and it needs Kim, not more code.
**Shipped this session:** **v0.3.2 → v0.3.3** (patch), bumped with the new `npm run version:patch` script.

**The real end-to-end run against Veradai happened — and worked.** Against live Veradai + real
Cloudflare: device enrolled, 3 provider rows registered, managed tunnel up at
`lcda947982a581f688.veradai.au` (4 edge connections), state **connected**, Veradai **browsed** every
share and deep subfolders, and a real **upload** (`PUT Orders.pdf`, 602 KB) landed on disk and read
back. So **link → register → browse → upload are proven for real.** The **offline → reconnect →
delivery** leg is the only one not yet demonstrated — see loose ends.

**Hard-won facts from the run (also in the `local-connect-handover` memory):**

- The companion must enrol against the **backend API directly at `http://localhost:3400`** (plain http
  on loopback is allowed in the *unpackaged* dev build). Not `https://localhost:5173` (no mkcert certs,
  and Node's fetch would not trust a mkcert cert anyway — the cause of the earlier "fetch failed"), and
  not via the 5173 proxy (its `changeOrigin` rewrites Host to :3400 and breaks the origin-pin).
- The `unique-local-connect://` deep link is still registered to the **stale packaged v0.1.0** build in
  `release/win-unpacked` (old parser rejects api-less links) — use the paste-a-code path, or rebuild +
  reinstall a packaged 0.3.x to re-own the scheme.
- **Enrolment-code UX papercut:** a wrong-but-*proxied* address (`:5173`) silently *spends* a code —
  the backend accepts it and returns tokens, then the companion discards them on the origin-pin
  mismatch, so the next attempt gets a `401` and you must re-mint. Combined with a short code TTL this
  reads as "the code expired instantly". Worth smoothing (clearer message, or a longer/reusable code).

**Dashboard changes (Kim's requests):** the status card shows the linked app's name to the left of the
badge and drops the descriptive + reachability lines in the connected state; new **Connection** page
(linked account + tunnel cards) and **Activity** page (recent-activity feed) in the left menu; and an
in-window **Quit** button in the sidebar footer (the tray was easy to miss, especially with the
dev-build's blank tray icon).

**Cleanup + security audit (this session, via a parallel-auditor + adversarial-verify workflow):**
**no critical or high-severity issues.** Renderer/window hardening (contextIsolation, sandbox, CSP,
theme sanitiser) and main-process protections (path confinement, secret handling, deep-link
validation, WebDAV auth) all hold. Applied fixes: the `warninging` colour typo (warn tint/border now
render); removed ~10 dead/test-only exports + the unused `@electron-toolkit/preload` dependency;
**dropped the bundled Playfair Display font** (installer shrinks — its woff2 subsets no longer build);
hardened log redaction (secret query-params + embedded token prefixes); added `format:check` +
`npm audit` gates to CI and release; added `version:*` scripts. The audit correctly dropped one false
positive (an arm64 `continue-on-error` claim disproved by the pinned single-file Windows cloudflared).

**Loose ends & follow-ups:**

- **Offline → reconnect → delivery** is still unproven. Kim tried it but never resumed (the companion
  was still paused), and suspected a **cog-ingest cross-module** interaction. The companion's delivery
  only covers uploads DM **stages against the owned default provider**; if cog-ingest ingests through
  its own pipeline, Local Connect's reconcile has nothing to deliver — a question to confirm with the
  DM / cog-ingest owner. To test cleanly: pause the companion, upload a plain file to the default
  (Uploads) target — not via cog-ingest — then resume and watch the reconcile.
- Deferred audit item recorded on the [roadmap](/document-management/local-connect/roadmap/#smaller-items):
  the release workflow publishes an unsigned build if signing secrets are absent (documented graceful
  degradation) — a guard could fail the release instead.
- Still open from before: render the app logo; trim the remaining bundled Noto Sans subsets.

**Recorded where:** the [changelog](/document-management/local-connect/changelog/) v0.3.3 entry; the
roadmap smaller-items; `package.json` (0.3.3) and its new `version:*` scripts; `CLAUDE.md` (version
scripts documented); and the session memory files.

**Open items for next session:** (1) the offline → delivery e2e leg, Kim-driven, once the cog-ingest
routing question is settled; (2) optionally render the app logo; (3) optionally trim the Noto Sans
subsets.

## 2026-09-07 (release prep) — cloudflared checksums, minified bundle, publish target, Veradai readiness (v0.3.2)

**Verdict:** ✅ **Safe to archive** — every quality gate is green and the working tree is clean in the companion and the docs submodule. The interactive Veradai end-to-end run is the one thing still outstanding, and it needs Kim present, not more code.
**Shipped this session:** **v0.3.1 → v0.3.2** (patch), companion commit `1fe1853`.

**Corrected on pickup:** the previous session's memory and handover said the repository had *no git remote*. It has one — `origin` is `github.com/ui-git-kim/dm-local-connect-companion` and every commit was already pushed and up to date. Kim's decision on the name: the **GitHub repository is `dm-local-connect-companion`** (the backend / module-system identity); *Unique Local Connect* stays the user-facing product name and the npm package name.

**Done this session:**

- **Filled the six `cloudflared.lock.json` SHA-256 values** from the pinned `2026.8.3` release, with each asset's byte size cross-checked against the GitHub release metadata. `node scripts/fetch-cloudflared.mjs --os win --arch x64` now installs a verified binary, so a packaged build is no longer blank. Cloudflare publishes no SHASUMS file, so the pins are the digest of what was downloaded — the byte-size cross-check is the second signal.
- **`resources/bin/` is now git-ignored.** Running the fetch script drops a 54 MB binary there that must never be committed; the previous session never ran the fetch (the checksums were empty), so the gap was invisible until now.
- **Fixed `electron-builder.yml` `publish.repo`** from the non-existent `unique-local-connect` to `dm-local-connect-companion`, so electron-updater reads the right GitHub release feed. (No releases exist yet, so nothing had to be migrated.)
- **Renderer bundle: ~769 kB → ~316 kB of JavaScript.** The root cause was that electron-vite was **not minifying the renderer** — it shipped readable production React. Enabled `minify: 'esbuild'`, split the build into `react` / `vendor` / app chunks, and lazy-loaded the setup wizard. Every chunk is now under the 500 kB threshold and the Vite size warning is gone.
- **Hardened the flaky metrics-port test.** Its base was `21000 + random·30000`, so a 100-port scan window could land inside the Windows ephemeral range (floor 49152), where the suite's parallel `fetch()` churn occupied every port and made `findFreeMetricsPort` throw. Capped the window below the floor (`20000 + random·20000`); four consecutive green full-suite runs since.

**Loose ends & follow-ups:**

- **The interactive Veradai end-to-end run is still not done.** It needs Kim to mint an enrolment code from a signed-in web session (`POST /auth/devices/pair`), so it can only be driven with Kim present. A **read-only** check of Veradai confirmed everything else is ready: Document Management **v1.14.0** enabled; the `doc_local_connect_tunnels` migration (`20260906063829_update_document_management`) and Prisma model present; the managed-tunnel `POST`/`DELETE /api/v1/document-management/local-connect/tunnel` endpoint with matching request/response shapes; device-token `enrol`/`refresh` with the `dvc_`/`dvr_`/`dve_` prefixes; public `/api/v1/theme` and `/api/v1/branding`; and the full operator Cloudflare config set, with `DOC_LOCAL_CONNECT_DOMAIN = veradai.au`. The **one item files cannot prove**: whether the two migrations are actually applied to the running database — confirm with `npx prisma migrate status` in Veradai before the run.
- **Stale repository-name references in Document Management's own docs.** `document-management/roadmap.mdx` (three places), `document-management/changelog.mdx` and `document-management/archive-audit.mdx` still call the companion repository `unique-local-connect`. Those are the module's pages, not the companion's, so under the "only ever change this repository" rule they were left for the module's owner to correct rather than edited across the boundary.
- **The app logo is still fetched but not displayed** — deliberately deferred this session (Kim's choice).
- **Font footprint.** The build still bundles many Playfair Display and Noto Sans subsets (Playfair was dropped as the default heading face in v0.3.0), several over 100 kB each. Trimming unused faces and subsets would shrink the installer further — a larger, separate change from the JavaScript split.

**Decisions & ideas:**

- **Minification was the real bundle win, not chunking.** The previous session read the 769 kB as "needs a `manualChunks` split"; the actual cause was that minification was off. The split is kept as well (it isolates the stable framework chunk and defers the wizard), but minification did the heavy lifting — a reminder to measure the build, not assume the diagnosis.

**Recorded where:** this page; the [changelog](/document-management/local-connect/changelog/) v0.3.2 entry; `package.json` (0.3.2); the session memory files (`local-connect-handover`, `local-connect-git-setup`, `local-connect-project-state`).

**Open items for next session:** in priority order — (1) the interactive Veradai end-to-end run (link → register → browse → upload → offline → reconnect → delivery), Kim-driven; (2) optionally render the app logo; (3) optionally trim the bundled font footprint.

## 2026-09-07 — Companion built end to end: WebDAV, managed tunnel, theming (v0.1.0 → v0.3.1)

**Verdict:** ⚠️ **Needs input first** — the code is finished and green, but the repository **has no git remote**, so all 13 commits exist only on the local disk. Everything else (the shared docs submodule, and the pin pointing at it) is pushed.

**Shipped this session:** the whole application, `v0.1.0` → **`v0.3.1`**, 13 commits ending at `df94a8f`. 537 tests across 41 files, plus `type-check`, `eslint`, `format:check`, `electron-vite build`, an unpacked Windows package, and headless `ULC_SMOKE=1` runs of both the dev bundle and the packaged `.exe`. Six public docs pages, the Document Management security and roadmap corrections, and a starter upstream issue raised and closed.

**What went in:** a hand-rolled WebDAV Class 1 + MOVE/COPY server verified against the real `webdav` client Document Management uses; a `cloudflared` supervisor; device-token enrolment with single-flight refresh and origin pinning; per-share provider registration; the delivery cadence; the Electron shell (tray, updater, autostart, deep links); a React dashboard and wizard; and runtime theming.

**Unfinished / WIP:** none. Working tree clean in all four repositories touched (companion, docs submodule, document-management, starter).

**Loose ends & follow-ups:**

- **The real end-to-end run against Veradai has never happened.** Every integration is contract-level plus a mock SaaS. It needs Kim to mint an enrolment code from a signed-in web session, and `npx document-management update` in Veradai plus the migration for `doc_local_connect_tunnels` — both of which change a live app, so they were deliberately not done unilaterally.
- `cloudflared.lock.json` still holds **6 empty `sha256` values**. `scripts/fetch-cloudflared.mjs` refuses to install an unverified binary, so a packaged build currently bundles no tunnel binary. Blocks a signed release, not development.
- The app logo is **fetched and cached but never rendered** — the renderer CSP is `img-src 'self' data:`, so showing it needs main to fetch it and hand over a `data:` URI.
- **Revoking a device in the web app leaves that machine tunnel alive** on the Cloudflare account: only the companion can delete it, and revocation removes its credential. Recorded on the roadmap as needing Document Management to reap orphans.
- Renderer bundle is 769 kB and Vite warns; a `manualChunks` split or a lazy wizard would quieten it.

**Decisions & ideas:**

- **One provider row per share, not a virtual root with named mounts.** An adversarial design review found Document Management resolves `?folder=` and node templates root-relative, and a requested folder *replaces* `uploadPath` rather than nesting under it, so a virtual root would have received writes outside every share. This was a design reversal before any code existed.
- **Origin authentication is the gate; the tunnel is transport.** Document Management can send Basic *or* one Bearer and cannot send Cloudflare Access headers, so the published "Cloudflare is the gatekeeper" model cannot hold for its own requests. The module security page was corrected to match.
- **The user never configures a tunnel.** Reversed mid-session on Kim's call: Document Management provisions one per machine and the wizard lost its Tunnel step entirely.
- **The theme is fetched, not baked into the installer.** Per-download modification would break code signing and notarisation; fetching also stays correct when an app is re-themed later. Adopted from `GET /api/v1/theme`, whose `appTheme` the platform types `unknown`, so it is parsed tolerantly and treated as hostile remote CSS.
- **Playfair Display was dropped as the default heading face** — shipping the Playfair + Noto pairing as "brand-neutral" would have been shipping one product's typographic identity. Flagged as easy to revert if disagreed with.
- **Rejected:** baking CSS into the download; scraping the app's built stylesheet (the frontend origin is not knowable from the API); and editing the starter directly to add the endpoint — see below.
- **Process correction:** an agent was started on the starter template to add the theme endpoint. Kim caught it ("are you changing the starter? or putting an upstream issue in the log?"). The starter was reverted to untouched, the need was logged as a starter upstream issue instead, and **"only ever change this repository"** is now the first hard rule in the companion `CLAUDE.md`, with routing for starter, module-starter and Document Management needs.

**Notable findings that a mock could never have caught:** checking the companion against the *shipped* starter (2.8.2) rather than its spec found that the minted deep link carries **no `api` parameter**, so every real pairing link would have been rejected; that the companion **cannot revoke itself** (device management is behind a web session by design); and that the logger redacted only `dvc_`, not the `dvr_` and `dve_` token prefixes. A later pass against Document Management 1.13.1 found the test mock validated requests far more loosely than the module does, which would have let a bad `machineKey` pass the suite and fail in production.

**Recorded where:** `ARCHITECTURE.md` (decisions D1–D15, the theming section, and the integration-status section); `spec/local-connect-build-prompt.md` errata E1–E10; the six public pages under `/document-management/local-connect/`; the starter [upstream-issues](/starter-template/upstream-issues/) entry, now under Completed; and the session memory files (`local-connect-project-state`, `local-connect-handover`, `local-connect-repo-boundary`, `local-connect-managed-tunnel`, `local-connect-real-saas`, `local-connect-git-setup`).

**Open items for next session:** a ready-to-paste handover prompt was produced in the session chat. In priority order: (1) create the GitHub remote and push — nothing is backed up until then; (2) the real end-to-end run against Veradai; (3) fill the `cloudflared` checksums before any signed release.

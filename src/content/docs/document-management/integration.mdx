<Aside type="note" title="Connector, not storage">
Document Management is a **connector** in V1 — it stores references, metadata, and user organisation (favourites, tags, node links), never file content. When you request a download stream, the bytes are proxied live from the underlying storage provider. Keep that in mind when designing your integration: a reference can exist while its provider is temporarily unavailable.
</Aside>

## Consuming the Service

The module registers a backend service under the id `document-management`. This is the **only** supported way for another module to read documents — never import directly from the `document-management` feature folder, or you break module isolation and the system can no longer detect a missing dependency.

### The public service interface

Document Management exposes a deliberately small, stable surface for cross-module use. The full interface (from `document-management.types.ts`) is reproduced here in its entirety:

```typescript
export interface DocumentManagementServiceInterface {
  /** Get the document references linked to a Structure node. */
  getDocumentsForNode(nodeId: string, userId: string): Promise<DocumentReference[]>;

  /** Get a single document reference (ownership-checked). */
  getDocument(documentId: string, userId: string): Promise<DocumentReference | null>;

  /** Get a readable download stream for a document's underlying file. */
  getDownloadStream(documentId: string, userId: string): Promise<Readable>;

  /**
   * Download a file directly by (providerId, remotePath) — the entry point for
   * upload-pipeline consumers that pull bytes for a documents.document.uploaded
   * event without going through a doc_document reference.
   */
  getDownloadStreamByPath(
    providerId: string,
    userId: string,
    path: string
  ): Promise<{ stream: Readable; fileName: string }>;

  /** Get live file metadata from the provider for a document. */
  getFileInfo(documentId: string, userId: string): Promise<FileInfo>;

  /** Count the documents linked to a Structure node. */
  getDocumentCount(nodeId: string, userId: string): Promise<number>;

  /**
   * Upload a file to the user's default provider (the user's own isDefault
   * provider, else the admin-set app-wide shared default). opts.folder is
   * honoured on EVERY target, resolved relative to the caller's effective
   * writable root (the provider root, or the per-user namespace u/<userId>/ on
   * an isolated shared default, where it is guarded against escape); omit it to
   * fall back to the provider's uploadPath, else basePath, else the root. Parent
   * folders are created as needed. Other modules (e.g. cog-ingest) pass folder
   * to direct where the file lands.
   */
  uploadToDefault(
    userId: string,
    fileName: string,
    file: Buffer | Readable,
    opts?: { folder?: string; mimeType?: string }
  ): Promise<UploadResult & { providerId: string }>;

  /**
   * Store a parsed artefact (external-parser output such as Docling JSON /
   * Markdown) for a source file. Versioned + checksummed; identical source
   * bytes (by contentHash) reuse the existing artefact instead of re-storing.
   * This module never parses — it only stores what a parser produced.
   */
  putParsedArtefact(userId: string, input: PutParsedArtefactInput): Promise<ParsedArtefact>;

  /**
   * Resolve a stored parsed artefact by source reference (documentId or
   * providerId+remotePath) and optional format/version. Returns metadata only;
   * pull the bytes with getParsedArtefactStream.
   */
  getParsedArtefact(
    userId: string,
    source: ArtefactSourceRef,
    opts?: GetParsedArtefactOptions
  ): Promise<ParsedArtefact | null>;

  /** All stored artefacts for a source, grouped by format, newest version first. */
  listParsedArtefacts(userId: string, source: ArtefactSourceRef): Promise<ParsedArtefact[]>;

  /** Readable stream of a stored artefact's bytes, by artefact id (ownership-checked). */
  getParsedArtefactStream(
    artefactId: string,
    userId: string
  ): Promise<{ stream: Readable; fileName: string; mimeType: string | null }>;

  /**
   * Request that a file be ingested into a knowledge base by re-emitting the
   * documents.document.uploaded pipeline event (the same path auto-ingest uses).
   * Ensures a stable reference (with contentHash) exists first. Inert when no
   * consumer subscribes; the returned enqueued flag reflects whether one was present.
   */
  requestIngest(
    userId: string,
    input: RequestIngestInput
  ): Promise<{ enqueued: boolean; documentId: string }>;

  /** Whether an upload-pipeline consumer (e.g. a knowledge base) is installed. */
  isIngestAvailable(): boolean;

  /**
   * Read-only provenance resolver for citations / chain-of-evidence.
   * Document-centric: resolve a documentId (or providerId+remotePath) to the
   * underlying document + latest parsed-artefact version per format. The ingest
   * engine's own sourceId never appears here. Returns null when the source
   * cannot be resolved. Never writes.
   */
  resolveProvenance(userId: string, ref: ProvenanceQuery): Promise<ProvenanceResult | null>;

  /** Whether the module is available (for optional detection by consumers). */
  isAvailable(): boolean;
}
```

The artefact, ingest, and provenance methods reference these input/result types — reproduced verbatim from `document-management.types.ts` so you can see the exact (flat) shapes:

```typescript
/**
 * Identifies the SOURCE file an artefact derives from — either by document id,
 * or by (providerId, remotePath). Provide one form.
 */
export interface ArtefactSourceRef {
  documentId?: string;
  providerId?: string;
  remotePath?: string;
}

export interface PutParsedArtefactInput extends ArtefactSourceRef {
  /** Artefact format, e.g. 'docling-json' | 'markdown' | 'text'. */
  format: string;
  /** The artefact bytes produced by the parser. */
  content: Buffer | Readable | string;
  mimeType?: string;
  /** What produced the artefact, e.g. 'docling@2.3.0'. */
  producer?: string;
  /** SHA-256 of the SOURCE file, if known (else read from an existing reference). */
  sourceContentHash?: string;
  metadata?: Record<string, unknown>;
  /**
   * Explicit artefact save location. When omitted, a derived writable area is
   * chosen automatically — artefacts never land on the original when it sits on
   * a read-only provider.
   */
  target?: { providerId: string; path?: string };
  /**
   * Optional Structure node id. When Structure is installed and its admin set a
   * "save location" field on this node, that folder is used as the artefact path
   * prefix (unless an explicit target is given).
   */
  nodeId?: string;
}

export interface GetParsedArtefactOptions {
  format?: string;
  /** A specific version; defaults to the latest. */
  version?: number;
}

export interface RequestIngestInput {
  documentId?: string;
  providerId?: string;
  remotePath?: string;
  /** Compute/refresh the source SHA-256 while ensuring the reference (default true). */
  computeHash?: boolean;
  /** Opaque hint forwarded to consumers (e.g. a target knowledge-base source). */
  hint?: Record<string, unknown>;
}

/** Provenance query — document-centric (a doc_document id, or providerId+remotePath). */
export interface ProvenanceQuery {
  documentId?: string;
  providerId?: string;
  remotePath?: string;
}

export interface ProvenanceResult {
  /** Always 'document-management' — identifies the citation's origin. */
  sourceType: string;
  document: DocumentReference | null;
  source: {
    providerId: string;
    remotePath: string;
    fileName: string;
    contentHash: string | null;
  };
  /** Latest stored artefact per format, newest first. */
  artefacts: ParsedArtefact[];
}
```

| Method | Returns | Description |
|--------|---------|-------------|
| `getDocumentsForNode(nodeId, userId)` | `Promise<DocumentReference[]>` | All document references linked to a Structure node, ownership-checked against `userId`. |
| `getDocument(documentId, userId)` | `Promise<DocumentReference \| null>` | A single reference, or `null` if it does not exist or is not owned by `userId`. |
| `getDownloadStream(documentId, userId)` | `Promise<Readable>` | A Node `Readable` of the underlying file, streamed live from the provider. |
| `getDownloadStreamByPath(providerId, userId, path)` | `Promise<{ stream: Readable; fileName: string }>` | A `Readable` (plus the derived `fileName`) for a provider path with no `doc_document` reference — how a job-worker consumer pulls the bytes for an uploaded file off the request path. |
| `getFileInfo(documentId, userId)` | `Promise<FileInfo>` | Live metadata (name, size, MIME type, timestamps) fetched from the provider. |
| `getDocumentCount(nodeId, userId)` | `Promise<number>` | The number of references linked to a node — cheaper than fetching them all. |
| `uploadToDefault(userId, fileName, file, opts?)` | `Promise<UploadResult & { providerId }>` | Upload a file to the user's default provider (own `isDefault`, else the admin-set shared default). `opts.folder` is honoured on **every** target — relative to the caller's effective root, nested under `u/<userId>/` on an isolated shared default (guarded against escape) — else the provider's `uploadPath`, else its root. Parent folders are created as needed. See [The upload contract](#the-upload-contract) — e.g. cog-ingest routes ingested files into an `Ingested/` folder. |
| `putParsedArtefact(userId, input)` | `Promise<ParsedArtefact>` | **Store** the output an external parser produced for a source (this module never parses). Bytes default to a derived writable area (`DOC_ARTEFACT_PREFIX`) unless `input.target` overrides; deduped by source `contentHash`. |
| `getParsedArtefact(userId, source, opts?)` | `Promise<ParsedArtefact \| null>` | Fetch the latest (or a given `format`/`version`) stored artefact for a source — so a consumer can re-ingest without re-parsing. |
| `listParsedArtefacts(userId, source)` | `Promise<ParsedArtefact[]>` | Every stored artefact for a source. |
| `getParsedArtefactStream(artefactId, userId)` | `Promise<{ stream: Readable; fileName: string; mimeType: string \| null }>` | Stream a stored artefact's bytes (ownership-checked), plus its `fileName` and `mimeType`. |
| `requestIngest(userId, input)` | `Promise<{ enqueued: boolean; documentId: string }>` | Ensure a durable reference exists (with `contentHash`), then re-emit `documents.document.uploaded` so manual ingest shares the auto-ingest job path. `enqueued` reflects whether a consumer was subscribed. |
| `isIngestAvailable()` | `boolean` | Whether an ingest consumer is subscribed to `documents.document.uploaded` (drives the **Ingest to KB** button visibility). Never names a specific consumer. |
| `resolveProvenance(userId, ref)` | `Promise<ProvenanceResult \| null>` | Read-only. Resolve a `documentId` (or `providerId`+`remotePath`) back to its document, source, and latest-per-format artefacts, for citations and chain-of-evidence — `null` when the source can't be resolved. Document-centric — the engine's own `sourceId` never appears here. |
| `isAvailable()` | `boolean` | Always `true` once registered; lets soft consumers confirm the module is present. |

The two return shapes you will work with most are `DocumentReference` and `FileInfo`. Both are reproduced in full so you do not have to import them just to read this page:

### Resolving the service (hard dependency)

If your module genuinely cannot function without Document Management, declare it with `requiredModules` in your `module.ts` and resolve the service with `serviceRegistry.get`:

```typescript
// src/module.ts (your module)
export const moduleDefinition: ModuleDefinition = {
  id: 'my-feature',
  name: 'My Feature',
  version: '1.0.0',
  requiredModules: ['document-management'],
  // ...
};
```

```typescript
// backend/src/features/my-feature/my-feature.service.ts
import { serviceRegistry } from '../../config/service.registry.js';

export const myFeatureService = {
  async listNodeFiles(nodeId: string, userId: string) {
    // Type-safe — the module augments ServiceTypes for 'document-management'
    const docs = serviceRegistry.get('document-management');
    return docs.getDocumentsForNode(nodeId, userId);
  },
};
```

<Aside type="caution" title="Never import across module boundaries">
Do NOT `import { documentManagementService } from '../../features/document-management/...'`. Always go through `serviceRegistry.get('document-management')`. The module augments `ServiceTypes` in its `service.registration.ts`, so `get('document-management')` is fully typed without any direct import.
</Aside>

### Resolving the service (soft dependency)

If Document Management is optional for your module, use `getOptional` and guard the result. This is exactly the pattern Document Management itself uses to detect Structure — so it is the idiomatic approach:

```typescript
// backend/src/features/my-feature/my-feature.service.ts
import { serviceRegistry } from '../../config/service.registry.js';
import type { DocumentManagementServiceInterface } from './types.js';

export const myFeatureService = {
  async maybeAttachFiles(nodeId: string, userId: string) {
    const docs = serviceRegistry.getOptional('document-management') as
      | DocumentManagementServiceInterface
      | undefined;

    if (!docs?.isAvailable()) {
      return [];               // degrade gracefully — module not installed
    }

    return docs.getDocumentsForNode(nodeId, userId);
  },
};
```

<Aside type="tip" title="get vs getOptional">
`serviceRegistry.get('document-management')` throws if the module is not installed — use it only when you have declared `requiredModules: ['document-management']`. `serviceRegistry.getOptional('document-management')` returns `undefined` when absent — use it for soft dependencies and always null-check before calling.
</Aside>

## Reacting to Events (Action Hooks Fired)

Document Management fires eight action hooks from its service as documents and providers change. Any module can subscribe with `actionRegistry.addActionAsync` and react — index a newly uploaded file, clean up derived data when a document is deleted, or refresh a cache when a provider connects.

The exact event ids and context shapes (from `action.registration.ts` and the service) are:

| Hook | Context | Fires when |
|------|---------|------------|
| `documents.document.linked` | `{ userId, documentId, nodeId, linkType }` | A document reference is linked to a Structure node. `linkType` is `'attachment' \| 'reference' \| 'primary'`. |
| `documents.document.unlinked` | `{ userId, documentId, nodeId }` | A document reference is unlinked from a node. |
| `documents.document.uploaded` | `{ userId, providerId, remotePath, fileName, mimeType, size, contentHash, documentId }` | A file is uploaded through the module, or manually re-emitted via `requestIngest`. Emitted as an **awaited async fan-out** (`doActionParallel`), so job-worker consumers receive it. `contentHash` is populated for streamed HTTP uploads (`null` for included-folder **Sync now**, which reads no bytes); `documentId` is set on the manual-ingest path (else `null`). |
| `documents.document.deleted` | `{ userId, documentId, providerId, remotePath }` | A document reference (and optionally its underlying file) is deleted. |
| `documents.document.created` | `{ userId, documentId, providerId, remotePath }` | A `doc_document` reference is created (favourite/link/tag/notes, or a cross-module `createDocument`). |
| `documents.document.updated` | `{ userId, documentId }` | A reference's tags, notes, favourite, or status changes. |
| `documents.provider.connected` | `{ userId, providerId, providerType }` | A storage provider is created/connected. `providerType` is `s3 \| r2 \| webdav \| local`. |
| `documents.provider.disconnected` | `{ userId, providerId }` | A storage provider is removed. |

### Subscribing to a fired hook

```typescript
// backend/src/features/my-feature/action.registration.ts
import { actionRegistry } from '../../config/action.registry.js';
import { myFeatureService } from './my-feature.service.js';

// Index every file uploaded through Document Management
actionRegistry.addActionAsync(
  'documents.document.uploaded',
  'my-feature-index-upload',
  async (context) => {
    const { userId, providerId, remotePath, fileName } =
      context as { userId: string; providerId: string; remotePath: string; fileName: string };
    await myFeatureService.indexFile(userId, providerId, remotePath, fileName);
  },
  30 // priority — Document Management's own Structure subscriptions run at 20
);

// React when a document reference is deleted (clean up derived data)
actionRegistry.addActionAsync(
  'documents.document.deleted',
  'my-feature-cleanup-on-delete',
  async (context) => {
    const { userId, documentId } = context as { userId: string; documentId: string };
    await myFeatureService.removeDerivedData(userId, documentId);
  },
  30
);
```

<Aside type="note" title="Hooks are inert until something fires them">
These hooks are emitted by the Document Management service itself, so they always fire when the module is installed — no Structure dependency required. If your subscriber is registered but Document Management is not installed, nothing ever calls your listener, which is harmless.
</Aside>

## Structure Hook Subscriptions

Document Management is a **standalone** module — Structure is optional and detected at runtime. When Structure *is* installed, the module keeps its document links and references in sync with node lifecycle events by subscribing to three Structure action hooks. All three are registered at priority `20` and are completely inert when Structure is absent (nothing emits the hooks).

| Subscribed hook | Context | What Document Management does |
|-----------------|---------|-------------------------------|
| `structure.node.deleted` | `{ userId, nodeId, nodeType }` | Calls `handleNodeDeleted(nodeId, userId)` — removes the `doc_node_link` rows for that node so links don't dangle. The document references themselves survive. |
| `structure.node.archived` | `{ userId, node }` | Calls `handleNodeArchived(node.id, userId)` — sets `status = 'archived'` on `doc_document` references linked to the node. |
| `structure.node.moved` | `{ userId, node, oldParentId, newParentId }` | Calls `handleNodeMoved(node.id, userId)` — nulls `lastSyncedAt` on the linked documents so cached context is refreshed on next access. |

This is the relevant slice of `action.registration.ts`:

```typescript
import { actionRegistry } from '../../config/action.registry.js';
import { documentManagementService } from './document-management.service.js';

// Clean up document links when a node is deleted.  Context: { userId, nodeId, nodeType }
actionRegistry.addActionAsync(
  'structure.node.deleted',
  'document-management-node-deleted',
  async (context) => {
    const { userId, nodeId } = context as { userId: string; nodeId: string };
    await documentManagementService.handleNodeDeleted(nodeId, userId);
  },
  20
);

// Archive linked documents when a node is archived.  Context: { userId, node }
actionRegistry.addActionAsync(
  'structure.node.archived',
  'document-management-node-archived',
  async (context) => {
    const { userId, node } = context as { userId: string; node: { id: string } };
    await documentManagementService.handleNodeArchived(node.id, userId);
  },
  20
);

// Refresh cached context when a node moves parent.  Context: { userId, node, oldParentId, newParentId }
actionRegistry.addActionAsync(
  'structure.node.moved',
  'document-management-node-moved',
  async (context) => {
    const { userId, node } = context as { userId: string; node: { id: string } };
    await documentManagementService.handleNodeMoved(node.id, userId);
  },
  20
);
```

<Aside type="tip" title="Soft Structure detection at the data layer too">
Beyond these hooks, the service also calls `serviceRegistry.getOptional('structure')` inside `linkDocument` to verify a node exists before creating a `doc_node_link`. If Structure is absent, that check is skipped and links are created without node validation. Your module gets the same graceful-degradation behaviour for free if you follow the `getOptional` pattern above.
</Aside>

## Raw document location on the node

When a document is linked to a node, Document Management records the document's **raw storage location** on that node — so anything looking at the node (cog-ingest, an evidence trail, another module) can find the source file **without calling back into this module**. This is a backend, optional-Structure integration: it goes through `serviceRegistry.getOptional('structure')` (no `@/features/structure` import), is best-effort, and is inert when Structure is absent.

`linkDocument` writes one entry **per document**, keyed `doc_<documentId>`, into the isolated `document-management` metadata namespace:

```typescript
// Written by document-management on link (best-effort, via the optional service):
await structureService.updateNodeMetadata(nodeId, userId, 'document-management', {
  ['doc_' + documentId]: {
    documentId,
    providerId,     // the storage provider the file lives on
    remotePath,     // the file's path within that provider
    fileName,
    mimeType,       // may be null
    linkType,       // 'attachment' | 'reference' | 'primary'
  },
});
```

Unlinking sets that key to `null`. Read it back off the node — metadata is returned on `getNode()`:

```typescript
const node = await structureService.getNode(nodeId, userId);
const docs = node?.metadata?.['document-management'] ?? {};
// { doc_<id>: { documentId, providerId, remotePath, fileName, mimeType, linkType }, ... }
for (const [, loc] of Object.entries(docs)) {
  if (!loc) continue;                       // null = an unlinked (removed) entry
  // loc.providerId + loc.remotePath is the raw source file
}
```

<Aside type="note" title="Location vs reference vs provenance">
Three ways to reach a node's source files, by increasing indirection: this **node metadata** (the location sits on the node, zero extra calls); the module's own `doc_node_link` + `getDocument(documentId)` (a query into document-management); and `resolveProvenance({ documentId })` (adds the parsed-artefact chain for citations). Use the node metadata when you only need "where does this node's raw file live".
</Aside>

<Aside type="caution" title="It records where a file IS, not where new uploads GO">
This is the *individual document's* saved location, recorded per link. Choosing a **destination folder for new uploads** to a node — e.g. routing every upload under a node-type folder — is a separate, planned feature; see the [roadmap](/document-management/roadmap/#planned-improvements).
</Aside>

## Structure Registry Registrations

When Structure is installed, Document Management contributes a full set of UI extensions to node pages: a Documents tab, an Overview widget, a card badge, two header actions, a sidebar section, and a per-node parsed-artefact save-location field. Each is generated as its own registration file under `registrations/`.

<Aside type="caution" title="Commented out by default — you must enable them">
The Structure registrations import from `@/features/structure`, which does not exist in a standalone install — so the side-effect imports are **commented out** in the generated `index.ts`. After installing Structure, uncomment them to activate the integration. The backend action subscriptions above need no such gating; they are inert without Structure but always compile.
</Aside>

This is the block you uncomment in `frontend/src/features/document-management/index.ts`:

```typescript
// ────────────────────────────────────────────────────────────────────────
// STRUCTURE INTEGRATION (optional)
// These registrations import from '@/features/structure'. Uncomment them
// only when the Structure module is installed; otherwise the build cannot
// resolve the import.
// ────────────────────────────────────────────────────────────────────────
// import './registrations/structure-tabs.registration';
// import './registrations/structure-widgets.registration';
// import './registrations/structure-cards.registration';
// import './registrations/structure-actions.registration';
// import './registrations/structure-sidebar.registration';
// import './registrations/structure-fields.registration';
```

<Steps>

1. **Install Structure** into the same app (`npx structure init` or your equivalent), so `@/features/structure` resolves.

2. **Uncomment the six side-effect imports** shown above in the module's `index.ts`.

3. **Rebuild the frontend.** The Documents tab, node widget, card badge, the two header actions, the Pinned Documents sidebar section, and the per-node save-location field now appear on node detail pages, cards, and node-type configuration.

</Steps>

## The upload contract

There are two ways bytes enter a provider through this module, and one resolution rule they both obey. If you are a consumer (cog-ingest, ai-chat, an evidence importer), this section is the whole contract.

**Entry points**

| Caller | Provider chosen | Destination |
|--------|-----------------|-------------|
| `upload(providerId, userId, path, file, metadata?)` (service) / `POST /upload/:providerId?path=` | The named provider, **ownership-checked** against `userId`. | `path` names the full destination (folder + filename), as given. |
| `uploadToDefault(userId, fileName, file, opts?)` (service) / `POST /upload?fileName=&folder=` | The user's own `isDefault` provider; **else** the admin-set app-wide shared default; else `BadRequestError`. | `opts.folder` (relative to the effective root, below), else `uploadPath`, else `basePath`, else the root. `fileName` is a basename. |

**The resolution rule for `uploadToDefault`.** `opts.folder` is honoured on **every** target — it is the destination folder *relative to the caller's effective writable root*. What that root is, and how `fileName` is treated, depends on the target:

| Target | Effective root | `opts.folder` | `fileName` |
|--------|----------------|---------------|------------|
| **Owned provider** (caller's own `isDefault`) | The provider root | Used relative to the root; replaces `uploadPath` when supplied | Joined as given (the caller owns the store) |
| **Shared default, isolation ON** (the default policy) | The per-user namespace `u/<userId>/` | Nested **under** the namespace, and **guarded** — a value that would escape `u/<userId>/` is rejected with `ForbiddenError` | Reduced to a **basename** (any path parts / traversal stripped) |
| **Shared default, isolation OFF** (communal opt-out) | The provider root | Used relative to the root; replaces `uploadPath` when supplied | Reduced to a **basename** |

When `opts.folder` is omitted, the destination is the provider's configured `uploadPath`, else its `basePath`, else the root — on every target. Parent folders are **created as needed** (S3 is key-addressed so folders are implicit; Local and WebDAV create the parent collection before writing).

<Aside type="tip" title="Why a consumer wants opts.folder to always work">
cog-ingest routes its uploads into a dedicated folder (e.g. `Ingested/`) so it can recognise and **skip** them on a catch-all auto-ingest source — the folder is the marker that a file is already in flight, which is what makes the double-ingest guard reliable. That only holds if the folder is honoured wherever the file lands, including when the user has no provider of their own and falls through to the shared default. It is, on both the isolated and communal shared default.
</Aside>

**Side effects (both entry points).** A successful write records a `doc_recent_access` `upload` row and emits the awaited async `documents.document.uploaded` event (a storage *reference*, never bytes). `uploadToDefault` on the **shared** default additionally upserts an **owned** `doc_document` reference (idempotent on `(userId, providerId, remotePath)`) so the user can find and download their file — they cannot `createDocument` against a provider they don't own, so this trusted server-side write is the only path to a browsable reference there.

<Aside type="caution" title="Document visibility is per-user in V1 — even on a communal shared default">
The isolation toggle governs where **bytes** land, not who can **see** them. Every `doc_document` reference is `userId`-scoped and browsing the shared provider is never granted to non-owners, so a file one user uploads to the shared default is not visible to other users — even in communal (isolation-off) mode. An admin-managed area that is *readable by everyone* is a distinct, not-yet-built capability (cross-user shared visibility); see the [roadmap](/document-management/roadmap/#planned-improvements). For per-user private folders on a shared NAS, keep isolation **on** — each user (admins included) gets their own `u/<userId>/` root automatically.
</Aside>

```typescript
// A consumer routing an upload into a chosen folder, wherever the file lands:
const dm = serviceRegistry.get('document-management') as DocumentManagementServiceInterface;
const { path, providerId } = await dm.uploadToDefault(userId, fileName, bytes, {
  folder: 'Ingested',          // → owned: <root>/Ingested/…; shared+isolated: u/<userId>/Ingested/…
  mimeType: 'application/pdf',
});
```

## Node-type upload destinations

Where a raw document *is* (recorded above) is the complement of where new uploads *go*. An admin can map a Structure node **type** to a folder **template**, so uploads for a node of that type land in a derived folder — set once per type, not per node.

An admin manages the mapping on `/admin/documents` (the **Node-type upload folders** card), or via the API:

| Method | Route | Who |
|--------|-------|-----|
| `GET` | `/node-upload-locations` | admin (the upload flow resolves templates server-side, not via HTTP) |
| `PUT` | `/node-upload-locations` | admin — body `{ nodeType, folderTemplate }` (upsert) |
| `DELETE` | `/node-upload-locations/:nodeType` | admin |

The template supports these variables, each substituted with a value reduced to a single safe path segment (separators collapsed, traversal neutralised):

| Variable | Resolves to |
|----------|-------------|
| `{nodeType}` | the node's type |
| `{nodeId}` | the node's id |
| `{nodeName}` | the node's name (falls back to title / label) |

Set `nodeType` to `*` for a catch-all default. Examples: `{nodeType}` (a flat per-type folder — `client/…`) or `Clients/{nodeName}` (a per-node subfolder under a fixed root).

A consumer routes an upload into the node's folder by passing `nodeId` to `uploadToDefault` (or `?nodeId=` on `POST /upload`); the Structure **Upload File** action already does. An explicit `opts.folder` still wins; otherwise the node-type template resolves the folder:

```typescript
// Upload for a node — lands in that node type's configured folder (if any):
await dm.uploadToDefault(userId, fileName, bytes, { nodeId, mimeType });
// Precedence: opts.folder > node-type template (nodeId) > uploadPath > basePath > root.
```

<Aside type="note" title="Optional, safe, and namespace-guarded">
The node's type / name is read through `serviceRegistry.getOptional('structure')` — no `@/features/structure` import, and resolution is inert (falls back to `uploadPath` / root) when Structure is not installed or the node is unreachable. The resolved template still flows through [the upload contract](#the-upload-contract): on a shared+isolated default it nests under `u/<userId>/` and is rejected if it would escape, so neither a template nor a node name can climb out of a user's namespace.
</Aside>

## Global uploads (admin)

Every path above lands a file in the uploading user's own space (their provider, or their `u/<userId>/` namespace on the shared default). **Global uploads** are the exception: an admin stores a file in a shared **global** space on the app-wide shared default, **outside** any user's namespace — for content that belongs to the whole app (e.g. a global knowledge base to ingest), not to one user.

```typescript
const dm = serviceRegistry.get('document-management') as DocumentManagementServiceInterface;
// Admin-authorized context only:
const { path, providerId } = await dm.uploadGlobal(userId, fileName, bytes, {
  folder: 'kb',        // optional — nested UNDER the global prefix
  mimeType,
});
// stored at <DOC_GLOBAL_PREFIX>/kb/<fileName> on the shared default (default prefix: "global/")
```

- **Where it lands:** the shared default provider, under `DOC_GLOBAL_PREFIX` (default `global`), never under a `u/<userId>/` namespace. A shared default must be configured. `opts.folder` / `opts.nodeId` still apply, nested under the global prefix.
- **Admin-only.** `opts.global` on `uploadToDefault` is a **trusted** flag that bypasses per-user isolation, so callers must authorize it. Over HTTP that's `POST /upload-global?fileName=&folder=&nodeId=`, gated by `requireAdmin` (the ordinary `POST /upload` never sets it). The destination is still guarded to stay within the global prefix.
- **Pipeline:** it emits the same `documents.document.uploaded` event, so cog-ingest ingests global content exactly like any other upload. How cog-ingest scopes the resulting KB entry is decided on its side.
- **Component:** `<DocumentUpload global />` uploads to the global space from an admin UI.

<Aside type="caution" title="Storage, not (yet) global visibility">
This is the storage half. Reads are **reference-gated**: the uploading **admin** owns the `doc_document` reference, so they — and a process pulling as them, e.g. cog-ingest via `getDownloadStreamByPath` — can read the global file back, but a regular user (who holds no reference to it) cannot yet browse or download the global space. Full cross-user visibility (global-scoped references so *everyone* sees them) is a planned follow-up; see the [roadmap](/document-management/roadmap/#planned-improvements).
</Aside>

## Worked Example: Requesting a Reference and Download Stream

A common pattern for processing modules such as `cog-ingest` or `ai-chat` is: create a **stable document reference** (which gives you a durable `documentId` to record as a source), then later fetch the **download stream** to read the bytes. Creating the reference also computes a SHA-256 `contentHash` for integrity, which is exactly what an evidence or provenance trail wants.

<Tabs>
  <TabItem label="cog-ingest">

```typescript
// backend/src/features/cog-ingest/cog-ingest.service.ts
import { serviceRegistry } from '../../config/service.registry.js';

export const cogIngestService = {
  async ingestProviderFile(
    userId: string,
    providerId: string,
    remotePath: string,
    fileName: string,
  ) {
    const docs = serviceRegistry.getOptional('document-management');
    if (!docs?.isAvailable()) {
      throw new Error('Document Management is required to ingest provider files');
    }

    // 1. Create a stable reference. We get a durable documentId + contentHash
    //    to record for provenance, so a citation can resolve back to this
    //    document via docs.resolveProvenance({ documentId }). createDocument is
    //    part of the full service; request computeHash for an evidence trail.
    const ref = await (docs as any).createDocument(userId, {
      providerId,
      remotePath,
      fileName,
      computeHash: true,        // server-side SHA-256 at creation
    });

    // 2. Later (or immediately), pull the bytes via the public interface.
    const stream = await docs.getDownloadStream(ref.id, userId);

    // 3. Feed the stream into the cognitive pipeline. Record the Document
    //    Management documentId for provenance — this is DISTINCT from
    //    cog-ingest's own sourceId (which ingest *configuration*): the documentId
    //    is what resolveProvenance resolves, the sourceId never crosses to DM.
    await this.processStream(stream, {
      documentId: ref.id,
      contentHash: ref.contentHash,
      mimeType: ref.mimeType,
    });

    return { documentId: ref.id, contentHash: ref.contentHash };
  },
};
```

  </TabItem>
  <TabItem label="ai-chat">

```typescript
// backend/src/features/ai-chat/ai-chat.tools.ts
import { serviceRegistry } from '../../config/service.registry.js';

// An AI tool that lets the assistant read a node's documents
export async function readNodeDocuments(nodeId: string, userId: string) {
  const docs = serviceRegistry.getOptional('document-management');
  if (!docs?.isAvailable()) return { available: false, documents: [] };

  const refs = await docs.getDocumentsForNode(nodeId, userId);

  // Stream the first text-like document into the model context
  const textDoc = refs.find((r) => r.mimeType?.startsWith('text/'));
  if (!textDoc) return { available: true, documents: refs, content: null };

  const stream = await docs.getDownloadStream(textDoc.id, userId);
  const content = await streamToString(stream);

  return { available: true, documents: refs, content };
}
```

## Parsed Artefacts & Provenance

A processing module such as `cog-ingest` does more than read bytes — it **parses** a source (e.g. through a Docling sidecar) into an extraction/chunking artefact, and later needs to re-ingest, re-extract, or re-chunk **without re-running the expensive parse**. Document Management provides a durable place to keep that output, and a read-only resolver that turns an ingest source back into a citable provenance chain.

<Aside type="note" title="This module stores artefacts — it never parses them">
Document Management does **not** parse content. `putParsedArtefact` only **stores** the output your parser produced, and hands it back on demand. This keeps the connector principle intact: the module manages references, storage, and now the parsed-artefact byproducts, but content extraction stays entirely in the producing module.
</Aside>

### Storing and reusing an artefact

The producer calls `putParsedArtefact` **in-process** via `serviceRegistry.get('document-management')` — there is deliberately no HTTP `PUT` for artefacts. Bytes default to a **derived writable area** (`DOC_ARTEFACT_PREFIX`, default `.derived-artefacts`) so the original source — which may sit on a read-only/evidence provider — is never written to; pass `input.target` to steer them elsewhere (e.g. a Structure-configured save location). Artefacts are deduped by the source `contentHash`, so identical source bytes reuse the existing row.

```typescript
// backend/src/features/cog-ingest/cog-ingest.service.ts
import { serviceRegistry } from '../../config/service.registry.js';

export const cogIngestService = {
  async ensureArtefact(userId: string, providerId: string, remotePath: string, contentHash: string) {
    const docs = serviceRegistry.get('document-management');

    // 1. Reuse the stored artefact if this exact source has already been parsed.
    const existing = await docs.getParsedArtefact(userId, { providerId, remotePath }, { format: 'docling-json' });
    if (existing) return existing;               // re-ingest without re-parsing

    // 2. Otherwise parse once (Docling sidecar), then STORE the output here.
    //    getDownloadStreamByPath returns { stream, fileName } — destructure it.
    const { stream } = await docs.getDownloadStreamByPath(providerId, userId, remotePath);
    const doclingJson = await this.parseWithDocling(stream);

    // Input is FLAT: the source ref (providerId/remotePath or documentId) plus
    // sourceContentHash are top-level fields — there is no nested `source` and
    // no `version` (versions are allocated server-side).
    return docs.putParsedArtefact(userId, {
      providerId,
      remotePath,
      sourceContentHash: contentHash,
      format: 'docling-json',
      producer: 'cog-ingest/docling',
      content: Buffer.from(JSON.stringify(doclingJson)),
      mimeType: 'application/json',
    });
  },
};
```

<Aside type="note" title="Per-node save location (Structure)">
`putParsedArtefact` input also accepts an optional **`nodeId`**. When Structure is installed and an admin has set the per-node **save location** field (`document-management.artefact_save_location`, registered via `structureRegistry.register` with `editableBy: 'admin'`), a producer that knows which node it is ingesting into — cog-ingest — passes `nodeId`, and that node's configured folder becomes the artefact path prefix (still namespace-guarded on shared providers). With no Structure, or no folder configured, artefacts fall back to the derived `DOC_ARTEFACT_PREFIX` default. This is the ergonomic seam that `input.target` left open — you set the location once per node rather than passing an explicit `target` on every call.
</Aside>

### Resolving provenance for citations

When assembled chat context or the Evidence Manager needs to cite a chunk, `resolveProvenance` resolves a **documentId** (the one a consumer such as cog-ingest recorded for the chunk's source) back to the underlying document, its source reference, and the latest artefact per format — all read-only.

```typescript
const provenance = await docs.resolveProvenance(userId, {
  documentId,                          // a doc_document id (providerId+remotePath is also accepted)
});
// → { sourceType: 'document-management', document, source: { providerId, remotePath, fileName, contentHash }, artefacts }
// Use `source.contentHash` + the recent-access trail for a defensible chain of evidence.
```

### HTTP routes

Artefact **writes** never cross the network. These read/action routes exist for consumers and UI:

| Method | Endpoint | Purpose |
|--------|----------|---------|
| POST | `/ingest` | Manual ingest — ensures a reference and re-emits `documents.document.uploaded` (returns `202 Accepted`). |
| GET | `/ingest/available` | Whether an ingest consumer is installed (`isIngestAvailable`). |
| GET | `/artefacts?documentId=\|providerId=&remotePath=` | List the parsed artefacts stored for a source. |
| POST | `/artefacts/prune` | **Admin-only.** Apply the artefact retention policy (`keepVersions` + `maxAgeDays`) across all users now. |
| GET | `/artefacts/:id/download` | Stream a stored artefact's bytes. |
| GET | `/provenance?documentId=` | Read-only provenance resolution for citations (or `providerId`+`remotePath`). |

### The provenance contract (agreed)

The contract is **document-centric**, with a clean split of ownership:

| Side | Owns | Carries for provenance |
|------|------|------------------------|
| Document Management | the `documentId` (a `doc_document.id`) | `resolveProvenance({ documentId })` → document + source + latest-per-format artefacts. |
| cog-ingest | its own `sourceId` (which ingest *configuration*) — engine-side only | records the Document Management **`documentId`** for each ingested source and stamps it on derived entities/chunks, then passes it to `resolveProvenance` when a citation is requested. |

The `documentId` is what `requestIngest` and reference-creation (`createDocument`) return. cog-ingest's `sourceId` (a *source-configuration* id) is a separate concept that **never crosses to Document Management** — this API takes a `documentId`, not a `sourceId`.

Given a `documentId`, `resolveProvenance` returns the document reference, the `source` (`providerId`, `remotePath`, `fileName`, `contentHash`), and the latest parsed artefact per format — enough to render a citation ("from *fileName*, SHA-256 *hash*") and to fetch the stored parsed copy for re-extraction. A `{ providerId, remotePath }` form is accepted when no `documentId` is available.

<Aside type="note" title="Resolved in v1.5.1">
An earlier draft of this contract had Document Management accept a `sourceType`/`sourceId` pair, which collided with cog-ingest's own `sourceId` (its ingest configuration). That is resolved: the Document Management provenance API is now purely `documentId`-based, so `sourceId` never appears on this side. cog-ingest keeps and passes the `documentId` it received when creating the reference.
</Aside>

```typescript
// backend/src/features/contract-review/contract-review.service.ts
import { serviceRegistry } from '../../config/service.registry.js';
import { prisma } from '../../config/prisma.js';

export const contractReviewService = {
  // Pull every document on a node and queue a review for each
  async queueReviewsForNode(nodeId: string, userId: string) {
    const docs = serviceRegistry.get('document-management');
    const refs = await docs.getDocumentsForNode(nodeId, userId);

    for (const ref of refs) {
      const fileInfo = await docs.getFileInfo(ref.id, userId);
      await prisma.cr_review.create({
        data: {
          userId,
          nodeId,                       // plain string FK — no @relation
          documentId: ref.id,          // plain string FK to doc_document
          fileName: ref.fileName,
          fileSize: fileInfo.size ?? null,
          status: 'queued',
        },
      });
    }
  },

  // Actually read the bytes when a review runs
  async runReview(documentId: string, userId: string) {
    const docs = serviceRegistry.get('document-management');
    const stream = await docs.getDownloadStream(documentId, userId);
    return this.analyse(stream);
  },
};
```

```typescript
// backend/src/features/contract-review/action.registration.ts
import { actionRegistry } from '../../config/action.registry.js';
import { contractReviewService } from './contract-review.service.js';

// When a new file is uploaded, queue a contract review automatically
actionRegistry.addActionAsync(
  'documents.document.uploaded',
  'contract-review-on-upload',
  async (context) => {
    const { userId, providerId, remotePath, fileName } =
      context as { userId: string; providerId: string; remotePath: string; fileName: string };
    if (fileName.toLowerCase().endsWith('.pdf')) {
      await contractReviewService.queueFromUpload(userId, providerId, remotePath, fileName);
    }
  },
  30,
);

// When a document reference is deleted, discard its pending reviews
actionRegistry.addActionAsync(
  'documents.document.deleted',
  'contract-review-on-delete',
  async (context) => {
    const { userId, documentId } = context as { userId: string; documentId: string };
    await contractReviewService.cancelReviews(userId, documentId);
  },
  30,
);
```

## Integration Checklist

Use this when building a module that integrates with Document Management:

- [ ] **Dependency declared** — `requiredModules: ['document-management']` for a hard dependency, or `getOptional` + `isAvailable()` guards for a soft one.
- [ ] **Service access via the registry** — `serviceRegistry.get('document-management')` (or `getOptional`), never a direct feature-folder import.
- [ ] **Public interface only where possible** — prefer the `DocumentManagementServiceInterface` methods; treat anything beyond them (e.g. `createDocument`) as tighter coupling.
- [ ] **Event subscriptions** — `addActionAsync` on the `documents.*` hooks you care about, with priority 30+ (the module's own subscriptions run at 20).
- [ ] **Provenance** — pass `computeHash: true` when creating references for evidence/audit use, and persist the returned `contentHash`.
- [ ] **Graceful degradation** — never assume Document Management (or Structure) is present; check `isAvailable()` and handle absence.
- [ ] **Self-contained schema** — reference `documentId` / `nodeId` with plain string fields and `@@index`, never `@relation`.

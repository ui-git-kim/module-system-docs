A running log of **archive-readiness audits**. Before a working session on the Document Management module is archived, it is audited for anything that would be lost — unfinished work, loose ends, decisions, and ideas — and the findings are recorded here so a fresh session can pick them straight up.

<Aside type="note" title="Why this page exists">
Session transcripts get archived and are then awkward to search. This page is the durable, reviewable home for "what was in that session" — decisions and their reasoning, ideas raised in passing, work left mid-flight, and anything the code and the rest of these docs don't already capture. Newest entry first. Nothing here is deleted; when an item is actually done, it's ticked and left in place for provenance.
</Aside>

## How to use this page

At the end of a session you want to archive, run the archive-readiness prompt (below). It audits the session and **appends a new entry at the top** of the log, using the entry template. Then it builds and pushes the docs. Review the entry on the live site; archive the session; start the next one by reading the open items here.

### The prompt

> **Archive-readiness check.** Audit this session end-to-end for anything that would be lost if I archive it: (1) unfinished work — started-not-finished, committed-not-pushed, coded-not-validated, or left WIP (check `git status` and recent commits in every repo touched, including the `docs/` submodule — **and if this is an older session the repo has since moved past, expect HEAD, the version number, and the working tree to look _newer_ than this session's output, and its commits to sit deep in history, absent from a short `git log`/reflog window; that is normal forward progress, not loss. Confirm the work survived by identifying this session's own commits from the transcript and checking each is an ancestor of `origin/main` (`git merge-base --is-ancestor <sha> origin/main`) — reachable from origin means preserved even though HEAD is far ahead. Real loss is only a commit that is on no branch _and_ absent from `origin`; do not infer loss from "HEAD isn't at my version" or "the working tree differs from what I edited"**); (2) loose ends — TODOs, "later" items, deferred fixes, promised follow-ups, checks I said I'd run; (3) decisions & ideas — any decision, trade-off, rejected approach and *why*, or idea raised in conversation not already written in code or docs; (4) undocumented reality — anything we changed or learned the docs don't reflect. Then **append a new entry to the top of the Archive Audit log** (`docs/src/content/docs/document-management/archive-audit.mdx`) using the entry template already on that page. Build the docs, push the docs submodule **and** the submodule pointer. Verify before ticking anything "done" (if a version was bumped, confirm `dist` was rebuilt after the bump; for an older session, confirm `dist` — if gitignored — stamps the **current HEAD** version, not the session's). Finish by telling me plainly whether it's safe to archive.

### Entry template

```mdx
## YYYY-MM-DD — <session focus>

**Verdict:** ✅ Safe to archive  ·  ⚠️ Needs input first  ·  ℹ️ Superseded (work integrated, session now historical)
**Shipped this session:** <version(s), key commits, what went live>

**Unfinished / WIP:** <or "none">
**Loose ends & follow-ups:** <deferred fixes, promised checks, TODOs — or "none">
**Decisions & ideas:** <decisions + why, rejected approaches, ideas raised — or "none">
**Recorded where:** <docs pages / memory files updated, so it's findable>
**Open items for next session:** <the pick-up list — or "none">
```

## 2026-09-03 — Upload & location features: shared-folder fix, node metadata, node-type folders, global uploads

**Verdict:** ✅ Safe to archive
**Shipped this session:** v1.5.4 → v1.7.0 (five releases), all built, verified, and pushed. Module `d43c3d9` (v1.7.0); docs `73a18f4`. Nothing unpushed; both working trees clean.

- **v1.5.4** — `uploadToDefault` honours `opts.folder` on the shared app-default (was owned-only); `WebDAVAdapter.upload` pre-creates parent folders (closed a Known Issue); the upload contract stated in one place.
- **v1.5.5** — conformance reconciliation: CRUD hooks now `doActionParallel` (C18, 7 sites — async consumers fire); service version `{{moduleVersion}}` (C10).
- **v1.5.6** — `linkDocument` records each linked document's raw storage location onto the Structure node's namespaced metadata via the **optional** structure service (no `@/features/structure` import); `unlinkDocument` clears it.
- **v1.6.0** — node-type upload destinations: admin maps a node **type** → folder **template** (`{nodeType}`/`{nodeId}`/`{nodeName}`, `*` default) in a new `doc_node_type_upload_location` table; `uploadToDefault` gained `nodeId`.
- **v1.7.0** — admin **global uploads** (storage slice): `uploadGlobal` / admin-only `POST /upload-global` store under `DOC_GLOBAL_PREFIX` on the shared default, outside any user namespace; reference-gated read carve-out in `resolveFileProvider`; `updateDocument` hardened to a field whitelist.

**Unfinished / WIP:** none. Every release passed `check:templates` / `type-check` / `conformance` / `build`, and each security-sensitive change was adversarially verified by multi-agent workflows (no namespace escape / cross-tenant read found; low-severity findings folded in).

**Loose ends & follow-ups:**
- Conformance sits at **6 violations by design** — the six optional Structure frontend registrations ship with commented-out imports (a frontend bundle can't guard an unresolvable `@/features/structure` import). No opt-out exists in the contract; logged to the [module-starter upstream-issues](/module-starter/upstream-issues/) page. Do **not** "fix" by adding active imports — it breaks standalone installs.
- Earlier-session task chips (conformance reconciliation; node-type feature) were completed and superseded by the work above.
- Scaffold update available (module on 1.31.11; 1.31.17 offered) — infra-only, deferred.

**Decisions & ideas:**
- **`doActionParallel` over `doActionAll`** for CRUD hooks — matches the module's existing `uploaded` hook and gives per-consumer error isolation so a downstream consumer can't fail a CRUD op; both satisfy the linter.
- **Node-type, not per-node, folders** — most nodes hold one document, so per-node folders would wrap a single file; a type with several docs uses a sub-templated path (`{nodeType}/{nodeName}/`). Per-document location is recorded separately (v1.5.6).
- **Global docs are NOT multi-tenant** — deployment is solo (`tenantId === userId` as the isolation key); global = a deliberate shared space for ingesting global content. Storage half shipped; **read is reference-gated** (admin + cog-ingest can pull; a regular user holds no reference, so can't); full cross-user browse visibility deferred (low priority).
- **Local Connect pulled forward** — connecting a local folder (raw never leaves the machine, ingestible, reachable only while connected) is the existing roadmap "Local Connect companion app", raised to pre-beta priority for the legal use case.
- Gotchas recorded: a stray backtick **inside a template comment** broke `SERVICE_TEMPLATE` (caught by `type-check`, NOT `check:templates`, which only flags `${`); `resolveFileProvider` is the security-critical isolation guard — verify any change adversarially.

**Recorded where:** docs — `document-management/` changelog, roadmap, integration; `module-starter/upstream-issues` (the C2 gap). Memory — `dm-upload-contract-v154`, `dm-conformance-drift-pending`, `dm-local-connect-and-priorities`, `MEMORY.md`.

**Open items for next session (priority order):**
1. **Local Connect** (pre-beta, legal use case) — companion app is a separate repo (`unique-local-connect`); DM-side follow-ups noted on the roadmap ("Local Connect companion app" callout) + the `dm-local-connect-and-priorities` memory.
2. **`{nodePath}`** template variable — extends `resolveNodeUploadLocation` in `src/templates/backend/services.ts`; needs Structure to expose the node ancestor chain.
3. **Full cross-user global visibility** (low) — global-scoped references + a read carve-out for all users; needs adversarial review.

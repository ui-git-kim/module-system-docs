Document Management ships a **self-contained** Prisma schema: eight tables, all prefixed with `doc_` — `doc_storage_provider`, `doc_document`, `doc_node_link`, `doc_folder_bookmark`, `doc_recent_access`, `doc_app_settings`, `doc_included_folder`, and `doc_parsed_artefact`. The schema adds **no `@relation` directives** and never modifies the `User` model or the Structure module's tables. Foreign keys to other modules (the owning user, a Structure node) are stored as plain `String` fields with `@@index` for fast lookups.

<Aside type="note" title="Connector, not storage">
These tables hold **references, metadata, and your organisation** of files (favourites, tags, node links, audit trail). They never store your files — the bytes stay in the external storage provider. The one exception is `doc_generation_template` (v1.19.0+), which holds the small Word templates an admin adds for making documents. `doc_document` is a pointer to a file that lives in S3, WebDAV, or a local folder.
</Aside>

The scaffold appends these models to your app's Prisma schema at `init` and **applies the schema migrate for you** — no manual migrate step is needed. As of module-starter scaffold **v1.31.9** it does this the drift-immune way (an offline `prisma migrate diff` → a real migration file → `prisma migrate deploy`, so a shared DB with runtime-created objects is never reset); older scaffolds ran `prisma migrate dev` at `init`. Avoid running `prisma migrate dev` by hand on an app that carries runtime-created DB objects — use `prisma migrate deploy` if you ever need to apply migrations manually.

## `doc_storage_provider`

A configured connection to an external storage service. The `config` column holds **AES-256-GCM encrypted JSON** (credentials) — never plaintext. See [Security](/document-management/security/) for the encryption model.

| Field | Type | Notes |
|-------|------|-------|
| `id` | `String` | `@id @default(cuid())` |
| `userId` | `String` | Owner |
| `name` | `String` | e.g. `"My NAS"`, `"Company R2 Bucket"` |
| `providerType` | `String` | `s3` \| `r2` \| `webdav` \| `local` |
| `config` | `String` `@db.Text` | Encrypted JSON connection details |
| `isDefault` | `Boolean` | `@default(false)` |
| `isReadOnly` | `Boolean` | `@default(false)` — blocks upload/modify/delete via the module |
| `isEphemeral` | `Boolean` | `@default(false)` — Local Connect: raw reachable only while the user's machine is connected. Derived artefacts are never stored here; raw bytes are never persisted server-side |
| `deviceId` | `String?` | Local Connect: opaque, stable per-device id the companion sets on every row from one machine, so the web app groups that computer's folders. Never used in a path or URL |
| `deviceLabel` | `String?` | Local Connect: optional human-readable device name (the group heading). Display-only |
| `status` | `String` | `@default("pending")` — `connected` \| `error` \| `pending` \| `unavailable` |
| `statusMessage` | `String?` | Human-readable status detail |
| `lastCheckedAt` | `DateTime?` | Last connection test |
| `basePath` | `String?` | Optional root path within the provider |
| `uploadPath` | `String?` | Default folder for app uploads (relative to the provider) |
| `metadata` | `Json?` | Provider settings/capabilities cache |
| `createdAt` | `DateTime` | `@default(now())` |
| `updatedAt` | `DateTime` | `@updatedAt` |

```prisma
model doc_storage_provider {
  id            String    @id @default(cuid())
  userId        String
  name          String
  providerType  String
  config        String    @db.Text
  isDefault     Boolean   @default(false)
  isReadOnly    Boolean   @default(false)
  isEphemeral   Boolean   @default(false)
  deviceId      String?
  deviceLabel   String?
  status        String    @default("pending")
  statusMessage String?
  lastCheckedAt DateTime?
  basePath      String?
  uploadPath    String?
  metadata      Json?
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt

  @@index([userId])
  @@map("doc_storage_providers")
}
```

## `doc_document`

A lightweight reference to a file in connected storage. A row is created when you interact meaningfully with a file (favourite, tag, note, link to a node) **or** when another module requests a stable reference via the service registry (for example cognitive-pipeline needing a durable `documentId` to cite). Not every browsed file gets a row.

| Field | Type | Notes |
|-------|------|-------|
| `id` | `String` | `@id @default(cuid())` |
| `userId` | `String` | Owner |
| `providerId` | `String` | References `doc_storage_provider.id` |
| `remotePath` | `String` | Full path within the provider |
| `fileName` | `String` | |
| `mimeType` | `String?` | |
| `fileSize` | `Int?` | Bytes |
| `contentHash` | `String?` | SHA-256 of the file at reference time (integrity) |
| `isFavourite` | `Boolean` | `@default(false)` |
| `status` | `String` | `@default("active")` — `active` \| `archived` \| `deleted` (in the trash, v1.20.0+). Since v1.18.4 a row can briefly be `uploading`: a reference reserved for an upload that is still being written. The service never returns such a row, and one left by a server that stopped mid-upload is removed at that user's next reference upload, once it is an hour old. |
| `tags` | `String[]` | `@default([])` |
| `notes` | `String?` `@db.Text` | User notes |
| `thumbnailPath` | `String?` | Cached thumbnail path/URL |
| `metadata` | `Json?` | Provider metadata cache |
| `lastAccessedAt` | `DateTime?` | |
| `lastSyncedAt` | `DateTime?` | Last metadata refresh from the provider |
| `createdAt` | `DateTime` | `@default(now())` |
| `updatedAt` | `DateTime` | `@updatedAt` |

```prisma
model doc_document {
  id             String    @id @default(cuid())
  userId         String
  providerId     String
  remotePath     String
  fileName       String
  mimeType       String?
  fileSize       Int?
  contentHash    String?
  isFavourite    Boolean   @default(false)
  status         String    @default("active")
  deletedAt      DateTime?
  tags           String[]  @default([])
  notes          String?   @db.Text
  thumbnailPath  String?
  metadata       Json?
  lastAccessedAt DateTime?
  lastSyncedAt   DateTime?
  createdAt      DateTime  @default(now())
  updatedAt      DateTime  @updatedAt

  @@unique([userId, providerId, remotePath])
  @@index([userId, createdAt])
  @@index([userId, isFavourite])
  @@index([userId, status])
  @@map("doc_documents")
}
```

The `@@unique([userId, providerId, remotePath])` constraint backs the `upsert` used when you favourite or link a file, so re-referencing the same file updates the existing row rather than duplicating it.

## `doc_document_revision`

Since v1.20.0. One row per version of a document, written in the same transaction as the change, and never updated or deleted, except with its document (deleted permanently from the trash, or the account erased). `doc_documents` also gained `deletedAt`: when the document went to the trash. See [Record History & Integrity](/document-management/history/).

| Field | Type | Notes |
|-------|------|-------|
| `id` | `String` | `@id @default(cuid())` |
| `documentId` | `String` | References `doc_document.id` |
| `userId` | `String` | The document's owner |
| `seq` | `Int` | 1, 2, 3 … per document, no gaps; unique with `documentId` |
| `action` | `String` | `baseline` \| `create` \| `upload` \| `replace-file` \| `update` \| `archive` \| `delete` \| `restore` \| `move` \| `link` \| `unlink` \| `revert` |
| `at` | `DateTime` | `@db.Timestamptz(3)`: the server's clock at the write |
| `actor` | `Json` | `{ id, kind: user \| module \| system, module? }` |
| `snapshot` | `Json` | The document's full state after the change |
| `changes` | `Json` | `[{ path, before, after }]` (not part of the hash) |
| `revertedTo` | `Int?` | For a restored version: the version it went back to |
| `prevHash` | `String?` | The previous version's `hash` |
| `hash` | `String` | The version's fingerprint, with `alg` |
| `alg` | `String` | `sha384` for new versions (`sha256` and `sha512` also verify) |
| `seal` | `String?` | HMAC of `hash` with `RECORD_SEAL_KEY`; `null` without a key |
| `sealKeyId` | `String?` | First 8 hex of SHA-256 of the seal key |
| `timestamps` | `Json?` | [Independent RFC 3161 timestamps](/document-management/history/#independent-timestamps-v1201): one, `role: "main"` (a version stamped before v1.22.0 may also carry a backup after it). Each `{ provider, role, url, status, requestedAt, tsaAt, serial, token, validation, error, nonce, tsaName, attempts, nextAttemptAt }`; a stamp waiting for the starter's timestamp service is `provider: "app"`, `url: ""` until it is answered. The only fields written after the version, and not part of its hash |
| `timestampStatus` | `String?` | v1.20.1+. The stamp queue: `pending` (a stamp is waiting), `failed` (none waiting, one failed), `done`; `null` when none was asked for |
| `timestampDueAt` | `DateTime?` | v1.20.1+. `@db.Timestamptz(3)`: when the next attempt is due (for a claimed one, its lease); `null` when nothing waits |

```prisma
model doc_document_revision {
  id         String   @id @default(cuid())
  documentId String
  userId     String
  seq        Int
  action     String
  at         DateTime @db.Timestamptz(3)
  actor      Json
  snapshot   Json
  changes    Json
  revertedTo Int?
  prevHash   String?
  hash       String
  alg        String
  seal       String?
  sealKeyId  String?
  timestamps Json?
  timestampStatus String?
  timestampDueAt  DateTime? @db.Timestamptz(3)

  @@unique([documentId, seq])
  @@index([userId])
  @@index([timestampStatus, timestampDueAt])
  @@map("doc_document_revisions")
}
```

## `doc_app_settings`

An app-wide **singleton** (always `id = "app"`) holding the admin policy: which adapter engines users may configure on their Document Storage settings page, the shared default, user self-service, upload limits, artefact retention and independent timestamps. It is **not** user-scoped. An empty `allowedAdapters` means "all installed engines are allowed".

| Field | Type | Notes |
|-------|------|-------|
| `id` | `String` | `@id @default("app")` — single row |
| `allowedAdapters` | `String[]` | Allowed engine ids (`s3` \| `webdav` \| `local`); empty = all installed |
| `defaultProviderId` | `String?` | App-wide shared default provider for users with no default of their own; `null` if unset |
| `defaultIsolateUsers` | `Boolean` | `@default(true)` — namespace each user's uploads under `u/<userId>/` on the shared default and confine access |
| `userProviderPolicy` | `String` | `@default("unlimited")` — `disabled` | `limited` | `unlimited`: whether a non-admin may connect their own storage |
| `userProviderLimit` | `Int?` | The cap when the policy is `limited` (`null` = 1) |
| `maxUploadSize` | `Int?` | Upload size limit in bytes, enforced on the server; `null` = `DOC_MAX_UPLOAD_SIZE` |
| `maxFileCount` | `Int?` | Files per multi-file upload (a client-side cap); `null` = `DOC_MAX_FILE_COUNT` |
| `acceptedMimeTypes` | `String[]` | File-picker filter (not a server gate); empty = `DOC_ACCEPTED_MIME_TYPES` |
| `artefactKeepVersions` | `Int?` | Retention: keep at most the N newest parsed-artefact versions per source + format; `null` = keep every version |
| `artefactMaxAgeDays` | `Int?` | Retention: delete parsed artefacts older than N days on prune; `null` = no age limit |
| `timestamps` | `Json?` | v1.20.1+. [Independent timestamps](/document-management/history/#independent-timestamps-v1201): `{ when: every \| create \| null }`; `null` = off. Saved before v1.22.0 it also held `main`, `backup` and `customUrl`, which are no longer read (the provider is the app's timestamp service) |
| `updatedAt` | `DateTime` | `@updatedAt` |

```prisma
model doc_app_settings {
  id                   String   @id @default("app")
  allowedAdapters      String[] @default([])
  defaultProviderId    String?
  defaultIsolateUsers  Boolean  @default(true)
  userProviderPolicy   String   @default("unlimited")
  userProviderLimit    Int?
  maxUploadSize        Int?
  maxFileCount         Int?
  acceptedMimeTypes    String[] @default([])
  artefactKeepVersions Int?
  artefactMaxAgeDays   Int?
  timestamps           Json?
  updatedAt            DateTime @updatedAt

  @@map("doc_app_settings")
}
```

The engine policy is read via `GET /settings` (any authenticated user) and written via `PUT /settings` (admin-only). It can only narrow the engines installed at init, never widen them. See [Configuration](/document-management/configuration/) for the user-settings vs admin-policy split.

`artefactKeepVersions` and `artefactMaxAgeDays` hold the admin **parsed-artefact retention** policy — both `null` by default, so **every artefact version is kept forever** (the knowledge base has no automatic decay; cleanup is an explicit admin choice). `keepVersions` is enforced on each `putParsedArtefact` write; `maxAgeDays` (and `keepVersions`) are applied when an admin runs `POST /artefacts/prune`. Both are set through the same admin-only `PUT /settings` and surfaced on the **Parsed-artefact retention** card at `/admin/documents`.

## `doc_included_folder`

Folders a user has marked as **included** — the auto-ingest scope for the **Included folders** picker (`/documents/included`). Checking a folder includes it recursively; **Sync now** (`POST /included-folders/sync`) walks these folders and fires the `documents.document.uploaded` pipeline event per file, so a consumer (cognitive-pipeline) ingests them. Backs `GET/POST/DELETE /included-folders`.

| Field | Type | Notes |
|-------|------|-------|
| `id` | `String` | `@id @default(cuid())` |
| `userId` | `String` | Owner |
| `providerId` | `String` | References `doc_storage_provider.id` |
| `folderPath` | `String` | Folder marked as included |
| `recursive` | `Boolean` | `@default(true)` — include descendant folders |
| `createdAt` | `DateTime` | `@default(now())` |

```prisma
model doc_included_folder {
  id         String   @id @default(cuid())
  userId     String
  providerId String
  folderPath String
  recursive  Boolean  @default(true)
  createdAt  DateTime @default(now())

  @@unique([userId, providerId, folderPath])
  @@index([userId])
  @@index([userId, providerId])
  @@map("doc_included_folders")
}
```

The `@@unique([userId, providerId, folderPath])` constraint means marking the same folder twice is idempotent. `addIncludedFolder` reuses the `resolveFileProvider` guard, so a user can only include folders they can actually reach.

## `doc_parsed_artefact`

Stores the **output an external parser produced** for a source file — for example the JSON the cognitive-pipeline Docling sidecar extracts. This module **never parses content itself**; it only persists the byproduct so re-ingest, re-extraction, and re-chunking never re-parse. A row points at both the original **source** (`sourceProviderId` + `sourceRemotePath`, optionally a `doc_document.id`) and the stored **artefact** (`artefactProviderId` + `artefactPath`).

Artefacts default to a **derived writable area** (`DOC_ARTEFACT_PREFIX`, default `.derived-artefacts`) rather than beside the original — the original may sit on a read-only/evidence provider that rejects writes — and an explicit `target` can override that. Versioning keeps a monotonic `version` ordinal, but the **content hash is the dedup key**: identical source bytes reuse the existing artefact. On the shared app-default provider, artefact bytes are namespaced under the user's `u/<userId>/` prefix.

| Field | Type | Notes |
|-------|------|-------|
| `id` | `String` | `@id @default(cuid())` |
| `userId` | `String` | Owner |
| `sourceProviderId` | `String` | Provider of the original source file |
| `sourceRemotePath` | `String` | Path of the original source within its provider |
| `documentId` | `String?` | Optional `doc_document.id` when a durable reference exists |
| `sourceContentHash` | `String?` | SHA-256 of the source bytes — the dedup key |
| `format` | `String` | Artefact format, e.g. `docling-json`, `markdown` |
| `version` | `Int` | `@default(1)` — monotonic ordinal per `(source, format)` |
| `artefactProviderId` | `String` | Provider the artefact bytes are stored on |
| `artefactPath` | `String` | Path of the artefact within its provider |
| `artefactHash` | `String` | SHA-256 of the artefact bytes (integrity) |
| `sizeBytes` | `Int?` | Artefact size in bytes |
| `mimeType` | `String?` | Artefact MIME type |
| `producer` | `String?` | What produced it, e.g. `cognitive-pipeline/docling` |
| `metadata` | `Json?` | Producer metadata |
| `createdAt` | `DateTime` | `@default(now())` |
| `updatedAt` | `DateTime` | `@updatedAt` |

```prisma
model doc_parsed_artefact {
  id                 String   @id @default(cuid())
  userId             String
  sourceProviderId   String
  sourceRemotePath   String
  documentId         String?
  sourceContentHash  String?
  format             String
  version            Int      @default(1)
  artefactProviderId String
  artefactPath       String
  artefactHash       String
  sizeBytes          Int?
  mimeType           String?
  producer           String?
  metadata           Json?
  createdAt          DateTime @default(now())
  updatedAt          DateTime @updatedAt

  @@unique([userId, sourceProviderId, sourceRemotePath, format, version])
  @@index([userId])
  @@index([documentId])
  @@index([userId, sourceProviderId, sourceRemotePath])
  @@index([sourceContentHash])
  @@map("doc_parsed_artefacts")
}
```

<Aside type="note" title="Byproduct, not content">
Storing parsed artefacts does not break the connector principle — the module still never authors or parses file content. It persists a derived byproduct that an external parser handed it, keyed to the source, so expensive parsing happens once. Producers write artefacts in-process via `serviceRegistry.get('document-management').putParsedArtefact(...)`; there is no HTTP `PUT`. See [Integration](/document-management/integration/#parsed-artefacts--provenance).
</Aside>

## `doc_local_connect_tunnel`

One row per Local Connect **computer**, holding the Cloudflare tunnel Document Management provisioned
for it. The companion generates a stable `machineKey` once and sends it with every request, so
provisioning is idempotent: the same computer always gets the same tunnel back, with its ingress
re-pointed if the companion's loopback port changed.

```prisma
model doc_local_connect_tunnel {
  id          String   @id @default(cuid())
  userId      String
  machineKey  String                               // Companion-generated stable id for one computer
  tunnelId    String                               // Cloudflare Tunnel id
  hostname    String   @unique                     // Public hostname, e.g. lc9f2c....lc.example.com
  dnsRecordId String?                              // Cloudflare DNS record id for the CNAME (for teardown)
  localPort   Int                                  // Companion's loopback WebDAV port - mirrored into the ingress
  label       String?                              // Optional human name for the computer (never sent to Cloudflare)

  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  @@unique([userId, machineKey])
  @@index([userId])
  @@map("doc_local_connect_tunnels")
}
```

No token is stored. The Cloudflare run token is re-read from Cloudflare when a companion asks again,
so a database leak never yields a working tunnel credential. Erasing an account tears the tunnels down
at Cloudflare before these rows are deleted.

## `doc_pending_reconcile`

Records a file uploaded to a **Local Connect (ephemeral) default while the machine was offline**. The bytes are staged on the durable shared default; the `doc_document` reference points at the staged location so the file is immediately usable, and this row records the intent to organise the bytes **into the local folder** — and re-point the reference route — once the machine reconnects. No document is ever duplicated; only the route changes. Rows are cleared on account erasure (along with the staged bytes).

| Field | Type | Notes |
|-------|------|-------|
| `id` | `String` | `@id @default(cuid())` |
| `userId` | `String` | Owner |
| `documentId` | `String` | The `doc_document` reference being re-pointed |
| `targetProviderId` | `String` | The local/ephemeral provider the file belongs in |
| `targetRemotePath` | `String` | Intended path within the local provider |
| `stagingProviderId` | `String` | Durable provider currently holding the bytes |
| `stagingRemotePath` | `String` | Path of the staged bytes within `stagingProviderId` |
| `fileName` | `String` | |
| `mimeType` | `String?` | |
| `status` | `String` | `@default("pending")` — `pending` \| `reconciled` \| `failed` |
| `attempts` | `Int` | `@default(0)` — reconcile attempts |
| `lastError` | `String?` | Last reconcile failure detail |
| `createdAt` | `DateTime` | `@default(now())` |
| `reconciledAt` | `DateTime?` | When the file was organised into the local folder |

```prisma
model doc_pending_reconcile {
  id                String    @id @default(cuid())
  userId            String
  documentId        String
  targetProviderId  String
  targetRemotePath  String
  stagingProviderId String
  stagingRemotePath String
  fileName          String
  mimeType          String?
  status            String    @default("pending")
  attempts          Int       @default(0)
  lastError         String?
  createdAt         DateTime  @default(now())
  reconciledAt      DateTime?

  @@index([userId])
  @@index([userId, targetProviderId, status])
  @@index([documentId])
  @@map("doc_pending_reconciles")
}
```

<Aside type="note" title="The route is the source of truth">
Reconcile moves bytes and updates the reference's `providerId` + `remotePath`; it never duplicates a document. A consumer (e.g. cognitive-pipeline) that holds the stable `documentId` reads the file wherever it currently lives — staging while offline, the local folder after reconnect — with no change on its side.
</Aside>

## `doc_node_type_upload_location`

Since v1.6.0. The folder an upload for a Structure record of each type is stored in, set by an admin on the **Structure** tab of `/admin/documents`. The template takes `{nodeType}`, `{nodeName}`, `{nodeId}`, `{nodePath}`, `{parentPath}` and `{parentName}`, filled in and namespace-guarded at upload time. `nodeType` `*` is a catch-all for types with no row of their own. Defaults other modules register through `nodeUploadLocationRegistry` are not stored here; a row here overrides them. ## `doc_document_part`

Since v1.24.0. Which documents are parts of a split PDF, and which pages each holds (see [Splitting a PDF into parts](/document-management/integration/#splitting-a-pdf-into-parts-v1240)). Each part is a `doc_document` of its own; a row here says which original it came from and which pages it holds. The rows of one split share a `setId`. Rows go when the original or the part is deleted for good, and with the person's account.

| Field | Type | Notes |
|-------|------|-------|
| `id` | `String` | `@id @default(cuid())` |
| `userId` | `String` | Owner of the original and its parts |
| `setId` | `String` | One split; its parts share it |
| `originalId` | `String` | The original `doc_document` |
| `originalHash` | `String` | The original file's SHA-256 (hex) when it was split; a different fingerprint now reads as `stale` |

| `partId` | `String` | This part's `doc_document`; `@unique` |
| `partIndex`, `partCount` | `Int` | Part n of m, in page order |
| `fromPage`, `toPage` | `Int` | The original's pages it holds (1-based, inclusive) |
| `createdAt` | `DateTime` | `@default(now())` |

## Conventions

- **Self-contained.** No `@relation` directives; foreign keys are plain `String` fields with `@@index`. This lets the module install independently without modifying other modules' tables. See the [Module Database](/module-starter/database/) guide.
- **User-owned.** Every per-user table carries `userId`; queries always filter by it and ownership is enforced in the service layer. The app-wide tables (`doc_app_settings`, `doc_node_type_upload_location`, `doc_generation_template`) are admin-managed instead.
- **Plural table names.** Each model `@@map`s to a snake_case table — usually pluralised (`doc_storage_providers`, `doc_documents`, `doc_node_links`, `doc_folder_bookmarks`, `doc_included_folders`, `doc_parsed_artefacts`); the singleton `doc_app_settings` and the `doc_recent_access` log keep their singular names.

After running `npx colour init`, the feature lives at `frontend/src/features/colour/`. Its `index.ts` exports the utilities, stores, hooks and types. **Pages are not re-exported** (see [Embedding a page](#embedding-a-page-lazy)), so they stay out of every visitor's first download.

<Aside type="note">
This page documents the **shipped implementation** — the store, components, and API that exist today. The palette save/generate flow described here is being superseded by the new [Palette Workspace](/colour-palette/palette/) (in development). The Colour Thesaurus admin (below) and the [colour engine](/colour-palette/colour/) are unaffected.
</Aside>

## Embedding a page (lazy)

Since v2.46.0, pages are code-split: each loads only when it is opened. The **palette generator** (brand import → 34 shadcn/ui variables) is still exported for embedding, but as a `React.lazy` component, so mount it inside a `Suspense`:

```tsx
import { Suspense } from 'react';
import { LoadingState } from '@/components/page-blocks';
import { ColourPage } from '@/features/colour';

export default function ThemingPage() {
  return (
    <Suspense fallback={<LoadingState />}>
      <ColourPage />
    </Suspense>
  );
}
```

To embed any other colour page, lazy-import it straight from `pages/`. Never import a page statically: that pulls it back into the first download.

```tsx
import { lazy } from 'react';

const ColourProfile = lazy(() =>
  import('@/features/colour/pages/ColourProfile').then((m) => ({ default: m.ColourProfile })),
);
```

When the optional **Structure** module is installed, a **Palette** tab (`ColourPaletteTab`) also registers on project nodes, with no extra wiring. See [Integration](/colour-palette/integration/).

## Pages and routes

| Route | Page | Purpose |
|-------|------|---------|
| `/colours` | `ColourProfile` | The colour profile, with tabs for Analyse / Gamut / Harmonies / Scales / Mix / Adjust |
| `/palette-playground`, `/palette-playground/:id` | `PalettePlaygroundPage` | Compose a new draft palette, or edit an existing one |
| `/palettes` | `PaletteLibraryPage` | Library grid of your palettes |
| `/palettes/:id` | `PaletteProfilePage` | Palette Profile (system view) |
| `/admin/colour-thesaurus` | `ThesaurusAdminPage` | Admin page: colour names, design systems and colour knowledge |
| `/admin/palette-methods` | `ColourMethodsAdminPage` | Admin page: palette generation method config |

Every page is `React.lazy`. Routes are wrapped in a keyed error boundary plus `Suspense`. The admin pages pass `preload`, which needs starter **v2.13.1+**, so the admin nav can prefetch them.

## The Store

The generator's **editing state** (colours being worked on, the generated palette, the dirty flag) lives in a Zustand store at `store/palette-store.ts`. The **saved palettes themselves are server state**. Since v2.48.0 they come only from TanStack Query hooks (see [Saved-palette hooks](#saved-palette-hooks)), never from the store.

```tsx
import { usePaletteStore, useSavedPalettes, useCreateSavedPalette } from '@/features/colour';

function MyToolbar() {
  const { brandColours, generatedPalette, generate, importColours } = usePaletteStore();
  const { data: saved = [] } = useSavedPalettes('ui');
  const create = useCreateSavedPalette();
  // …
}
```

### Store Properties

| Property | Type | Purpose |
|----------|------|---------|
| `brandColours` | `BrandColour[]` | Current input colours with role tags and weights |
| `importSource` | `ImportSource` | Where the current colours came from |
| `generatedPalette` | `PaletteOutput \| null` | The generated light + dark palette |
| `currentPaletteId` | `string \| null` | The saved **UI** palette the editor is bound to, if any. Saves update it; when it is `null`, a save creates a new palette. |
| `currentPaletteName` | `string` | Name shown in the Save dialog |
| `isDirty` | `boolean` | True when state has changed since the last save or load |
| `previewMode` | `'light' \| 'dark'` | Which mode the preview shows |
| `isGenerating` | `boolean` | Generation-in-progress flag |

### Store Actions

| Action | Signature | Purpose |
|--------|-----------|---------|
| `importColours` | `(input: string) => void` | Parse a Coolors / Adobe / hex / CSS string and replace brand colours |
| `addColour` | `(hex: string, roles?: ColourRole[]) => void` | Append a brand colour |
| `removeColour` | `(index: number) => void` | Drop a brand colour and rebalance weights |
| `updateColourHex` | `(index: number, hex: string) => void` | Edit one colour's hex value |
| `setColourRoles` | `(index: number, roles: ColourRole[]) => void` | Replace a colour's role tags |
| `toggleColourRole` | `(index: number, role: ColourRole) => void` | Add or remove a single role |
| `setColourWeight` | `(index: number, weight: number) => void` | Set a colour's weight (0–1) |
| `autoAssignRoles` | `() => void` | Run the assessment and assign suggested roles |
| `generate` | `() => void` | Build the full `PaletteOutput` from the current input |
| `setCurrentPaletteName` | `(name: string) => void` | Set the name shown in the Save dialog |
| `applySavedPalette` | `(saved: SavedPalette) => void` | Put a fetched saved palette into the editor. Only a `ui` record binds the editor. A brand or scheme record loads its colours as a starting point, and the next save creates a new UI palette, so the original is never overwritten. |
| `markSaved` | `(saved: SavedPalette, snapshot) => void` | After a save succeeds: bind to the record, and clear `isDirty` only if nothing was edited while the save was in flight |
| `unbindSavedPalette` | `(id: string) => void` | Unbind the editor from a deleted record. Its content becomes unsaved (`isDirty`). |
| `resetPalette` | `() => void` | Clear state to start a fresh palette |
| `setPreviewMode` | `(mode: 'light' \| 'dark') => void` | Toggle the preview mode |
| `reset` | `() => void` | Reset all state including UI flags |

### Saved-palette hooks

TanStack Query hooks from `hooks/useMyFeature.ts`, exported from the barrel. Keys sit under `createModuleQueryKeys('colour')` in a `saved` segment.

| Hook | Purpose |
|------|---------|
| `useSavedPalettes(type?)` | The user's saved palettes, optionally filtered by `'ui' \| 'brand' \| 'scheme'` |
| `useSavedPalette(id)` / `savedPaletteQuery(id)` | One saved palette. Use the query-options form with `queryClient.fetchQuery` for on-demand loads. |
| `useActivePalette()` | The palette marked active |
| `useCreateSavedPalette()` / `useUpdateSavedPalette()` | Create / update a saved palette. The caches are invalidated for you. |
| `useSetActivePalette()` | Make a palette active (one transactional request) |
| `useDeleteSavedPalette()` | Delete a palette. It also unbinds the editor if it was showing that palette. |

Show failures inline with `ErrorAlert` and `getApiErrorMessage(err, 'Fallback')` from `@/lib/api`, never raw error text. The host mounts no toast container.

## Components

Only `ColourPage` (lazy) and `SwatchWithActions` / `StripSegmentPopover` are exported from the barrel. The rest are internal: import them from `components/` or `pages/` inside the feature, and lazy-import pages.

| Component | Props | Purpose |
|-----------|-------|---------|
| `ColourPage` (barrel, `React.lazy`) | _none_ | The palette generator: brand import → 34 shadcn/ui variables. Mount inside `Suspense`. |
| `ColourPaletteTab` (internal) | `{ node: { id, nodeType, data? } }` | Tab variant for Structure project nodes, registered automatically when Structure is installed |
| `BrandImport` (internal) | _none_ | Input area for pasting Coolors / Adobe / hex / CSS |
| `PalettePreview` (internal) | _none_ | Renders the generated palette grid (reads from the store) |

## Backend API

All endpoints are mounted at `/api/v1/colour-palette` and require authentication. The current user is taken from `req.user` — there is no `userId` in the path.

| Method | Path | Body | Returns |
|--------|------|------|---------|
| `GET` | `/` | — | `SavedPalette[]` for the current user |
| `GET` | `/active` | — | The user's currently active `SavedPalette` (or null) |
| `GET` | `/:id` | — | A single `SavedPalette` |
| `POST` | `/` | `CreateSavedPaletteInput` | Created `SavedPalette` (201) |
| `PATCH` | `/:id` | `UpdateSavedPaletteInput` | Updated `SavedPalette` |
| `PATCH` | `/:id/activate` | — | Updated `SavedPalette` (sets `isActive: true`, clears others) |
| `DELETE` | `/:id` | — | 204 No Content |

## Utility Functions

The colour utilities are pure functions. Import them when you need to do colour maths outside the store. (Because the barrel re-exports them, the parts the pages use currently sit in the first download, about 24 KB minified. Moving those re-exports to deep imports is a planned follow-up.)

| Module | Notable Exports |
|--------|-----------------|
| `utils/color-utils.ts` | `hexToOklch`, `oklchToHex`, `hexToHsl` |
| `utils/colour-convert.ts` | OKLCH conversion primitives; `tryHexToOklch` returns `null` for input it can't parse (v2.53.0) |
| `utils/colour-mix.ts` | `mixColours`, `gradientStops`, `gamutMap` |
| `utils/colour-math.ts` | Distance, contrast, lightness helpers |
| `utils/colour-schemes.ts` | Generate analogous, triadic, complementary schemes |
| `utils/colour-painter.ts` | Painter-style operations on a working colour |
| `utils/colour-analyse.ts` | Harmony detection, perceptual ordering |
| `utils/colour-modify.ts` | Sass-style modify / transform / alpha helpers |
| `utils/colour-accessibility.ts` | Colour-vision simulation (Machado 2009 protan/deutan, Brettel 1997 tritan, linear sRGB) and checks: `simulateCvdOklab`, `simulateCvdHex`, `cvdPaletteReport`, `colourBlindSimulate`, `colourBlindSafe`, `CVD_MIN_DELTA_E` (0.05) |

## Admin — Colour Thesaurus

The module registers an admin page at `/admin/colour-thesaurus` for curating the **database-backed** colour thesaurus (see [Thesaurus](/colour-palette/thesaurus/)). It is admin-only and lazy-loaded, and so is everything it reads and writes.

**One thesaurus, two layers.**

- **Colour names** are single labels from one source: CSS "aqua", XKCD "cyan", Tailwind "neutral-100".
- **Groups** bundle the names that mean the same colour, under one headline name and colour, with your notes.
- **Links** connect them. Every name has one home group and may have see-also links to others.

Colour Knowledge (psychology, culture, brands) is a separate library on the same page.

| Tab | Purpose |
|-----|---------|
| Names | Every colour name, in a server-paged `DataTable`. You can search by name, code or a hex (`#0ff` works), filter by source or design-system flag, and sort by name, hex or last change. **Add name** puts a name into a group, or starts a new group with it as the headline, and warns about names already at that colour or spelled the same. Row actions: Open group, Move to another group, Split into its own group, Delete name. Click a row to edit the name. |
| Groups (default) | Every group, server-paged. Search names, codes, sources or a hex; filter by hue family, source or status ("Empty", "No headline"). Actions: **Add name**, **Merge into…** per row, **Merge selected…** (pick which group stays), and bulk delete. Click a row to open the group editor. |
| Sources | Every source with its name count, a design-system switch, **Rename** (the key stays, so imports still match), and **Delete** with a preview of exactly what goes. Add a source below the list; an existing key is refused. |
| Import | Paste or upload JSON in the editorial export shape, or a raw `{ records: [...] }` batch. Large pastes go in chunks with progress, and the report lists every record's outcome. Names that joined one group by colour but are spelled like a name in another group appear under **Needs review**, with Open and Merge actions. |
| Data check | Counts every breach of the thesaurus rules. **View** shows examples, each opening its name or group. **Fix** repairs a row, and **Fix all safe problems** repairs everything. Empty groups are for review, and possible duplicates and one-code-at-several-colours are reports. |
| Knowledge | Psychology / Cultural / Brands records (see [Colour Knowledge](/colour-palette/colour-knowledge/)), each a `DataTable` with Anchor filtering, plus seeding and bulk JSON import. |

### The group editor

A sheet showing the group's names:

- **Headline:** the crown buttons choose the headline name and colour. A headline can be changed but not cleared.
- **Header actions:** **Add name** and **Merge into…**.
- **Per name**, in a ⋯ menu: Edit, Move, Split and Delete. Deleting a group's only name says the group and its notes go too.
- **See-also links:** each row says where the name lives, opens that group, and can be removed. **Link a name…** adds one.
- **Notes:** deprecated names, meaning, attributes and origin. Save sends only the fields you changed.
  - If the saved notes change while the sheet is open (another group was merged into this one), untouched fields refresh. Fields you edited are kept, with a note and **Discard my edits**.
  - Merging this group away waits until your note changes are saved or undone.
- **Delete group:** says how many names go and offers **Merge instead**.
- **After a merge,** the sheet follows to the group that stays.

### The name editor

A stacked sheet for one name:

- its hex (with a live swatch and OKLCH readout), name, alt names, code, design-system flag and scale fields;
- its groups, where the home group offers Open / Move / Split and each see-also link offers Open / Remove;
- **List under another group…**;
- other names at the same colour.

Changing a name's hex or code means the next import from its source adds a new copy instead of updating it.

### What the rules guarantee

The server enforces these whatever screen or API call makes the change (see [the rules](/colour-palette/thesaurus/#the-rules-v2510)):

- every name keeps one home group;
- a group is never left empty without you choosing it;
- a headline is always one of the group's own names;
- structural changes run one at a time.

The Import tab's JSON shapes are documented under [Import Format](/colour-palette/thesaurus/#import-format).

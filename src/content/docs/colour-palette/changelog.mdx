## 2.50.1 — 2026-10-17

### Thesaurus data-loss fixes (cleanup and security audit, Batch K)

- **Deleting a source no longer deletes unrelated groups.**
  - **Before:** the delete removed *every* group in the thesaurus that had no home name, even ones with nothing to do with that source. Two kinds of group were wiped, together with their meaning, attributes, origin and deprecated names:
    - groups created empty;
    - groups left empty by deleting their last name in the name sheet.
  - **Now:** the delete removes only the groups that source leaves without names. In one transaction it also:
    - releases the headline pointers aimed at the deleted names;
    - removes other names' see-also links into the deleted groups;
    - gives each surviving group that lost its headline its oldest remaining name.
  - **Large sources:** the delete uses subselects instead of an unbounded `IN` list, so it can no longer hit Postgres's parameter limit, and it gets a 60-second budget.
  - **Measured on the e2e host:** deleting XKCD removes 949 names and 339 groups and reassigns 68 headlines in about half a second. The old code would have left those 68 headlines pointing at deleted names.
- **The admin Sources tab previews a delete before it happens.**
  - Delete opens a dialog that lists what will go (names, groups and how many have notes, headlines reassigned, see-also links). Delete is enabled only once you type the source key.
  - Behind it, the new admin-only `GET /sources/:id/impact` shares one planning function with the delete, so the numbers match. `DELETE /sources/:id` now answers 200 with the same counts.
  - The delete writes an audit log line (`audit: true`, with the admin's id). The `source.deleted` action now carries the counts.
- **Importing a source without codes keeps names that share a colour.**
  - XKCD and Resene matched an existing row on source + hex alone, so a second name at the same hex (CSS-style `aqua` and `cyan`) overwrote the first.
  - Code-less rows now match on source + hex + name.
  - Re-import XKCD or Resene to restore any names lost this way; they show as "joined by hex".
- **Split no longer fails on a group's headline name.**
  - It returned a 500 because the new group claimed the headline before the old group released it.
  - The old group now keeps a headline, its oldest remaining name.
  - Splitting a group's only name is refused with a 409.
- **Structural writes no longer interleave.** Source delete, import records and split take one transaction-scoped write lock. A write that waits more than 20 seconds gets a readable 409 ("The colour thesaurus is busy with another change…") instead of a server error.
- **Verified:** a rolled-back test against the e2e host's database. Every integrity counter was unchanged afterwards, and so was the live data. Also verified with host strict `tsc` (0 colour errors), a production build and a backend boot. No schema change, so `npx colour update` is enough.

## 2.50.0 — 2026-10-15

### Shared blocks, canonical primitives and accessibility (standards audit, Batch F)

The module now builds its UI from the host's shared blocks and the canonical shadcn primitives instead of hand-rolled markup, as the starter's "compose shared blocks, then canonical shadcn, never hand-roll" rule asks.

- **Admin tables are `DataTable`s:**
  - The **Groups** list is server-paged, with the same search, sort, page size, family and source filters and bulk delete as before. The two filters now sit under **More filters**, because the endpoint takes one value each.
  - **Sources** has a per-row design-system switch and a delete action.
  - Each **Knowledge** sub-tab lists its records with an Anchor column and filter (Cultural also gets a Caution column and filter).
  - Loading, empty and error states use the shared `LoadingState` / `EmptyState` / `ErrorAlert`, with Retry.
- **Palette Methods admin** uses settings-blocks rows (`SectionHeader`, `Row`, `Divider`) and a `PageHeader`.
  - **Every switch and slider now has an accessible name.** About 20 controls had none.
  - Stage pills are `Badge`s and the reset links are `Button`s. Only the interactive canvases stay custom.
- **Comboboxes use `Popover` + `Command`:** the header colour search and the Playground palette selector. Arrow-key navigation is built in, and Enter on the colour-picker button still opens the native picker.
- **Segmented choices use `ToggleGroup`:** the preview light/dark switch and the Method-panel option pills. Each axis is one tab stop, with arrow keys to choose.
- **Buttons are `Button`s.** About 40 hand-rolled chrome buttons are now `Button` variants with accessible names. Mix Lab's raw `<select>`/`<table>` are `Select`/`Table`. Library uses `PageHeader` / `EmptyState`.
- **Keyboard users can see and reach every control.**
  - Swatch hover controls also appear on `focus-within`.
  - The favourites grid's remove buttons are reachable.
  - The colour-name inputs show a focus ring.
- **No more `!important` sheet widths.** The colour view and thesaurus edit sheets use the `data-[side=right]:` overrides the host's `SheetContent` expects. They are **full width on phones** (the 44rem minimum used to overflow) and keep their desktop width. The favourites and palette sheets now get the width they always intended.
- **New primitives declared** in `shadcnComponents`: `command`, `spinner`, `toggle-group` and `toggle`. Hosts that lack them get them on `npx colour update`.

## 2.48.0 — 2026-10-14

### Data layer and error messages (standards audit, Batch E)

- **Saved palettes are server state only.** The palette generator's saved-palette list and the load / save / delete actions moved out of the Zustand `palette-store` onto TanStack Query hooks (`useSavedPalettes`, `useSavedPalette` / `savedPaletteQuery`, `useActivePalette`, `useCreateSavedPalette`, `useUpdateSavedPalette`, `useSetActivePalette`, `useDeleteSavedPalette`), now **exported from the barrel**. The store keeps only editing state, with three new client actions: `applySavedPalette`, `markSaved` and `unbindSavedPalette`. The dead brand-palette actions on `colour-page-store` were deleted, and the Mix page's "save scheme" uses the create hook.
- **Loading a brand or scheme palette no longer risks overwriting it.** Only a `ui` record binds the editor. Any other type loads as a starting point, and the next save creates a new UI palette. Before, loading a scheme then saving would have replaced its scheme config with a generated theme.
  - The picker labels these "Brand · opens as a copy" / "Scheme · opens as a copy".
  - The picker is now controlled, so a failed load can be retried by re-selecting.
  - The Save dialog can't be closed while a save is in flight.
- **Friendly inline errors everywhere.** Every failed save, update, publish, fork, delete, import and admin action now shows an `ErrorAlert` with `getApiErrorMessage(err, '…')` next to the action, never raw server text and never silence.
  - The Playground header shows a compact error indicator. It is tied to the palette's current load, so it disappears if the palette is reloaded.
  - The admin pages show real validation errors instead of always blaming permissions.
  - The legacy page-level error banner is gone.
- **Real loading, error, offline and not-found states.** The Library and Palette Profile no longer say "No palettes yet" or "not found" when a fetch fails. A deleted palette shows *Palette not found* with a way back, other errors show a Retry, and being offline is said plainly.
- **Thesaurus:**
  - Query keys now live under the `colour` namespace (conformance C13), with one shared key factory.
  - Group and entry writes invalidate everything they touch, including the Groups admin search, design systems and nearest names. The Groups list no longer shows stale rows for five minutes.
  - The import tab's five `console.*` calls are gone.
- **Breadcrumbs** use `useSetBreadcrumbs()` and clear on leave.
- **Palette version chains** refresh after update and delete.

**Breaking (pre-launch clean break):**
- `usePaletteStore` no longer has `savedPalettes`, `isLoadingSaved`, `isSaving`, `error`, `loadSavedPalettes`, `savePalette`, `loadPalette` or `deletePalette`. Use the saved-palette hooks above.
- `useColourPageStore` no longer has the brand-palette list and its actions, `saveSchemePalette` or `error` / `clearError`.
- Saved-palette query keys moved under a `saved` segment.

## 2.47.0 — 2026-10-14

### Bugs found in the standards audit (Batch D)

- **The Palette Methods "Engine" and "Slots" controls now do something.** The admin page saved `tunables`, `slots` and `weights`, but the generator ignored them and used its own constants. They are now threaded through as explicit options, with no global state:
  - **Start-hue lean, separation floor, locked-neighbour floor and distinct samples** reach every generator path the Playground and Profile use.
  - **Palette size:** a fresh Playground uses `slots.default`. Add buttons are disabled at `slots.max`, and Remove at `slots.min`. "Apply structure" fits into the range.
  - **Accent share** drives auto-weighting in the workspace store.

  **With the default config, output is byte-identical to before.** That was checked across 13,662 seeded comparisons.
- **Accent-share units fixed.** The sliders treated the values as fractions (0–0.3, 0–0.6), while the engine uses percentages (default 5% and 25%). The sliders now run 0–30% and 0–60%.
  - A config saved with the old fractional sliders (e.g. `0.05`) is read as a percentage (5%).
  - Out-of-range values are clamped instead of discarding the whole override.
- **Gamut chart draws again.** It wrapped theme tokens in `hsl(...)`, but the tokens are OKLCH, which made the CSS invalid: no boundary line, no axes, black fills. It now uses `var(--token)` with SVG opacity attributes. The gamutMap3D marker uses `--chart-2` instead of a fixed green, and its label uses `fill-foreground`.
- **Palette Profile Analytics no longer shows NaN.** Entry weights are passed through, and the tab uses equal weights when none are set.
- **The Playground keeps your locks, undo and roll history after saving.**
  - **Update** no longer reloads the palette from the server.
  - The **first Save** of a new palette binds the live draft to the new palette (a new `bindSaved` store action) before the URL changes, so it isn't reloaded either.
  - An untouched Playground still picks up fresher server data.
  - A fresh Playground no longer stays blank while offline.
- **Removed the placeholder Colour settings page and Preferences section.** Neither saved anything, and no tool read them. Existing hosts are offered the 4 orphaned files for removal (backed up) on `npx colour update`; `--force` removes them.
- **Tighter write APIs:**
  - `PATCH /api/v1/colour/:id` no longer accepts `isActive`; activation only goes through the transactional `/:id/activate`.
  - The palette create/update APIs strip `isGlobal`/`isSystem`, which are server-owned privilege flags.
  - The matching frontend input types were updated, and the unused `ColorFormat` type was removed.
  - **Breaking (types only, pre-launch clean break):** `@/features/colour` no longer exports `ColorFormat`, `UpdateSavedPaletteInput.isActive` or `CreatePaletteInput.isGlobal` / `isSystem`. No known consumer used them.
- **Saving keeps your work, and stale copies can't overwrite newer ones.** Both workspace stores now keep a **server-sync baseline**: the `updatedAt` of the copy they last loaded or saved. Each save in flight also carries a **save token** (palette id plus a load generation), so a save started before a palette switch can't hide, or wrongly adopt, the reloaded copy. Pages reload a draft only when the store isn't bound to it, or when the server copy is genuinely newer and isn't the echo of their own save.
  - The palette query cache **never goes backwards**. Update and Publish cancel an in-flight GET of that palette, and `usePalette` keeps whichever copy is newer, so a slow GET can't overwrite the fresher copy a save just cached.
  - **Playground:**
    - Update and the first Save (a new `bindSaved` action) keep locks, undo, roll history and un-snapshotted edits such as renames and reorders.
    - Coming back to a palette also keeps unsaved work, unless the palette was saved elsewhere in the meantime.
    - While a newly opened palette is loading, the page shows a loading state. Space, Undo/Redo, Update and Favourites → add are disabled, so they can't act on the previous palette.
    - A missing palette shows an error instead of loading forever.
    - The first Save **replaces** the history entry, so browser Back leaves the Playground instead of resetting the saved draft.
    - A failed first Save keeps the dialog open.
    - Space on an empty canvas seeds the default number of slots, so "New playground" is no longer a dead end.
    - Stale aesthetic crown labels are cleared when you switch palettes.
  - **Palette Profile:** after the palette is Updated from the Playground, the Profile reloads the newer copy. Previously it kept its old copy, and **Save / Publish would write it back over the Playground's changes**. A failed Save now stops Publish.
- **The palette sheet's "Create draft" and "Add to existing"** now use the admin's Accent Share.
- **Method config validation:** every numeric leaf must be finite, since a pasted `1e999` used to save as `null` and silently reset the whole override. Legacy fractional weights lift to whole percents.

## 2.46.0 — 2026-10-14

### Pages load only when opened (standards audit, Batch C)

Every colour page used to be in every visitor's first download, including the admin-only ones. On the e2e host, the **initial JavaScript fell from 3.79 MB to 3.43 MB (−363 KB)** and the **entry chunk from 1.34 MB to 0.89 MB**. No colour page code is left in the initial chunks; this was verified with sourcemaps.

- **Routes are `React.lazy`.** `/colours`, `/palette-playground(/:id)`, `/palettes` and `/palettes/:id` each get their own chunk. Each route is wrapped in a **keyed** error boundary plus `Suspense` (with `LoadingState`). The keys mean an error on one colour page no longer sticks to the others, and moving between colour pages shows the loading state instead of freezing on the old page. Both Playground paths share one key, so Save → `/palette-playground/:id` keeps its state.
- **Admin pages are lazy with `preload`.** Colour Thesaurus and Palette Methods load only for admins who open them. `preload` (the same `import()`) lets the admin nav prefetch them. **This requires starter v2.13.1+**, where `AdminPage.preload` exists.
- **The settings page is lazy.**
- **The error boundary works again.** It passed `title`/`message` to page-blocks `ErrorAlert`, whose props are `{ error }`, so it rendered **nothing**. It now shows a friendly message (never the raw error) with **Try again**. A **stale chunk after a redeploy** is handed on to the host's route error element, which shows "This app has been updated. Reload" and reports the error.

**Breaking (pre-launch clean break):** 11 page components are no longer re-exported from `@/features/colour`:
- `ColourProfile`, `PaletteLibraryPage`, `PalettePlaygroundPage`, `PaletteProfilePage`
- `ColourHarmoniesPage`, `ColourDataVisPage`, `ColourScalesPage`, `ColourAdjustPage`, `ColourMixPage`, `ColourAnalysePage`, `ColourGamutPage`

`ColourPage` (the embeddable palette generator, formerly a static export) is now a `React.lazy` export, so mount it inside `Suspense`. No known consumer imported any of these. To embed a page:

```tsx
const ColourProfile = lazy(() =>
  import('@/features/colour/pages/ColourProfile').then((m) => ({ default: m.ColourProfile })),
);
```

## 2.45.0 — 2026-10-14

### Conformance, data rights and storage usage (standards audit, Batch B)

`npm run conformance:check`, which arrived with the scaffold update to **v1.31.20** in this release cycle, now reports **0 violations**, down from 22.

- **Account deletion refuses to run unscoped (C9).** In the host, `DeletionSubject.userId` is optional; it is omitted for a tenant offboard. The deletion handler used to pass it straight into `deleteMany({ where: { userId } })`, and Prisma drops an undefined filter, so such a call could have erased **every user's** saved palettes, workspace palettes and favourites. It now resolves `userId ?? tenantId` and throws if neither is set. This is the canonical module-starter guard.
- **Action hooks reach async listeners (C18).** All 21 `actionRegistry.doAction` calls are now `doActionAll`, so `addActionAsync` subscribers hear them too.
- **12 new hooks** on writes that used to be silent: favourites, colour knowledge, method config, thesaurus source upsert and membership set, and the legacy-to-workspace migration. Favourite add/remove and knowledge remove/import fire only on a real change. See [Integration → Action Hooks Fired](/colour-palette/integration/#action-hooks-fired-backend).
- **GDPR export handler.** "Download my data" now includes the user's saved palettes, workspace palettes and favourites. It needs starter v2.13.0+ and is skipped on older starters.
- **Storage usage.** A new `usage.registration.ts` reports the three per-user tables' row counts and stored bytes in the account's **Storage** section. It needs starter v2.14.0+ (guarded dynamic import) and does nothing on older starters.
- **Shared services.** `colour-knowledge` and `colour-method-config` are now registered in `serviceRegistry` with `ServiceTypes` augmentation, so other modules can read colour knowledge and the active generation config without cross-module imports. `listByAnchor` no longer relies on `this`, so destructuring it is safe. `remove()` refuses an empty id.

Verified:
- The module type-checks and builds, `check:templates` passes, and `conformance:check` reports 0 violations.
- The generated files compile against the e2e host's real types.
- The host backend booted cleanly with the regenerated module (module registry and routes up, no errors).
- An adversarial review (3 lenses) found no blockers. Its nits were fixed or logged on the roadmap.

## 2.44.1 — 2026-10-14

### Installs no longer break on current starters (standards audit, Batch A)

Two problems found by the [2026-10-14 standards audit](/colour-palette/roadmap/#standards-alignment-gaps-2026-10-14-audit) could stop a host app from building at all.

- **Router imports moved from `react-router-dom` to `react-router`.** Starter **v2.5.0+** ships only `react-router` v8; `react-router-dom` is no longer installed, so 9 generated files failed to resolve on a fresh app. They now import the same hooks (`useNavigate`, `useLocation`, `useParams`) and the `RouteObject` type from `react-router`. That is the package the host's own shell, Structure and admin features already use, so the colour pages also share the host's router context.
  - On a partly migrated host that renders the v8 `RouterProvider` but still lists `react-router-dom` v7, the old imports read a different (nested v7) router context. The header colour toolbar's `useLocation` would then fail at runtime; that is now fixed.
  - Older npm hosts that only have `react-router-dom` v6/v7 keep working, because the hoisted `react-router` is the same copy `react-router-dom` re-exports.
- **The Structure module is now a genuinely optional companion.** `registrations/structure.registration.ts` used to `import { nodeTabRegistry } from '@/features/structure'` unconditionally, so installing Colour into an app without Structure failed the build. It now resolves Structure with Vite's eager `import.meta.glob('../../structure/index.ts', { import: 'nodeTabRegistry' })`, which compiles to a named import, so the bundle size is unchanged:
  - When Structure is installed, this is an ordinary static import, and the **Palette** tab registers on project nodes exactly as before.
  - When Structure is absent, the glob is empty and the registration is a no-op.
  - Nothing has to be uncommented by hand, and nothing is lost on `npx colour update`.
  - The registry is typed locally, so the file also type-checks without Structure.

Verified: the module type-checks and builds; `npx colour update --force --skip-schema` was run on the e2e host; the host type-check is clean for the changed files; the host `vite build` passes; and a scratch Vite 8 app builds both with and without a Structure folder.

## 2.43.0 — 2026-07-03

### Dark aesthetics get a background surface

In **Cyberpunk, Lunarpunk and Goth**, the dark base isn't a brand hero — it's the **background** the neon foreground sits on. Previously the combine styled it like a hero, so picking a light Style (e.g. **Neon**) washed the darks out entirely.

- These aesthetics now carry a **`surface` flag**. When one themes a fresh palette, **one rolled slot is drawn from the dark base band and kept dark** (exempt from the Style lightness combine) — so Neon brightens the *foreground pops* while the surface stays dark to sit them on. It's shown as **"background"** (a wrench crown) in the Playground.
- A dedicated **`surface` band role** keeps this distinct from the aesthetic's light *text* functional band; the darkest slot is the surface, and other slots can still be light **or** dark foreground colours.
- **Admin-tunable:** a per-aesthetic **"Base is background surface"** toggle in `/admin/palette-methods → Look`. It's on for the three dark aesthetics and off elsewhere; you can flip it for any aesthetic. `AESTHETIC_CONFIG_VERSION` → 3.
- Playground display only for the crown; the slot's structural role and its promote/demote dropdown are unchanged. Non-dark aesthetics are unaffected.

## 2.42.0 — 2026-07-03

### Aesthetic accent pops now roam (and the crown tells the truth)

When an aesthetic themes a fresh all-hero palette, it borrows some slots to sample from its **accent** band so the palette reads as base + pop out of the box. Previously the borrowed slots were the fixed last ~40% — so the bright pops were always in the same positions and every slot was still crowned "Hero".

- The borrow now **varies its count (~30–60% of the heroes) and shuffles which slots it takes** each Space press (Fisher-Yates), so the pops move around instead of being pinned to the end.
- A borrowed slot's **crown now shows "Accent"** (the band role it's playing this roll) instead of a misleading "Hero". The slot's **structural** role — and its role dropdown (promote/demote) — are unchanged; this is a display of what the colour is doing this roll.
- Playground-only; no engine or config change. With a palette that already has real accent slots, nothing changes (no borrow).

## 2.41.0 — 2026-07-03

### Aesthetics combine with the other axes (never ignore a selection)

Selecting an **Aesthetic** used to override the other axes' hue and lightness/chroma in Auto mode — so "Cyberpunk + Finance/Tech" stayed pink/purple and the fintech-blue was dropped. Now every selected axis is honoured, on the property it owns:

- **Aesthetic** → hue + the base/accent look (its identity).
- **Style** → **saturation, authoritatively** (Muted mutes the neon accents; Neon/Vibrant brightens any aesthetic) and shares lightness (the aesthetic keeps its dark/light structure, Style nudges it).
- **Impact / Purpose / Culture** → **hue lean within the aesthetic's windows** (Finance/Tech pulls Cyberpunk toward the cyan/blue end and sheds the pinks; it can't become pure corporate blue without leaving "cyberpunk", so contradictory picks *meet in the middle*).
- **Purpose** → structure (via "Apply structure").

Because the Playground is for **exploring**, the blend point **roams each Space press**: every selection always registers (a hard Style pick is never dropped), but successive rolls span the intersection — one roll holds the dark cyberpunk structure, the next lightens toward Style, the next leans bluer toward Purpose — so you Space through the space and keep your favourite.

- Engine: `aestheticColours` now takes a `combine` argument (the resolved bounds + working range) and blends each band toward the other axes' hard bounds (a lerp, not an intersection — they can be disjoint, e.g. muted chroma vs a neon band) and *stretches* toward their soft targets, with a **per-roll random emphasis** (chroma reach 0.4–0.9 = Style-led; lightness reach 0.15–0.6 = aesthetic-led; hue lean 0.25–0.8). Hue is biased toward the nearest **other-axis** lean (the aesthetic's own hue centres are excluded via axis provenance), kept inside the window so it stays on-vibe.
- With **only an aesthetic** selected, behaviour is unchanged.

## 2.40.0 — 2026-07-03

### Palette Methods admin, redesigned by intent

The `/admin/palette-methods` config page was re-organised around admin *intent* instead of the config's data shape (informed by a research pass into expert-config UX — CAD constraint solvers, audio plugins, feature-flag prerequisites, Unity/VS Code override indicators).

- **Pipeline strip.** A read-only strip names the five generation stages (Pick method → Merge axes → Criteria hues → Generate → Guarantees); each section is tagged with the stage it affects.
- **Intent tabs.** Look / Conflicts / Guarantees / Engine / Advanced replace the old data-shaped tabs. **Look** puts every constraint axis on one screen — **Aesthetic is now a peer axis**, not a separate tab.
- **Shared L/C region canvas.** One OKLCH plane (chroma across, lightness up, painted as a perceptual slice) shows the nested geometry — working range ⊃ option **Limits** ⊃ aesthetic role bands — as layered rectangles. Drag the solid-edged **fence** to set hard Limits and the glowing **magnet** dot to set the soft **Bias** target; sibling bands sit faintly behind for context. A **hue wheel** edits hue leans (dots) and aesthetic hue windows (arcs). Numeric sliders remain beneath every visual control for precise and accessible editing.

- **Priority** — `Harmony > Aesthetic > Purpose > Style > Impact`: a strong driver that still yields to an explicit Harmony. It emits the same `ConstraintContribution` (a soft L/C lean + hue centres) and composes through the merge engine; the real per-role bands ride alongside and are applied at generation time, so a dark base + bright accent don't collapse into one region.
- **Functional colour type** — a third colour type now surfaces in the Playground *up with* hero and accent (backed by the existing functionals model), **absent by default**. Convert a swatch to **Functional** from its role menu; when the active aesthetic defines a functional band, a re-roll recolours those slots from it.
- **Honest by design** — the Aesthetic axis constrains *hue* more firmly than Style/Impact because it encodes a visual-style convention, not a mood effect; overall muted-vs-vibrant is left to the Style axis. Copy stays "tends to read…".
- First of a staged batch: 8 aesthetics across all six families; the remaining ~8 (Steampunk, Dark Academia, Studio Ghibli, Brutalist, Pop Art, Psychedelic, Postmodern/Memphis, Gen-Z Preppy) follow as config-data adds. See the [Roadmap](/colour-palette/roadmap/).

## 2.17.0 — 2026-06-21

### Method panel (four-axis generation) + colour semantics layer

Two foundations for more intelligent — and honest — palette generation.

**Method panel — Harmony × Style × Impact × Purpose-&-Industry.** A new slide-in panel in the Playground with four optional axes, each defaulting to **Any**. Every axis value maps to an OKLCH `ConstraintContribution` held in versioned JSON config, tagged with its **evidence** (peer-reviewed vs convention). A merge engine composes the active axes: hard bounds **intersect**, soft targets **weight-average**, conflicts resolve by **priority** (Harmony > Purpose > Style > Impact), and a lower-priority bound **relaxes to a soft target** when the intersection would be empty. Style and Impact are driven mostly by lightness and chroma — the replication-proof levers (Valdez & Mehrabian 1994) — while hue biases stay soft. When any axis is set it drives generation; otherwise the existing mode + mood controls do. Copy is deliberately honest — "tends to feel…", never "makes users feel…" — and the panel surfaces each axis's evidence tag, the resolved constraints, and any relaxations. New `palette-method.ts` (engine + config); `palette-generators.ts` gains a soft-bias layer and a split-complementary scheme.

**Colour semantics — cultural & symbolic associations (data model).** A new global, admin-curated `colour_semantics` reference table keyed to the 14 Berlin–Kay + extended anchors (red … grey, gold, silver, turquoise). Self-contained (no `userId`, no relations); reads are open to any authenticated user, writes are admin-gated; ships an idempotent seed of 62 built-in records under `/api/v1/colour/semantics`. `source` is intentionally left **empty** (real citations are attached later — nothing is fabricated) and `confidence` is preserved so low-confidence/folkloric rows can be down-weighted. A new Berlin–Kay anchor classifier (`palette-bk-category.ts`) maps any OKLCH colour to its nearest anchor using **lightness and chroma, not hue alone**, so brown, pink and the neutrals are distinguished — the keystone the semantics lookup resolves against.

The frontend semantics consumer, the full per-colour attribute vector, the per-region localisation feed with non-blocking caution surfacing, and a native-reviewer pass on the regional claims are next — see [Method panel](/colour-palette/method-panel/), [Colour semantics](/colour-palette/colour-semantics/) and the [Roadmap](/colour-palette/roadmap/).

## 1.48.95 — 2026-04-29

### Refactor

- **Harmony pipeline rewritten as cusp-line projection.** The previous five-stage pipeline (H-K corrections, warm-lift, neon bell, multi-pass refinement) has been replaced by a single-pass geometric construction. `harmonyMap` decomposes the source colour as `(t, r)` inside a perceptual sub-triangle (vertices: `A` at the threshold-curve × gamut-boundary intersection, `B` at the constant-chroma threshold × gamut-boundary intersection, and `cusp` at the gamut peak). It then reconstructs the destination using the same `(t, r)` in the destination's sub-triangle. The mapping is mathematically self-inverse: `harmonyMap(harmonyMap(x, 180), 180) === x` in float OKLCH, with hex round-tripping limited only by 8-bit channel quantisation.
- **New helper `findThresholdCurveEdge(h, loL, hiL, rising)`.** Binary-searches for the L value where the gamut boundary crosses the chromatic-threshold *curve* (which itself varies with L). Used to place vertex A on the rising side where the gamut narrows fast.
- **Green/cyan neon suppression.** A Gaussian chroma cap centred at H=165° (σ=35°, peak strength 30%) pulls chroma back from the gamut boundary in the green-cyan band only, where sRGB's unusually wide gamut produced overwhelming neon results. Other hues are untouched.
- **Removed:** `CUSP_L_CEILING`, `warmBase` / `warmLiftL` / `warmLiftC`, `neonBell`, `neonRisk`, `coolnessSharp`, `hkDeficit`, the asymmetric Pass 5 reduction, and the dual-cusp pattern. The single-pass cusp-line projection subsumes all of these geometrically.
- **`harmonyMap` no longer calls `gamutMap3DShaded`.** The destination sits inside its own sub-triangle by construction, so containment is guaranteed without a final mapping step.

### Research section redesign

- The Harmonies tab's interactive **Research** view is now a hue slider (0–360° destination hue) instead of a relative angle offset, with three side-by-side gamut cross-sections — Source, Raw bary, and Harmony — at full width. The Harmony triangle shows the three construction lines (cusp→Q, B→edge-A→cusp, A→edge-cusp→B) converging at the destination point, and the values panel surfaces the three preserved ratios (`%cusp`, `%B`, `%A`).

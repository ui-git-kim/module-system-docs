All notable changes to **cognitive-db** are recorded here. The engine uses semantic versioning (`major.minor.patch`) and follows the [module system's versioning conventions](/getting-started/). It ships vendored inside the [Cog Ingest module](/modules/cog-ingest/), so an engine release reaches apps through the next module release.

<Aside type="note">
  This page mirrors the engine repository's `CHANGELOG.md`. For where the project is heading, see the [Roadmap](/cognitive-db/roadmap/); for what the engine is and does, see the [Overview](/cognitive-db/).
</Aside>

## 1.7.0 — 2026-08-09

More tier-1-3 behavioural wiring (batches 5 + 9), verified through the host app on Neon.

### Added

- **Relation-class-aware traversal + `connectionTypes` expansion** — an opt-in filter expansion resolves a super-property filter to its sub-properties via the `superProperty` chain (a `knows` filter also matches `friend_of` / `family_of` / `colleague_of`) across graph traversal and semantic / lexical / fused search; `fusedSearch` expands once so both legs agree. New `classScopedCone` / `classScopedShortestPath` answer class-scoped questions ("what led to X" follows `sequential` edges backward; "what is X part of" follows `hierarchical`), wrapping the pure path-search core. Purely structural (hop distance only) — never-decay-safe; per-class spreading decay stays deferred to R2.
- **Deterministic `followed_by` sequential-adjacency edges at ingest** (opt-in) — a `followed_by` edge links the previous content node in a thread to the current one, with no LLM (same spirit as the content-hash change-gate). Feeds the temporal channel and narrative-ordered retrieval. The edge weight is a static constant and its `evidenceTier` is `observed` (a structural ordering fact); timestamps only order predecessor selection — never-decay-safe.

<Aside type="note">
  Both are additive and flag-guarded — engine defaults are unchanged until a host opts in. The class-aware traversal + expansion ship on the v1 `cog_node` path; the Structure-native path is unblocked once the host surfaces the relation-class / super-property overlay on its connection types and seeds the `followed_by` type. Remaining tier-1-3 wiring: non-destructive caveat emission, the missing-slot → question expectation pass, the analogical proxy, and gap-diagnostics → questions.
</Aside>

## 1.6.0 — 2026-08-08

More tier-1-3 behavioural wiring (verified through the host app on Neon).

### Added

- **`getEffectiveProperties(conceptName)`** — resolves a concept's own + inherited properties (with defaults), the expected-slot set for perception prompts and the expectation pass.
- **`evidenceTier` on connections** — explicit relationships are tagged `observed`, engine-discovered connections `inferred`; a categorical provenance quality carried on the connection, orthogonal to numeric confidence and never age-based.

## 1.5.0 — 2026-08-08

First behavioural wiring of the v1.4.0 tier cores. Runtime verification runs through the host app on Neon.

### Added

- **Relationship-type entailment in connection validation** — a connection is now validated against its relationship type's *effective* domain/range, resolved up the `superProperty` chain, so a sub-property (e.g. `friend_of`) is checked against its parent's (`knows`) constraints instead of being unconstrained.
- **R5 sequential pattern detection strategy** — wired into the detection pipeline (enabled under temporal analysis): groups events into sequences by thread or day and mines frequent ordered subsequences with PrefixSpan, emitting `sequential` patterns. Timestamps are mine-time analysis input only — nothing time-based is stored (never-decay-safe).

<Aside type="note">
  The remaining tier-1-3 behavioural wiring (evidence-tier assignment, non-destructive caveat emission, the missing-slot → question expectation pass, deterministic sequential edges, class-aware traversal, gap-diagnostics → questions) is in progress and verified through the host app.
</Aside>

## 1.4.0 — 2026-08-08

R-track + ontology foundations — the pure, tested cores of a set of neuroscience/knowledge-graph refinements, plus the ontology vocabulary they build on. All additions are storage-free and never-decay-safe; the DB-bound behavioural wiring is tracked as a follow-up for host verification. Neutral naming throughout.

### Added

- **Sequential pattern mining (`prefixSpan`)** — the pure PrefixSpan core of the planned R5 temporal-pattern track: mines frequent ordered subsequences ("A is reliably followed by B, then C"). A higher layer promotes hits into `sequential` pattern nodes.
- **Relation-class-aware path search** — `bidirectionalShortestPath` (meet-in-the-middle, class/type-pruned) and `typedReachable` (forward/backward class-filtered cones — e.g. "what led to X" follows `sequential` edges backward).
- **Ontology inheritance + entailment** — `resolveEffectiveProperties` (a concept inherits its ancestors' expected slots + defaults) and `superProperty` entailment (`isSubPropertyOf` / `expandToSubProperties`), so a `knows` filter also matches `friend_of` / `family_of`.
- **Structural gap diagnostics** — `analyzeStructure` reports sources / sinks / isolated / convergence-hubs to feed proactive gap and question generation.
- **Ontology vocabulary:** a coarse `relationClass` overlay `{associative, sequential, hierarchical, descriptive}`; a categorical `evidenceTier` `{observed, inferred, analogical, theoretical}` (provenance quality, orthogonal to numeric confidence); an optional `default` on concept properties; and new `qualifies` (non-destructive caveat) and `followed_by` (sequential adjacency) base relationship types.

<Aside type="note">
  This release ships the pure, unit-tested cores (69 tests). The behavioural wiring that makes them runtime effects — entailment inside connection validation/traversal, evidence-tier assignment during perception/discovery, non-destructive caveat emission, the missing-slot → question expectation pass, the R5 detection strategy, and deterministic sequential edges at ingest — is DB-bound and follows next, verified through the host app.
</Aside>

## 1.3.0 — 2026-08-08

Retrieval-quality maths + Structure-native ingest hardening — pure, storage-free ranking primitives with a genuine lexical + semantic hybrid search, plus a change-gate that skips re-perceiving unchanged docs and a set of ingest correctness fixes.

### Added

- **`./retrieval` domain** — pure, storage-free ranking primitives that work identically over the v1 `cog_node` path and the Structure-native path and never touch the never-decay invariant: **`rrfFuse`** (Reciprocal Rank Fusion), **`mmrSelect`** (Maximal Marginal Relevance, + `embeddingSimilarity`), **`dedupe`** (exact + near-duplicate), **`budgetAssemble`** (token-aware assembly), and `cosineSimilarity` / `dotProduct` / `magnitude`. New `./retrieval` export subpath; 38 unit tests (vitest — the engine's first test runner).
- **`fusedSearch`** — the true lexical + semantic hybrid: runs the semantic and lexical legs and fuses them with `rrfFuse` (by rank, so incomparable score scales never need reconciling). Completes the roadmap's "true hybrid lexical + semantic search" item.
- **`lexicalSearch`** — full-text search ranked by PostgreSQL `ts_rank` (computed on the fly, no index or schema change), the ranked lexical leg for `fusedSearch`.

### Ingest — Structure-native path

- **Change-gate ("is this doc already known?").** `ingest()` fingerprints content and, keyed by `sourceId` (or the content hash when absent), classifies each doc as **new**, **unchanged** (skips perception + embedding, `tokensUsed: 0`), or **changed** (updates the content node in place and re-perceives). Surfaced as `IngestResult.changeStatus`; `IngestInput.force` bypasses the skip. ("Chunk only what changed" stays cog-ingest's concern — the engine's grain is the doc/node.)
- **Discovered-connection buffer truthfulness.** The `cog_intelligence_discovery` row is resolved to `promoted` only after `promoteConnection` actually succeeds (previously it claimed `promoted` the instant the pending edge was created).
- **Normalised-name entity dedup** — `resolveEntity` matches on `normaliseName()` (case + whitespace), so casing/whitespace variants resolve to one node.
- **Unknown types are always queued** for admin review (`proposeNodeType`) regardless of `ontologyGrowth` mode — never silently dropped; the instance stays deferred until approved.

### Changed (breaking — pre-launch clean break)

- **`hybridSearch` → `filteredSemanticSearch`** (and `HybridSearchOptions` → `FilteredSemanticSearchOptions`) — the old name misdescribed it; it never blended a lexical score. The genuine blend is now `fusedSearch`.

<Aside type="note">
  Deferred to a host-tested follow-up: cross-item batch dedup (blocked in Structure mode until the `updateNode` seam gains a node-archival capability) and `bulkCreateNodes` / `embedBatch` batching. The DB-bound `lexicalSearch` / `fusedSearch` SQL is verified end-to-end through the host app against Neon.
</Aside>

## 1.2.0 — 2026-08-08

Phase 3 (Structure-native storage) — the engine can ingest through the Structure service instead of its own `cog_node` tables, flag-guarded alongside v1.

### Added

- **Structure-native ingest path.** When a Structure adapter is injected, `ingest()` runs the RFC §6 filter pipeline over it — perceive → type against the ontology read from Structure → resolve/dedup entities (semantic over `structure_node`) → write records (content as a field) → enrich (summary-based embeddings; typed emotion / concept / question nodes; explicit and discovered connections). It writes no `cog_node` and owns only the `cog_intelligence_*` process tables; v1 remains the degrade-safe fallback.
- **Storage-mode resolution** — `getStorageMode()` resolves to `structure` whenever an adapter is present, else `cog_node`. Adds `storage.autoPromoteThreshold` (default 0.9) and `getAutoPromoteThreshold()`.
- **Engine-discovered connections** written pending (`origin: 'discovered'`) and auto-promoted above the threshold, tolerating `promoteConnection`'s typed failures.
- **Ontology growth** — unknown node types file a `proposeNodeType` proposal (the admin review queue); adds `'approve'` to `OntologyGrowthMode`. Entity re-observation is recorded in `cog_intelligence_log` rather than as a version-chain row.

## 1.1.0 — 2026-08-08

Chunk-aware embedding groundwork — the node-level vector is now summary-based for long content, ending the silent 8,000-character truncation.

### Fixed

- **Silent truncation eliminated for every embeddable node.** `generateEmbeddingText` previously truncated `rawContent` at `DEFAULT_MAX_TEXT_LENGTH` (8,000 chars), so a long document was retrievable only from its opening ~8,000 characters. Every raw-content-bearing node type (content, question, memory / decision / emotion, default) is now **fit-first**: the full raw text when it fits, the perception-generated summary when it does not, and truncation only as an unreachable last resort. Composed vectors (entity, pattern, connection) are clamped to the threshold too.
- **Ingest embedded a stale content node.** The summary generated during perception was persisted but never embedded at ingest time (a different in-memory object was embedded); ingest now embeds `perception.contentNode` (summary-bearing) and returns it, so `contentNode.summary` is consistent across ingest-time and re-embed.

### Added

- `perceptionService.ensureContentSummary(prisma, node, content)` — guarantees a summary for over-threshold content on the minimal ingest path (which skips full perception), so minimal never produces a truncated node vector.
- `DEFAULT_MAX_TEXT_LENGTH` is now exported from `core/embedding.service` as the single source of truth for the summary-trigger threshold.

### Removed

- **`needsChunking()`** and its re-exports — dead code with no caller, and its default was expressed in *tokens* (8,000) while the only truncation in the embed path was 8,000 *characters* (~4× mismatch). Chunking is not an engine concern: the ingesting module (cog-ingest) splits content and stores per-chunk vectors in Structure directly. `estimateTokens()` is retained.

<Aside type="note">
  Chunk storage stays host-side (cog-ingest → Structure `structure_chunk`); the engine owns only the coarse node-level summary vector. Truthful embed coverage is reported by cog-ingest / AI Core, not the engine.
</Aside>

## 1.0.0 — 2026-07-14

First stable release. Hardened by a comprehensive code audit and moved to the module system's vendored delivery. This marks a stable public API — semantic versioning applies from here.

### Fixed — audit remediation

84 findings across 96 files (see `docs/AUDIT-2026-07-14.md` in the engine repository).

| Area | Remediation |
|------|-------------|
| **Security** | SQL injection in graph search closed — every filter value now binds as a numbered placeholder (`QueryParams`); scaffold `execSync` no longer interpolates the target path; `retentionDays` bound in cleanup SQL. |
| **Correctness** | Graph adjacency now resolves the far endpoint (centrality / community / pathfinding had been operating on connection ids); atomic `createVersion` (`$transaction`); `userId` set on relationship connections; connection-limit truncation removed; version-chain cycle guards; preference-detection valence parsing; and roughly 40 more. |
| **Performance** | DB-side aggregation instead of full scans; a single batched connection fetch; windowed trend queries. |

<Aside type="caution" title="Security model">
  The SQL-injection and binding fixes are query-hygiene hardening. They are distinct from the engine's isolation model, which is **ownership by `userId`** (`tenantId === userId`, the solo-business model) — there is no multi-tenant layer. See [Security & data ownership](/cognitive-db/) for the full picture.
</Aside>

### Changed — minor API

- Removed the unused `semanticWeight` option from `HybridSearchOptions` — it was never applied, because `hybridSearch` is **filtered semantic search** (metadata-filtered vector search, not a lexical blend).
- `matchEntities` now keys its result map by input index instead of `name:type`, avoiding collisions.
- Stricter types on several exported functions (proper unions, explicit return types).
- Extended the minimal `PrismaClientInterface`; added `NodeStatus.ANSWERED`, `FindNodesOptions.createdAfter` / `createdBefore`, and `getConnectionsForNodes()`.

### Added

- A `prepare` script builds `dist/` on install, enabling Git and vendored installs without a published package.
- `core/node.mapper.ts` — a single shared row-to-`Node` mapper, deduplicated from four call sites.

### Delivery

- Vendored into the Cog Ingest module and installed via its `onInstall` / `onUpdate` lifecycle hook — no npm registry or GitHub authentication required, and the engine version is locked to the module release. A standalone install is also available via `npm install github:ui-git-kim/cognitive-db`.

### Design

- Confirmed **`tenantId === userId`** as the tenant model (solo-business focus): isolation is by `userId` ownership, with no multi-tenant layer.

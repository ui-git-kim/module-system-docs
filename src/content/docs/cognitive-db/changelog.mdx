All notable changes to **cognitive-db** are recorded here. The engine uses semantic versioning (`major.minor.patch`) and follows the [module system's versioning conventions](/getting-started/). It ships vendored inside the [Cog Ingest module](/modules/cog-ingest/), so an engine release reaches apps through the next module release.

  This page mirrors the engine repository's `CHANGELOG.md`. For where the project is heading, see the [Roadmap](/cognitive-db/roadmap/); for what the engine is and does, see the [Overview](/cognitive-db/).

## 1.12.10 — 2026-08-23

**B read-lane flip — `algorithms/similarity` + adapter-mirror groundwork.** Completes the graph-algorithms cluster (centrality/community/paths landed in v1.12.9) and declares the optional adapter lifecycle methods Structure now exposes.

### Fixed

- **`algorithms/similarity` inert under Structure storage.** Reads route through the shared bridges (v1 byte-identical). Under Structure the Jaccard lane works via `getNodeConnections` and the cosine lane degrades to 0 (a mapped record has no `embedding`), so pairwise/duplicate similarity becomes Jaccard-only; `findSimilarByEmbedding` delegates to the embeddings adapter (`structureStore.findSimilar`).

### Added

- **`StructureAdapter` optional methods** `archiveNode` / `moveNode` / `mergeNode` / `deleteConnection`, mirroring the now-available Structure service methods, so the host can wire them in `buildStructureAdapter`; the engine consumers flip in a following batch.

<Aside type="note">
  Remaining read-lane (engine): `connection.service`/`traversal` are mostly flippable but `strengthen`/`weaken`/`updateConnectionStrength` need a connection-by-id read Structure does not yet expose; `pattern`/`confirmation`/`propagation` flip via status-in-`data` + `archiveNode` with documented degrades; `ontology.service` needs Structure to surface its ontology hierarchy (`superClasses` on node types, `relationClass`/`superProperty` on connection types) in the config API. The host wiring (`seedEngineOperations` + the adapter methods) is what activates all of this — see the engine → cog-ingest handoff.
</Aside>

## 1.12.9 — 2026-08-23

**B read-lane storage flip (batch 1).** Eight read/intelligence-lane services that hard-bound the legacy v1 `cog_node` store — so under Structure-native storage they read the empty parallel store and went silently inert — are now storage-aware. The v1 path stays behaviourally identical (the shared bridges' no-adapter branch calls `node.repository` exactly as before). None are host-invoked yet (dormant public API), so this is anticipatory work toward `cog_node` retirement (greenfield, no backfill).

### Fixed

- **Graph algorithms** (`community` / `paths` / `centrality`), **pattern detection** (`detection.service`), **confidence** (`confidence.service`), the **degradation queue** (`degradation.service`), **usage metrics** (`metrics.service`), and the whole **search surface** (`search.service`, all seven functions — the "B2" raw-SQL centrepiece) now branch on the resolved storage mode and read/write through the injected adapter (via the shared bridges) under Structure, instead of the empty `cog_node` store.

### Added

- **Shared bridge helpers** `loadNode` and `loadAllUserNodes` in `intelligence/intelligence-store.ts` (single-vertex and whole-user vertex loads); `connectionToNode` now surfaces an edge's `strength` / `confidence` from its `data`, defaulting to `1` to mirror the v1 column defaults so a connection weighs the same over either store.

<Aside type="note">
  Search under Structure keeps the documented degrades: `lexicalSearch` has no `ts_rank` (ordinal scoring); `filteredSemanticSearch`'s structured filters are applied in memory; status sets Structure can't express are fetched as a safe superset and refined in memory. `applyDecay` is a no-op under Structure (never-decay). `ontology.service` is deferred to a follow-up batch: the engine's minimal `StructureNodeType` / `StructureConnectionType` mirror doesn't yet read the ontology hierarchy metadata Structure exposes — extend the mirror, then flip. All flipped services stay dormant until the host wires the relevant read surface. Adversarially reviewed (8 files → verify); 176 tests.
</Aside>

## 1.12.8 — 2026-08-23

The **intelligence lane** — temporal reminders, trend detection, and structural-gap diagnostics — is now storage-aware, via one shared read bridge. It read only v1 `cog_node`, so under Structure-native storage it analysed an empty graph.

### Fixed

- **Temporal / trend / structural-gap detectors inert under Structure storage.** `temporal.service`, `trend.detector`, and `gap.detector` (incl. `detectStructuralGaps`) called `node.repository` directly. They now branch on the resolved storage mode through a new shared bridge, `intelligence/intelligence-store.ts` (`loadNodes` / `loadNodeConnections` / `loadConnectionEdges`): Structure mode reads through the injected adapter — **paginated** `listNodes` (caps at 100/page) for bulk loads, `getNodeConnections` for per-node edges, and the new batch edge read for structural gaps — mapped to the shared `Node` view. The v1 path is behaviourally identical.

### Added

- **`StructureAdapter.getConnectionsForNodes?`** (optional) — a batch edge read for structural-gap diagnostics over a large vertex set. **Degrade-safe:** when the host has not wired it, `detectStructuralGaps` skips rather than asserting false "unconnected / dead-end" insights over edges it cannot see.

<Aside type="note">
  Structure-mode `loadNodes` loads newest-first up to the limit (paginated) and windows by created-at in memory (`listNodes` has no date filter). cog-ingest / Structure follow-up: implement `getConnectionsForNodes` (a thin `fromNodeId|toNodeId in (...)` read) and wire it in `buildStructureAdapter` — temporal + trend already work once the adapter is injected; structural gaps stays dark until then. This completes the C1-part-2 intelligence lane.
</Aside>

## 1.12.7 — 2026-08-23

C1 part 2: the **surprise detector** is now storage-aware — under Structure-native storage it gathers each seed's neighbourhood via the adapter's `expandGraph` primitive instead of the empty parallel `cog_node` graph.

### Fixed

- **Surprise detection inert under Structure storage.** `detect` / `findSurprises` / `findAllSurprises` traversed only v1 `cog_node`, so under Structure they saw an empty graph and surfaced nothing on the Suggestions-Inbox path. They now branch on the resolved storage mode: a shared `expandFrom` helper gathers the seed's neighbourhood via `StructureAdapter.expandGraph` (batch N-hop, auto-confined to the seed's enforced space, seeds excluded), fetches the reached records via `getNode`, and maps them to the shared `Node` view. The similarity scoring is unchanged and the v1 path is behaviourally identical.

### Added

- **`StructureAdapter.expandGraph?`** (optional) + `GraphExpandOptions` / `GraphExpansionResult` mirror types. **Degrade-safe:** when the host has not wired `expandGraph` (or the seed / userId is missing, or it throws), surprise detection yields nothing rather than failing — so it stays dark until cog-ingest wires it, like retrieve-to-connect.

<Aside type="note">
  Remaining C1 part 2 (tracked): the temporal / trend ports are standalone, low-value analytics (not on the inbox path), deferred; structural gaps under Structure is blocked on a Structure-side batch edge read (`getConnectionsForNodes`) that does not exist yet. cog-ingest follow-up: wire `expandGraph` into `buildStructureAdapter` (forward to `structureService.expandGraph`) so surprise activates.
</Aside>

## 1.12.6 — 2026-08-22

Defence-in-depth follow-up to v1.12.5.

### Changed

- **The `related-entities` context item is now injection-fenced (`injectionRisk: true`).** v1.12.5 passed it as trusted context, but the entity **names** it carries originate from earlier-ingested (possibly external) content — so replaying them into a later extraction prompt is a second-order injection surface. It is now fenced defensively: the host sanitises + fences the block, and linking still works because the names remain visible inside the fence.

## 1.12.5 — 2026-08-22

Graph-aware extraction (**retrieve-to-connect**): before `extract-entities` runs in the Structure-native ingest path, the engine searches the existing (scope-confined) graph for related entity **instances** and feeds them to the op as context — so the model **links** a new mention to the existing node instead of re-minting it. Plus an ontology-sprawl guard: organically-grown relationship types now carry a coarse `relationClass`. Additive, flag-gated (`features.retrieveToConnect`, default off), degrade-safe.

### Added

- **Retrieve-to-connect (retrieval-augmented extraction / entity linking).** When enabled, `ingestViaStructure` runs a pre-extraction step: embed an entity-free summary of the content, semantically search existing entities **within the active scope**, enrich the top hits with a few salient relationships, and pass them as a new `role:'context'` item (marker `cognitive-db/related-entities`) to both `extract-entities` and `-with-proposals`. It is additive — the engine's dedup remains the backstop — and degrade-safe: flag off, embeddings off, no active scope, an empty graph, or any failure emits no context and extraction runs exactly as before.
- **`IngestInput.scopeRootId` + `unreadableTypes`.** The host resolves the active-scope root and the user's unreadable node types and pushes them in; the engine forwards them to the (host-honoured) adapter searches. This confines retrieve-to-connect *and* the existing entity-dedup + discovery searches (closing the unscoped-search gap), satisfying isolation without the engine gaining a resolver seam.
- **Organic-growth `relationClass` classification.** `extract-entities-with-proposals` proposes a coarse `relationClass` (`associative | sequential | hierarchical | descriptive`) per new relationship type; it flows onto `IngestResult.proposedRelationshipTypes` (for the host to persist on the Structure connection type) and into the v1 `addRelationshipType`. Keeps a growing relationship vocabulary anchored to the small, fixed backbone.

### Changed

- **`StructureEmbeddingsAdapter` search methods gain `scopeRootId?` / `excludeNodeTypes?` options** (the host runtime already honours them — Structure v1.34.2 / v1.34.13; only the engine's mirror lacked them). No-ops when the host supplies no scope, so unscoped behaviour is unchanged.

<Aside type="note">
  Query vector is an entity-free summary (the node vector is summary-based and derived from the extracted entities, so it cannot exist pre-extraction). cog-ingest follow-ups: resolve + push `scopeRootId` / `unreadableTypes` into `ingest()` and forward them through `buildStructureAdapter` (until then the feature stays dark by design); seed the `cognitive-db/related-entities` marker on re-vendor; persist a proposed `relationClass` onto the Structure connection type; and add a per-source "extraction guidance" field (§7) that rides in as `additional-context`.
</Aside>

<Aside type="tip">
  Adversarially reviewed pre-release — fixed a bug where an invalid model-supplied `relationClass` would have discarded the whole extraction (now degrades to `associative`), and restricted the related-entities search to genuine entity types.
</Aside>

C3: aged-content summarisation now uses the AI Core `cognitive-db/summarise` op instead of a first-3-sentences fallback, and never discards a node's raw content unless it was both summarised and durably archived.

### Fixed

- **Summarisation quality + raw-content safety.** `summariseOldContent` used a naive extractive summary and cleared the node's `rawContent` even when the archive insert silently failed. It now summarises through the `cognitive-db/summarise` op, and `archiveRawContent` no longer swallows its insert error — so raw content is cleared only after a real summary is produced *and* the original is durably archived. A failed summary or archive skips the node (raw content preserved), logged for retry.

<Aside type="note">
  Host follow-up: provision the `cog_content_archive` table and configure the `cognitive-db/summarise` op in AI Core — otherwise summarisation now safely skips (preserving raw content) rather than reclaiming storage. `generateLLMSummary` gains a `userId` argument.
</Aside>

## 1.12.0 — 2026-08-21

The engine ships its AI Core operation catalogue as a real package export, so the host can seed the operations the engine's `runLanguage()` calls resolve against — unblocking end-to-end extraction.

### Added

- **`./operations` export — the AI Core operations catalogue.** `COGNITIVE_DB_OPERATIONS` (and its `Engine*` types) at the new `cognitive-db/operations` subpath, also re-exported from the root. It is the recipe the host seeds into AI Core: the five **language** operations (`extract-entities`, `-with-proposals`, `-concepts`, `infer-implicit`, `summarise`) — each with an `objective`, shared deduped `approaches`, a `format`, and its `role:'input'` `inputItems` — plus a catalogue-wide `markers[]`. Built directly to the host's `seedLanguageOperation` record shape, so seeding needs no per-op glue. Embedding ops stay host-owned (`cognitive-db/embed-*`).
- **`COGNITIVE_DB_MARKERS`** — the namespaced (`cognitive-db/*`) marker ids for the material the engine sends. Single source of truth: the catalogue's `markers[]` and the runtime context builders both read it, so a runtime marker id is always a seeded one.

### Changed

- **`AiContextItem` gains `role?: 'input' | 'context'`.** Perception's four extraction builders now stamp `role` and a namespaced `marker` on every context item — the primary `content` as `role:'input'` (still fenced), reference material as `role:'context'` with its marker — so the host adapter can route the op's input vs context slots instead of treating content as just another context item. Backward-compatible (absent `role` means `context`).

<Aside type="note">
  The catalogue content previously lived in a `docs/ai-core-operations.json` handoff file that the package never shipped (and which had drifted); that file is removed. This is a minor because the `./operations` subpath is new exported surface — the engine's runtime behaviour is otherwise back-compatible. 10 new tests (131 total) assert the catalogue invariants and its alignment with the runtime markers.
</Aside>

## 1.11.0 — 2026-08-10

The final tier-1-3 behavioural wiring (batch 6 — the analogical proxy): the engine ships the primitives for a host-side retrieval fallback. Verified through the host app on Neon.

### Added

- **Analogical-proxy primitives** — when a matched node's supporting connections are sparse or low-evidence, the host can surface a better-evidenced *analog* as an explicitly-labelled proxy. The engine provides `analogous_to` / `proxy_for` relationship types (associative); a pure `retrieval/proxy` module — `summariseSupport` (degree + per-evidence-tier counts + strongest strength), `isSupportSparse`, and `selectAnalogProxy` (ranks candidates by static evidence tier → support degree → link strength; the result is labelled `analogical`); and `getSupportProfile`, the read seam that gathers a node's active connections across the v1 and Structure paths. Gated by the new host-facing `features.analogicalProxy` flag.

<Aside type="note">
  Additive and flag-guarded (default off); the engine writes no durable proxy edge (ephemeral only) and ranks on purely static signals, so "never decay" holds. Retrieval assembly and rendering the proxy label are host-side. With this, the tier-1-3 behavioural wiring surfaced by the reading-list scan is complete.
</Aside>

## 1.10.0 — 2026-08-09

More tier-1-3 behavioural wiring (batch 7 — the expectation pass), verified through the host app on Neon.

### Added

- **Expectation pass (missing expected slot → question)** — at ingest, for each entity the engine resolves its concept's *effective* (inherited) properties and, for a required-or-defaulted slot the instance leaves unfilled, raises a **flagged, low-confidence Question node** ("expected but missing") with an `about` edge to the entity — the first path that persists Question nodes on the v1 store. It never fabricates the value: the question records that a slot is *expected* (and whether the concept declares a default), never the default itself. Dedups on a version-stable identity so a re-observed entity never accumulates duplicates. Gated behind the new `features.expectationPass` flag.
- **Expected slots fed to extraction** — when the flag is on and a concept declares expected slots, those slot names are passed to entity extraction as a labelled context item (a data hint, not a prompt) so the extractor tries to fill them. Adds a batch `getAllEffectiveProperties` resolver.

<Aside type="note">
  Additive and flag-guarded — engine defaults are unchanged until a host opts in, and the pass is **inert until a concept declares a `required` or `default` slot** (the base ontology declares none). Durable question emission is the v1 store for now; the Structure-native path is a follow-up. Remaining tier-1-3 wiring: the analogical proxy.
</Aside>

## 1.9.0 — 2026-08-09

More tier-1-3 behavioural wiring (batches 10 + 4), verified through the host app on Neon.

### Added

- **Structural gap diagnostics → proactive insights** — a new `detectStructuralGaps` reads the shape of the user's active graph (dead-ends with no follow-up, orphans with no relationships) via pure directed-graph diagnostics and surfaces them from the proactive full check as gap insights, behind the new `features.structuralGaps` flag. Purely structural (degree and shape only — never age, access, or frequency), read-only and ephemeral; it runs only over the complete active graph and stands down on very large graphs rather than assert a false "unconnected" claim.
- **Non-destructive contradiction caveats** — when a contradiction is detected, the engine can now record a durable `qualifies` edge *from* the disconfirming evidence *to* the standing claim (behind the new `emitCaveats` option), carrying the conflicting fields as provenance. The claim is never mutated or down-weighted — only ever `qualifies`, never `contradicts` (which would reduce the claim's confidence and break "never decay"). This is the decay-free way to hold disconfirming evidence.

<Aside type="note">
  Both are additive and flag-guarded — engine defaults are unchanged until a host opts in. Rendering the dead-end / orphan gaps and the caveat edges, and any durable question persistence, are host concerns. Remaining tier-1-3 wiring: the missing-slot → question expectation pass and the analogical proxy.
</Aside>

## 1.8.0 — 2026-08-09

**Breaking (pre-launch): the engine no longer bundles a model provider or authors prompts.** All language + embedding access moves to a single host-injected **AI adapter** (`config.ai`), implemented over AI Core; the extraction prompt instructions are extracted out of the engine into AI Core operations configured by the host.

### Changed (breaking)

- **`llm` + `embedding` config removed; `ai: AiAdapter` added.** The engine imports no provider SDK (`ai` / `@ai-sdk/*` gone). The adapter is its whole model surface — `runLanguage(op, { context, schema?, maxOutputTokens?, temperature? }, ctx)` and `embed(op, values, ctx)` — and every call carries the acting `userId` for AI Core's ledger + tenant scoping (replacing the host's AsyncLocalStorage binding).
- **Prompts moved to AI Core.** The engine passes labelled `context` items (document content flagged injection-risk, so AI Core sanitises + fences it) instead of authoring prompt strings; per-call temperature and token budgets now reach the model on every run. The engine ships the extracted instructions as an operations catalogue for the host to import.

<Aside type="caution">
  A breaking config change, delivered lockstep: the host (cog-ingest) implements the adapter over AI Core and imports the engine's operations catalogue. Apps pick it up on the next module release. Until the host cuts over, the engine's own provider/integration guides describe the previous `llm` + `embedding` shape.
</Aside>

## 1.7.0 — 2026-08-09

More tier-1-3 behavioural wiring (batches 5 + 9), verified through the host app on Neon.

### Added

- **Relation-class-aware traversal + `connectionTypes` expansion** — an opt-in filter expansion resolves a super-property filter to its sub-properties via the `superProperty` chain (a `knows` filter also matches `friend_of` / `family_of` / `colleague_of`) across graph traversal and semantic / lexical / fused search; `fusedSearch` expands once so both legs agree. New `classScopedCone` / `classScopedShortestPath` answer class-scoped questions ("what led to X" follows `sequential` edges backward; "what is X part of" follows `hierarchical`), wrapping the pure path-search core. Purely structural (hop distance only) — never-decay-safe; per-class spreading decay stays deferred to R2.
- **Deterministic `followed_by` sequential-adjacency edges at ingest** (opt-in) — a `followed_by` edge links the previous content node in a thread to the current one, with no LLM (same spirit as the content-hash change-gate). Feeds the temporal channel and narrative-ordered retrieval. The edge weight is a static constant and its `evidenceTier` is `observed` (a structural ordering fact); timestamps only order predecessor selection — never-decay-safe.

<Aside type="note">
  Both are additive and flag-guarded — engine defaults are unchanged until a host opts in. The class-aware traversal + expansion ship on the v1 `cog_node` path; the Structure-native path is unblocked once the host surfaces the relation-class / super-property overlay on its connection types and seeds the `followed_by` type. Remaining tier-1-3 wiring: non-destructive caveat emission, the missing-slot → question expectation pass, the analogical proxy, and gap-diagnostics → questions.
</Aside>

## 1.4.0 — 2026-08-08

R-track + ontology foundations — the pure, tested cores of a set of neuroscience/knowledge-graph refinements, plus the ontology vocabulary they build on. All additions are storage-free and never-decay-safe; the DB-bound behavioural wiring is tracked as a follow-up for host verification. Neutral naming throughout.

### Added

- **Sequential pattern mining (`prefixSpan`)** — the pure PrefixSpan core of the planned R5 temporal-pattern track: mines frequent ordered subsequences ("A is reliably followed by B, then C"). A higher layer promotes hits into `sequential` pattern nodes.
- **Relation-class-aware path search** — `bidirectionalShortestPath` (meet-in-the-middle, class/type-pruned) and `typedReachable` (forward/backward class-filtered cones — e.g. "what led to X" follows `sequential` edges backward).
- **Ontology inheritance + entailment** — `resolveEffectiveProperties` (a concept inherits its ancestors' expected slots + defaults) and `superProperty` entailment (`isSubPropertyOf` / `expandToSubProperties`), so a `knows` filter also matches `friend_of` / `family_of`.
- **Structural gap diagnostics** — `analyzeStructure` reports sources / sinks / isolated / convergence-hubs to feed proactive gap and question generation.
- **Ontology vocabulary:** a coarse `relationClass` overlay `{associative, sequential, hierarchical, descriptive}`; a categorical `evidenceTier` `{observed, inferred, analogical, theoretical}` (provenance quality, orthogonal to numeric confidence); an optional `default` on concept properties; and new `qualifies` (non-destructive caveat) and `followed_by` (sequential adjacency) base relationship types.

<Aside type="note">
  This release ships the pure, unit-tested cores (69 tests). The behavioural wiring that makes them runtime effects — entailment inside connection validation/traversal, evidence-tier assignment during perception/discovery, non-destructive caveat emission, the missing-slot → question expectation pass, the R5 detection strategy, and deterministic sequential edges at ingest — is DB-bound and follows next, verified through the host app.
</Aside>

## 1.3.0 — 2026-08-08

Retrieval-quality maths + Structure-native ingest hardening — pure, storage-free ranking primitives with a genuine lexical + semantic hybrid search, plus a change-gate that skips re-perceiving unchanged docs and a set of ingest correctness fixes.

### Added

- **`./retrieval` domain** — pure, storage-free ranking primitives that work identically over the v1 `cog_node` path and the Structure-native path and never touch the never-decay invariant: **`rrfFuse`** (Reciprocal Rank Fusion), **`mmrSelect`** (Maximal Marginal Relevance, + `embeddingSimilarity`), **`dedupe`** (exact + near-duplicate), **`budgetAssemble`** (token-aware assembly), and `cosineSimilarity` / `dotProduct` / `magnitude`. New `./retrieval` export subpath; 38 unit tests (vitest — the engine's first test runner).
- **`fusedSearch`** — the true lexical + semantic hybrid: runs the semantic and lexical legs and fuses them with `rrfFuse` (by rank, so incomparable score scales never need reconciling). Completes the roadmap's "true hybrid lexical + semantic search" item.
- **`lexicalSearch`** — full-text search ranked by PostgreSQL `ts_rank` (computed on the fly, no index or schema change), the ranked lexical leg for `fusedSearch`.

### Ingest — Structure-native path

- **Change-gate ("is this doc already known?").** `ingest()` fingerprints content and, keyed by `sourceId` (or the content hash when absent), classifies each doc as **new**, **unchanged** (skips perception + embedding, `tokensUsed: 0`), or **changed** (updates the content node in place and re-perceives). Surfaced as `IngestResult.changeStatus`; `IngestInput.force` bypasses the skip. ("Chunk only what changed" stays cog-ingest's concern — the engine's grain is the doc/node.)
- **Discovered-connection buffer truthfulness.** The `cog_intelligence_discovery` row is resolved to `promoted` only after `promoteConnection` actually succeeds (previously it claimed `promoted` the instant the pending edge was created).
- **Normalised-name entity dedup** — `resolveEntity` matches on `normaliseName()` (case + whitespace), so casing/whitespace variants resolve to one node.
- **Unknown types are always queued** for admin review (`proposeNodeType`) regardless of `ontologyGrowth` mode — never silently dropped; the instance stays deferred until approved.

### Changed (breaking — pre-launch clean break)

- **`hybridSearch` → `filteredSemanticSearch`** (and `HybridSearchOptions` → `FilteredSemanticSearchOptions`) — the old name misdescribed it; it never blended a lexical score. The genuine blend is now `fusedSearch`.

<Aside type="note">
  Deferred to a host-tested follow-up: cross-item batch dedup (blocked in Structure mode until the `updateNode` seam gains a node-archival capability) and `bulkCreateNodes` / `embedBatch` batching. The DB-bound `lexicalSearch` / `fusedSearch` SQL is verified end-to-end through the host app against Neon.
</Aside>

## 1.2.0 — 2026-08-08

Phase 3 (Structure-native storage) — the engine can ingest through the Structure service instead of its own `cog_node` tables, flag-guarded alongside v1.

### Added

- **Structure-native ingest path.** When a Structure adapter is injected, `ingest()` runs the RFC §6 filter pipeline over it — perceive → type against the ontology read from Structure → resolve/dedup entities (semantic over `structure_node`) → write records (content as a field) → enrich (summary-based embeddings; typed emotion / concept / question nodes; explicit and discovered connections). It writes no `cog_node` and owns only the `cog_intelligence_*` process tables; v1 remains the degrade-safe fallback.
- **Storage-mode resolution** — `getStorageMode()` resolves to `structure` whenever an adapter is present, else `cog_node`. Adds `storage.autoPromoteThreshold` (default 0.9) and `getAutoPromoteThreshold()`.
- **Engine-discovered connections** written pending (`origin: 'discovered'`) and auto-promoted above the threshold, tolerating `promoteConnection`'s typed failures.
- **Ontology growth** — unknown node types file a `proposeNodeType` proposal (the admin review queue); adds `'approve'` to `OntologyGrowthMode`. Entity re-observation is recorded in `cog_intelligence_log` rather than as a version-chain row.

## 1.1.0 — 2026-08-08

Chunk-aware embedding groundwork — the node-level vector is now summary-based for long content, ending the silent 8,000-character truncation.

### Fixed

- **Silent truncation eliminated for every embeddable node.** `generateEmbeddingText` previously truncated `rawContent` at `DEFAULT_MAX_TEXT_LENGTH` (8,000 chars), so a long document was retrievable only from its opening ~8,000 characters. Every raw-content-bearing node type (content, question, memory / decision / emotion, default) is now **fit-first**: the full raw text when it fits, the perception-generated summary when it does not, and truncation only as an unreachable last resort. Composed vectors (entity, pattern, connection) are clamped to the threshold too.
- **Ingest embedded a stale content node.** The summary generated during perception was persisted but never embedded at ingest time (a different in-memory object was embedded); ingest now embeds `perception.contentNode` (summary-bearing) and returns it, so `contentNode.summary` is consistent across ingest-time and re-embed.

### Added

- `perceptionService.ensureContentSummary(prisma, node, content)` — guarantees a summary for over-threshold content on the minimal ingest path (which skips full perception), so minimal never produces a truncated node vector.
- `DEFAULT_MAX_TEXT_LENGTH` is now exported from `core/embedding.service` as the single source of truth for the summary-trigger threshold.

### Removed

- **`needsChunking()`** and its re-exports — dead code with no caller, and its default was expressed in *tokens* (8,000) while the only truncation in the embed path was 8,000 *characters* (~4× mismatch). Chunking is not an engine concern: the ingesting module (cog-ingest) splits content and stores per-chunk vectors in Structure directly. `estimateTokens()` is retained.

<Aside type="note">
  Chunk storage stays host-side (cog-ingest → Structure `structure_chunk`); the engine owns only the coarse node-level summary vector. Truthful embed coverage is reported by cog-ingest / AI Core, not the engine.
</Aside>

## 1.0.0 — 2026-07-14

First stable release. Hardened by a comprehensive code audit and moved to the module system's vendored delivery. This marks a stable public API — semantic versioning applies from here.

### Fixed — audit remediation

84 findings across 96 files (see `docs/AUDIT-2026-07-14.md` in the engine repository).

| Area | Remediation |
|------|-------------|
| **Security** | SQL injection in graph search closed — every filter value now binds as a numbered placeholder (`QueryParams`); scaffold `execSync` no longer interpolates the target path; `retentionDays` bound in cleanup SQL. |
| **Correctness** | Graph adjacency now resolves the far endpoint (centrality / community / pathfinding had been operating on connection ids); atomic `createVersion` (`$transaction`); `userId` set on relationship connections; connection-limit truncation removed; version-chain cycle guards; preference-detection valence parsing; and roughly 40 more. |
| **Performance** | DB-side aggregation instead of full scans; a single batched connection fetch; windowed trend queries. |

<Aside type="caution" title="Security model">
  The SQL-injection and binding fixes are query-hygiene hardening. They are distinct from the engine's isolation model, which is **ownership by `userId`** (`tenantId === userId`, the solo-business model) — there is no multi-tenant layer. See [Security & data ownership](/cognitive-db/) for the full picture.
</Aside>

### Changed — minor API

- Removed the unused `semanticWeight` option from `HybridSearchOptions` — it was never applied, because `hybridSearch` is **filtered semantic search** (metadata-filtered vector search, not a lexical blend).
- `matchEntities` now keys its result map by input index instead of `name:type`, avoiding collisions.
- Stricter types on several exported functions (proper unions, explicit return types).
- Extended the minimal `PrismaClientInterface`; added `NodeStatus.ANSWERED`, `FindNodesOptions.createdAfter` / `createdBefore`, and `getConnectionsForNodes()`.

### Added

- A `prepare` script builds `dist/` on install, enabling Git and vendored installs without a published package.
- `core/node.mapper.ts` — a single shared row-to-`Node` mapper, deduplicated from four call sites.

### Delivery

- Vendored into the Cog Ingest module and installed via its `onInstall` / `onUpdate` lifecycle hook — no npm registry or GitHub authentication required, and the engine version is locked to the module release. A standalone install is also available via `npm install github:ui-git-kim/cognitive-db`.

### Design

- Confirmed **`tenantId === userId`** as the tenant model (solo-business focus): isolation is by `userId` ownership, with no multi-tenant layer.

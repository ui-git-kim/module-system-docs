## Pages

The builder generates four frontend pages:

### Builder Page (`/builder`)

The main visual builder. It provides a full-screen layout with:

- **Component Panel** (left sidebar, upper ~60%) — drag components from the palette onto the canvas
- **Layers Panel** (left sidebar, lower ~40%) — a tree-outline of the block hierarchy for quickly selecting nodes (distinct from the drag-and-drop Canvas panel)
- **Preview Panel** (top centre) — live render of your block in an iframe, compiled with Sucrase at runtime. When the project has a pinned [component snapshot](/modules/builder/integration/#per-project-component-snapshots), the preview compiles and renders against *that* snapshot — the project's real component library (radix or base) and style; otherwise it falls back to the shared pristine components. Supports responsive viewport switching (desktop, tablet, mobile) and, since v1.33.0, a **light/dark toggle** (Sun/Moon). The toggle switches the preview between the theme's light (`:root`) and dark (`.dark`) tokens. It is a per-session preview choice, separate from the app's own colour scheme, and starts in light mode.
- **Canvas Panel** (bottom centre) — the block tree editor with drag-and-drop reordering and positional drop intents (before, after, inside)
- **Property Panel** (right sidebar) — edit the selected node's properties. Extensible with additional tabs from companion modules via the property panel tab registry.

All panels are resizable. The layout auto-collapses the app sidebar to maximise canvas space.

**URL parameters:**

| Parameter | Description |
|-----------|-------------|
| `?blockId=xxx` | Load an existing block for editing |
| `?projectId=xxx` | Pre-select a project scope for saving |

Both values must be id-shaped (`[A-Za-z0-9_-]`, at most 64 characters). Anything else is ignored (v1.33.0).

**Saving.** The **Save** dialog's name becomes the block root's Component Name, which is the function the saved code exports, so the `Function` shown in the dialog is exactly what the file exports. For a project block, the dialog also shows the real install facts: the `npx shadcn@latest add @<project-slug>/<name>` command, the install target `components/<install-dir>/<name>.tsx`, and the matching `import`. The install folder is the kebab-case form of the project slug, identical to the slug for every kebab-case slug; the command keeps the `@<project-slug>` alias. Global and system blocks have no project registry, so the dialog shows none for them. **Update Block** keeps the block's category. A non-admin who opens a **system** block gets **Save as New** instead of Update Block, and the copy defaults to their own first category.

### Canvas Page (`/builder/canvas`)

The render surface loaded **inside** the preview iframe (`IframeCanvas`) — not a page you navigate to directly. It receives generated JSX via `postMessage`, compiles it with Sucrase, and renders against the project's component snapshot. It contains none of the builder panels; the `layout: 'bare'` route handle gives it no app chrome.

<Aside type="caution" title="Not a security boundary">
The canvas is a same-origin route of your app, so everything it compiles runs with the signed-in viewer's session. Its iframe `sandbox` doesn't change that. If you deploy a Content Security Policy, the canvas needs its own path-scoped policy. See [Integration → Preview Trust Model](/modules/builder/integration/#preview-trust-model).
</Aside>

### Blocks Library Page (`/blocks`)

Browse, search, and manage all your saved blocks:

- Grid and list view toggle
- Filter by scope: all, system, or global blocks (project-scoped blocks are browsed from the project node's Blocks tab, not here)
- Filter by category: a category filter appears next to the scope tabs when you have categories (v1.33.0)
- Search by name. A filter or search with no results shows "No matching blocks".
- A block built for the other shadcn variant than the app's active one shows an outline **Radix** or **Base** badge. It is a mark, not a filter.
- Actions: open in builder, duplicate, delete. Only admins can delete (or update) a **system** block, and for everyone else the menu item reads "Open in Builder".

### Admin Block Builder Page

Accessed via **Admin → Block Builder** (`/admin/block-builder`, admin role only). Full CRUD interface for managing native component definitions, field templates, and module settings (the **Project Node Type**, which now asks for confirmation before it changes); a **Component Sources** tab (browse the shadcn registry index and sync pristine component sources into the builder — development only since v1.33.0); plus bulk **Import** (paste or upload JSON, both the builder-export and shadcn-components.json shapes) and **Export**. See the [Configuration](/modules/builder/configuration/#admin-page) page for details and the [JSON Import & Export reference](/modules/builder/json-reference/) for the component schema and worked examples.

## Frontend Components

### Canvas Components

| Component | File | Purpose |
|-----------|------|---------|
| `CanvasPanel` | `components/canvas/BuilderCanvas.tsx` | The block tree editor with drag-and-drop support |
| `BlockRenderer` | `components/canvas/BlockRenderer.tsx` | Renders individual nodes with sortable, droppable, and drop intent logic |
| `IframeCanvas` | `components/canvas/IframeCanvas.tsx` | Iframe-based live preview with Sucrase compilation |

#### Iframe Preview Protocol

The `IframeCanvas` component communicates with the preview iframe via `postMessage`. This protocol handles code updates, theme injection, node selection, and viewport changes.

**Messages sent to the iframe (parent → iframe):**

| Message Type | Payload | Description |
|-------------|---------|-------------|
| `foundry:global-css` | `{ css, darkMode }` | Inject global CSS (theme variables, base styles). Extensible via the `builder.canvas.globalCss` filter. `darkMode` comes from the Preview panel's light/dark toggle. |
| `foundry:code-update` | `{ code }` | Send generated JSX code for Sucrase compilation and rendering |
| `foundry:component-set` | `{ files }` | Send the merged component snapshot (`files` = `{ name: source }`) for runtime compilation; `null` files → static pristine fallback. (The unused `style` field was dropped in v1.33.0.) |
| `foundry:select-node` | `{ nodeId }` | Highlight a node in the preview (selection sync) |
| `foundry:viewport-resize` | `{ width }` | Resize the preview viewport. `width` is a number for Tablet or Mobile, or `null` for full width (Desktop). Since v1.33.0 it is always sent, so switching back to Desktop releases the width. |

**Messages received from the iframe (iframe → parent):**

| Message Type | Payload | Description |
|-------------|---------|-------------|
| `foundry:ready` | — | Iframe has loaded and is ready to receive messages |
| `foundry:node-clicked` | `{ nodeId }` | User clicked a node in the preview |

`foundry:node-hovered` and `foundry:node-unhovered` were removed in v1.33.0. Nothing ever rendered a hover highlight from them. Both sides of the protocol are the module's own generated files and always update together.

Every message targets `window.location.origin` (never `'*'`). The parent accepts messages only from the iframe's own window on the same origin, and the canvas accepts them only from its parent on the same origin. Since v1.33.0 both listeners also drop non-object data and type-check every payload field before using it.

<Aside type="tip">
The `foundry:global-css` message sends a complete CSS string (not individual variables). Companion modules can replace or extend the CSS via the `builder.canvas.globalCss` filter hook — see the [Integration](/modules/builder/integration/#buildercanvasglobalcss--preview-theme-css) page.
</Aside>

## Hooks

### `useBuilder`

Main builder state management hook. Call this to manage the block tree, selection, and editing operations. Since v1.33.0 BuilderPage itself runs on it, and the canvas's remove action is its `removeNodeById`, so a change to this hook (undo history, for example) reaches the live builder.

```typescript
import { useBuilder } from '@/features/builder/hooks/useBuilder';

const {
  block,           // Current root NodeInstance
  selectedId,      // ID of the currently selected node
  setBlock,        // Replace the entire block tree
  setSelectedId,   // Select a node by ID
  updateNodeProps, // Update properties on a specific node
  removeNodeById,  // Remove a node from the tree
  resetBlock,      // Reset to a fresh default block
} = useBuilder(initialBlock?);
```

### `useBlockTree`

Low-level tree manipulation utilities. Used internally by `useBuilder`, but available for custom integrations:

```typescript
import {
  generateId,          // Generate a random node ID
  createNodeFromType,  // Create a new node with defaults from registry
  createDefaultBlock,  // Create a fresh root block
  findNode,            // Find a node by ID in the tree
  findParent,          // Find a node's parent
  updateNodeIn,        // Update a node's properties (immutable — returns a new tree)
  removeNodeIn,        // Remove a node from the tree (immutable)
  insertNodeIn,        // Insert a node under a parent at an index (immutable)
  moveNodeIn,          // Move a node to a new parent/index (immutable)
  isContainerType,     // Check if a type is a container (registry-aware)
} from '@/features/builder/hooks/useBlockTree';
```

<Aside type="caution" title="Removed in v1.33.0">
The mutable helpers `cloneTree`, `updateNode` and `removeNode` were removed, along with the undocumented `insertNodeAt`. The builder hasn't launched, so it makes clean breaks with no deprecation period. Use `updateNodeIn` and `removeNodeIn` instead, or `structuredClone` for a deep copy. The immutable `*In` helpers clone only the changed path, so unchanged subtrees keep their references.
</Aside>

### `useCodeGeneration`

Generates React component code from a block tree. Requires `NativeComponentsProvider` context. Integrates with the code generation registry — any hooks registered by companion modules (e.g. builder-logic, builder-style) are automatically applied.

```typescript
import { useCodeGeneration } from '@/features/builder/hooks/useCodeGeneration';

// Inside a component wrapped by NativeComponentsProvider
const generatedCode = useCodeGeneration(block, projectId);
// Returns: string (the generated .tsx source code)
```

The code generator is fully config-driven — it uses `codePlacement`, `codeAlias`, `codeFormat` and `variant` from property definitions to determine output. There are no hardcoded property key or component type checks.

Pass `projectId` so the generator knows the project's shadcn variant: properties marked for the other variant are dropped (Radix's `asChild` never reaches a Base project). See [`useActiveVariant`](#useactivevariant).

### `useActiveVariant`

Resolves which shadcn variant (`radix` | `base`) the builder is targeting — the project's component set first (it is what the preview actually compiles), then the app-wide global set, then the `shadcn:builder-style` config.

```typescript
import { useActiveVariant } from '@/features/builder/hooks/useActiveVariant';

const variant = useActiveVariant(projectId);
// Returns: 'radix' | 'base' | undefined
```

`undefined` means **do not filter** — the safe state while those queries load, so a slow query degrades to unfiltered output rather than briefly emitting the wrong props.

### Importing JSX (`shared/jsx-walker.ts`)

The **Import block** toolbar action opens a dialog: paste a shadcn component (or just its JSX) and it becomes an editable block tree — the preview and the normal **Save** flow then behave as they do for a hand-built block.

`importJsx` is the inverse of `tree-walker`, reading the same registry config backwards: `jsxTag` resolves the component, `codeAlias` reverses the attribute name (`type="single"` → `accordionType`), a `codePlacement: 'inner'` property takes a text child, and `codeFormat` / `invertValue` / boolean shorthand reverse deterministically.

```typescript
import { importJsx } from '@/features/builder/shared/jsx-walker';

const { nodes, issues, nodeCount } = await importJsx(code, registry, variant);
```

Anything the registry cannot describe becomes an `ImportIssue` rather than being dropped silently — an unknown tag, an attribute with no matching property, or a runtime expression (`{expr}`, `.map()`, spreads). The dialog shows them as a mapping report before you commit.

- Text inside a container with no inner property (e.g. `AccordionContent`) becomes a node of its own via the registry's dynamic-tag text primitive (Typography).
- An unknown PascalCase tag resolves to the `$icon` primitive **only** when the snippet imports it from a known icon module (`lucide-react`, Tabler, Phosphor, Remix, Hugeicons) — evidence, not a name-shaped guess.
- `@babel/parser` is lazy-loaded, so it stays out of the bundle until the dialog opens.

### `useNativeComponents`

Provides the component registry context. Wrap your builder UI with `NativeComponentsProvider` to access it.

```typescript
import {
  NativeComponentsProvider,
  useComponentRegistry,
} from '@/features/builder/hooks/useNativeComponents';

// In your component tree
<NativeComponentsProvider>
  <YourBuilderUI />
</NativeComponentsProvider>

// Inside child components
const {
  registry,           // ComponentRegistry (type -> ComponentDefinition)
  nativeComponentDefs,// ComponentDefinition[] — the same definitions as an array
  getByCategory,      // (category) => ComponentDefinition[]
  getChildrenFor,     // (parentType) => ComponentDefinition[]
  isLoading,          // boolean
  error,              // string | null
  refetch,            // () => Promise — refetch the catalogue
  projectNodeType,    // string | null — the effective project node type slug (config, else "projects"); null only before load
} = useComponentRegistry();
```

v1.33.0 **removed** the unused `isContainer` and `getDefaultChildren` members (a pre-launch clean break). Use `isContainerType(type, registry)` from `hooks/useBlockTree` and `registry[type]?.defaultChildren` instead. (Shared field templates come from `GET /components`, not from this context.)

### `useProjectBlocks`

Fetches and manages blocks scoped to a specific project.

```typescript
import { useProjectBlocks } from '@/features/builder/hooks/useProjectBlocks';

const {
  blocks,       // BlockData[] (project-scoped)
  globalBlocks, // BlockData[] (global blocks)
  isLoading,    // boolean
  deleteBlock,  // (id: string) => Promise<void>
} = useProjectBlocks(projectId);
```

### `useProjectComponentSet`

Fetches and manages a project's pinned component snapshot — the versioned shadcn sources the preview compiles against. See [per-project component snapshots](/modules/builder/integration/#per-project-component-snapshots).

```typescript
import { useProjectComponentSet } from '@/features/builder/hooks/useProjectComponentSet';

const {
  set,          // ProjectComponentSet | null (the pinned snapshot + pending diff)
  isLoading,    // boolean
  sync,         // ({ style, names? }) => Promise — create/replace the snapshot
  checkUpdates, // () => Promise — diff latest sources vs current (stores pending)
  promote,      // () => Promise — apply the pending update
} = useProjectComponentSet(projectId);
```

### `useBlocksLibrary`

Powers the Blocks Library page — fetching, filtering, and searching blocks across all scopes.

```typescript
import { useBlocksLibrary } from '@/features/builder/hooks/useBlocksLibrary';
```

Since v1.33.0 its `isLoading` covers only the block lists. Categories arrive separately and fill the category filter when they load.

### `useNativeComponentsAdmin`

Admin-only hook for managing native component definitions.

```typescript
import { useNativeComponentsAdmin } from '@/features/builder/hooks/useNativeComponentsAdmin';
```

## Types

The core types are defined in `features/builder/types/index.ts`:

```typescript
// What category a component belongs to
type ComponentCategory = 'container' | 'element' | 'child' | 'primitive' | 'layout';

// Source library
type ComponentLibrary = 'shadcn' | 'primitive' | 'plate' | 'custom';

// A property definition on a component
interface PropertyDefinition {
  key: string;
  label: string;
  type: 'string' | 'number' | 'boolean' | 'select' | 'icon' | 'textarea' | 'id' | 'className';
  default?: unknown;
  options?: PropertyOption[];
  /** Help text the property panel shows under the field. */
  description?: string;
  placeholder?: string;
  /** Shows a required marker in the property panel (from the catalogue's isRequired). A hint only — saving is not blocked. */
  required?: boolean;
  codePlacement?: 'attribute' | 'inner' | 'hidden';
  codeAlias?: string;
  codeFormat?: 'default' | 'array';
  unique?: boolean;
  invertValue?: boolean;
  /** shadcn variant this prop belongs to; omit = applies to both. */
  variant?: 'radix' | 'base';
}

// A component in the registry
interface ComponentDefinition {
  type: string;
  library?: ComponentLibrary;
  label: string;
  description?: string;
  category: ComponentCategory;
  icon: LucideIcon;
  jsxTag?: string;
  importPath?: string;
  selfClosing?: boolean;
  isContainer?: boolean;
  acceptsAny?: boolean;
  parent?: string;
  properties: PropertyDefinition[];
  allowedChildren?: string[];
  defaultChildren?: Array<string | DefaultChildConfig>;
  codeStructure?: CodeStructureConfig;
}

// Code-generation hints on a component
interface CodeStructureConfig {
  conditionalWrapper?: { tag: string; conditionProp: string; classNameProp?: string };
}

// A node in the block tree (runtime)
interface NodeInstance {
  id: string;
  type: string;
  children?: NodeInstance[];
  [key: string]: unknown;  // Property values stored directly on the node
}

// The full registry
interface ComponentRegistry {
  [type: string]: ComponentDefinition;
}
```

v1.33.0 removed the never-implemented `richText` and `classNameKey` from `PropertyDefinition`, and `wrapper`, `siblingsBefore` and `siblingsAfter` from `CodeStructureConfig`. Stored catalogue JSON that still has them is ignored. It also removed `ComponentDefinition.defaultConfig`, which the catalogue never populated: a node's initial values come from each property's `default`.

## Backend API Endpoints

All endpoints are under `/api/v1/builder` and require authentication unless noted.

<Aside type="note" title="Conventions (v1.33.0)">
- **404 for a project you don't own.** Every route that takes a project answers "Project not found or access denied" with `404`, whether the project doesn't exist or isn't yours. Before v1.33.0 the block, category, collection and component-set routes answered `403`.
- **Step-up.** Routes marked *step-up* run the starter's `requireStepUp` after the auth check. It passes requests through at the `standard` security tier. At `hardened` and `strict` it answers `403` with code `step_up_required` until the user enters an emailed code; the `@/lib/api` client shows that dialog and retries. Device tokens are always refused (`403 web_session_required`).
- **Client-safe errors.** The `errors` arrays from syncs, source checks and imports hold fixed messages (for example `<name>: could not be fetched from the shadcn registry`). The underlying error is logged on the server.
</Aside>

### Native Components

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/components` | All components + shared fields + project node type |
| `POST` | `/components` | Create or update a component (upsert by type). Admin only. `400` with the reason if the component fails [catalogue validation](/modules/builder/json-reference/#import-behaviour) |
| `DELETE` | `/components/:type` | Delete a component. Admin only |
| `POST` | `/components/import` | Bulk import components from `{ components: [...] }`. Admin only. Invalid rows are skipped and listed in `errors` |
| `POST` | `/components/import-json` | Import from `shadcn-components.json` format. Admin only. Invalid rows are skipped and listed in `errors` |

`GET /components/:type` was removed in v1.33.0 (it had no caller). Read the whole palette with `GET /components`.

### Component Sources & Global Set

The global set is the app-wide fallback snapshot the preview compiles for global/system blocks (and when no project is selected); the source routes keep the pristine component folder in sync with the upstream shadcn registry. Every route except `GET /components/global-set` is admin-only. The routes that take a `style` accept only one of the 16 [supported styles](/modules/builder/configuration/#shadcn-style) (`400` otherwise).

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/components/global-set` | The app-wide fallback component snapshot |
| `POST` | `/components/global-set/sync` | Sync the global fallback set from the current palette (`502` when no source could be fetched) |
| `POST` | `/components/sync-pristine` | Incrementally add palette components missing from the pristine folder. **Development only**: in production it adds nothing and returns `{ added: [], errors: [] }`, so the import flow that calls it doesn't fail |
| `POST` | `/components/source-updates/check` | Diff synced pristine sources against the latest registry; returns slugs with updates |
| `GET` | `/components/:type/source-diff` | Current vs latest pristine source for a component |
| `POST` | `/components/:type/source-promote` | Write the latest registry source into the component's pristine file. *Step-up.* **Development only**: `409` in production |

### Config

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/config/:key` | Get a config value. Only `projectNodeType` and `pristineSourceUpdates` are served; any other key, or a key with no stored row, answers `404` |
| `PUT` | `/config/:key` | Set a config value. Admin only, *step-up*. Only `projectNodeType` can be set here (`400` for any other key), the body must include `value`, and it must be the slug of an existing node type |

Shared fields, the builder style and the icon library have their own routes. Registry caches and one-time flags are managed by the server and can't be read or written through these routes. The key names are exported as `CONFIG_KEYS` from the backend barrel. The frontend API client's `getConfig` and `setConfig` are typed to the same allowlists.

### Shared Fields

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/shared-fields` | Create or update a shared field template. Admin only. `name` must be a string of at most 100 characters and `field` an object |
| `DELETE` | `/shared-fields/:name` | Delete a shared field template. Admin only |

### Blocks

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/blocks` | List blocks (supports query filters) |
| `GET` | `/blocks/:id` | Get a single block |
| `POST` | `/blocks` | Create a block. Only admins may set `isSystem` |
| `PUT` | `/blocks/:id` | Update a block (auto-appends changelog). A **system** block can be updated by any admin and by nobody else. `409` on a rename onto an existing name |
| `DELETE` | `/blocks/:id` | Delete a block. A **system** block can be deleted by any admin and by nobody else |
| `POST` | `/blocks/:id/duplicate` | Duplicate a block (including a system block). The copy keeps the source's category only when the source block is yours |

**Limits on block bodies** (`POST` / `PUT`): `data` must be an object of at most 1,000,000 characters (as JSON), `generatedCode` at most 512,000, `displayName` at most 200, `description` at most 2,000 and `changelogMessage` at most 500. An oversize field answers `413` and a wrong type answers `400`. A block keeps its 100 most recent changelog entries. A `categoryId` or `collectionId` that the block's owner doesn't own is stored as `null`.

**Block list filters** (query parameters on `GET /blocks`):

| Parameter | Description |
|-----------|-------------|
| `?projectId=xxx` | Blocks scoped to a project |
| `?collectionId=xxx` | Blocks within a collection (no UI caller yet, kept for the planned Collections & Layouts layer) |
| `?global=true` | Global blocks (no project scope) |
| `?system=true` | System blocks (admin-created, available to all) |

|--------|------|-------------|
| `GET` | `/categories` | All categories for the user |
| `POST` | `/categories` | Create a category. `name` must be a kebab-case slug, `label` at most 100 characters and `sortOrder` an integer. A duplicate name answers `409` |
| `DELETE` | `/categories/:id` | Delete a category (no UI caller yet) |

| `POST` | `/collections` | Create a collection. `name` must be a slug, `displayName` at most 200 characters, `description` at most 2,000, and `type` one of `collection`, `layout`, `page`. A duplicate name answers `409` |

| `GET` | `/check-handle?handle=xxx` | Check if a registry handle is available |
| `PUT` | `/handle` | Claim (or change) the caller's registry handle. Web session and *step-up*. `409` if already taken |

Handle format: lowercase, 3–30 characters, letters/numbers/hyphens only, cannot start or end with a hyphen. A denylist of reserved names (`www`, `api`, `app`, `admin`, `registry`, `r`, and other infrastructure subdomains) is rejected on both routes.

### Shadcn Registry Proxy

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/shadcn/index` | Fetch (cached) shadcn component index. `?refresh=true` forces a refetch for admins only, and is ignored for everyone else |
| `POST` | `/shadcn/sync-builder` | Sync pristine components to the builder folder. Admin only, *step-up*. **Development only**: `409` in production. `names` is optional, with at most 200 slugs |
| `GET` | `/shadcn/builder-style` | Get current builder style |

`GET /shadcn/components/:name` was removed in v1.33.0. It had no caller and let any signed-in user trigger an outbound fetch. The service method `getShadcnComponent` remains, because the syncs use it. The builder-style and icon-library routes have no UI yet. They are kept for the planned multi-library work.

Each project can pin its own versioned shadcn sources — the snapshot the preview compiles against. These routes are ownership-guarded (`404` if you don't own the project).

## Public Registry API

<Aside type="tip">
These endpoints are **public** (no authentication required for public projects). They serve JSON consumed by the `shadcn` CLI, which sends no `Origin` header — the router is registered with `allowNoOrigin` so the production CORS gate lets it through. Only **active** projects are served: an archived or (soft-)deleted project answers the same `404` as an unknown slug.
</Aside>

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/r/:projectSlug` | List available blocks in a project. `project.namespace` is the locked project slug as-is (the `@` alias and URL key), and `project.installDir` is the folder items install into. `globalBlocks` is filled only when the project has [included its global blocks](/modules/builder/private-registries/#include-global-blocks), and leaves out any global block a project block shadows |
| `GET` | `/api/v1/r/:projectSlug/:blockName.json` | Get registry JSON for a specific block. Its file installs to `components/<installDir>/<block-name>.tsx` |

Since v1.33.0 each project installs into **its own folder**, `components/<installDir>/`, so same-named blocks from two projects no longer overwrite each other. Before that, every item targeted `components/foundry/`. `installDir` is the kebab-case form of the project slug, which is identical to the slug for every kebab-case slug. New projects whose client-supplied slug isn't kebab-case get a generated kebab-case slug, and existing slugs never change. Consumers who re-run `npx shadcn add` get the new folder and must update their imports.

Registry URLs use subdomain-based user identification:

```
https://handle.usefoundryui.app/api/v1/r/my-project/hero-section.json
```

For local development, you can use the `?handle=` query parameter instead:

```
http://localhost:3001/api/v1/r/my-project/hero-section.json?handle=myhandle
```

`?handle=` works on any host that isn't a `<handle>.<REGISTRY_DOMAIN>` subdomain. On a handle subdomain, the subdomain wins. See [Configuration](/modules/builder/configuration/#environment-variables).

### Private Projects

If a project's registry is set to `visibility: 'private'`, every `/api/v1/r` request must present a Bearer token:

```bash
curl -H "Authorization: Bearer <token>" \
  https://handle.usefoundryui.app/api/v1/r/private-project/my-block.json
```

The token is minted on the project's **Registry** tab and stored **encrypted at rest** on the project node's `data.registryAccessToken` field — sealed with `encryptField` (AES-256-GCM, bound to the project) as `{ __sealed: … }`, never in plaintext. The `/api/v1/r` route decrypts it with the owner as tenant and does a constant-time compare; a missing, plaintext, undecryptable, copied, or mismatched token is a uniform `401`. (Tokens minted before v1.32.0 are retired — mint a new one.)

See [Private Registries](/modules/builder/private-registries/) for the full token and visibility flow.

### Installing Blocks

The install namespace is the **project slug** (`@my-project`), not your user handle — each project is its own namespace, so installing from two of your projects never collides.

<Tabs>
  <TabItem label="Public registry">
    Add the registry to your consumer app's `components.json`, keyed on the project slug:

    ```json
    {
      "registries": {
        "@my-project": "https://myhandle.usefoundryui.app/api/v1/r/my-project/{name}.json"
      }
    }
    ```

    Then install blocks by name:

    ```bash
    npx shadcn@latest add @my-project/hero-section
    ```
  </TabItem>
  <TabItem label="Private registry">
    A private registry needs the bearer header, so use the **object form**:

    ```json
    {
      "registries": {
        "@my-project": {
          "url": "https://myhandle.usefoundryui.app/api/v1/r/my-project/{name}.json",
          "headers": { "Authorization": "Bearer ${FOUNDRY_REGISTRY_TOKEN}" }
        }
      }
    }
    ```

    Add the token you minted in the Registry tab to your consumer app's `.env.local`:

    ```bash
    FOUNDRY_REGISTRY_TOKEN=<the token you minted in the Registry tab>
    ```

    Then install as usual — the CLI reads the token from the environment:

    ```bash
    npx shadcn@latest add @my-project/hero-section
    ```
  </TabItem>
  <TabItem label="Direct URL">
    Install directly without configuring `components.json` (public registries only — a direct URL can't carry a bearer token):

    ```bash
    npx shadcn@latest add https://myhandle.usefoundryui.app/api/v1/r/my-project/hero-section.json
    ```
  </TabItem>
</Tabs>

See [Private Registries](/modules/builder/private-registries/) for the full token and visibility flow.

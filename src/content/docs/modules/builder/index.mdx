The **Block Builder** module provides a visual component builder for useFoundryUI. You drag components onto a canvas, configure their properties, preview the result live, and save blocks that generate shadcn-compatible registry JSON — ready to install into any project with `npx shadcn add`.

<Aside type="note">
This module requires the [Structure](/modules/structure/) module (≥ 1.37.5) for project integration (organising blocks into projects, per-project registry URLs), and a **starter ≥ 2.13.0** host (since v1.32.0). The current release, **v1.33.0**, has the same requirements. Updating to it renames the builder's tables to `builder_*` in place, so run `npx builder update` with its schema step, before updating any other module. See the [changelog upgrade notes](/modules/builder/changelog/#v1330--october-2026).
</Aside>

## Quick Install

```bash
npx builder init
```

The CLI walks you through installation — it creates database tables, generates frontend and backend code, installs shadcn components, seeds default configuration, and (in development) syncs pristine shadcn component source files for the live preview.

- Structure module integration (tabs, widget, card badge, column, lifecycle hooks)
- Blocks Library page with grid/list views, scope and category filtering, search, and a Radix/Base variant badge
- Block duplicate and edit-in-place with changelog tracking
- Admin page for native component management (admin role only)

## Architecture

The builder follows a **config-driven** approach. Block types are defined in a database-driven component registry (`native_component` table), not hardcoded. This means you can add, remove, or modify available components without touching code.

### Component Categories

| Category | Can Have Children? | Examples |
|----------|:------------------:|----------|
| **Containers** | Yes | Card, Dialog, Accordion, ScrollArea |
| **Elements** | No | Button, Input, Badge, Avatar |
| **Layouts** | Yes | Flexbox/grid wrappers, sections (rendered as the palette's "Layouts" group) |
| **Child** | Varies | CardHeader, AccordionItem — parent-scoped, shown nested rather than as a top-level palette group |
| **Primitives** | Varies | Div, Icon, Span |

The runtime category values are `container`, `element`, `layout`, `child`, and `primitive` (see `ComponentCategory`). The palette surfaces Containers, Elements, Layouts, and Primitives as top-level groups; child components appear nested under their parent.

### Extension Points

The builder provides registries and filter hooks for companion modules:

- **Property Panel Tab Registry** — add tabs to the right-side property panel (e.g. Style, Logic). A `BaseRegistry` since v1.33.0, with `order` and `moduleId`
- **Code Generation Registry** — hook into import generation, component body injection, and prop transforms. A `BaseRegistry` since v1.33.0; hooks run in `order`
- **`builder.canvas.globalCss`** filter — override the iframe preview CSS with project-specific themes (HSL or OKLCH)
- **`builder.registry.componentsJson`** filter — enrich the `components.json` snippet with additional config (e.g. `$schema`, `style`, `tailwind`)
- **11 CRUD action hooks** — react to native-component, block, category, and collection lifecycle events (including one bulk `builder.component.imported`)
- **6 registry action hooks** — `builder.registryToken.minted`, `builder.registryToken.revealed`, `builder.registryToken.revoked`, `builder.registryVisibility.changed`, `builder.registryIncludeGlobal.changed`, and `builder.handle.claimed`. See [Private Registries](/modules/builder/private-registries/) for the full token/visibility flow.
- **5 app-wide admin change hooks** (v1.33.0) — `builder.config.updated`, `builder.projectNodeType.changed`, `builder.pristine.synced`, `builder.pristine.promoted`, and `builder.globalComponentSet.synced`

See the [Integration](/modules/builder/integration/) page for full details.

### Registry Output

The builder generates shadcn-compatible registry JSON served via per-project public URLs:

```
https://handle.usefoundryui.app/api/v1/r/project-slug/block-name.json
```

Consumer apps install blocks using the standard shadcn CLI:

```bash
npx shadcn add https://handle.usefoundryui.app/api/v1/r/my-project/hero-section.json
```

Since v1.33.0, each block installs to `components/<installDir>/<block-name>.tsx` in the consumer app. Before that, it was `components/foundry/` for every project. `installDir` is the kebab-case form of the project slug, and the registry listing reports it as `project.installDir`. It is identical to the slug for every kebab-case slug.

### Database Tables

Since v1.33.0 every table carries the `builder_` prefix. The Prisma model names (first column) are unchanged, and existing installs are renamed in place by `npx builder update`. See [Configuration → Table names](/modules/builder/configuration/#table-names-v1330).

| Model | Table | Purpose |
|-------|-------|---------|
| `native_component` | `builder_native_component` | Component palette definitions (public, no userId) |
| `block` | `builder_block` | User-saved block trees with generated code |
| `block_category` | `builder_block_category` | User-created folders for organising blocks |
| `block_collection` | `builder_block_collection` | Multi-block compositions (layouts, page sets) |
| `builder_config` | `builder_config` | Module-level config (shared fields, project node type, shadcn style, icon library, caches and one-time flags) |
| `builder_component_set` | `builder_component_set` | Per-project pinned snapshot of the shadcn component sources (`library` + `style`) plus the derived per-`data-slot` `baseClasses` manifest; unique per project, drives the live preview and feeds the style module |
| `registry_handle` | `builder_registry_handle` | Public handle → user mapping — the uniqueness authority and indexed fast path for public `/api/v1/r` handle resolution (shipped v1.31.2; since v1.32.0 the only path, after a one-time migration of legacy preferences handles) |

### Philosophy

"Design down to dev, not dev up to design" — users see what they're building before code is generated.

## Prerequisites

- **Structure module ≥ 1.37.5** (verified on 1.37.5 and 1.38.0) — must be installed first (`npx structure init`); `npx builder init` aborts on an older one
- **Starter template ≥ 2.13.0** — the builder uses its `DataTable`, `react-router` v8, `requireWebSession`, export-handler and `getApiErrorMessage` APIs
- **Node.js 22.22+** and a running starter template app
- **Neon database** (or compatible PostgreSQL) with Prisma configured

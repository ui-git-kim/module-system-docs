## Veradai-Driven Build Sequence

<Aside type="tip">
Added 2026-07-26 after mapping the **veradai app's** structure requirements against the code (a per-cluster audit). Most requirements are **already shipped**; the items below are the verified gap set, sequenced — the current active priority driver. The recurring theme (again): most gaps are **missing enforcement of config that already exists**, the same shape as the v1.23.0 trust-fix. See the detailed [Build Plan](/modules/structure/build-plan/) for phase-by-phase, grounded insertion points.
</Aside>

1. **Primary-node scope selector + parent enforcement** — ✅ **Shipped v1.24.0.** A `primaryScope` node-type config (`isPrimary` marks the **primary scope type**, e.g. Matter; `scopedTypes` lists which types the selection filters); a header-toolbar `ScopeSelector` (`headerToolbarRegistry` `type: 'custom'` + `NodeSelector`) to pick the current instance; a client `useCurrentScope` store persisted to `structure_settings`; and `NodeListPage` scoping via `pathPrefix` to the selected node's subtree. **Scoped types are an admin choice** — empty/`*` scopes every type, a specific list scopes only its members (global/reference types like legislation stay unscoped unless included), and the primary type's own list is never self-scoped. Ships with the **enforcement half**: `createNode`/`moveNode` now enforce the previously config-only `rules` (`isRoot` requires a parent, `allowedParents`/`allowedChildren`, `maxChildren`, `maxDepth`), opt-in per rule so unconfigured types are unaffected. Built for one primary now, config shaped for multiple/secondary later. *(Follow-ups: `bulkCreateNodes` enforcement, subtree-aware move `maxDepth`.)*
2. **AI fields** — ✅ **Node-type half shipped v1.30.0.** A per-node-type `aiFields` config (`{ promptSegments?, outputExamples? }`) stored by Structure and consumed by AI Core for prompt assembly — added via the `contextHints`/`governance` mirror-site pattern. The shape is aligned to AI Core's `ConsumerSegment` contract (`promptSegments[].type` = `'context' | 'task' | 'external'`, `content: string`). Structure is **storage + exposure only**; the AI **tab** is AI Core's to self-register (`StructureModuleRegistration.tabs`) — present iff AI Core is installed, no module-presence check in Structure. *(Phase 2 is now **complete**: the connection-type half shipped in **v1.34.24** — `contextHints` + `aiFields` columns on `structure_connection_type`, wired through create/update/list/get, the Zod schemas, the config bundle, and an AI tab in the connection-type editor gated on AI Core.)*
3. **Generic node-type rules section** — ✅ **Shipped v1.25.0.** A generic, extensible `governance` config whose first rule type is **classification**: ordered per-type sensitivity `levels` (`{ value, label, rank, color? }`) + a `default`, optional per-field `sensitivity`, and a per-node `structure_node.classification` override column (with a `classificationChanged` hook). Structure stores + evaluates via exported `getEffectiveClassification` / `isExportSafe(node, type, level)`; a consuming module's export pipeline enforces the gate. *(Levels are per-type; the per-node override UI picker shipped v1.33.21 — Settings tab, for types with classification levels; deferred: app-wide shared scheme.)*
4. **Field UX** — ✅ **Shipped v1.26.0.** A `defaultCollapsed` field property (any field or `field-group` renders collapsed by default under a label+chevron trigger — the "hidden until revealed" complement to `visibleWhen`, honoured in edit + read-only via shadcn `Collapsible`, toggled from the field editor), **and** the fix so `visibleWhen` / `computedTemplate` now work inside `field-group` repeaters (the renderer now passes `{ ...topLevel, ...row }` to sub-fields — previously dropped, so they silently no-op'd). *(The repeater fix is a behaviour change for existing repeater sub-fields — see the changelog.)*
5. **Merge-field exposure** — ✅ **Shipped v1.28.0.** Structure exposes its merge fields so an external visual builder (useFoundry) can bind to a node type's fields: a `getMergeFieldSchema(nodeType)` metadata API returning `MergeFieldToken[]` (built-ins + fields + `field-group` subfields + one-hop node-ref deref, from a single pure `flattenMergeFields` core); the resolver extracted to a React-free `utils/merge-fields.ts` and **exported** (`resolveTemplateAsync` with an injectable node-fetch + a `resolveMergeFields` convenience); a merge-field-driven card (`titleTemplate`/`bodyTemplate` on `CardTemplateConfig`, resolved by `NodeCard` — which now also honours `cardTemplateId`); the admin "Insert field…" pickers upgraded to surface group + deref tokens; and a public `GET /:type/schema` endpoint returning the secret-filtered flattener inputs. This **rescoped [Custom Detail Page Layouts](#custom-detail-page-layouts)** (below) — structure = data + exposure, presentation lives in the builder. *(NodeCard applying `cardTemplateId` is a behaviour change — see the changelog.)*
6. **Shared field templates across node types** — ✅ **Shipped v1.29.0.** Define a field set once (`structure_field_template` `{ name, slug, description, fields }`, with CRUD + a Field Templates admin page) and attach it to many node types via a `fieldTemplateIds` config. Template fields merge into `resolved.fields` (own › template › inherited, tagged `fieldTemplateId`) **and** through the write-path walkers (`getFieldDefs`) so template secret fields are sealed and locked fields enforced. Attach-only (not inherited via `superClasses`); provenance shown in the Fields tab; JSON authoring for now (visual editor is a fast-follow).

**Also on the list (lower / as-pulled):**
- Rename **workflow → `stage`** — ✅ **Shipped v1.33.17.** The `workflow`/`workflowState`/`workflowConfig` surface is renamed to `stage`/`stageConfig` across the schema, service, public API, types and admin UI (`status` was rejected — it collides with the node lifecycle column, so `stage` was chosen). DB columns are preserved via Prisma `@map` (no data move); a one-time migration renames the inner JSON keys (`states → stages`, `defaultState → defaultStage`, `features.workflowStates → features.stages`). **Stage-transition enforcement is now real** — `updateNode` rejects a change the `stageConfig.transitions` map does not permit (opt-in: an unset from-stage or empty map is unconstrained), with a new admin allowed-transitions editor. Consumers must update the renamed API params / JSON keys (pre-launch clean break).
- **Search** — ✅ **Shipped v1.27.0.** The free-text keyword search now scans custom `data` field values (values, via a guarded `jsonb_each_text` fold into the search `OR`), on top of name + description. Structured querying stays the 13-operator `dataFilters` engine; retrieval/ranking stays cog-ingest / AI Core.
- **Bulk connection creation** — ✅ **Shipped v1.27.0.** `bulkCreateConnections` service method (partial-success, reuses `createConnection` validation) + `POST /connections/bulk`, exposed via the service registry for cog-ingest; `skipHooks` fires one `structure.connections.bulkCreated` summary instead of per-row hooks.

**Not structure's job:** audit-log storage → **Activity** module (CRUD hooks already fire); semantic-search query embedding → **cog-ingest / AI Core** (structure owns vector storage + kNN). **Server-side field validation** is no longer parked — it is **Stage 1** of the Generic Platform Hardening plan below (it must cover the public API and cog-ingest's programmatic writes, not just forms). Graph-derived values still flow the same way (cog-ingest computes → writes to a structure `editableBy:'system'` field — storage already exists).

## Generic Platform Hardening (2026-08-09 audit + plan)

<Aside type="tip">
Added 2026-08-09 after a nine-agent gap-analysis audit of the whole module against generic data-platform benchmarks (Directus, Strapi, PocketBase, Supabase, Airtable, Salesforce, JetEngine). Framing is **generic** — Structure is the admin-configurable architecture, not any one app's domain. The standing calls are in [Design Decisions](/modules/structure/decisions/); the grounded, phase-by-phase insertion points are in the [Build Plan](/modules/structure/build-plan/#generic-platform-hardening--stages-13-2026-08-09).
</Aside>

The audit's headline: the field/type **definition** layer the research flagged as the "biggest gap" is already built and rich (`NodeTypeField`, `nodeFieldTypeRegistry`, shared field templates, groups, node-ref deref, `superClasses` DAG). The real gaps are **server-side enforcement** and a few platform features.

**Stage 1 — write-path integrity + two new generic requirements**

- **Server-side field validation** — ✅ **shipped v1.33.31**: one `validateNodeData` validator over the resolved field set (required / pattern / min-max / enum / type), run on create / update / bulk / public-API writes; cog-ingest inherits it. *(Follow-ups: `requiredWhen`, field-group sub-field validation.)*
- ~~Computed-value server trust~~ — **removed** (2026-08-09): solo app whose only external surface is the API-key public API (the user's own keys), so there is no untrusted writer to spoof computed values. Formulas + merge fields keep working client-side.
- **Node-type permission enforcement** — ✅ **shipped v1.33.32**: the config-only `permissions` block is enforced server-side in the service methods, tier extended to `'anyone' | 'admin' | 'system'`. The **simplified model dropped the separate `inputScope`/`global` fields** (they duplicated `permissions` + structural scope membership — see the [D7 follow-up](/modules/structure/decisions/#resolved-follow-ups-2026-08-09)).
- **Shared / reference nodes** — `global` types stored with a nullable (blank) owner (`null` = shared, read-to-all/admin-write), connectable-to-shared. The cog-ingest house pattern.
- **Enforced scoping (generic "spaces")** — ✅ **shipped v1.34.0**: opt-in `primaryScope.isolation: 'filter' | 'enforced'` + a denormalised `rootNodeId` column; server-side, fail-closed confinement in **two modes** — *ambient* (list / tree / keyword search / getNode / neighbourhood reads / connections → the active space, read from the persisted `currentScopeNodeId`) and *anchored* (context / graph / `findSimilarNodes` → the seed node's own space — the AI-context leak fix). Connection carve-out (no cross-enforced-space edges), out-of-space-move gate (`rules.allowCrossSpaceMove`, default off + audited), `rootNodeId` on node lifecycle payloads. Scope-exemption is structural (a node not inside an enforced root). See [Decision B](/modules/structure/decisions/#decision-b--enforced-scoping-generic-spaces). **Follow-ups:** the vector/BM25 retrieval arm now takes an **opt-in `scopeRootId`** on all six search methods (nodes + chunks, semantic / lexical / hybrid) as of **v1.34.2** — the Structure-side half (a self-contained `rootNodeId` predicate); cog-ingest/ai-core still need to *pass* the active space to actually confine retrieval. Also: surface a failed scope-switch persist to the user.
- **Node revision history + restore + `auditEvents` contract** — the **`auditEvents` contract shipped v1.34.2**: the security manifest declares all ~40 fired lifecycle events (read via `securityRegistry.getAuditEvents()`). **Still open:** the `structure_node_revision` table + snapshot-on-update + restore — generic node-record versioning (no tamper-evident hash chain — that's document-management's / the app's job).

**Stage 2 — make it a real platform**

- **Config env-promotion** — ✅ **core shipped v1.33.34**: atomic server-side full-bundle export/import covering all five categories (node types + connection types + groups + field templates + functions) via `GET`/`POST /config/import`, in one transaction, with a per-category created/updated/deleted result summary and `replace`-mode pruning of every present category. **Diff/dry-run preview + per-category *unchanged* counts shipped v1.34.2** — `POST /config/import` with `dryRun: true` computes the exact diff inside a rolled-back transaction, and the admin dialog gains a **Preview** button. **Still open:** per-definition versioning.
- **Node-instance import/export (CSV/JSON)** — bulk instance data with field mapping + validation.
- **jsonb + path indexing at scale** — GIN / functional indexes on `data` for the `dataFilters` engine. *(The `rootNodeId` equality indexes for scoped reads shipped with v1.34.0: `@@index([userId, rootNodeId])` + `@@index([userId, rootNodeId, nodeType])`.)*
- **Retention / purge** — for soft-deleted nodes and old revisions.

**Stage 3 / future**

- **Blueprints / starter-packs** — a "stamp out a whole node-type + connection set" primitive (a CRM pack, a PM pack). Deferred — relevant if the module system is distributed to third parties.
- Outbound webhooks, saved full views (columns + sort), slug auto-derive + `publishedSlug` serving, i18n labels, sibling drag-reorder UI, bulk-update/bulk-move endpoints.

**Follow-ups since settled (see [Decisions](/modules/structure/decisions/#resolved-follow-ups-2026-08-09)):** the three questions this section once left open all have a call. Cross-space *move* is **admin-configurable per node type** — off by default, permitted and audited when a type opts in via `rules.allowCrossSpaceMove` (D3). There is **no** admin "see-all" data mode: `admin` is a configuration authority, not a data-access super-role, so every read stays owner- and space-scoped (D4). The scope-exempt marker was *decided* as an explicit **`global`** flag, but as shipped it is **structural** (D7): a type absent from a non-empty `primaryScope.scopedTypes` list is never confined (`typeIsScoped` — an *empty* list confines every type), and a cross-space connection is allowed whenever either endpoint's root is not an enforced-space root (`enforcedRootIds`, read by `createConnection` and the connection reads).

**🟡 Moderate — Security**

**Security and data integrity**

- **Cross-user connection read (IDOR).** `createNode` writes client-supplied `fromNodeId`/`toNodeId` with no ownership check (`backend/index.ts` ~L2431); `getNodeConnections` / `listConnections` then hydrate `include: { fromNode, toNode }` with no `userId` predicate (~L4155 / ~L4203), so a connection pointed at another user's node id returns that user's full node row — name, description, and the entire `data` blob. - **Deletion handlers can wipe entire tables.** Every erasure handler derives `const userId = ctx.subject.userId ?? ctx.subject.tenantId` then calls `deleteMany({ where: { userId } })` (`backend/registrations.ts` ~L83 onward). - **`bulkCreateNodes` reports partial success from an aborted transaction** (`backend/index.ts` ~L2994). Per-row errors are caught *inside* an interactive transaction Prisma has already rolled back, so rows reported "created" were never committed.

### Chunk storage — deferred refinements

**Priority:** Low — the v1.22.0 foundation is complete; these are lean-first deferrals

The `structure_chunk` table, its `structureEmbeddings` chunk methods, and `semanticSearchChunks` shipped in v1.22.0. Deliberately deferred to keep the first contract lean:

- **`semanticSearchChunks` could hydrate the parent node inline.** The query already joins `structure_nodes` for the status/type filter, so returning the node alongside each chunk is cheap — deferred so the first result shape stays `{ chunk, nodeId, score, distance }`. Add an `includeNode?` option if a consumer needs it.

### Searchable Encrypted Fields

**Priority:** Low — depends on a starter-provided primitive

A future capability to let a node-type field be flagged `encrypted` (AES-256-GCM at rest, key never in the database) while still being **filterable within a single user's own data space**. Today an encrypted field is genuinely un-filterable and un-sortable: `buildDataFilterQuery` emits raw SQL against `data->>'field'`, and a non-deterministic GCM envelope is opaque to `=`, `ILIKE`, and range comparisons. This entry scopes how we will restore *limited* search without ever implying false security. Nothing here ships until the dependency below lands.

- **Dependency on the starter.** This will require a starter-provided **per-tenant blind-index primitive** — a keyed `HMAC(indexKey, normalize(value))` helper, with the index key derived *separately* from the encryption key. That primitive does not exist yet and is the **remaining** blocker. The earlier prerequisite — the starter actually deriving **per-tenant keys (HKDF)** instead of sharing one global key — **shipped in starter v1.64.0** (the envelope's `{ tenantId }` option is now honoured), so a blind index built on it would get real per-tenant isolation once the primitive lands.
- **Per-field `encrypted` flag.** Admins will be able to flag a field encrypted; an additional opt-in will enable a blind-index sibling tag column (`dataIndex`) for that field. The blind index will be **restricted to high-entropy fields** — never booleans, status enums, country, or short codes, whose plaintext is recoverable from a deterministic tag via frequency analysis.
- **Exact-match / keyword only on encrypted fields.** A blind index will support `equals`, `in`, membership, dedupe, and whole-word keyword lookups only. **Range, sort, and substring (`contains`/`starts_with`) cannot use it** — these will fall back to **decrypt-in-memory** (the default, viable because per-user datasets are small and bounded) or be **disabled** in the filter UI for encrypted fields.
- **Honest leakage model.** A deterministic blind index *always* leaks the equality pattern and value frequency, and a per-tenant key only **limits cross-user correlation** — it does not remove within-user leakage. The admin UI will warn accordingly; decrypt-in-memory (which leaks nothing to the database) stays the recommended default, with the blind index reserved for the narrow case where dataset size forces SQL-side equality.
- **Safe backfill.** Adding the flag, rotating keys, or building the index will re-encrypt existing values, so the work must guarantee a fresh random IV per encryption (GCM nonce reuse is catastrophic) and maintain the tag transactionally alongside the ciphertext.

## Known Issues

The six issues recorded here from the July 2026 alignment audit all lived in the **legacy template surface**, and all were **resolved by deletion** — v1.1.0 replaced that surface wholesale (see the [Changelog](/modules/ai-core/changelog/)). These are the current known issues.

### ~~First Live Provider Call Not Yet Made~~ (made in v1.7.0)

**Resolved:** 2026-08-01 (v1.7.0)

`aiCore.run()`, `embed()` and `rerank()` have now executed end to end against live providers (Anthropic Claude Opus 4.6, Voyage) in a real installed app — prompt assembly → adapter → schema validation → deterministic checks → feedback → ledger write, every path leaving a ledger row. As predicted, the first call surfaced exactly one patch: an operation with no segments, disciplines or schema assembles an empty system prompt, and the adapter was sending it as an empty system content block (`system: text content blocks must be non-empty`). The adapter now omits the system field when instructions are empty; structured-output and embed calls were never affected. See the [Changelog](/modules/ai-core/changelog/).

The `sensitive`-floor terms gate held exactly as designed: under a sensitive floor a first-party Anthropic call refuses (`no-model-under-acceptable-terms`) until zero-retention terms are attested. For verification that means either a real ZDR attestation, or a temporary `normal` floor for the pipeline test alone — the gate itself is sound.


### Knowledge Cutoff Must Be Admin-Entered

**Severity:** Low
**Where:** model records / capability refresh

Capability refresh reads the providers' REST model listings, but does not derive a model's knowledge cutoff from them. The cutoff feeds the date-context segment — the model's anchor for the edge of its own knowledge — so an unset or stale value weakens that anchor. It must be entered on the model record in the admin.

### No CI Lint Yet for Seed Discipline/Check Integrity

**Severity:** Low
**Where:** `src/templates/migrations/`

Write-time and resolution-time enforcement are live (see [Usage](/modules/ai-core/usage/)), but the designed CI lint — the one that reports orphaned checks and unreferenced rules in the *seed data* before it ships — has not been built.

### Embedding Coverage Is Reported as Full

**Severity:** Low
**Where:** `providers/adapters.ts` (`fullCoverage`)

The embed adapter reports every input as fully covered (`covered === total`), because the AI SDK exposes no partial-embedding signal: a call either embeds each value in full or fails. The run engine's `partial-embedding-coverage` branch is therefore currently unreachable. Truthful per-value coverage needs a real over-length signal — a per-model maximum input length recorded on the model record, and/or cog-ingest's chunk-length policy — and neither exists yet. The design forbids inventing a truncation signal where the provider gives none, so coverage stays honest-but-coarse until that signal lands. Deferred deliberately, not overlooked.

### Pre-v1.6.0 Installs Ignore the Embedding Width Requirement

**Severity:** Low (deployment, not a current-code defect)
**Where:** a host whose generated `records.service.ts` predates v1.6.0

The v1.6.0 width filter — `ensureOperation` selects an embedding model of exactly the required `dimensions` or refuses — only exists in generated code from v1.6.0 onward. A host installed earlier binds embedding operations to the oldest enabled embedding model, ignoring `dimensions`, so a consumer requiring 1024 can silently bind a 1536-width model; the run-time dimension gate then (correctly) refuses on first embed. Fix: `npx ai-core update` to v1.6.0+. Surfaced verifying cog-ingest's embed operations against a real app running mixed-version generated files, alongside the v1.7.1 async dimension-gate fix (the gate had never actually fired live until Structure was registered).

### ~~Frontend Prop Shapes Verified Against Stubs~~ (resolved in v1.1.2)

The first real install confirmed exactly this class: `ErrorAlert`'s real prop is `error`, and the query-keys helper takes scalar parts. Both fixed in v1.1.2–v1.1.3; the host app's frontend now type-checks the feature clean against the real starter components.


## Planned Improvements

### Short-Term

#### ~~Install Verification~~ (complete — v1.7.0)

Done. Installed into a real starter app, migrations and seeds applied, admin page exercised, and `run()` / `embed()` / `rerank()` all run live against real providers (v1.7.0). The frontend compiles against the real starter components. This gate is closed.

### Prompt Model Evolution — settled 24 July 2026

The prompt taxonomy was reviewed end to end against authoritative prompt-engineering guidance, the old Wysli app's prompt system, and AI Core's own code, and **settled** — see the [Prompt Model](/modules/ai-core/prompt-model/) page for the full shape. The two-layer Frame/Substance split, per-model frameworks and the discipline↔guardrail pairing all ship today; the pieces below are the agreed evolution, in priority order.

#### ~~Guardrail-check execution~~ (shipped — v1.12.0)

**Done.** The rule-and-check pairing now EXECUTES. **Source verification** (a deterministic builtin, no model call) verifies every extracted item verbatim against the source and, where an independent denominator exists, whether everything the source contains was returned — saying so plainly where no count exists. A real **groundedness scorer** (a `grounding` check) runs a nested judge that decomposes the output into claims and produces a measured support score, which **abstention now compares against instead of the model's self-reported confidence**; where only self-report is available, the run *names* that provenance. Opt-in per operation through a discipline; a batteries-included judge is seeded, bound to a model by requirements. This subsumed **Groundedness Scorers** (below). See the [Changelog](/modules/ai-core/changelog/). Follow-ups: an admin editor for custom checks, and an `ensureCheck` consumer seed for a custom source-verification path.

#### ~~Markers — generalising framing~~ (shipped — v1.15.0)

A small admin-managed catalogue of `{ id, meaning, renderingHint }` records (`ai_marker`) that replaces the single `framing` segment. Content is wrapped in a marker; the meanings of the markers in use are stated on the system side; the framework picks the wrap syntax per model. One mechanism now covers external content, examples, sources and conversation history, and it is consumer-extensible (`ensureMarker` — chat adds a `conversation-history` marker fed by its own memory). Markers apply to content items only (external + context), never the operation's instructions or the task; `external` is a non-overridable safety floor (a custom marker on external content is ignored and named). The built-ins seed on install; managed in a Markers admin tab. Still open (deferred, low): recording applied marker ids in the ledger for audit-by-reference on the success path, and honouring `renderingHint` in the framework's wrap syntax.

#### Preferences — per-user

Per-user terminology (preferred / avoided terms) plus style and detail, registered through the starter's `personalInfoFieldsRegistry` (saved to `User.preferences`, no schema change) and injected selectively — only the terms that match the input. AI Core registers the fields and owns the assembly; the app owns the stored values, so AI Core holds no user data.

#### input-data / context split, and contextual-time

Two smaller refinements. Distinguish **input-data** — the new data the user brings this call — from **context** — what the app already knows — on a *new vs known* line (trust is carried by the item's marker, not a separate type). And grow the date anchor into **contextual-time** by adding *time since the last message*, so a reply after an overnight gap does not read as though no time passed.

### Consumer requirements — cog-ingest (Stage-1 live + Stage-2)

cog-ingest **seeds and calls** these operations; AI Core must **resolve + run** them. These are requirements (model *kinds*), never provider names — cog-ingest names jobs only, and AI Core owns the SDK/gateway (Vercel AI SDK now, possibly TanStack AI later).

**Stage-1 — make what already shipped actually run (done, v1.7.0–v1.7.1):**

- ~~**Live `embed`** at the app's vector width~~ **(shipped — v1.7.0/v1.7.1).** cog-ingest's `cog-ingest/embed-document` and `cog-ingest/embed-query` (kind `embedding`, `dimensions` = Structure's `getCognitiveCapabilities().embeddings.dimensions`) resolve and run live; the width-selection and dimension gate are verified against Voyage with Structure present.
- ~~**Live `run`** for language and vision ops~~ **(shipped — v1.7.0/v1.7.1).** `cog-ingest/contextualise-chunk` and the vision ops (`cog-ingest/analyse-image`, `-url-screenshot`, `-pdf-page`) produce output end to end.

**Stage-2 — new capabilities (mostly shipped):**

- ~~**Prompt caching**~~ **(shipped — v1.9.0).** `contextualise-chunk` can be fed the full source document per chunk affordably; the repeated document is cached across its chunks (contextual-retrieval shape), Anthropic-only.
- ~~**Multimodal / visual embedding op**~~ **(shipped — v1.11.0).** `aiCore.embedMultimodal` embeds images and text into one vector space (voyage-multimodal class), so screenshots/figures are retrievable by visual similarity.
- **Rich transcription op** — a transcription kind returning speakers + sentiment + **tone/prosody** + timestamps (Docling's built-in Whisper ASR is text-only). **Still open** — deferred until a recording use case is real; optional if Docling ASR suffices, required to capture tone.
- ~~**Parse-QA judge op** + **per-source summary op**~~ **(addressed — v1.10.0).** Both are consumer-seeded language operations needing no new AI Core capability; the `deterministic` dial (v1.10.0) supplied the temperature-0 determinism the judge required.
- ~~**Callable `rerank`**~~ **(shipped — v1.7.0).** rerank is a callable op (`aiCore.rerank`); its dial now drives reranking within the retrieval pipeline (v1.13.0), so cog-ingest's `retrieve()` can reorder and cut top-k.

**Dimensions gate:** the existing `embedding-dimension-mismatch` refusal already enforces width; cog-ingest passes the required width at seed time (converges on `getCognitiveCapabilities().embeddings.dimensions` under the Structure-storage retarget).

Cross-reference: cog-ingest [Stage 2 roadmap](/modules/cog-ingest/roadmap/).

### Medium-Term

#### ~~Retrieval (design §16)~~ (shipped — v1.13.0)

Semantic retrieval is now an operation — `aiCore.retrieve()`. If AI is doing the retrieving, AI Core owns the mechanism: it uses a model, it can be wrong, it reports what it found **and the shape of what it missed**. The grounding dials (breadth, rerank, abstention) that were recorded but inert now drive an embed → Structure chunk search → optional rerank/graph-expansion pipeline, degrading to named gaps rather than failing. AI Core retrieves; Structure stores. See [Integration → Retrieval](/modules/ai-core/integration/#retrieval).

Still open here: node-level retrieval (chunk-level ships first), a store-surfaced topK ceiling so the breadth clamp is cap-agnostic rather than coupled to Structure's current cap, and lexical/hybrid search once Structure exposes it.

#### ~~Evaluation harness~~ (shipped — v1.14.0)

A generic, portable harness that measures an operation's quality offline over a golden set of cases — configured per operation (`ai_operation.evalConfig`) and run with `aiCore.runEval()`. Deterministic metrics (`exact-match`, `context-precision`, `context-recall`) and judge metrics (`faithfulness` reusing the groundedness judge, `answer-correctness` via a seeded correctness judge). It runs the real pipeline and reports per-metric scores **and how many cases could not be evaluated** — a partial eval is never a clean pass; cases are synthetic fixtures and results carry no content. Managed in a new Evals admin tab; consumers seed cases with `ensureEvalCase`. Still open: a domain golden set (the planted "prepaid funeral" surfacing test, the density benchmark) lives in the consuming app, and gating promotions (chunk strategy, rerank on/off) is a consumer workflow over the scores.

#### ~~Groundedness Scorers~~ (shipped — v1.12.0)

**Done** as part of guardrail-check execution (above). A `grounding` check runs a nested judge (claim decomposition + entailment) and produces a measured score in `[0,1]` that the abstention threshold compares against and that lands in the new `feedback.groundedness` — an input to feedback, never a certificate the output is true. Pluggable per operation via the check's `config`. The provider-native-citation and dedicated-grounding-service implementations remain open as alternative scorer types.

#### Semantic Cache

AI Core sees all provider traffic, so every consumer benefits without knowing the cache exists. Cache keys are scoped to the owner, hard — a cache keyed on similarity alone will serve one person's answer to another, and that is a real, reproduced leak. Sensitive content is not cached, or cached only where provider terms permit.

#### Re-embedding Migration

AI Core owns the embedding model, so it owns the moment the model changes: the existing vectors are invalid, and only AI Core knows it. Report the scale, then migrate in batches with progress. Silently leaving stale vectors in place is the same failure as silent truncation.

#### Review-Queue UI Polish

The review-queue table and its feed from abstentions and low-confidence outcomes shipped in v1.1.0. What remains is surface polish: the consumer-facing component a module can drop in, and the admin gaps alongside it — most visibly a Flows tab (flows have full admin CRUD endpoints but no tab of their own).

#### User Model-Choice UI

The API capability shipped in v1.1.0 — model choice is admin-granted per operation with an allow-list, default off, and a user-selected model outside the allow-list is refused. There is no user-facing UI for making the choice yet.

### Long-Term / Open Questions

The design's own open questions (§21), carried here so they stay visible.

#### Discipline Authority Enforcement

The design's original question — can a registry reject a registration that conflicts with another registry's contents? — was answered in July 2026: registration-time rejection is unsound for **code registries** in the starter's ESM side-effect model, where a rule may register before the rule it conflicts with. The implementation landed somewhere stronger than the startup-barrier fallback the design reached for: disciplines are **database records**, which have no such ordering problem, so v1.1.0 enforces the hierarchy at **write time** — admin CRUD refuses violations transactionally — and re-validates at **resolution time**, where `aiCore.run` refuses an invalid set (see [Usage](/modules/ai-core/usage/)). What remains open is the CI lint for seed discipline/check integrity, recorded under Known Issues. The principle underneath held throughout: **prose asks; code holds.**

#### Which Groundedness Scorer per Operation

The mechanism is settled and pluggable; which implementation runs on which operation is a per-operation decision that needs measurement, not a design argument.

#### Image and Video Provider Data-Handling Terms

Black Forest Labs and Replicate have materially weaker data-handling terms than the model providers. In v1.1.0 their provider rows are seeded **disabled** and their generation adapters are unbuilt (a call throws a typed not-implemented error) — nothing can be routed to them at all yet. Confirm their terms before they are ever enabled; the likely answer for sensitive content is that it never is, enforced by the sensitivity gate in resolution.

#### Chat Module or Generic Chat

If chat goes generic, persona has nowhere natural to live. Persona is the user's, conversation-scoped, and only chat has conversations — chat owns the records and hands AI Core a segment.

#### Naming Collisions

`prompt`, `token` and `model` collide with the module system's own terms. A naming pass is needed before the admin surface freezes.

## Completed

Items that have been done.

### v1.9.0 — Prompt Caching (August 2026)

The first of the **cog-ingest hand-off** items to ship. An operation gains a `cache` policy (`{ instructions?, context?, ttl? }` on `ai_operation`) so it can reuse its stable prompt prefix — the system prompt, and/or the context block (a source document) — instead of paying for it on every call. Providers cache by prefix, so the two breakpoints nest: system-only across every call, system-plus-document across every chunk of one document (Anthropic's contextual-retrieval shape). Confined to the adapter; Anthropic-only for now, with a named `prompt-cache-unsupported` feedback shortfall on any other provider — it never pretends to have cached. Raised by cog-ingest's contextualise step. (The system-prompt breakpoint was corrected for AI SDK v7 in v1.11.3.) See the [Changelog](/modules/ai-core/changelog/).

**The cog-ingest hand-off.** Stage-1 (embed-at-width, language/vision operations) shipped through v1.6.0–v1.8.0. Stage-2 began with prompt caching (v1.9.0), then the **parse-QA judge / per-source summary** pair (v1.10.0): both are plain language operations the *consumer* seeds — AI Core ships no operations — so the summary needs nothing new, and the judge needed exactly one thing AI Core lacked, a way to be deterministic, delivered as the `deterministic` dial (temperature 0). Then **multimodal/visual embedding** (v1.11.0): `embedMultimodal` embeds images and text into one vector space through Voyage's multimodal models, added alongside `embed` with a `multimodal` model marker and two loud refusals. That closes the hand-off's active items. **Deferred:** a **rich transcription** operation (speakers, sentiment, tone, timestamps) — not needed for recording v1, since the upstream Docling pipeline is wired for document ingest only, not audio recordings; it waits until a recording use case is real. Callable **rerank** (item 7) shipped in v1.7.0. Truthful partial `EmbedCoverage` stays deferred under Known Issues.

### v1.3.0 — Consumer-Integration Surface (July 2026)

Closed the six raise-now gaps from cog-ingest's consumer-side readiness audit: `additionalProperties: true` free-key records in both zod builders (undeclared keys were being silently stripped — silent data loss, the exact failure this module exists to prevent); `ensureOperation` / `ensureSegment` idempotent seeding where consumers state model *requirements* rather than model names and admin edits always win; `RunOptions.maxOutputTokens` as a tighten-only cap recorded in the ledger; automatic framing for external content, with a missing framing segment reported in feedback rather than proceeding unframed; and corrected `run()` examples throughout the docs.

### v1.2.0 — Vision Input (July 2026)

Media attachments on consumer segments (`media: [{ mediaType, data }]`), handed to the provider adapter as file parts alongside the assembled input — never into the prompt text, the logs or the ledger. A model whose fetched capabilities are known to lack image input refuses the run rather than failing obscurely at the provider.

### v1.1.1–v1.1.3 — First Real Install (July 2026)

`npx ai-core init` into a real app, end to end: schema appended, feature generated, registrations wired, all six seed migrations applied (the module migration runner's first real use). Three defect classes the type harnesses could not have caught were found and fixed — Prisma 7 custom-output client imports, real starter component prop shapes, and the barrel's routes export — after which the host app type-checks the feature clean. A scaffold bug (scoped package specs mangled to `@scope/name@^4@latest`) was fixed upstream in module-starter scaffold v1.19.2.

### v1.1.0 — The Redesign Implemented (July 2026)

The whole former Short-Term column shipped as module **v1.1.0** (2026-07-23):

- **The `ai_` schema** — twelve models via the migrations runner, plus six seed migrations (providers, frameworks, segments, disciplines, checks, models). Every battery is a row: seeded, editable, resettable
- **Provider adapters on Vercel AI SDK v7** — Anthropic, OpenAI, Google, Voyage — confined to a single adapter file behind an interface AI Core defines
- **The operations resolver and `aiCore.run`/`runEmbed`** — the sensitivity gate, explicit parameter transforms, the Structure dimension gate, structured feedback on every return
- **Prompt segments, frameworks and assembly** — the computed date anchor and EXT-marked external content
- **Disciplines and guardrail checks** — authority enforced at write time and re-validated at resolution time
- **Flows with suspend/resume** and `initialState`; **the usage ledger** (references only) with the `getCurrentUsage` billing callback; **the review queue**
- **The tabbed admin page** at `/admin/ai-core` (order 30, platform section) and **the security registration** with deletion handlers
- **The legacy v2 surface deleted wholesale** — resolving all six known issues from the July 2026 audit

**Verification:** strict type harnesses over the extracted generated code — the backend against the real published SDK packages, the frontend against React 18 and TanStack Query v5. **Install verification has not yet been performed**; installing into a real starter app is the next gate, recorded under Known Issues. See the [Changelog](/modules/ai-core/changelog/) for the release detail.

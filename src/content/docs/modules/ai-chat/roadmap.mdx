## Shipped — the 1.0.0 rebuild

The ground-up rebuild described in the [Changelog](/modules/ai-chat/changelog/): a pure AI Core consumer with streamed replies and a non-streamed fallback, branching with AI-written handover, personas resolved to AI Core prompt variables, CoALA memory with background extraction, summaries and alignment checkpoints, drift detection, the action bank, admin-defined saved sections with the destination ladder, the shadcn AI Elements chat UI, and the four-tab admin page with the Ensure-defaults seeding button and the reply provenance inspector. Eleven self-contained tables, six idempotent background jobs, full security and usage registrations, and the versioned data envelope.

## Next

- **Wire `ai-el-inline-citation` for context-ref citations.** The Inline Citation element template already exists in the repo (`src/templates/frontend/ai-el-inline-citation.ts`) but is deliberately unwired in `module.ts` — it alone needs the `carousel` and `hover-card` primitives. Wiring it means: add the template to `frontend.templates`, declare the two primitives in `shadcnComponents`, and render citations in the message thread from the context refs a reply's provenance lists (the Sources element already surfaces them collectively).
- **Per-conversation working-memory session scope via AI Core's context-assembly engine.** When AI Core's curated context engine lands (it reads Structure, where working memory lives), ai-chat's reply runs receive ecosystem context through it — and the Structure session mirror (`structureNodeId`) gives it a per-conversation session node to scope against. Contribution hooks (ai-chat feeding the working set) are revisited then; the `cognitive-boost` seam is where they slot in behind the same feature detection.
- **Cognitive Pipeline `chat` ingest source option — their side.** ai-chat already exposes everything needed: `getConversationContent` (`{ title, transcript, summaries }`, also at `GET /conversations/:id/content`) and the `ai-chat.conversation.*` / `ai-chat.summary.created` hooks. The source-option UI and pull wiring belong to Cognitive Pipeline and are filed on its roadmap; nothing further is needed here.
- **`useMessages` infinite scroll.** The chat view currently loads the first message page at the server maximum (200). Cursor pagination is already wired end-to-end in the service and API — swap the page's `useQuery` for `useInfiniteQuery` and prepend older pages as the user scrolls up.
- **`GET /config` advertising streaming availability.** The public config slice could carry a `streaming: boolean` (from the gateway's `supportsStreaming()`), letting the client pick its send path up front instead of discovering the 501 on the first streamed send. The fallback stays regardless — the gate is cheap and the degrade already clean.

## Ideas

- **Tools via AI Core `toolIds`.** AI Core owns the tool framework; operations opt in by naming `toolIds` (web research and friends already exist there). The chat seam is ready: tool events live in message `parts` and render through the Tool element. Turning it on is an admin edit to the `ai-chat/reply` operation plus stream-event handling for tool parts when AI Core ships them over `RunStream`. A dedicated `ai_chat_tool_call` log table stays out of v1 — added later by migration only if a real need appears.
- **Document Management as a saved-sections destination.** Today Document Management manages documents coming *into* the app; managing created artefacts is its future. When that lands, saved sections (email copy, affidavit paragraphs, orders) become natural artefacts — a fourth rung on the destination ladder, behind the same visible-degrade contract as the existing rungs.

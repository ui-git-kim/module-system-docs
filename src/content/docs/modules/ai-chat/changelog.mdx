This page documents notable changes to the AI Chat module. The module uses semantic versioning: **major.minor.patch**.

- **Major** (1.0.0 → 2.0.0): Breaking changes requiring migration
- **Minor** (1.0.0 → 1.1.0): New features, backwards compatible
- **Patch** (1.0.0 → 1.0.1): Bug fixes, template fixes

<Aside type="tip">
Check your installed version with `npx ai-chat info`.
</Aside>

## 1.5.0 — The sidebar's contents are an admin decision (2026-10-28)

- New `contextSidebar` admin-config key: per-section **Shown** and **Open by default** for the five sidebar sections, seeded by Ensure defaults, served on the public config slice, and edited on a new **Sidebar** sub-tab in the admin Configuration double-tab. A disabled section simply does not exist for users, and with every section off the header-toolbar toggle itself disappears.

## 1.4.0 — The context sidebar (2026-10-28)

The hideable right panel from the approved mocks: toggled by a **PanelRight** header-toolbar item (shown only while a conversation is open), open state remembered per user, hidden below `lg`. Collapsible sections, each rendering only what exists:

- **What the AI knows** — the latest reply's persisted provenance made user-facing: how many messages and roughly how many tokens it drew on, the summary, pending checkpoint, memories and records it was given, and the run-feedback line when AI Core raised one.
- **Relevant records** — the conversation's context refs: list, remove, and a small attach form (name, type, reference id or URL).
- **Background activity** — pending action-bank items with act / park / dismiss, parked items with pick-back-up.
- **Saved sections** — this conversation's sections, with copy.
- **Uploads** — placeholder until the composer wiring lands.

The `collapsible` shadcn primitive joins the module's component list — answer **Yes** to the update's *Sync UI components?* prompt, or run `npx shadcn@latest add collapsible` in the app's `frontend/`.

## 1.3.0 — AI Core 1.80 consumer: status, session time, reply-ride extraction; sections render in chat (2026-10-28)

Four slices, the first three consuming [AI Core v1.80.0](/modules/ai-core/changelog/):

- **The placeholder narrates the stream** — ai-core's chat-UI helper forwards the run's status events as transient `data-status` parts; the pending turn now reads *Thinking… / Searching (tool)… / Writing…* instead of a static label. Older hosts and the non-streamed path stay on *Thinking…*.
- **Session time** — the gateway derives the session start from the message timestamps (the unbroken chain of turns ending now with no gap over 30 minutes) and passes `sessionStartedAt` beside `lastMessageAt`, so the prompt's date anchor can say how long the session has run. Completes the Phase 1 *contextual timestamps* row.
- **Reply-ride extraction** — declare extra answer sections named `memories` and/or `patterns` on the `ai-chat/reply` operation (AI Core's operation editor; each an array of the same item shape the canonical extract/detect operations answer) and one reply call does that background work too: the module persists what parses through the **same floors, dedupe and caps** the jobs use and skips the matching job for that reply; anything absent, invalid or failing falls back to the job. Declaring nothing changes nothing.
- **Sections render in the chat** — the reply run is now taught a tag convention (wrap a drafted section in a fenced block tagged with its type id), and the thread maps tagged blocks onto the type's [display component](/modules/ai-chat/configuration/#sectiontypes--saveable-section-types): an email arrives as a code block with copy and **save-as-section** (pre-filled with the block's content and type) — mid-stream too, with an unterminated fence rendering as it grows. Untyped fences render as plain code blocks.

## 1.2.1 — Guidance runs as authored instruction (2026-10-28)

- **Fix:** the section-formats guidance reached the prompt injection-fenced as untrusted data (every context section defaulted that way), which a model may treat as reference material rather than a format to follow. Admin-authored guidance now runs with `origin: 'authored'` and no fence; chat-derived sections (summary, memories, refs, focus) stay fenced exactly as before.

## 1.2.0 — Section types carry destination and AI guidance (2026-10-28)

Section types grow toward richer entities (the Structure-type direction):

- **Per-type destination** — each section type can override the app-wide destination ladder with its own (same shape: local / Structure with parent + node type / Cognitive Pipeline ingest). Absent means the app default, and every route still degrades visibly to local. Email copy can stay local while affidavit paragraphs land on a Structure node.
- **AI guidance** — each type can carry *how the assistant should draft this kind of section*. Every reply run receives the guided types as a `section-formats` context section, so when the model drafts an email (or an affidavit paragraph, or an order) it knows the expected shape. The seeded `email` type ships ready-to-send-email guidance. Guidance is domain data filling the run's context — prompt text stays in AI Core records.
- **Editor sheet** — the admin Sections sub-tab becomes summary rows (label, id, display, destination, guidance flag) with a per-type editor sheet on the operation-editor house pattern: identity, display component, destination override and AI guidance, still draft-then-Save.

## 1.1.8 — Breadcrumb link fix (2026-10-28)

- **Fix:** the starter's `BreadcrumbItem` takes `path`, not `href` — since 1.1.1 the **Chat** crumb rendered as a dead label instead of the way back to the welcome screen. The checkpoint submit event is also typed explicitly.
- Updating note: `npx ai-chat update` asks *Sync UI components?* with a default of **No** (so shadcn never re-runs over components the app customised). The 1.1.7 `questionnaire` component needs that prompt answered Yes once — or cleaner, a one-off `npx shadcn@latest add questionnaire` in the app's `frontend/`.

## 1.1.7 — Section display components, checkpoint questionnaire (2026-10-28)

- **Admin-chosen section display** — each [section type](/modules/ai-chat/configuration/#sectiontypes--saveable-section-types) gains a `display` setting: *Text* (default) or *Code block*. Code-block types render their content on the sections page in the shadcn Code Block — a header with the section title and a copy button over a wrapped monospace body — the right fit for email templates and other paste-ready text. The seeded `email` type now defaults to it.
- **Checkpoint card rebuilt on the shadcn Questionnaire** — one required question: pick *Looks right* or type a correction (the same form field carries both; the submitted value tells them apart), with *Dismiss* bypassing the form. The `questionnaire` primitive joins the module's declared shadcn components.
- **Two approved design directions recorded** (DESIGN-OVERHAUL + [roadmap](/modules/ai-chat/roadmap/)): the Dalton-style chat surface (composer options popover, inline tool/search trace cards, reply document-cards opening in a sliding side panel through the admin-chosen display component) and the **section refinement box** (admin-defined refine actions — Rephrase, Simplify, Shorten, Change tone — each bound to an AI Core operation, with alternatives and Insert/Replace).

## 1.1.6 — Bottom-follow thread, chrome fully into shell, persona variables fixed (2026-10-28)

- **Thread follows at the bottom** — sending no longer jumps your message to the top of the viewport (the upstream Chat pattern's scroll anchor); the sent message stays by the composer and the reply streams in at the live edge.
- **The last of the page chrome moves into the shell** — the in-thread bar (back arrow, title, archived badge, archive button) and the thread border are gone. The breadcrumb **Chat** crumb is the way back, and **Archive** joins Saved sections in the header toolbar — a conversation-aware item that renders only while an active conversation is open. The *Branched from* chip now sits at the top of the thread.
- **Reply actions under the reply** — copy, save-section and branch render in a row under the reply text instead of beside it.
- **Persona fix: the variables now reach the prompt** — the resolver flattened raw persona columns (`name`, `directness`, …) while the operations declare `persona_*` tokens, so no key ever matched and every slot rendered blank (*"You are ."*, *"/100"*). The resolver now maps the declared fifteen-token catalogue explicitly — sliders as numbers, composed explanation-style and content-preferences sentences (now folding the interaction and ND-support switches in), empty user-authored fields omitted so `onMissing` applies, and the language cascade writing `persona_language`.

## 1.1.4 — Toolbar registration emitted JSX into a .ts file (2026-10-28)

- **Fix:** the 1.1.1 Saved sections header-toolbar registration returned JSX from a plain `.ts` file, failing the host frontend type-check on update. The component now builds with `createElement`; the emitted path is unchanged, so `npx ai-chat update` overwrites the broken file in place. Hosts that updated to 1.1.1–1.1.3 and hit the TS1005 wall just update again.

## 1.1.3 — Thread scrolling, thinking placeholder, run feedback (2026-10-28)

- **Wheel scrolling in the thread fixed** — the starter shell scrolls the *document*, so the chat page's old `h-full` never capped the page: the thread grew to content height, the window scrollbar took over, and wheel/touchpad input over the messages died inside a no-overflow scroll container whose `overscroll-contain` swallowed the delta. The page now pins its own height to the visible viewport (per shell layout, via `--header-height`), making the thread viewport the one true scroller — wheel, scrollbar, stick-to-bottom and the jump-to-bottom button all act on the same element. The welcome screen centres via an inner `m-auto` wrapper so short viewports scroll instead of clipping the top.
- **Thinking placeholder** — a pending assistant turn (spinner + *Thinking…*) fills the silent wait between send and the first streamed text, and the whole non-streamed fallback wait; the first real text replaces it.
- **Run feedback in provenance** — AI Core run feedback (e.g. a discipline self-check failure like `self-check-failed:D2`) is persisted on the reply's provenance (`feedbackReason`) and surfaced in the admin provenance inspector as a destructive-toned **Run feedback** row; clean runs show nothing.
- **Slider pole anchors** — the persona Voice & Style sliders anchor each end of the track with pole words (Softened ↔ Straight, Challenging ↔ Agreeable, Casual ↔ Formal, Brief ↔ Thorough, Reserved ↔ Energetic, Plain ↔ Expert), so you can see what you are sliding towards.

## 1.1.2 — Double-tab admin, operation sheets, custom background tasks (2026-10-28)

- **Double-tab admin layout** — the admin page adopts AI Core's double-tab idiom: nested pill sub-tab rows inside Configuration (*Tasks · Starter cards · Sections · Integrations · Personas · Streaming*) and Activity (*Overview · Provenance*), with panes force-mounted so unsaved drafts survive switching.
- **Operation editor sheet** — the AI operations tab lists every operation as a row with an **Edit** button opening AI Core's full embedded operation editor in a right-side sheet (the Cognitive Pipeline house pattern), plus a **Create operation** sheet with the owner pre-filled. The row list includes any custom operation id the configuration references.
- **Custom background tasks** — new `tasks.custom` array (up to 10): each admin-defined task names an AI Core operation, a cadence (`everyNMessages`, 1 = every reply) and an output — a long-term memory with a chosen CoALA type, or an action-bank item titled with the task label. One generic job runs per enabled task on its cadence after assistant replies; see [Configuration](/modules/ai-chat/configuration/#tasks--background-tasks).

## 1.1.1 — Page chrome moves into the app shell (2026-10-28)

- **Conversation title in the breadcrumbs** — the chat page drops its own page header; an open thread's title now rides the host header breadcrumbs (dynamic trail while a thread is open, cleared on unmount; the welcome screen keeps automatic crumbs).
- **Saved sections in the header toolbar** — the page-level Saved sections button becomes a header-toolbar registration (ghost bookmark icon linking to `/ai-chat/sections`, the house pattern).

## 1.1.0 — Admin-wired starter cards and operation mapping (2026-10-28)

- **Admin-configurable starter cards** — the welcome screen's cards are now an admin-config record (`starterCards`, up to 12 cards): id, title, description, composer seed, a Lucide icon name rendered through the starter's shared `IconRenderer`, and an optional AI Core `operationId`. A card carrying an operation binds the conversation it starts (`metadata.replyOperationId`), and every reply in that conversation runs that operation instead of the canonical `ai-chat/reply`.
- **Per-task AI operation mapping** — every background-task row (summarise, extract-memories, detect-patterns, drift-check and title generation included) carries a configurable `operationId`, defaulting to the task's canonical seeded id; a blank input saves back to the canonical, and the admin AI operations tab lists any custom id the configuration references so it can be edited in place.
- **Conversations rail removed** — the welcome screen (greeting, starter cards, hero composer that creates-and-sends, six recent conversations) is now the navigation; the thread header gained a back arrow to the welcome screen and the archive action.
- **Streaming UI throttle** — new `streaming.uiThrottleMs` admin knob (0–2000 ms, default 60, `0` = unthrottled) pacing how the browser paints a streaming reply; server-side word pacing is a planned AI Core operation dial (see the [roadmap](/modules/ai-chat/roadmap/)).

## 1.0.0 — The rebuild

A ground-up rebuild on a fresh module-starter clone (scaffold v1.31.20). The old module had zero installs, so v1.0.0 locks the contract with no migration constraints; the 0.1.x pre-scaffold module is preserved in `zArchive/` and on the `zarchive/old-module` branch — background only, nothing was carried across unexamined.

### Architecture

- **Pure AI Core consumer** — `depends: { 'ai-core': '>=1.78.0' }`. Models, prompts, the usage ledger, guardrails and tools all come from AI Core; the module ships zero provider SDKs and never names a model id. One generated gateway file is the single LLM seam.
- **Admin-authored prompts** — the module's prompt domain lives in AI Core as `ai-chat/*` records (seven operations, persona style approaches with declared prompt variables, an epistemic discipline with a grounding guardrail). Nothing seeds at boot; the admin page's **Ensure defaults** button plants everything create-if-absent, and admin edits always win.
- **Baseline plus boost** — the baseline install (ai-chat + ai-core) is fully functional. Structure, Cognitive Pipeline and Document Management are feature-detected boosts behind structural facades; every absence degrades visibly, never silently.
- **Admin-first** — the four-tab admin page (Configuration, AI operations, Activity with a reply provenance inspector, Data) shipped early as the observation surface, and admin config is runtime records, not build-time decisions.

### Features

- **Streaming replies end-to-end** via AI Core v1.79's `RunStream` + UI message stream adapters, with the non-streamed JSON path as the baseline contract and automatic 501 fallback; both paths share one context assembly and one persistence half.
- **Branching with AI-written handover** (summary, key decisions, open questions), personas re-aimed at AI Core prompt variables, CoALA memories with background extraction, rolling summaries, alignment checkpoints, drift detection with action-bank nudges, context refs, and automatic titling.
- **Saved sections** (new): admin-defined section types with a destination ladder — local table, Structure node, or Cognitive Pipeline ingest — and a visible local fallback.
- **shadcn AI Elements UI** shipped as module-owned source (conversation, message, prompt-input, reasoning, sources, suggestion, tool) over 22 declared shadcn primitives; TanStack Query throughout.
- **Eleven self-contained `ai_chat_*` tables**, full security registrations (deletion cascade + personal-data export over the ten user-keyed tables), a usage provider, module registry registration, six idempotent background jobs behind the host jobs seam, and a versioned data export/import envelope.

### Removed (relative to the archived 0.1.x module)

The bespoke CLI and regex host-file surgery, taki-ui, the dead chat templates, local/S3 storage adapters, the hand-rolled logger and CSS, hardcoded model lists, prompt fragments as code (now AI Core records), the standalone/cognitive variant system, and the `chat_tool_calls` / `chat_processing_logs` tables.

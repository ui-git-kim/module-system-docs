This page documents notable changes to the AI Chat module. The module uses semantic versioning: **major.minor.patch**.

- **Major** (1.0.0 → 2.0.0): Breaking changes requiring migration
- **Minor** (1.0.0 → 1.1.0): New features, backwards compatible
- **Patch** (1.0.0 → 1.0.1): Bug fixes, template fixes

<Aside type="tip">
Check your installed version with `npx ai-chat info`.
</Aside>

## 1.15.2 — Quieter citations (2026-10-31)

- **Citations are small and easy to skim.** A citation of an earlier message is a small speech icon; any other is its number (1, 2, 3), or a web page's site. They no longer repeat a long title inside the sentence.
- **The pop-out shows what was cited:** its title and the cited text itself (the message, memory, summary, focus line, checkpoint or attached record), with **Go to message** for a message. The general description only shows when there is no text to quote.
- Why the old chips were upper case: the chip is a small Button, and the host theme sets buttons in capitals. Numbers and icons don't show it.

## 1.15.1 — Empty this turn is not "not wired" (2026-10-31)

- A block the reply operation places now always gets its list, even an empty one (no checkpoint pending, no focus set, a conversation's first message). AI Core then reports it as empty this turn (`supplied-list-empty:<name>`, `context-memory-empty`, `context-session-empty`) instead of `supplied-list-missing:<name>`, which reads as a wiring bug.
- A Supplied list block naming a list AI Chat does not keep is still left unsent, so AI Core names that real gap.

## 1.15.0 — Every reply goes through AI Core's builder (2026-10-31)

AI Core v1.81.10 places only what an operation's builder holds, and its release 2 will refuse anything sent another way. AI Chat now sends each piece of material through its own door, and the admin can see and change every one of them in AI Core.

- **Two Context builders for the reply.** `ai-chat/reply-foundation` places the Soul and Persona segments at the top of every reply prompt. `ai-chat/reply-context` places the conversation focus, the summary, memories, attached records, any pending checkpoint, the user's communication style and the earlier messages, each in its own block. Reorder, re-word or remove any block in AI Core's Context tab.
- **Earlier messages and memories can be cited one by one.** Each earlier message is its own Session item and each memory its own Memory item (AI Core v1.81.7), so a citation names the exact message (with **Go to message**) or memory.
- **Every operation takes its material through named Inputs.** The reply's message goes to its `message` Input. The six background operations take the conversation on a `transcript` Input, plus their own extras (`previous-summary`, `latest-message`, `focus`, `branch-reason`). AI Chat no longer sends loose context segments, origin or verification.
- **AI Chat reads each operation before it runs it** (`getOperationInfo`), and sends only what the operation places. Anything it does not place is not sent, is logged, and is listed on the reply's provenance in the Activity inspector. A drift check whose operation has no Input for the focus is skipped with a reason rather than run blind.
- **The user's AI communication style** (Personal information, saved by AI Core's fields) now reaches the reply through the Communication style block.
- **Ensure defaults checks the wiring.** After seeding it reads each operation back and lists what an existing one is missing: Inputs to add, Context builders to choose, blocks to add.
- **No longer seeded:** the three persona style approaches and the `ai-chat/persona-style` segment (the Persona segment replaced them in 1.7.8), and the `chat-section-formats` marker (section formats reach the reply through its `{section_formats}` task line).
- The operation editor's Edit sheet now fills in `ai-chat` as the owner of anything made with **+ New …**.
- Requires **AI Core v1.81.10 or later**.

<Aside type="caution" title="Existing hosts: wire the operations once">
AI Core never changes an existing operation, so operations created before 1.15.0 keep running without contexts or Inputs. Until you add them, replies have no history, memories, summary or focus, and the background jobs send only the transcript. After updating, restart, press **Ensure defaults** and follow its list in AI Core's operation builder:

1. On `ai-chat/reply`, choose `ai-chat/reply-foundation` as the Foundation context and `ai-chat/reply-context` as the Background context, add a **Message** Input (key `message`, text), and take the old **Persona style** segment off.
2. On each background operation, add the Inputs the list names (key, kind, marker, injection risk).

The list empties once everything is wired.
</Aside>

## 1.14.0 — AI Core records are created at startup (2026-10-30)

- **AI Chat now creates its AI Core records itself, each time the server starts:** operations, the Soul and Persona segments, approaches, variables, markers and the epistemic discipline. It creates only what is missing, so an admin's edits are never overwritten. It waits up to a minute for AI Core to register and never holds up startup. This follows AI Core's own guidance that a module seeds at boot.
- **Why:** after an update, new records only appeared once someone pressed **Ensure defaults**, which was easy to miss. One host ran without the Soul and Persona segments and the newer persona variables for several releases.
- **Ensure defaults stays.** It runs the same seed straight away and shows the report, including *Needs a manual update* for seeded records an earlier version created differently.

<Aside type="note" title="Existing hosts">
Restart after updating; the missing records are created on startup. Records listed under *Needs a manual update* still need the admin's hand until AI Core can refresh a seeded record nobody has edited (requested).
</Aside>

## 1.13.0 — Citations point at the exact message (2026-10-30)

- **A citation of something said earlier in the conversation now points at that message,** not at *Conversation history* as a whole. Its chip reads *Your message* or *An earlier reply*, and its card shows when it was sent and the cited text. **Go to message** scrolls the thread to the message and highlights it for a moment. A message too far back to be loaded says so instead.
- **How:** each earlier message now goes to AI Core as its own labelled item, with its id as the citation ref (`message:<id>`), instead of one combined history item. When a reply cites one, ai-chat saves that message's id, who sent it, when, and up to 600 characters of its text with the citation. That way the card still shows the text after the message has scrolled out of the loaded thread.
- Citations saved before 1.13.0 keep their *Conversation history* chip.

<Aside type="note" title="Existing hosts">
Nothing to set up. It applies to replies made after the update, when the reply operation asks for citations.
</Aside>

## 1.12.0 — Comparison tables in replies (2026-10-30)

- **Replies can show a table when they compare options,** where the comparison sits in the answer, the way citation chips work. The table comes from an AI Core **extra section** named `comparisons` on the reply operation. The answer marks each table's place with its label, such as `[T1]`, on a line of its own.
- **The Operations sub-tab shows the three values to add** (name, what goes in it, shape), each with a copy button, under *Comparison tables*.
- ai-chat checks each table and saves the usable ones with the message (`metadata.comparisons`). While a reply streams, the marker reads *Preparing the comparison…* until the table arrives with the finished reply.
- Each table can be copied as Markdown.

<Aside type="note" title="Existing hosts">
Nothing changes until you add the `comparisons` extra section to the reply operation in AI Core. The reply operation must answer in JSON sections (the default). The update adds the shadcn `table` component if the app doesn't have it.
</Aside>

## 1.11.1 — Add several words at once (2026-10-30)

- **The persona editor's lists take several items at once:** preferred formats, words to use, words to avoid and roles. Separate them with commas, and pasting a whole list works too; semicolons and middle dots (·) also count as separators. Duplicates are skipped. An item over the length limit, or anything past the list's limit, stays in the box with a note saying why.

## 1.11.0 — Admin lists are starter DataTables (2026-10-30)

Every list on the admin page is now the starter's `DataTable`, following its rule that every admin table is one. The lists are custom tasks, section types, starter cards, tones, notice dialogs and the AI operations.

- **One way to edit a list.** **New …** in the table's toolbar opens an editor sheet, and each row has **Edit** and **Delete**. Delete asks first.
- **A sheet's Save writes that one change straight away.** The other settings in a section (the built-in tasks, the notice text) keep their own **Save**, and an edit there no longer has to wait for a list to be valid.
- **Notice dialogs** each show their `dialog:` link with a copy button, plus a **Preview** action.
- **The AI operations table** shows each operation's id with a copy button, and whether it is seeded or comes from your configuration.
- **Tones** are edited with sliders.
- **Rows keep their stored order,** which is the welcome screen's order for starter cards and the editor's order for tones.

## 1.10.0 — Chat notices (2026-10-30)

A new **Notices** sub-tab on Configuration, for the warnings an app needs around AI use. Documented under [Configuration → `notices`](/modules/ai-chat/configuration/#notices--the-before-you-start-notice-the-line-under-the-message-box-and-dialogs).

- **Before you start.** A notice that opens before a user's first chat. Sending waits until they press its accept button (*I understand*), and an optional second button can link out or open a dialog (*Read PD-AI*). It can also show as a note at the top of every chat.
- **Each acceptance is recorded,** per notice version, in a new `ai_chat_notice_acceptance` table. Each acceptance fires `ai-chat.notice.accepted` for an AI-use ledger. **Ask everyone again** raises the version, so everyone accepts once more. The records are in the data export and erased with the account.
- **A line under the message box,** on the welcome screen and in every conversation.
- **Dialogs.** Pages of admin-written text that a `dialog:<id>` link opens — *About AI and your case*, say. A dialog can link to another; *Back* returns.
- **A Markdown editor with a toolbar** for all of it: bold, italic, lists, web links and dialog links, with a live preview where the dialog links work. The renderer is deliberately small and never injects HTML.
- **For other pages:** `BeforeYouStartDialog`, `NoticeText`, `useNoticeStatus` and `useAcceptNotice` are exported, so a page such as document analysis can show the same notice.
- **The records note at the top of Configuration is gone.** What it said is on the [Configuration](/modules/ai-chat/configuration/#configuration-tab) docs page.

<Aside type="note" title="Existing hosts">
`npx ai-chat update` adds the new table and applies the migration. The notices are **off** until you switch them on in Configuration → Notices. Pressing Ensure defaults plants the `notices` row; until then the defaults are read.
</Aside>

## 1.9.0 — Voice lines in two parts, collapsible persona settings, the icon picker (2026-10-30)

- **Voice examples have two fields:** the wording, and an optional example. The line still goes out as the wording, then `, e.g. "…"` with the example, but the *e.g.* and the quotes are now added for you. The `voiceExamples` config holds `{ text, example }` for every line.

- **Icons come from the starter's icon picker,** for tones and starter cards, instead of a typed icon name.

<Aside type="note" title="Existing hosts">
Nothing to do. Voice examples saved as single lines are split into wording and example when read, and send exactly the same text. They are stored in the new shape the next time you save the section.
</Aside>

## 1.8.0 — The app default persona and the persona editor (2026-10-29)

The rest of the [persona redesign](/modules/ai-chat/roadmap/#persona-refinement). Documented on **[Personas](/modules/ai-chat/personas/)**.

- **The app default persona.** The admin builds one persona for the whole app in **Configuration → Personas** — a new `appPersona` record — and every user has it, live. It replaces the automatic *Assistant* each user used to be given.
- **Customising makes a persona of your own.** On **Settings → AI Assistant**, *Customise* starts a new persona from the app default; your first becomes your default. Personas sit in a list beside the editor, with *Use by default*, *Duplicate* and *Delete*.
- **One editor for everyone.** Six tabs hold every stored field — Identity, Voice, Behaviour, Support, Words and Instructions — so the avatar, colourway, language, greeting, words, roles and personality can all be set at last. It also has:
  - tone cards that set all six voice dials at once, from a new `tonePresets` record (six seeded, edited in the new **Tones** section);
  - each dial's voice example under it;
  - a live preview card.
- **Locks belong to the app default.** The admin's editor has a lock on every control. A locked field is left out of users' editors, and **their personas speak with the app default's value for it**.
- **Two toggles.** *Users can create their own personas* (off: everyone uses the app default) and *More than one each* (off: one of their own), with the cap.
- **One default.** The star is it; the *Preferred persona* preference is gone. A new `POST /personas/:id/default` route sets it, and `app` hands the default back to the app default persona.
- **A persona picker in the message box**, once a user has more than one persona: on the welcome screen it picks the new conversation's persona; in a conversation it switches it.
- **Replies record their persona.** The provenance has `persona: { id, name }`, shown in the admin's context inspector.
- **API.** `GET /personas` lists the app default first (id `app`). `GET /config` adds `tonePresets` and `voiceExamples`. The service gains `listPersonaChoices` and `setDefaultPersona`. `persona.created` and `persona.updated` no longer carry `autoCreated` or `autoReactivated`.

<Aside type="caution" title="Existing hosts">
- **Update, then press Ensure defaults** (AI operations tab) to create the `appPersona` and `tonePresets` rows. Until then both read their seeded defaults: an app default named *Assistant*, and the six tones.
- **Build the app default persona** on Configuration → Personas, and lock what users should not change. Locks set before 1.8.0 keep working, and now carry the app default's value.
- **Automatic *Assistant* personas are retired.** One still exactly as created is no longer listed or used, so its user moves to the app default. It stays in their data export and is erased with their account. One the user edited stays as their own persona — and if it is starred, it remains their default.
- **The *Preferred persona* preference is no longer read.** Stored values stay in user preferences, unused.
- **No schema change** and no migration.
</Aside>

## 1.7.8 — Soul and persona context segments (2026-10-29)

The first build of the [persona redesign](/modules/ai-chat/roadmap/#persona-refinement): the prompt pieces, ready for the admin to assemble. Documented on [Personas → The Soul and Persona Segments](/modules/ai-chat/personas/#the-soul-and-persona-segments).

- **Ensure defaults creates standalone AI Core records for you to place.** Nothing is attached to any operation, and `ai-chat/reply` is left as it was.
  - `ai-chat/soul`, a context segment: *What you value* and *What you never do*.
  - `ai-chat/persona`, a context segment: the persona's identity, the six voice dials (each a number and an example), switches, supports, words, greeting and standing instructions.
  - Eight soul approaches, such as *read first*, *act or check*, *disagree once* and *read the moment*.
  - Their prompt variables. Anything a user typed is fenced.
- **Configuration → Soul** (new) holds the core values and what the assistant never does. Who the assistant is belongs in the app's own system prompt.
- **Configuration → Personas → Voice examples** (new) holds one example line per dial for each band. Every reply sends the line for the persona's band beside the number. This answers the finding that bare slider numbers read to the model as "vibes, not dials".
- **Every reply sends the new values:** the soul lists, the band examples, yes/no switches, supports, and the formats, terms, terminology and greeting that used to be stored only.
- Tests cover the seeding (and that no operation is touched), the band choice and the values sent (24 tests).

<Aside type="note" title="Existing hosts">
Run `npx ai-chat update`, then press **Ensure defaults** once. That creates the new records and the `soul` and `voiceExamples` rows. Then place the segments and approaches where you assemble your prompts.
</Aside>

## 1.7.7 — Choose each item's operation; test replies as the builder (2026-10-29)

- **Admin → AI Chat → Configuration → Operations** (a new first sub-tab, the new `operations` config key): choose the app's **reply** operation and the **branch handover** operation. Replies run the app's reply operation unless a starter card binds the conversation to its own.
- **Every "which operation" setting is now a dropdown** — the reply and handover, each background task, each custom task and each starter card — listing every enabled AI Core operation that writes an answer, with the item's default first (AI Core **1.81.5+** `listOperations`). An id AI Core does not list is kept and marked; an older AI Core falls back to typing the id.
- **Reply operation picker in the composer (admins only)** — choose the operation the next replies run, to test prompts against a real conversation; *Other operation…* takes any id and remembers it in the browser. The choice resets on reload. The server accepts the override (`operationId` on `POST /reply` and `/reply/stream`) only from an admin (`requireAdmin`).
- **Each reply records the operation that produced it** (`provenance.operationId`, plus `operationOverride` for an admin pick): a badge under each reply for admins, and an *Operation* row in the Activity tab's provenance inspector.
- **Security:** a browser could bind a conversation to *any* AI Core operation by writing `metadata.replyOperationId` on create or update. Over HTTP the server now keeps a binding only when a configured starter card offers it; service callers (other modules) are unchanged. `POST /reply` also accepts no body, as before.
- New `GET /admin/operation-options`; the integration tests cover the precedence, the provenance, the binding guard and the listing (22 tests).

<Aside type="note" title="Existing hosts">
`npx ai-chat update`, then press **Ensure defaults** once to plant the `operations` row (until then the canonical reply and handover apply). For the dropdowns, update AI Core to 1.81.5 or later. Any operation you point replies at needs the `ai-chat/persona-style` segment for personas to apply.
</Aside>

## 1.7.6 — Persona fixes (2026-10-29)

The no-decision half of the [persona refinement](/modules/ai-chat/roadmap/#persona-refinement) list. Documented on [Personas](/modules/ai-chat/personas/).

- **The automatic *Assistant* persona exists once per user.** Its id derives from the user id, so concurrent replies cannot create two; a user who deactivates every persona gets the same *Assistant* back (reactivated, firing `ai-chat.persona.updated` with `autoReactivated: true`), not another row each time. It clears only *inactive* stars, so it can never take the star from a persona the user chose.
- **One usable default.** The default lookup has a stable order; imports keep one default (a merge respects the user's active star; an envelope's active star beats an older inactive one); and when 1.7.5 left two starred personas, either star on the settings page now makes its persona the only default.
- **Inactive personas cannot be attached** to a conversation — create and switch answer 400 *Unknown or inactive persona* (was *Unknown persona*). An empty `personaId` / `languageOverride` is stored as none.
- **A stale Preferred persona no longer blocks new chats.** The welcome screen ignores one that is deleted or inactive, retries a refused create without it, and deleting a persona clears a preference naming it. The Preferences dropdown lists active personas only and shows a stale choice as *Default persona*.
- **Locks.** `personaGating.lockedFields` must be persona field ids — anything else is a 400. The admin lock list covers every writable field, in two groups (settings-page controls, API-only fields); stored unknown ids are dropped on the next save.
- **Settings page.** Personas open view-only when editing is off; a locked field shows the value the server will actually save (a locked name reads *Assistant*, so creating works); the name and custom-instruction boxes stop at their limits with a count; the star has its own pending state and a toast; the pencil is disabled while a persona is open; a stored response length outside Concise/Balanced/Detailed (such as `adaptive`) stays visible and selectable.
- **Prompt records (fresh installs).** `persona_explanation_style`, `persona_response_length`, `persona_greeting_style` and `persona_language` are now seeded injection-fenced, and the content approach ends *Reply in `{persona_language}`.* **Ensure defaults** now reports existing records that need a manual update.
- Persona integration tests (16) run the generated backend against PGlite: `npm test`.

<Aside type="caution" title="Existing hosts — one-time steps">
Re-seeding never edits an existing AI Core record, so a host that pressed **Ensure defaults** before 1.7.6 must make two edits by hand:

1. Run `npx ai-chat update` (no schema change, no new shadcn components), then press **Admin → AI Chat → AI operations → Ensure defaults**. Its *Needs a manual update* note lists what follows.
2. In AI Core's prompt-variable admin, switch **Injection risk** on for `persona_explanation_style`, `persona_response_length`, `persona_greeting_style` and `persona_language`.
3. In AI Core's approach admin, edit `ai-chat/persona-content` to read: `Content preferences: {persona_content_preferences}. Greeting style: {persona_greeting_style}. Reply in {persona_language}.` (If you had customised it, just drop the trailing *when a preferred language is set*.)
4. Optional — users who show two starred personas can click either star. To repair every user at once:

```sql
UPDATE ai_chat_persona p SET "isDefault" = false
WHERE "isDefault" AND id <> (
  SELECT q.id FROM ai_chat_persona q
  WHERE q."userId" = p."userId" AND q."isDefault"
  ORDER BY q."isActive" DESC, q."createdAt" ASC, q.id ASC
  LIMIT 1
);
```

API callers that send unknown `lockedFields` ids, or attach an inactive persona to a conversation, now get a 400.
</Aside>

## 1.6.0 — Every context section carries a chat marker (2026-10-28)

- Per the [prompt model](/modules/ai-core/prompt-model/#markers) (a marker is a label **with an authored meaning**, and the catalogue is consumer-extensible), the module now seeds six markers of its own — `chat-focus`, `chat-summary`, `chat-checkpoint`, `chat-memories`, `chat-context-refs`, `chat-section-formats` — beside `conversation-history`, and tags every reply context section with its marker. The instructions-side meanings block then frames each item instead of items arriving bare; the section-formats meaning carries the fence-convention framing, strengthening the fallback path. Press **Ensure defaults** once to plant the markers (create-if-absent; admin edits win).

## 1.5.5 — The fence convention becomes operation instruction (2026-10-28)

- Per the [AI Core integration contract](/modules/ai-core/integration/#the-context-slot), the context slot is framed to the model as *material to examine, never direction* — so the fence convention sent as a context section carried no instruction weight. It now lives in the reply operation's **own authored prompt**: a seeded task line referencing a new declared, module-derived prompt variable **`{section_formats}`**, filled per run with each type's tag, label and guidance (or hint). The 1.5.4 context section stays as the visible fallback.
- **Existing hosts** (the operation record is never edited by re-seeding): press **Ensure defaults** to create the variable, then add one line to `ai-chat/reply` in the operation editor — *"When you draft one of the saveable section types, wrap that section in a fenced block tagged with its type id: a line of three backticks followed immediately by the id to open, a line of three backticks to close. The types: `{section_formats}`"*. Fresh installs seed it automatically.

## 1.5.4 — Section formats reach every reply (2026-10-28)

- **Fix:** the fence convention (and with it the in-chat display components) only entered the prompt when a type carried AI guidance — and stored `sectionTypes` rows predate that field, so in a live host the model was never told the email component existed. ## 1.0.0 — The rebuild

A ground-up rebuild on a fresh module-starter clone (scaffold v1.31.20). The old module had zero installs, so v1.0.0 locks the contract with no migration constraints; the 0.1.x pre-scaffold module is preserved in `zArchive/` and on the `zarchive/old-module` branch — background only, nothing was carried across unexamined.

### Architecture

- **Pure AI Core consumer** — `depends: { 'ai-core': '>=1.78.0' }`. Models, prompts, the usage ledger, guardrails and tools all come from AI Core; the module ships zero provider SDKs and never names a model id. One generated gateway file is the single LLM seam.
- **Admin-authored prompts** — the module's prompt domain lives in AI Core as `ai-chat/*` records (seven operations, persona style approaches with declared prompt variables, an epistemic discipline with a grounding guardrail). Nothing seeds at boot; the admin page's **Ensure defaults** button plants everything create-if-absent, and admin edits always win.
- **Baseline plus boost** — the baseline install (ai-chat + ai-core) is fully functional. Structure, Cognitive Pipeline and Document Management are feature-detected boosts behind structural facades; every absence degrades visibly, never silently.
- **Admin-first** — the four-tab admin page (Configuration, AI operations, Activity with a reply provenance inspector, Data) shipped early as the observation surface, and admin config is runtime records, not build-time decisions.

### Features

- **Streaming replies end-to-end** via AI Core v1.79's `RunStream` + UI message stream adapters, with the non-streamed JSON path as the baseline contract and automatic 501 fallback; both paths share one context assembly and one persistence half.
- **Branching with AI-written handover** (summary, key decisions, open questions), personas re-aimed at AI Core prompt variables, CoALA memories with background extraction, rolling summaries, alignment checkpoints, drift detection with action-bank nudges, context refs, and automatic titling.
- **Saved sections** (new): admin-defined section types with a destination ladder — local table, Structure node, or Cognitive Pipeline ingest — and a visible local fallback.
- **shadcn AI Elements UI** shipped as module-owned source (conversation, message, prompt-input, reasoning, sources, suggestion, tool) over 22 declared shadcn primitives; TanStack Query throughout.
- **Eleven self-contained `ai_chat_*` tables**, full security registrations (deletion cascade + personal-data export over the ten user-keyed tables), a usage provider, module registry registration, six idempotent background jobs behind the host jobs seam, and a versioned data export/import envelope.

### Removed (relative to the archived 0.1.x module)

The bespoke CLI and regex host-file surgery, taki-ui, the dead chat templates, local/S3 storage adapters, the hand-rolled logger and CSS, hardcoded model lists, prompt fragments as code (now AI Core records), the standalone/cognitive variant system, and the `chat_tool_calls` / `chat_processing_logs` tables.

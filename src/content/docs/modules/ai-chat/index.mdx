The **AI Chat** module adds a full conversational AI surface to apps built on the starter template: branching conversations with handover summaries, user-customisable personas, long-term memory, alignment checkpoints, an action bank of detected patterns, and **saveable reply sections** — admin-defined pieces of a reply (email copy, affidavit paragraphs, notes) that can be kept and routed to other modules.

The module is a **pure [AI Core](/modules/ai-core/) consumer**. Models, prompts, the usage ledger, guardrails and tools all live in AI Core; ai-chat never imports a provider SDK and never names a model id — its operations bind model *purposes* (`chat`, `summary`, `analysis`, `titles`) that the host admin maps to models in the AI Core admin. Replies stream end-to-end through AI Core's `RunStream` contract, with a non-streamed fallback for hosts whose AI Core predates streaming.

<Aside type="tip" title="Baseline plus boost">
The **baseline** install is ai-chat + ai-core only, and everything on this page works there. [Structure](/modules/structure/), [Cognitive Pipeline](/modules/cognitive-pipeline/) and [Document Management](/document-management/) are **optional boosts** reached through `serviceRegistry` feature detection — they add behaviour (session-node mirroring, saved-section destinations, attachments), never correctness. A configured boost whose module is absent degrades visibly, never silently.
</Aside>

## Quick Install

```bash
npx ai-chat init
```

The CLI checks the AI Core dependency, creates the database tables, generates the frontend and backend code, and installs the shadcn primitives the UI builds on.

## Key Features

<CardGrid>
  <Card title="Branching Conversations" icon="right-arrow">

  </Card>

  </Card>

  </Card>
  <Card title="Checkpoints and Summaries" icon="approve-check">
    Rolling summaries compress history; checkpoints *verify* alignment — the AI restates where things stand and the user confirms, corrects or dismisses it.
  </Card>
  <Card title="Action Bank" icon="list-format">

  </Card>
  <Card title="Saved Sections" icon="document">
    Admin-defined section types let users keep useful pieces of a reply — stored locally, or routed to a Structure node or through Cognitive Pipeline ingest.
  </Card>

### Full Feature List

- Streamed assistant replies (AI SDK UI message stream via AI Core v1.79's UI message stream adapters), with an automatic non-streamed fallback on older hosts
- Branching with AI-generated handover context (summary, key decisions, open questions)
- [Personas](/modules/ai-chat/personas/): an admin-built app default persona every user has, personas of their own customised from it in one tabbed editor (identity, voice dials with tone cards, behaviour, support, words, instructions) with a live preview, and a persona picker in the message box; filling AI Core prompt slots; admin locks, two gating toggles and a persona cap
- Admin-written [notices](/modules/ai-chat/configuration/#notices--the-before-you-start-notice-the-line-under-the-message-box-and-dialogs): a before-you-start notice users accept before their first chat (recorded per version, with an event for an AI-use ledger), a line under the message box, and dialogs their links open — written in Markdown with a toolbar and preview
- CoALA long-term memory with CRUD, keyword/tag search and background extraction
- Rolling summaries and alignment checkpoints (time / drift / return triggered)
- Drift detection that scores conversations against their declared focus and nudges the action bank past a threshold
- Action bank over eight detected pattern types, surfaced in-chat as suggestions
- Context references attached to a conversation (documents, Structure nodes, URLs, memories, other conversations)
- Saved reply sections with an admin-configured destination ladder and a visible local fallback
- Automatic conversation titling from the opening turns
- Admin page with four tabs: Configuration, AI operations (AI Core's embedded prompt editor), Activity (counters + a reply provenance inspector) and Data (versioned JSON export/import)
- Admin-configurable background tasks over the host jobs seam
- Every reply's material reaches AI Core through the reply operation's own Context builders and Inputs, so an admin sees and edits all of it in AI Core
- Reply provenance: every assistant message records exactly which messages, summaries, checkpoint and memories were supplied, anything the operation did not place, and the AI Core ledger reference
- Security registrations: deletion cascade and personal-data export over all eleven user-keyed tables
- Dashboard widget (recent chats), per-user preferences section and an AI Assistant settings page

## Architecture

```
┌──────────────────────────────────────────────────────────────┐
│                         Frontend                             │
│                                                              │
│  Chat page (AI Elements) · Sections page · Persona settings  │
│  Admin page · Dashboard widget                               │
│     │ TanStack Query hooks        ▲ useChat (streamed turn)  │
│     ▼                             │                          │
│  API service ────► /api/v1/ai-chat routes                    │
└───────────────────────────│──────────────────────────────────┘
                            ▼
┌──────────────────────────────────────────────────────────────┐
│                         Backend                              │
│                                                              │
│  aiChatService ──► pipelines (summarise · memories ·         │
│      │              patterns · drift · title · handover)     │
│      │ enqueue              │                                │
│      ▼                      ▼                                │
│  host jobs seam        llm-gateway ───► AI Core (hard dep)   │
│                        (run / stream)   models · prompts ·   │
│  optional boosts:                       usage · guardrails   │
│  cognitive-boost ──► structure / cognitive-pipeline          │
│  doc-boost ──────► document-management                       │
│                                                              │
│  Prisma (11 ai_chat_* tables)                                │
└──────────────────────────────────────────────────────────────┘
```

Every LLM call goes through one generated file, `ai-chat.llm-gateway.ts` — a structural facade over the AI Core service with the reply runners (streamed and non-streamed, assembled identically), six JSON operation runners that Zod-parse structured results and **degrade visibly** rather than fabricate, and the admin-triggered seeding of the module's `ai-chat/*` records. The service supplies only the module's **own** domain context to a run (recent messages, the latest summary, a pending checkpoint, relevant memories, context refs); ecosystem context is the job of AI Core's context-assembly engine when it lands.

## Prerequisites

| Requirement | Details |
|-------------|---------|
| **AI Core module** | Hard dependency (`depends: { 'ai-core': '>=1.81.10' }`) — owns all model access. AI Chat reads each operation's Inputs and Context builders before running it (`getOperationInfo`, v1.81.7) and sends each piece through its own door (v1.81.10) |
| **Structure module** | Optional boost — enables the session-node mirror toggle and the Structure saved-section destination |
| **Cognitive Pipeline module** | Optional boost — enables the Cognitive Pipeline saved-section destination (and can pull chat content as an ingest source) |
| **Document Management module** | Optional boost — enables message attachments (references only, never files) |

The module creates its AI Core records itself when the server starts (create-if-absent; an admin's edits are never overwritten). **Admin → AI Chat → AI operations → Ensure defaults** runs the same seed on demand and shows the report. See [Configuration](/modules/ai-chat/configuration/).

## What Gets Installed

When you run `npx ai-chat init`, the module generates:

**Frontend** (26 files in `frontend/src/features/ai-chat/`):
- 4 pages — chat, saved sections, persona settings, admin
- 2 components — dashboard widget, preferences section
- 7 AI Elements — conversation, message, prompt-input, reasoning, sources, suggestion, tool (shipped as module-owned source)
- 4 hook files — query keys, chat data, user data, admin data
- 1 API service, 1 types file, 1 routes config
- 5 registrations — navigation, dashboard, preferences, settings page, admin page
- 1 barrel (`index.ts`)

**Backend** (15 files in `backend/src/features/ai-chat/`):
- 4 core domain files — types, service, pipelines, routes
- 3 seams — `ai-chat.llm-gateway.ts` (AI Core), `ai-chat.cognitive-boost.ts` (Structure + Cognitive Pipeline), `ai-chat.doc-boost.ts` (Document Management)
- 1 jobs file — six background job handlers
- 6 registrations — route, service, security, module, usage, jobs
- 1 barrel (`index.ts`)

**Database** — 11 Prisma models, all prefixed `ai_chat_` (see [Database](/modules/ai-chat/database/))

**UI dependencies** — 22 shadcn primitives (message, message-scroller, prompt-input building blocks, code-block, trace and friends) plus `@ai-sdk/react` and `ai` for the streaming chat transport.

See [Usage](/modules/ai-chat/usage/) for a walkthrough of the features, or [Configuration](/modules/ai-chat/configuration/) for the admin surface.

## v1.16.0 — October 2026

**Current release.** Part 2 of the starter catch-up: the visual layer for the starter's [Data Table](/starter-template/data-table/). The starter owns the table's behaviour, structure and hooks, and leaves its look to this module. This release adds three catalogue entries, a `dataTable` field on `StyleConfig`, and a **Data tables** tab on the admin Theme page. It also changes three dark-mode foreground defaults, so every status tone passes WCAG AA. The minimum host is now **starter v2.15.5**. Read the upgrade notes at the end of this entry before you run `npx style update`.

### Catalogue entries

All three are unlayered and wrapped in `:where()`, like `style.designer-density`, so they beat the table's Tailwind utilities at zero specificity and any other unlayered rule can override them.

- **`style.table-density`** (always on, order 70, not listed on the Style catalogue tab). It restates the starter's compact and comfortable density steps through tokens, so they can be retuned. Body cells get `padding-block` from `--style-table-compact-cell-py` or `--style-table-comfortable-cell-py`, and header cells get `height` from `--style-table-compact-head-h` or `--style-table-comfortable-head-h`. Each token falls back to the starter's own step (`calc(var(--spacing) * 1)`, `* 8`, `* 4` and `* 14`, which are `py-1`, `h-8`, `py-4` and `h-14`), so a table looks the same until a token is set. Skeleton rows follow. Full-width rows (the error panel, empty, "No results" and expanded rows) and the cells of a table nested inside a cell are not retuned.
- **`style.table-sheet`** (opt-in, order 60, the **Sheet-style tables** switch in the **Data table** group). A quiet spreadsheet look:
  - **Borders:** the frame at 80% of `--border`, body row dividers at 60%, and the header's bottom rule at the full `--border`.
  - **Header:** a 20% `--muted` wash on the header row, labels in `--muted-foreground` at weight 500, and the sorted column's label in `--foreground` at 600.
  - **Sort arrows:** on pointer devices, only the sorted column shows its arrow until a header is hovered or keyboard-focused. Touch screens show every arrow. The fade is off under reduced motion, and `aria-sort` still tells screen readers.
  - **Figures:** tabular figures on every cell and on the progress label.
  - **Missing values:** `--muted-foreground`, with no opacity.
  - **Error panel:** the title in `--foreground`, the description muted at a 50ch measure, and the icon muted, never red. **Try again** keeps the outline button.
  - **Person cells:** the avatar size comes from `--style-table-avatar-size` (default `1.5rem`), the initials scale with it but never drop below `--text-xs`, and the email line is `--text-xs` and muted.
  - **Progress:** a 20% `--primary` track and a `--primary` bar, with the height from `--style-table-progress-height` (default `0.375rem`). A complete bar turns `--success`.
  - **Copy buttons:** on pointer devices they stay hidden until the row is hovered, the id cell has focus, or a copy result is showing. Touch screens always show them. The icon is muted, then `--success` after a copy and `--destructive` when the browser refused.
  - **Links:** `--primary`, underlined on hover.
  - **Focus:** 2px `--ring` outlines, inset on column headers and links, and 2px outside **Try again** and the copy button.
- **`style.table-zebra`** (opt-in, order 60, the **Striped rows** switch). Every second body row gets a 20% `--muted` wash. Only real rows are counted, so an expanded detail row never shifts the stripes. Selected rows keep shadcn's selection colour, and a hovered row shows shadcn's 50% hover whether it is striped or not. The stripes use `:nth-child(… of S)` (Chrome 111, Firefox 113, Safari 9); older browsers show no stripes.

### `StyleConfig.dataTable`

- **New optional field** `dataTable?: DataTableStyle`, shaped `{ density?: { compact?, default?, comfortable? }, statusTones?: { value, tone }[] }`. Each density step is `{ cellPaddingBlock?, headHeight? }`. New types, exported from `features/style/types`: `StatusTone`, `DataTableStatusTone`, `DataTableDensityStep` and `DataTableStyle`.
- **Outside the preset layer.** It is not in the preset code or the shadcn-config layer, and it never touches the palette, so the Shadcn Config history doesn't record it. It is versioned with the combined theme config and kept across preset changes and rebases, like `defaultStyling`.
- **Density tokens.** `generateDataTableCSS` declares `--style-table-{compact,default,comfortable}-{cell-py,head-h}` on `:root`, only for the sizes the config sets. A size must be a non-negative length in `px`, `rem` or `em` with up to four digits each side of the point, or a bare `0`. Anything else (other units, `%`, `calc()`, `var()`, negative values, upper-case units) is skipped, not clamped.
- **Default density.** The starter's default step adds no utilities, so the cells keep the app's shadcn style spacing. It has no neutral fallback, so the generated theme CSS adds its two rules only when the config sets a default size. They use the same guards as the catalogue's rules.
- **Status tones.** Each `{ value, tone }` entry colours the badges inside a data table whose `data-status` matches `value`, ignoring case for A to Z only. The tones are `success`, `warning`, `info` and `destructive` (the token and its `-foreground`), and `neutral` (`--secondary` / `--secondary-foreground`). The badge's border turns transparent, so an outline badge loses its frame. A tone falls back to `--secondary` / `--secondary-foreground` when the palette lacks its token. Values are written as escaped CSS strings, so none can leave its selector. A value that is empty, longer than 64 characters or holds a control character is ignored, and when two entries name the same value, the later one wins.
- **Where it applies.** The layer is part of the module extensions, so the running app (`style.app-theme`), the exported `global.css` and the builder canvas all carry it.
- **Stored configs.** `coerceStyleConfig` keeps only the well-formed parts of `dataTable` and removes the key when nothing usable is left. The generator checks lengths and escapes values again, because the builder canvas reads stored configs without coercion.
- **New exports** from `utils/css-generator.ts`: `generateDataTableCSS(config, scope?)`, `DATA_TABLE_DENSITIES`, the `DataTableDensity` type, `STATUS_TONES`, `STATUS_VALUE_MAX_LENGTH` (64), `dataTableTokenName(density, field)` and `isDataTableLength(value)`.

### Admin page: Data tables tab

- **Four tabs.** The Theme page's tabs are now Theme, **Data tables**, Style catalogue, and Import and export.
- **One draft.** The tab edits `config.dataTable` in the same draft as the Theme tab, with the same **Revert** and **Save**, captioned "Saved with the app theme, so Save also keeps any changes on the Theme tab." History stays on the Theme tab. Revert also clears any text in a size field that isn't a valid length yet.
- **Density.** A cell padding and a header height for each of Compact, Default and Comfortable. Placeholders show what an empty field keeps. Text that isn't a valid length shows an error once you leave the field, and is never stored.
- **Status colours.** Rows of a status value and a tone, each with a live sample badge. **Add status** adds a row, and a value listed twice is flagged.
- **Live preview.** The starter's `DataTable` over 12 sample accounts that use every column kind, with its Density menu and a **Show load error** switch. Unsaved density and status edits show straight away. A caption points to the Style catalogue tab for the sheet and zebra looks.
- **New generated files:** `components/theme/DataTableSettingsPanel.tsx` and `components/theme/DataTablePreview.tsx`, in both install modes.

### Contrast

- **Dark-mode foregrounds default to dark text.** New configs default dark `--destructive-foreground`, `--success-foreground` and `--info-foreground` to `oklch(0.205 0 0)`, as dark `--warning-foreground` already was. Near-white text on dark mode's lighter tones measured under 4.5:1: 2.77 on destructive, 2.95 on success and 2.75 on info. Dark text gives success 5.82 and info 6.23.
- **The sync writes `--destructive-foreground` per mode.** It is the module's own token: `tools/sync-shadcn.mjs` now writes light `oklch(0.985 0 0)` and dark `oklch(0.205 0 0)` into `utils/shadcn-data.ts`, and `DEFAULT_STYLE_CONFIG` mirrors both.
- **Contrast tests.** `tests/style.data-table.test.ts` measures every colour pair the table styling uses, in all seven base colours, light and dark. Every status tone passes 4.5:1 against its foreground. Muted text on the 20% washes passes wherever it passes on a plain page; light mist is the tightest, at 4.52. The recorded exceptions are all shadcn's own colours: light `--ring` on `--background` is under 3:1 in every base (2.32 to 2.63), light olive's `--muted-foreground` is under 4.5:1 on its own surfaces (4.26, and 4.18 on the washes), and shadcn's 50% row hover takes light mist to 4.38 and light olive to 4.06.
- **Quiet light-mode washes.** The light stripe and header wash are deliberately faint: light mist's `--muted-foreground` keeps 4.5:1 only up to a 23% wash. Dark mode reads clearly. An admin-tunable stripe strength is on the [Roadmap](/modules/style/roadmap/).

### Tooling

- `lightningcss` is a new dev dependency: the tests parse the generated CSS with it.
- `tests/support/frontend-sandbox.ts` renders frontend templates through the scaffold's `processTemplate`, so tests can import the generated CSS generator, shadcn data and preset codec.

### Upgrade notes

1. **The minimum host is starter v2.15.5.** The Data tables tab uses the DataTable column kinds, `densityToggle`, `error` / `onRetry` and the density memory under `rememberColumns` that v2.15.5 added. Tested against starter v2.15.5.
2. **Run `npx style update`.** It adds the two Data tables files. There is no schema change and no new shadcn primitive.
3. **Data tables look the same until an admin changes them.** With no tokens set, `style.table-density` gives exactly the starter's sizes, and the sheet and zebra entries ship off. One exception: on a compact or comfortable table, a column `className` that sets the cell's `padding-block` or `height` (such as `py-0` or `h-12`) now loses to the always-on rule, because that rule is unlayered.
4. **Switch the looks on in the Style catalogue tab.** **Sheet-style tables** and **Striped rows** are in its **Data table** group.
5. **Saved themes keep their stored dark foregrounds.** Dark `--destructive-foreground` is part of the base palette, so in a saved theme the old near-white value shows as a one-off custom delta, like the v1.15.0 chart note. The next palette change on a project asks you to keep, rebase or discard: Discard (or **Reset to shadcn defaults**) takes the new dark text, while Rebase keeps the old value, because it re-applies the delta. On the admin Theme page a palette change regenerates the palette straight away and takes it. Dark `--success-foreground` and `--info-foreground` are module tokens, which palette changes never touch. A project theme can set them on its Theme tab's Colours section; the admin Theme page edits preset settings only, so an app theme saved before v1.16.0 keeps them.
6. **Status colours match the stored value.** A badge's `data-status` is the raw value the app stores (`active`, `past_due`), which can differ from the label the badge shows.

## v1.15.0 — October 2026

A catch-up release (Part 1). The module moves to scaffold 1.32.2, stores the app theme in the starter's `AppSettings.appTheme`, adds a Style catalogue tab and a JSON import and export to the admin Theme page, reaches token parity with shadcn 4.23.0, and rebuilds its designer UI on shadcn primitives and the starter's typography. The minimum host is now **starter v2.13.1**. Read the upgrade notes at the end of this entry before you run `npx style update`.

### Scaffold & tooling

- **Scaffold 1.18.1 → 1.32.2.** This brings the newer module contract and the `reconfigure` and `rename` CLI commands (alongside `migrate-db`, `enable` and `disable`). It also fixes how shadcn components install: the scaffold runs `npx shadcn@latest add`, using the `npx` that sits next to the running Node rather than whatever comes first on the PATH. The "Sync UI components?" prompt on `update` is now opt-in: it defaults to no, and `--force` still syncs. The build is `tsup && tsc --emitDeclarationOnly` on TypeScript 7, with esbuild 0.28.
- **Conformance:** `npm run conformance:check` reports 0 violations. The fixes behind that are listed under Backend.
- **Tests:** `npm test` runs the scaffold's PGlite harness (an in-memory Postgres) over the generated backend: 16 service tests and 5 security tests.
- **Styling audit:** new `npm run audit:styling` (`tools/audit-styling.mjs`) renders every frontend template the way `npx style init` does and runs the starter's structure-only styling audit over the result. It needs a starter checkout: pass `--starter <path>`, set `STYLE_AUDIT_STARTER`, or keep the starter at `../../unique-react-fullstack-starter`.
- **shadcn sync:** `npm run sync:shadcn` moved from `scripts/` (scaffold-owned) to `tools/sync-shadcn.mjs` (module-owned), so `scaffold:update` can't replace it. It is pinned to `shadcn@4.23.0`; the synced data is the same as at 4.13.0. shadcn 4.21.1 moved the preset codec to `packages/registry/src/preset/preset.ts`, so the tool tries that path first and falls back to the old one for older tags.
- **Project node type:** change it after install with `npx style reconfigure --set projectNodeType=<slug>`.
- The generated route config imports `RouteObject` from `react-router`, the starter's router package since React Router v8.

### Backend

- **One shared app-theme history.** `PUT /api/v1/style/app/config` now records every admin's saves on one shared history row (the most recently updated `app-config` override) and makes it the only active app override. Before, each admin had a row of their own, and a re-save left the active flag as it was. `GET /app/active` now always returns the same row: the most recently updated active one. New admin-only `GET /app/versions` and `GET /app/versions/:version` return that history in the same shapes as the project version routes.
- **Admin JSON export and import.** New admin-only `GET /api/v1/style/export` returns a versioned envelope, `{ version: 1, moduleId: 'style', exportedAt, counts, data }`. It holds the exporting admin's own personal themes, every system theme and every app override, each with its theme history and shadcn-config history. Row ids and owner ids are left out. `POST /api/v1/style/import` merges that envelope in one transaction. It adds records and deletes nothing:
  - personal themes land under the importing admin, and one with the same project and name has its content updated;
  - existing system themes and app overrides are kept as they are, history included, and versions already present are skipped;
  - activation never changes on an existing row, and `AppSettings.appTheme` is never touched;
  - a wrong `moduleId` or `version` answers `400` before anything is written, and an invalid body answers `400` listing the problems; a failed write answers `409`, and nothing changes.
- **Applying a system theme no longer writes the shared row.** `PUT /projects/:nodeId/activate/:themeId` with a system theme copies its config into the caller's own project config for that node, activates it, and records a version labelled `Applied <name>`. The system row is never changed, so one user's choice can no longer switch another user's theme. Activating one of your own themes that belongs to another node, or to no node, now answers `400`. `GET /projects/:nodeId/config` prefers your own active row, then an active global or system row.
- **Saving a project config makes it active again.** If you had activated another of your own themes on a node, a later save through `PUT /projects/:nodeId/config` landed on the inactive project-config row while `GET /config` kept returning the other theme, so the builder's node mirror and the API disagreed. The save now reactivates the project config and deactivates your other rows for that node, in one transaction.
- **Clearer errors.** A request body that fails validation on any module route is now a `400` listing each problem (`path: message; …`) instead of a `500`.
- **Action hooks reach every listener.** Every hook now fires through `doActionAll`, so listeners registered with `addActionAsync` receive it too (`doAction` skipped them). Every payload includes `userId`. Create, update, save, activate and restore payloads also carry the row as `theme`, label updates carry `themeVersion` or `shadcnConfigVersion`, and deletes carry `themeId`. Two new hooks, `style.data.exported` and `style.data.imported`, carry `{ userId, counts }`.
- **Account erasure and export.** The `style.personal-themes` deletion handler resolves the subject as `userId ?? tenantId`. In this single-user product the tenant is the user, so a space offboard now erases that user's personal themes instead of failing. A subject with neither is refused. A new export handler with the same id returns the subject's personal themes, theme versions and shadcn-config versions: the same scope as erasure.
- **Registration.** The service registers under the exported `STYLE_SERVICE_KEY` (re-exported from the backend barrel), with the module's own version. `module.registration.ts` supplies an empty `init`, so the host can gate the module, and a genuine `register()` error now surfaces instead of being swallowed.
- **Service signatures.** `setActiveAppTheme(id, userId)` now takes the acting user. The activate response's `id` can differ from the requested theme id, because it is the caller's copy.

### App theme storage (Route 2)

- **The app theme lives in `AppSettings.appTheme`.** The admin page saves an envelope, `{ kind: 'style.app-theme', schemaVersion: 1, config, css, savedAt }`, through the starter's `setAppTheme`. The module's own table now keeps only the version history. A save writes `appTheme` first, then records the history entry, then applies the theme straight away. The history entry is best effort: if it fails, a warning shows and the save still counts.
- **First paint and signed-out visitors.** `style.registration.ts` applies the CSS this device cached on its last load or save (`localStorage` key `style.app-theme-css`) synchronously when it loads, so a returning visitor sees their theme from the first paint. It then reads the starter's public `GET /api/v1/theme`, which answers signed-out visitors too, so the old race with sign-in is gone. The CSS is regenerated from the stored config with the current generator, falling back to the CSS stored with it. With no envelope yet, it falls back to the legacy `GET /api/v1/style/app/active` row; a signed-out `401` there is ignored and the cached CSS stays. The CSS generator is loaded lazily on this path, so it stays out of the first download.
- **One-time migration.** When `appTheme` is null and a legacy app-theme row exists, the first admin visit to the Theme page loads the editor from that row and copies it into `appTheme`. A non-null `appTheme` the module doesn't recognise is left alone until an admin saves.
- **Hooks.** New `hooks/useAppTheme.ts` exports `useAppTheme()`, `useSaveAppTheme()` and `buildAppThemeEnvelope()`. `hooks/useProjectTheme.ts` also exports `useThemeDraft()` and the `ThemeDraft` type, the editing model both editors share. New query hooks in `hooks/useStyleQueries.ts`: `useLegacyAppTheme`, `useAppThemeVersions` and `useAppThemeVersion`, plus `appThemeVersionQuery`, the query options for one version.
- **Registration exports.** `STYLE_REGISTRY_ID`, `APP_THEME_ENVELOPE_KIND`, `coerceStyleConfig`, `parseAppThemeEnvelope`, `applyAppTheme` and `bindMenuColor`. The app-wide menu-colour observer is skipped for the default menu colour, watches only added elements, and stays a single observer however often the colour changes.

### Admin page

- **Where it is.** The Theme page stays at `/admin/app-theme` (id `app-theme`) and now sits in the admin sidebar's **Appearance** section, beside the starter's own look-and-feel pages. It loads lazily, and it registers the same loader as `preload`, so the admin panel can fetch its code ahead of time.
- **Three tabs:** Theme, Style catalogue, and Import and export.
- **Theme tab.** The editor fills the rest of the window height in both the side and top navigation layouts. The History menu lists the shared app versions; Restore asks first, applies that version for everyone (normalised, so an old combination shadcn now rejects is corrected), and records it as "Restored from vN". The preset paste box accepts a bare code, `--preset <code>`, the full `npx shadcn@latest init --preset <code>` command, or a URL with `?preset=`. Panel edits and pasted codes are normalised the way shadcn create does it (see shadcn alignment). Picking a style applies its defaults at the moment you pick it, so loading or restoring a saved theme no longer re-applies style defaults over it (a bug fix).
- **Style catalogue tab.** One switch per opt-in catalogue entry (`style.tabs-line-primary`, `style.button-bold`, `style.card-elevated`, `style.sidebar-rounded`), grouped by the shadcn primitive each one restyles. A change applies at once and is saved to `AppSettings.styleOverrides` through the starter's `PUT /api/v1/admin/style-overrides`. If the save fails, the switch rolls back and the error shows. "Reset to default" clears an explicit override.
- **Import and export tab.** Export downloads `style-export-YYYY-MM-DD.json` from `GET /api/v1/style/export`. Import reads a `.json` file, checks that it is a style export, lists the counts in a confirm dialog, and posts it to `/api/v1/style/import`. It then shows what was written, skipped records included, and refreshes every `['style', …]` query.

### shadcn alignment

- **Token parity with shadcn 4.23.0.** For any preset shadcn accepts, the generated `:root` and `.dark` palette tokens match what shadcn's `/init` returns: the same tokens, values and order, with `--radius` after `--chart-5`. This was checked live against 9 preset codes. The file is not byte-identical to the CLI's output (indentation, blank lines, mapping order and the font import lines differ), and isn't meant to be.
- **`--radius` is always emitted.** Radius "Default" now writes `--radius: 0.625rem`, as shadcn does, instead of leaving it out.
- **`@theme inline` has shadcn's variable set.** Font variables come first, and the radius scale is multiplicative from `--radius-sm` to `--radius-4xl` (`calc(var(--radius) * 0.6)` and so on). Non-colour tokens (fonts, spacing, letter spacing, shadows) no longer become `--color-*` mappings, so stray utilities such as `bg-font-sans` are gone. Custom variables with colour values map as `--color-<name>`; others map as `--<name>`.
- **The module's own tokens sit after the baseline.** `destructive-foreground`, which shadcn 4.x themes no longer define, moved out of the baseline into the module's extensions, next to the status and code tokens, fonts, spacing, letter spacing, shadows and custom variables. The sidebar accent and default styling layers work as before.
- **Menu colour now reaches the app's own menus.** shadcn applies Menu Colour when it *installs* a component: its CLI turns the `cn-menu-target` hook class into `dark` and `cn-menu-translucent` into utilities, so installed primitives keep neither, and the module's runtime class binding never matched anything in an app. The generated theme CSS now carries it on the menu surfaces' `data-slot`s (dropdown, context and menubar menus and their sub-menus, select and combobox content): Inverted gives them the dark palette, Translucent ports shadcn's translucent backdrop. Popovers aren't menu surfaces in shadcn, so they keep the page palette, and the preview's popover card no longer inverts either. The runtime binding stays for raw registry copies that still carry the class, such as the builder's pristine primitives.
- **Preset codes are interchangeable with ui.shadcn.com/create.** v2 codes encode and decode exactly as shadcn 4.23.0's codec does (fuzz-tested against it). v1 codes now take their chart colour from shadcn's v1 chart map; before, it was looked up by the base colour, which was wrong. Codes longer than 10 characters are rejected, as upstream. A custom free-text font can't be encoded, so it encodes as the field's default.
- **Settings never produce a code shadcn rejects.** Panel edits, pasted codes, restored shadcn-config snapshots and "Reset to shadcn defaults" are all normalised the way create does it:
  - a theme or chart colour the base doesn't offer falls back to the base colour;
  - a bold menu accent becomes subtle under a translucent menu colour;
  - a heading font equal to the body font becomes `inherit`;
  - `gray` becomes `neutral`.

  Before, choosing Base Colour Stone with Theme Neutral gave a code shadcn refused with HTTP 400. An unset or "Default" chart colour still follows the theme.
- **Charts follow shadcn under an accent theme.** When the chart colour equals the base colour, `resolveTheme` now gives the base tone's charts under an accent theme, as shadcn does. Earlier versions kept the accent's charts. This changes 238 of the 4,536 valid combinations (see the upgrade notes).
- **Settings panel options come from the synced data.** The Font and Heading Font pickers list all 26 shadcn preset fonts, grouped Sans Serif / Monospace / Serif; EB Garamond and Instrument Serif were missing. "Custom…" opens a free-text font box with a note that custom fonts aren't part of the preset code. The icon library, radius, menu colour and menu accent lists come from the synced arrays too.
- **The preview renders the chosen fonts.** Its font stacks started with shadcn's fontsource family names ("Inter Variable"), which Google Fonts doesn't serve, so the chosen font never showed. The loaded family now comes first, and Geist, Geist Mono, EB Garamond and Instrument Serif were added to the loader.
- **Generated counterparts follow shadcn for inputs and rings.** When you edit a token in one mode, the generated dark input is 15% white (borders stay 10%), and rings stay opaque, one step darker or lighter. Dark focus rings no longer nearly vanish.
- **Known limitation:** the running app still uses the `:root` font tokens. `config.font` and `config.fontHeading` drive the preview, the preset code and the exported `global.css`, but nothing loads fonts at runtime. This is tracked on the [Roadmap](/modules/style/roadmap/).

### Designer UI (Rule 7/8)

[Rule 7](/getting-started/llm-rules/#7-template-components-use-structure--semantic-tokens-only) says template components use structure and semantic tokens only; [Rule 8](/getting-started/llm-rules/#8-compose-the-shared-blocks-then-canonical-shadcn--never-hand-roll) says compose the starter's shared blocks, then canonical shadcn primitives, and never hand-roll controls. The generated designer UI now follows both.

- **Styling audit: 417 to 0.** Before this release the starter's styling audit found 417 violations in the generated frontend (typography, font-weight, opacity and shadow utilities). None remain. 52 hits carry an annotated exception that is legitimate: the class designer's Tailwind vocabulary in `class-parser` and `class-generator` (classes the designer writes into builder content, not module styling), the transition "shadow" option value, swatch contrast edges, and a font specimen.
- **Designer text density.** A new always-on catalogue entry, `style.designer-density`, sizes all designer text to `--text-xs`. It is scoped by the `data-style-designer` attribute, which sits on each designer root and on the popovers, selects, menus and tooltips they open, so the panel markup sets no font sizes. Retune it with `--style-designer-text-size`, `--style-designer-caption-size` and `--style-designer-leading`. It is injected unlayered, so its zero-specificity rules beat Tailwind utilities, while any unlayered app rule still overrides them. `style.tabs-line-primary` now reads `--style-tabs-line-size` (default `1rem`) and `--style-tabs-line-gap` (default `2rem`).
- **`style.tabs-line-primary` works.** Its label rules selected `[data-variant="line"]` on the tab triggers, but shadcn puts `data-variant` on the tabs list, so only the wider gap ever applied. It now selects triggers inside a line list and colours the active tab's underline bar with `--primary`.
- **Builder Style tab.** Display, Direction, Wrap, Justify, Align, grid Columns/Rows and text Align use `ToggleGroup`; clicking the selected item still clears it. The sections and the Overflow sub-section open and close with `Collapsible`. Opacity is a `Slider`; an arbitrary value such as `opacity-[.35]` shows the slider at 100, while the number field shows the raw value. Field labels are `Label`s tied to their controls, so screen readers name each control, and group headings use `Text variant="overline"`. Selects are full width at the small size, and inputs are 32px tall. The `StylePanel` now loads lazily through the property-panel registration (builder 1.33.0 wraps each panel tab in `Suspense`).
- **Theme colour picker.** It is built from `Tabs` (Solid and Gradient are real tab panels), `DropdownMenu` radio menus for gradient type and colour format, ghost icon `Button`s, `Input`s and `Label`s. No inline font sizes or full-screen click-catchers remain, and it no longer draws its own card: the popover provides the surface. The New/Current swatch is a keyboard-reachable revert button, and icon buttons and swatches have accessible names.

### Upgrade notes

1. **The minimum host is starter v2.13.1.** The module now uses `Text` (v2.6.0), `getApiErrorMessage` and `registerExportHandler` (v2.13.0), admin-page `preload` (v2.13.1), admin-page `section` (v1.56.0), the public `GET /api/v1/theme` (v2.9.1) and `AppSettings.appTheme` (v1.25.0). It was tested against starter v2.15.4 and v2.15.5.
2. **Run `npx style update` and accept the orphan removal.** The six removed files are listed as orphaned files, and approving moves them to the update backup. Nothing imports them, so declining is harmless.
3. **Answer yes to "Sync UI components?"** The module now needs eleven more shadcn primitives: `alert`, `alert-dialog`, `collapsible`, `dropdown-menu`, `empty`, `field`, `item`, `slider`, `spinner`, `toggle` and `toggle-group`. All but `slider` are in the starter's shadcn baseline. The prompt defaults to no since scaffold 1.32.1, and shadcn asks before it overwrites a component you already have. If you skip the sync, run `npx shadcn@latest add slider` (plus any other primitive your app lacks) in the frontend folder.
4. **Open the admin Theme page once.** The first admin visit copies the legacy app theme into `AppSettings.appTheme`. Until then the bootstrap reads the legacy row, which needs a session: signed-out visitors get a `401`, which the module ignores, and see the cached or default theme.
5. **`StylePanel` is no longer exported from the barrel.** If your app imported it from `@/features/style`, remove that import; the builder gets the panel from its property-panel registry.
6. **The `style.sidebar-accent-bold` entry is gone.** Set Sidebar Accent in the theme instead. A stale `style.sidebar-accent-bold` key left in `AppSettings.styleOverrides` is harmless, and the Style catalogue tab keeps it when it saves.
7. **Action payloads gained fields, and `addActionAsync` listeners now receive them.** The changes are additive (`userId` everywhere, the row as `theme`, and so on). An async listener on a `style.*` hook that never ran before will start running.
8. **Some saved themes show a one-off chart delta.** Configs with an accent theme and a chart colour equal to the base colour now resolve shadcn's base-tone charts. Their saved `cssVars` still hold the accent's charts, so `chart-1` to `chart-5` show as a custom delta, and the next palette change asks you to keep, rebase or discard. The live app keeps the saved charts until then.
9. **`--radius` is always written.** A theme with radius "Default" now sets `--radius: 0.625rem`, which overrides a different radius in the host's own `globals.css`. The starter uses `0.625rem`, so a starter app looks the same.
10. **If you call the module's API or service directly:** `setActiveAppTheme` now takes the acting user's id; activating your own theme from another project, or one with no project, answers `400`; and activating a system theme returns your project-config copy, whose id differs from the theme id.

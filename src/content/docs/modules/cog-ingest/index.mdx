The **Cog Ingest** module provides an admin-configurable content ingestion system powered by the [cognitive-db](https://github.com/ui-git-kim/cognitive-db) intelligence engine. You install one module (`npx cognitive-ingest init`) and get the full cognitive stack — perception, entity extraction, connection discovery, and ontology management.

Admins configure **ingest sources** (e.g. "Court Document", "Research Paper") with processing levels and extraction rules. Users submit content through the ingest UI — text, URLs, images, PDFs, Office documents, and audio/video recordings — and the cognitive-db engine extracts entities, discovers connections, raises questions, and grows the knowledge graph. Results are stored as jobs with full history and stats.

<Aside type="tip" title="One module, full stack">
cognitive-db is bundled as a dependency, not installed separately. The module's schema includes the six engine tables (`cog_node`, `cog_working_memory_event`, `cog_processing_log`, plus the engine-v2 `cog_intelligence_log`, `cog_intelligence_discovery`, and `cog_intelligence_event` — inert until the Structure-native storage flag flips) alongside the module tables. Model access is delegated to the [AI Core](/modules/ai-core/) module (a hard dependency); init only asks for the embedding width and default processing level.
</Aside>

## Quick Install

```bash
npx cognitive-ingest init
```

The CLI walks you through provider selection (LLM, embeddings), creates database tables, generates frontend and backend code, and installs shadcn components.

### Full Feature List

- Content ingestion powered by cognitive-db intelligence engine
- Six content types: text, URL, image (vision model), PDF, Office documents (DOCX/XLSX/PPTX), audio/video recordings (transcribed via Docling ASR)
- Admin-configurable ingest sources with processing levels (minimal, standard, deep)
- Per-source configuration — context fields, extraction focus, prompt overrides, auto-tags
- Dynamic context fields on the ingest form driven by source configuration
- Entity extraction, connection discovery, and ontology growth
- Structure module integration — tabs and widgets on node detail pages
- Source-to-node-type mapping with custom extraction rules
- RSS/Atom feed polling with automatic ingestion and per-entry review
- Ingest job history with detailed processing results
- Dashboard widget showing processing activity
- User preferences for default processing behaviour
- Settings page for ingestion configuration
- Batch ingestion support
- Extensible preprocessor registry for content transformation
- Filter and action hooks for pipeline customisation
- Working memory — seeded `working-memory` Structure node type with a namespaced `workingMemory` service and `cog-ingest.working-memory.*` filter/action hooks for per-user or per-session focus sets (backend-only; nodes render via the generic Structure node UI)

## Architecture

```
┌─────────────────────────────────────────────────┐
│                  Frontend                        │
│                                                  │
│  Ingest Page ──► API Service ──► Backend Routes  │
│  Admin Page       ▲                   │          │
│  Dashboard Widget │                   ▼          │
│  Node Tab/Widget  │          Ingest Service       │
│                   │            │         │        │
│                   │    Preprocessors    Filters   │
│                   │            │                  │
│                   │            ▼                  │
│                   │      cognitive-db             │
│                   │       (bundled)               │
│                   │            │                  │
│                   │            ▼                  │
│                   │   AI Core (all model calls)   │
│                   │     (Anthropic/OpenAI/Voyage) │
│                   │            │                  │
│                   │            ▼                  │
│                   │    Prisma (cog_* tables)      │
│                   └────────────┘                  │
└─────────────────────────────────────────────────┘
```

The ingest pipeline flows: **Content → Preprocessors → Filters (before) → cognitive-db → Filters (after) → Job Record**. Other modules can hook into any stage via the filter and action registries. **All** model access — the module's own (embeddings, vision, parse-QA) *and* the vendored cognitive-db engine's (perception, extraction, node embeddings) — routes through the **[AI Core](/modules/ai-core/)** module, which owns model choice, prompts, the provider SDKs, and the usage ledger. cog-ingest makes no direct provider calls (v1.21.9).

## Prerequisites

| Requirement | Details |
|-------------|---------|
| **Structure module** | Must be installed first (`depends: { structure: '>=1.16.0' }`) |
| **AI Core module** | Hard dependency (`depends: { 'ai-core': '>=1.15.0' }`) — owns all model access. Enable a language model + a matching-width embedding model, and configure the engine's `cognitive-db/*` operations in its admin |
| **PostgreSQL with pgvector** | Required for semantic search embeddings |

## What Gets Installed

When you run `npx cognitive-ingest init`, the module generates:

**Frontend** (in `frontend/src/features/cog-ingest/`):
- 4 pages — main ingest, job detail, settings, admin
- 5 components — dashboard widget, node tab, node widget, preferences, source config dialog
- 5 hook files — ingest operations, source CRUD, job queries, engine config, RSS feeds
- 1 service file — API client
- 7 registration files — navigation, dashboard, settings, admin, preferences, structure tab, structure widget

**Backend** (in `backend/src/features/cog-ingest/`):
- Service files — routes, service, types, processors, config — plus docling (sidecar client), structure-adapter (engine-v2 storage), ai (AI Core seam), rss (feed polling), and working-memory
- 8 registration files — route, service, jobs, action, filter, module, security, context-schema — plus the preprocessors registry

**Database** — 11 Prisma models (6 engine + 5 module; the three `cog_intelligence_*` engine-v2 tables are inert until Structure-native storage is enabled)

See [Configuration](/modules/cog-ingest/configuration/) for environment variables and init prompts, or [Usage](/modules/cog-ingest/usage/) for a walkthrough of the features.

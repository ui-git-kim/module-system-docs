<Aside type="caution" title="The Pickers module was retired">
There is no standalone **Pickers** module — it was never shipped as one. Its capabilities now live in the foundation and in dedicated modules:

- **Icon selection** — the starter template's [Icon Picker](/starter-template/icon-picker/) (`@/components/icon-picker`: `IconPicker`, `IconPickerDialog`, and the headless `useIconPicker` / `IconPickerGrid` / `IconRenderer` primitives).
- **Colour selection & palettes** — the [Colour Palette](/colour-palette/) and [Style](/modules/style/) modules.

Please update any bookmarks or links accordingly.
</Aside>

## Repository updates

The old `pickers` repository is kept and still gets the module-wide template fixes. This doesn't bring the module back; it only keeps the code in line with the other modules.

### v1.2.4 — 2026-10-01

- **Faster first load:** the admin page it generates now loads only when someone opens it. Its registration file imported the page directly, and the module's barrel runs that file when the app starts, so the page (and everything it imports) was in every visitor's first download, signed in or not. It now registers through `React.lazy`, so the page is its own chunk. The barrel gains a comment saying why it never re-exports pages. Found by the starter's 2026-09-30 performance audit; same fix as [module starter scaffold v1.31.20](/module-starter/changelog/#scaffold-v13120). No host change needed (the host already shows admin pages inside a loading boundary).

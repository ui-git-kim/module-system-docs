## The win

"The win" (the owner's word for a task's output). In the task editor, under **The win**:

- **What done looks like**: a few words ("the form in the post", "the washing in").
- **Why it matters**: a few words, for the days it's hard to start.

Both are optional and never asked for when adding a task. Bite sized reads them when it asks AI Core for a task's pieces. They're real Structure fields Tasks supplies, so they show on the task's page in Structure too.

---

## The debrief

Marking a task done stays one tap. After it, a debrief is **offered, never required**: **Debrief** sits beside Today's quiet "Done" line, and a done task's editor has a **Debrief** section. The headings are the owner's own ("review, reflect, adjust (i quite like these terms)"):

| Heading | Prompts (the admin's, these to start) |
|---|---|
| **Review** | What happened? What went well? |
| **Reflect** | What was hard? How did I feel? Why did it matter? |
| **Adjust** | What would I change next time? What's next? |

- Each heading has one answer, saved as it's written, kept as a field on the task (Review, Reflect and Adjust on its page in Structure).
- **What's next?** adds a task of the same type, filed where this one is, that comes after it.
- Nothing is scored, counted or compared: the debrief asks what happened, never whether it went well enough.

---

## Setting it up (an admin)

- **Admin › Tasks › Prompts › Debrief**: **Offer a debrief after done** (on unless switched off), and the prompts under each heading, one a line, up to six each.
- **Admin › Tasks › Entry types**, a type's **Edit** › Tasks: **The win** and **Debrief**, each on unless switched off. Switched off, the fields stay on the type as its own, with their values.

<Aside type="note" title="Kept in the configuration export">
The debrief's settings travel with the rest of Admin › Tasks in the Data tab's export and import.
</Aside>

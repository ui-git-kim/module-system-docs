**Proposed** (2026-11-28), for the owner to approve. Nothing is built. The owner asked for it while settling the [Modes and Views Plan](/modules/tasks/modes-plan/): several named checklists in one task, "Yes, add it", as a plan of its own. The rule for every choice in it (the owner): "Nothing should be hardcoded in, if it requires a judgment call, then it becomes an admin config."

<Aside type="note" title="Where it comes from">
The owner's ClickUp, used for a photo booth business: one setup task held several named checklists (Top Booth, Bottom Booth, Road Case, Loose), with the done items folded away. What the owner wanted to leave behind: "0 of 11", "33 open", progress bars and percentages, "as you can see it's overwhelming".
</Aside>

---

## What's there now

- **One checklist per task** (v1.13.0; **Add a checklist** since v1.22.62): a few words and a tick each, up to 50, kept on the task in Tasks' own data (`tasks.steps`), since Structure has no checklist field.
- **Next: …** under the task wherever it shows: its first item not ticked.
- **Make it a task of its own** turns an item into a subtask.
- The **Checklist** widget for a type's page, Bite sized (which sends the checklist to AI Core with the task's own words), and an admin's switch per type.
- Not yet: changing an item's words, or moving items.

---

## The shape

- **A task can hold several checklists, each with a name** ("Top Booth", "Road Case"). A task's one checklist today is its first list, with no name, and reads exactly as now: nothing is copied or changed.
- **Items stay where they are kept now.** Each item can say which list it's in; the task keeps its lists' names and order beside them. One read and one write, as now.
- **Done items fold away** under a quiet **Done** in each list, opened with a tap, never with a number on it.
- **Never a count**: no "3 of 11", no "8 left", no bar or percentage, on the list, the task, Today or the widget.

---

## How it works for the person

In the task editor, under **How it gets done**:

- **Add a checklist** asks for a name (it can be left blank for the first one). Each list shows its name, its items not ticked, and **Done** folded.
- Type an item and press Enter, as now. Tick it, and it folds into Done.
- **Rename** and **Remove** on a list. Removing a list with items asks first, and its items go with it.
- **Make it a task of its own** on any item, as now.

Elsewhere:

- **Next: …** stays one line: the first item not ticked, in the lists' order, with its list's name where the task has more than one list ("Next: Pack the props (Road Case)").
- **The Checklist widget** shows each list with its name, done items folded.
- **Bite sized** sends each list with its name ("Road Case: pack the props, strap the lid"), so suggested pieces can follow the lists.

---

## Settings an admin chooses

In **Admin › Tasks › Entry types**, under a type's **Tasks** (beside the **Checklist** switch there now):

| Setting | Choices | Unless changed |
|---|---|---|
| **Several checklists** | On or off | On (off keeps one checklist, as now) |
| **Done items** | Fold away under Done, or stay in place ticked | Fold away |
| **A regular task's lists, when it's done for the day** | Untick them for next time, or leave them | Leave them (as now) |

## Releases (proposed)

| Release | Adds |
|---|---|
| **CL1 — Named lists** | Several named checklists per task, Done folded, rename and remove, the Next line, the widget, Bite sized reading the names, the admin's settings. Every existing checklist carries over as the first, unnamed list. |
| **CL2 — Changing items** | Change an item's words, move items within a list or into another, and put the lists in another order. |
| **CL3 — Ready-made lists** (only if wanted) | An admin keeps named lists to add to any task in one go ("Setup": Top Booth, Bottom Booth, Road Case, Loose). |

## Questions to settle first

1. **The shape:** several named checklists in one task, built on the one it already keeps, so nothing existing changes. *Proposed: yes.*
2. **Done items:** folded under a quiet **Done** in each list, as an admin's setting (fold away unless changed). *Proposed: yes.*
3. **The Next line:** one line, the first item not ticked across the lists in order, naming its list only when the task has more than one. *Proposed: yes.*
4. **How many:** up to ten lists in a task and fifty items in a list (fifty in all today). *Proposed: yes.*
5. **Regular tasks:** a regular task's lists unticked when it's done for the day, as an admin's setting (leave them unless changed). Useful for a setup list used every time. *Proposed: yes, as a setting.*
6. **Ready-made lists (CL3):** an admin's lists to add to a task in one go. Wanted, or is copying from another task enough? *Proposed: ask after CL1.*

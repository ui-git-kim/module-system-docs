This page is a **proposed** plan. The owner set out the ideas on 2026-11-20, with reference images (a book page on input, process, output and outcome, and planner-pad sheets on waiting-on lists, decision logs, weighing tasks and checking in). **Nothing on this page is built.** It waits for the owner's answers to the [questions](#questions-to-settle) and an approval.

The owner's starting point: "we need bite sized jobs we can do", and every task has an **input** (what's needed), a **process** (how it gets done), an **output** ("what the user is wanting to achieve, and why") and an **outcome** (marking it done, what's next, and a debrief).

<Aside type="note" title="How this fits what's built">
Since v1.22.60 a kind switched on for tasks gets Tasks' fields as real Structure fields (Size, Essential, Due, Happened on, Done on). Everything new here would arrive the same way: fields Tasks supplies to each task kind, which an admin can lay out on the kind's Fields tab, switch off per kind, or point at a field of the kind's own instead (decision [TASK-022](/modules/tasks/decisions/#task-022--today-suggests-tasks-and-reads-dials)). Which kinds of entry are tasks stays the admin's choice in Structure and Entry types, so there is no separate "category" or "task type" field.
</Aside>

## What's already there

| The owner asked for | What Tasks has now | What's missing |
|---|---|---|
| Subtasks | A task filed under a task, wherever Structure's hierarchy lets a kind sit under itself (v1.13.0). Subtasks are ordinary tasks on Today, All tasks and the Board. | Tasks' own seeded type holds none until an admin clears "Maximum children per node" in Structure. Today also suggests the whole task beside its pieces. There's no **Break it down** button. |
| Bite-sized pieces | The **Checklist** ("What's the first small thing?") on a task, shown as "Next: …". A checklist item can be made a subtask. | Checklist items never reach Today. |
| Waiting | A stage meaning, **Waiting** ("Today won't suggest these"), in the starter templates. | Who or what it's waiting on, when it was asked, when to check back, and a Waiting list. |
| How long, how hard, how firm | **Size** (Light, Medium, Big) and **Essential** (on or off). The capacity plan's dials for size, energy, firmness and essential were decided on 2026-11-16 (TASK-022) and are not built. "Firmness" waited for a better word. | Words for each measure, and a measure of how hard a task feels for the person. |
| Repeating tasks | Repeats on calendars (C2): one entry with a rule. | Today knows nothing about a task that comes round each day or week. |
| Follow-ups that make tasks | A journey's if-step can add a follow-up task. | Follow-ups from a decision. |
| A who field | Schedules have one. | Who a task is for. |
| A check-in | Your own check-in (feelings and how each felt, which set the kind of day) and check-ins about other people (v1.22.60). | Mood, energy and mind on a scale, and what you need most. |

## A task in four parts

The book's idea of focusing on the output (the finish line) rather than the outcome you can't control fits Tasks' no-guilt rules well: Tasks asks what *done* looks like, never whether it went well enough.

| Part | The owner's word | Proposed name on screen | What it holds |
|---|---|---|---|
| Input | "What's needed" | **What it needs** | Tasks that come first, things I need (resources), decisions to make, and what it's waiting on |
| Process | "Process" | **How it gets done** | Its rhythm (once, regular, or comes next), its pieces (Break it down), its checklist, and its journey |
| Output | "we need a more fun term" | **Finish line** | What done looks like, and **why it matters** |
| Outcome | "outcome or debrief" | **Debrief** | Marking it done, what's next, and review, reflect, adjust |

On the task's page in Structure, an admin lays these out like any other fields. In Tasks' own task editor they show as four sections, closed unless they hold something, so a task with just a name stays as light as it is today. Each part can be switched off per kind in Entry types.

**Other names for the finish line:** "The win", "Done looks like", "The point". The book itself says "define your finish line".

---

## What it needs (input)

- **Comes after**: the tasks this one waits for (a link to tasks). Until they're done, it waits quietly: Today doesn't suggest it, and the task it waits for shows "Then: …" under it. When they're done, it joins the pool by itself. This is the owner's "flow task" (a task that flows on from another one), so it is also the third rhythm under [How it gets done](#how-it-gets-done-process).
- **Things I need**: resources, as a short list of words ("the car", "Sam's birth certificate").
- **Decisions to make**: links to [decisions](#decisions) not made yet, or a few words.
- **Waiting on**: see [The Waiting list](#the-waiting-list).

## How it gets done (process)

### Its rhythm

| Rhythm | What it means | How it works |
|---|---|---|
| **Once** | The usual | As now |
| **Regular** | Comes round each day, week or chosen days ("a daily task that needs to be done") | The repeat rule calendars already use, on the task. Today shows it on its days, and ticking it done marks that day without making a new entry each time. A release of its own (see [Releases](#releases)). |
| **Comes next** | Flows on from another task | **Comes after** (above) |

### Break it down

A **Break it down** button on a task: in the task editor, on its row on Today and in lists, and in the task's page header.

1. It asks for the pieces one at a time ("What's the first small thing?", then "And then?"), the way the checklist does, each sized **Quick** unless changed.
2. Each piece becomes a **subtask**: a task of its own filed under this one, so it goes into the pool for Today and planning the day.
3. While a task has pieces still open, Today suggests the pieces, not the whole task (an admin setting, on unless switched off).
4. When the last piece is done, Tasks asks quietly whether the whole task is done too.

Where the kind can't hold subtasks, Break it down says exactly what to change on its Hierarchy tab in Structure (Tasks never changes a type's hierarchy itself), and offers to keep the pieces as a checklist for now. AI chat could later suggest pieces, but Tasks only takes what the person keeps (decision TASK-021).

### Its journey

A task a journey made already shows its journey. Nothing new here.

## Finish line (output)

- **What done looks like**: a few words ("the form posted", "the washing in").
- **Why it matters**: a few words, for the days it's hard to start.

Both are optional and never asked for when adding a task.

## Debrief (outcome)

Marking a task done stays one tap. After it, an optional **Debrief** is offered, never required, with the owner's three words as its headings:

| Heading | Prompts (an admin's list, these to start) |
|---|---|
| **Review** | What happened? What went well? |
| **Reflect** | What was hard? How did I feel? Why did it matter? |
| **Adjust** | What would I change next time? What's next? |

- An admin keeps the prompt list, as with the check-in's feelings, and chooses which kinds offer a debrief.
- The answers are kept as fields on the task, so they show on its page and in Structure's lists.
- **What's next** offers to add it as a task that comes after this one.

## The measures, in words

Every measure is a field Tasks supplies, shown as words and never as a score. An admin keeps each list of words (these are Tasks' starting words), and Today's rules can test any of them.

| The owner's idea | Proposed name | Starting words | Notes |
|---|---|---|---|
| "weight", and how much they "should" be doing it | **How firm** | Fixed · Important · Flexible · Optional | One measure for both ideas. Fixed covers "commitments that cannot move". This is the firmness dial of TASK-022, so it would also settle the word that was waiting. "Must finish" and "Priority" can't be used: Tasks' no-guilt rules keep "must" and "priority" out of every screen. |
| "important, maintenance, future" and "move forward, maintain" | **What it's for** (optional, a second measure) | Moves things forward · Keeps things steady · Someday | Only if the owner wants two measures; see [Questions](#questions-to-settle). |
| How hard it is for the person | **How hard it feels** | Easy · A bit of a push · Hard to start · Really hard | About the person, not the task: hanging out washing can be really hard while a complicated project is easy. |
| How long, "not in a how many mins type thing" | **Size**, kept, with time words | Quick · A sitting · A few sittings | The stored values (light, medium, big) stay, so every task keeps its size and Today's rules keep working. Only the words change. |
| No deadline | **Time sensitive** (on or off) | | Off: the task has no date that matters and shows **When it suits** instead. On: its due date shows as now. |
| A preferred time | **When it suits** (choose any) | Morning · Afternoon · Evening · Late at night · Any time | "After I've done this" is **Comes after**. Today can lean towards what suits the time you check in. |
| Who it's for | **Who it's for** | A link to an entry | A client, a child, you, or the court: whichever kinds the admin picks, never decided by a kind's name. |
| Travel | **Travel** | Needed (on or off), **Where** (words, or a link to a place entry), **Travel time** (A short trip · About an hour · Half a day · All day) | Later, capacity can count travel time on a day. |
| Reminders | **Remind me** | How (in the app, a notification, a text message later) and when | Waits for Notifications in the starter; the in-app prompts already exist. A later release. |

**Essential:** today's on-or-off switch would be read from How firm (Fixed and Important count as essential on a hard day), so nothing has to be set twice. Tasks that already have Essential on would read as Important.

## Statuses

The owner likes **Active, Waiting, Scheduled, Completed** as the top-level statuses. Stages stay the admin's own, so this becomes a **starter template** an admin can apply, as Now, Next, Later is. Each stage needs a meaning:

| Stage | Meaning | Today |
|---|---|---|
| Active | Doing (or Not started) | Suggested |
| Waiting | Waiting | Not suggested |
| Scheduled | **New: Scheduled** (it has its time) | Not suggested before its day; on its day it shows as fixed |
| Completed | Done | Shown on the done list |
| No longer needed | No longer needed | Not shown |

"Scheduled" has no meaning yet. The other choice is to leave it out of stages and show "Scheduled" wherever a task has a date and time. See [Questions](#questions-to-settle).

## The Waiting list

From the owner's waiting-on sheet:

- **Waiting on** on a task: **Who** (a link to an entry, or words), **What for**, **Asked on** (a date) and **Check back** (a date).
- Moving a task to a stage that means Waiting asks "Who or what is it waiting on?", and nothing has to be filled in.
- A **Waiting** page in Tasks, beside Today and All tasks: a row per task with Who, What for, Asked on and Check back, in check-back order.
- On the check-back day, one quiet prompt naming what it's for ("Check in about the repair quote?").

Calm rules: no "follow up now", no red, and a check-back day that has gone is just a date. Nothing on the page counts anything.

## Decisions

The owner: "i think decisions might need to be their own node type".

- **A Decision kind in Structure**, made by the admin with the sheet's fields: Decision, Reason, Date and People. Pros and cons are Structure's own fields (two lists, or a field group), so they need nothing from Tasks.
- **A decision log on a task**: the decisions filed under it, or linked to it, listed in a section on the task.
- **Follow-ups make tasks**: Tasks supplies **Follow up** fields to the decision kind (what, and when: in so many days or weeks). Saving one makes a task dated then, filed under the decision's task, the way a journey's follow-ups are made.
- **Decisions to make** (in What it needs) lists the decisions not made yet. This also covers the "decide or do" sheet: a task waiting on a decision can say so.

## The check-in

Your own check-in would borrow from the "How am I, really?" sheet, beside the feelings an admin keeps (v1.22.59):

- **Mood**: Heavy to Light, five steps in words.
- **Energy**: Empty to Full (the same words check-ins about people already use).
- **Mind**: Scattered to Clear.
- **What I need most**: Rest · Space · Connection · Comfort · Clarity · Action.
- **"I don't know what I need"** opens the helper from the "needs check" sheet: I'm exhausted → Rest, I feel stuck → Clarity, I feel alone → Connection, I feel overwhelmed → Space, I feel hurt → Comfort, I keep avoiding something → Action.

Each question is optional and an admin's setting, like the feelings list. Today's rules could test them ("when I need Rest, suggest only Quick and Easy"). The kind of day still comes from the feelings. This belongs with SR2 of the [Suggest and Capacity Rules Plan](/modules/tasks/rules-plan/) (the check-in configured). A check-in stays the person's own private record.

## Ideas kept for later

- **Task migration** (Reschedule · Simplify · Hand off · Remove): a calm weekly tidy for tasks that keep sitting, beside "Not now".
- **Review, reflect, adjust for the week**, using the same words as the debrief. The reference sheet counts tasks and percentages, which Tasks never does, so only its words and questions carry over.

## Questions to settle

1. **The finish line's name.** Finish line, The win, Done looks like, or another? *Proposed: Finish line.*
2. **One measure or two for weight?** How firm (Fixed · Important · Flexible · Optional) alone, or also What it's for (Moves things forward · Keeps things steady · Someday)? *Proposed: How firm alone to start, which also settles TASK-022's firmness word.*
3. **Size as time.** Should Size become how long (Quick · A sitting · A few sittings), with How hard it feels as a separate measure? *Proposed: yes.*
4. **Pieces on Today.** While a task has open pieces, should Today suggest only the pieces? *Proposed: yes, as an admin setting that's on unless switched off.*
5. **Subtasks for Tasks' own type.** A fresh app's own task type holds no subtasks. Should a fresh app's seeded type allow them? Existing apps would still change it in Structure. *Proposed: yes.*
6. **"Scheduled".** A new stage meaning (not suggested before its day, fixed on it), or just a label for tasks with a date and time? *Proposed: a new meaning, in the starter template only.*
7. **Essential.** Read Essential from How firm (Fixed and Important count), or keep both? *Proposed: read it from How firm.*
8. **Waiting on.** One per task, or several? *Proposed: one per task to start.*
9. **Debrief answers.** Kept as fields on the task, or as a debrief entry filed under it? *Proposed: fields on the task.*
10. **Decisions.** A Decision kind the admin makes in Structure, with Tasks supplying its follow-up fields? *Proposed: yes.*

The **Tasks** module is a task manager built to work with an ADHD mind. It isn't a project-management suite: the point is how it feels to use. Every screen should feel achievable, not like a wall of obligations.

You can capture a thought in a few words without committing to it. An optional "How are you today?" check-in sets the kind of day — **survival**, **steady** or **full-energy** — and the Today view then suggests **three tasks at a time** sized to that day. A done list counts what actually got done, including things you never planned. List, board and timeline views are there when you want to see more.

<Aside type="note" title="Built on Structure">
Every task is a **Structure entry** of a seeded `task` type, and its status is a Structure **stage**. So tasks can sit under any Structure entry that can hold them (a project, say), stages are edited in Structure's own type settings, and tasks travel with Structure's account deletion and data export. Tasks itself only stores your settings and your check-in history.
</Aside>

## Quick Install

Structure must be installed first.

```bash
npx tasks init
```

This generates the frontend feature (`frontend/src/features/tasks/`), the backend feature (`backend/src/features/tasks/`) and two database tables, wires the routes, and installs the shadcn primitives the screens use. The first time the backend starts, Tasks creates the `task` and `task-category` types in Structure.

### Full Feature List

- **Capture** — header quick capture and an inline field on every Tasks page; a quiet "Captured. You can tackle this when you have capacity."
- **Check-in** — Energetic, Calm, Joyful, Angry, Tired, Anxious, with optional sub-feelings. Your feeling-to-day-type map is editable in settings, including fine-tuning by sub-feeling.
- **Today** — survival days show essentials only (lightest first), steady days light and medium tasks, full-energy days anything (biggest first); nearest due date first within those. "Not now" hides a task for the rest of the day.
- **Done** — everything that reached a Done stage today, and unplanned things logged straight into Done (with an optional back-date).
- **All tasks** — everything in one place, filterable by what's not done, what needs a size, stage, category and the entry tasks sit under.
- **Board** — one column per stage; drag a card (or use its menu) to change its stage.
- **Timeline** — a chronology of what happened and what got done, optionally with what's coming up, filtered by dates, category and parent entry.
- **Tasks tab on Structure entries** — the tasks under a project (or anything that can hold tasks), with "Add task".
- **Dashboard widget** — today's three and how many things are done today. Never a "remaining" count.
- **Categories** — your own list, seeded with Personal, Business, Home and Study, kept as Structure entries.

**No-guilt rules apply everywhere:** no overdue badges and no red for anything late (a past due date is shown as a plain date), no "X remaining" counts, no percentages, no streaks.

## Architecture

```
            ┌──────────────────────── Tasks (frontend) ─────────────────────────┐
            │ Today · Done · All tasks · Board · Timeline · Settings · Widget   │
            │ Quick capture (header) · Tasks tab + fields on Structure entries  │
            └───────────────────────────────┬───────────────────────────────────┘
                                            │ /api/v1/tasks
            ┌───────────────────────────────▼───────────────────────────────────┐
            │ Tasks (backend): rules for Today, check-in, done_at, validation   │
            │ tasks_settings · tasks_checkin                                    │
            └───────────────────────────────┬───────────────────────────────────┘
                                            │ serviceRegistry('structure')
            ┌───────────────────────────────▼───────────────────────────────────┐
            │ Structure: 'task' and 'task-category' entries, stages, fields     │
            └───────────────────────────────────────────────────────────────────┘
```

The module integrates with the host entirely through registries — no core files are modified:

| Registry | What Tasks registers |
|----------|----------------------|
| `navigationRegistry` | A **Tasks** sidebar section: Today, Done, All tasks, Board, Timeline |
| `headerToolbarRegistry` | Quick capture (`tasks-quick-capture`) |
| `dashboardRegistry` | The Today widget (`tasks-today`) |
| `settingsPagesRegistry` | `/settings/tasks` — check-in, feelings and kinds of day, categories |
| `adminPagesRegistry` | `/admin/tasks` — export or import settings and check-ins |
| `routeRegistry` | `/api/v1/tasks` |
| `serviceRegistry` | `tasks` — create and list tasks from other modules |
| `securityRegistry` | Manifest, deletion handler and export handler for the two tables |
| `actionRegistry` | Fires `tasks.*` actions; listens to `structure.node.stageChanged` and `structure.node.created` |
| `filterRegistry` | Applies `tasks.dayTypeRules`, so an app can retune Today's rules |
| `moduleRegistry` | Runtime registration (guarded import); its `init` seeds the node types |
| Structure: `structureRegistry` | The `tasks.*` fields on the `task` type |
| Structure: `nodeTabRegistry` | The **Tasks** tab on entries that can hold tasks |
| Structure: `nodeActionRegistry` | "Add task" for the entry page header (shown once Structure renders that spot) |
| Structure: `nodeCardExtensionRegistry`, `nodeColumnRegistry`, `nodeFilterRegistry` | Size badge, Size/Category/Due columns and Size/Category filters in Structure's own task lists |

## What Gets Installed

**Frontend** (in `frontend/src/features/tasks/`): routes for `/tasks/today`, `/tasks/done`, `/tasks/all`, `/tasks/board` and `/tasks/timeline` (`/tasks` opens Today), the registrations above, data hooks, and the components behind each screen.

**Backend** (in `backend/src/features/tasks/`): the routes, the service, the Today rules (`tasks.defaults.ts`, `tasks.suggest.ts`), the Structure bridge (`tasks.structure.ts`) and the registrations.

**Database** — `tasks_settings` (one row per person) and `tasks_checkin` (one row per person per day). Self-contained: no `@relation` directives, no edits to the `User` model. Tasks and categories are stored in Structure.

**In Structure** — an app-level `task` type with the stages Inbox, To do, Doing and Done (in the groups `open`, `active` and `done`), and a `task-category` type. Both can be edited by an admin in Structure afterwards.

**Dependencies** — none new. The board's drag-and-drop uses `@dnd-kit/core`, which the starter already ships.

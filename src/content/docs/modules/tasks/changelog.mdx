## v1.1.2 — 2026-10-28

**The first Tasks release: capture without committing, an optional check-in, three suggestions sized to the day, a done list, and list, board and timeline views — built on Structure.**

**Added**
- **Tasks are Structure entries (decision TM-003).** The backend seeds an app-level `task` type with the stages Inbox, To do, Doing and Done (groups `open`, `active`, `done`) and a `task-category` type, the first time it starts. Task details are `tasks.*` fields: `size` (light / medium / big), `essential`, `category`, `due_on`, `happened_on`, `done_at` and `not_now_until`. Nothing matches a stage by name: "is done" means "in the `done` group".
- **Capture.** Quick capture in the header and an inline field on Today, All tasks and the node Tasks tab. A few words is all it needs; new tasks go to the Inbox. "Captured. You can tackle this when you have capacity."
- **Check-in.** "How are you today?" the first time Today opens each day: Energetic, Calm, Joyful, Angry, Tired or Anxious, with optional sub-feelings. The feeling suggests a survival, steady or full-energy day, which is one tap to change. Skipping is recorded, so Today doesn't ask again that day. The map from feelings to kinds of day is a setting, including optional fine-tuning by sub-feeling.
- **Today.** Three suggestions at a time by simple, config-driven rules: survival days show essentials only, lightest first; steady days light and medium tasks; full-energy days anything, biggest first; nearest due date first within those. A task you've started stays in view. **Doing it**, **Not now** (hidden for the rest of the day) and **Done** (a quiet "Done: …" with Undo), then "Show me the next three". Tasks without a size are never suggested.
- **Done.** What reached a Done stage today, plus "Add something I did", which logs straight into Done with an optional back-date.
- **All tasks**, **Board** and **Timeline.** All tasks is filterable by view (not done, needs a size, done, everything), stage, category and parent entry, a page at a time with no totals. The Board has one column per stage, and dragging a card (or its "Move to" menu) changes its stage. The Timeline shows what happened (`happened_on`, or `done_at` when that's empty) and, optionally, what's coming up, filtered by dates, category and parent entry. Entries can be added straight to it.
- **On Structure entries.** A **Tasks** tab on any entry that can hold tasks, with "Add task", and an "Add task" node action for the entry page (dormant until Structure renders it). On Structure's own task lists: a size badge, Size / Category / Due columns, and Size / Category filters.
- **Dashboard, settings and admin.** A Today widget (today's three and the done-today count, never a remaining count); `/settings/tasks` for the check-in, the feeling map and categories; `/admin/tasks` to export or import settings and check-ins.
- **Categories.** Per-person `task-category` entries, seeded with Personal, Business, Home and Study once. Removing one clears it from the tasks that used it.
- **For other modules.** A `tasks` service (`createTask`, `listTasks`, `listNodeTasks` and the rest), `tasks.*` actions after every write (including tasks completed in Structure's own screens), and the `tasks.dayTypeRules` filter (sync and async filters both run).
- **Security.** A manifest, deletion handler and personal-data export handler for `tasks_settings` and `tasks_checkin`. Task and category entries are erased and exported by Structure's own handlers.

**Decided against**
- **A Tasks table for tasks.** Tasks are Structure entries, so hierarchy, stages, deletion and export come from Structure (TM-003).
- **Toasts.** The host mounts no toast area; feedback is inline and quiet.
- **A drag-and-drop library.** The starter already ships `@dnd-kit/core`.

**Upgrade notes**
- Structure **v1.39.0** or later is required (`depends: { structure: '^1.39.0' }`), which needs starter v2.13.0 or later.

Verified: `check:templates`, `conformance:check`, `type-check` and the build pass; 22 runtime tests pass (`npm test`, PGlite with an in-memory Structure); the generated frontend and backend type-check clean inside a host built from a real app with Structure 1.39 rendered in; the starter's styling audit passes on all 38 generated frontend files. A five-part adversarial review (contracts, spec and tone, conventions, robustness, frontend behaviour) confirmed 44 findings before release, all fixed or recorded as decisions — among them a check-in panel that closed on the first tap, a title edit lost when the editor closed with Escape, views that dropped the newest tasks at their caps, tasks stranded by a stage rename, a capture field that swallowed the next keystrokes, and a page left open overnight keeping yesterday's date. Not yet installed into a starter app with `npx tasks init` — see the [Roadmap](/modules/tasks/roadmap/).

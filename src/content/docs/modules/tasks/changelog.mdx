Current version: **v1.22.96** (2026-11-28).

<Aside type="note">
Versions bump with every template or `module.ts` change — that's how `npx tasks update` detects there is something to apply. Patch releases may therefore be small. ## v1.22.96 — 2026-11-28

**"Type", not "kind"** (the owner: "i think we can keep entry = node, but change kind to type").

**Changed**
- Tasks' screens and the messages people see now say **type** where they said **kind** for a Structure node type, as Structure's own screens do: **Entry type**, **Task types**, **Event type**, **Add a type**, "There's no entry type called …", and so on. **Entry** stays for a node.
- A **kind of schedule** is now a **schedule type** (Admin › Tasks › Schedules & journeys › Schedules: **New schedule type**, "No schedule types yet").
- Left as they were: **kind of day** (Survival, Steady, Full-energy), which is a different thing, and Structure's own **Type kind** (Task, Profile).
- The guides say the same. The Changelog, Design Decisions and the plans written before today keep the words used at the time.

**For developers**
- Wording only: no behaviour, route, setting or stored value changes. Names inside the code (`kinds`, `TaskKind`, `kindsFor`) stay. No schema change. Run `npx tasks update`.

## v1.22.95 — 2026-11-28

**A switch for each of the Tasks page's views** (the owner: "we need a switch for each one, that turns on a ... global type view on the tasks main page").

**Added**
- **Admin › Tasks › Views** now lists **Calendars**, **Timelines**, **Schedules** and **Boards** (then Now, Next, Later), and each of those four starts with its switch: **Calendar on the Tasks page**, **Timelines on the Tasks page**, **Schedules on the Tasks page** and **Board on the Tasks page**. Switched off, the view leaves the view switcher at the top of every Tasks page and the sidebar's Tasks section. Each is on unless an admin switches it off, so nothing changes until someone does.
- The switches only decide what the Tasks page offers. Calendars, timelines and schedules on entries' pages (tabs and widgets) stay as they are, and a link to a switched-off view still opens it.
- **Views › Schedules** holds its switch and a way to **Kinds of schedule**, which are still set up under **Schedules & journeys**.

**Changed**
- **Views** opens on Calendars (it opened on Now, Next, Later).
- **Views with their own link** (General › Sidebar) lists only the views the Tasks page offers. A view switched off keeps its place in the section, ready for when it's back on; if every view with a link is switched off, the sidebar shows one Tasks link.
- An old link to `?tab=views&list=schedules` (from before v1.22.49) now opens Views › Schedules, which links to the set-ups.

**For developers**
- `tasks_config.settings.views.onPage` `{ calendar, timeline, schedules, board }` (each on unless `false`), returned as `config.views.onPage` and carried in the configuration export's settings (a file from before leaves the switches as they are). A save of `views` changes only what it names (`withViewChanges`), so Now, Next, Later and the switches never overwrite each other. `PAGE_VIEWS` (backend defaults and the screens' catalogue) lists the views that have a switch; `isOfferedView` and `offeredNavigation` apply it.
- No schema change. Run `npx tasks update`.

## v1.22.93 — 2026-11-26

**Lighter to keep running** (the [2026-11-26 resource audit](/modules/tasks/roadmap/#resource-audit-2026-11-26): batches R1, R2 and R3). Nothing here changes what anyone sees.

**Changed**
- A journey that's going keeps its steps and settings but no longer a copy of its triggers (they only start journeys); one started before this drops them the next time it's worked out. Lists that leave out steps not shown yet read only the journeys that show their next steps.
- The kinds of entry a journey can use are kept per person for 30 seconds as before, but let go as soon as they're stale (at most 100 people's at once), and people asking at the same moment share one read.
- **Sync now** reads one kind of entry at a time and stops once it has enough, instead of holding every kind's lists at once.
- Calendar jobs: entries changed while a person's calendar job is waiting go in that same job, which works out what syncs once for all of them (an Add to calendar's hundreds of new entries are one job, not hundreds). A bulk import's entries are passed on ten at a time.
- Reading the person's Google calendars asks only for each event's times, title, status and Tasks' mark (never descriptions, guests or attachments). An answer Tasks doesn't read (a refusal, an event already gone) is let go straight away.
- Tasks' app-wide settings are read once when many things ask at the same moment.
- Today's kept suggestions go as soon as they're replaced or forgotten (their timer no longer holds them for the rest of the minute).
- A journey on an entry that has gone is left alone for the rest of the day by the visit's catch-up.
- A Board move keeps only the moved card's earlier state (to put back if the move is refused), not the whole board's.
- Only the main **Calendar** page reads the next month ahead; an entry's calendar tab or widget reads only what it shows.
- Signing out takes down the timeline tabs, Tasks' Structure fields and the Journeys tab registered for the person, as well as what the browser kept.
- **Side by side** remembers the entries chosen beside the most recent 30 entries; older choices are let go.

## v1.22.87 — 2026-11-26

**Limits, step-up, each person's own kinds, and privacy** (Batches 2 and 3 of [the cleanup and security audit](/modules/tasks/roadmap/#cleanup-and-security-audit-2026-11-26)).

**Fixed**
- The kinds a journey works with are kept per person. They were kept for 30 seconds in one list for everyone, although the list holds the first person's own kinds, so in an app with more than one person someone else's Journeys tab could briefly offer them, refuse its own, or use their stages. The next prompt now reads the same short-lived list instead of working it out on every ask.
- Two full calendar syncs for one person no longer run at once (they could both make the same event): a second waits for the first, then reads afresh.

**Changed**
- **Suggest pieces** runs an AI model each time, so one person can ask ten times a minute; after that it says to try again in a minute. AI Core leaves limiting an in-process call to the module.
- A full calendar sync (Sync now, starting sync, choosing calendars to read, the all-day reminder time) can run six times in a couple of minutes for one person, then says to try again in a minute or two. Google and Microsoft limit the whole app's calls, so one person's loop could have paused everyone's sync. The catch-up when the app opens and the changes Structure sends aren't limited.
- Starting sync again with **A new calendar called Tasks** on the same account keeps the one it made last time, instead of making another.
- Applying a stage template and saying where stray stages count ask an admin for the starter's step-up (a dry run doesn't): both move everyone's entries off the stages they retire, which can't be undone.
- The check-in's action (`tasks.checkin.saved`) says who and which day only, never the feeling or the fuller check-in's answers, so an audit listener can't keep how someone feels.
- The data download includes a journey offer's reason and a kind's role (what it is).
- **Suggest pieces** no longer passes the entry's id to AI Core, so an admin's own operation can't read more of the entry than the task's own words. The docs now say the task's win goes too (it always did).
- The test of declared audit events now fails on any `doActionAll` call whose name it can't read.

## v1.22.86 — 2026-11-26

**Calendar sync safety** (Batch 1 of [the cleanup and security audit](/modules/tasks/roadmap/#cleanup-and-security-audit-2026-11-26)).

**Fixed**
- **Stop** with "remove the ones Tasks made" no longer deletes your own events. Since v1.22.71 it also asked Google or Microsoft to delete every event Tasks had brought in from your calendars (your own appointments, and meetings you organise, which sent cancellations to everyone invited), and left their copies behind in Tasks. It now removes only the events Tasks made, and takes the copies out first. Until you update, stop with "leave them".
- A copied entry gets a calendar event of its own. Structure's **Duplicate** (and a repeat's "from this day on") copied Tasks' note of the original's event, so changing the copy changed the original's event and finishing it removed it. A note now counts only where it's the entry's own, and Tasks' own copies leave it behind.
- After an admin chooses **What an event says: Busy** (or back to its name), each person's next catch-up re-sends their events, so the ones already in their calendar say it too (it used to wait for Sync now or a change to the entry). An event someone moved in their calendar no longer keeps its real name.
- Reading your calendars in stops at 500 events: a calendar it didn't read to the end no longer has its other copies taken out as "gone", and one calendar's read asks for at most 20 pages.

**Changed**
- The account-erasure record says the events Tasks put in the person's own calendar stay there (the connection is revoked before Tasks' handler runs).

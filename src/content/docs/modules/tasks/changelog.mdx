## v1.22.40 — 2026-11-16

**Safety fixes from the cleanup and security audit** (the owner: "Safety fixes first").

**Changed**
- **Saving or removing a kind of schedule asks for the emailed code** where the app's security asks for one (the starter's step-up, at its hardened and strict tiers; at the standard tier nothing changes). Saving can change every arrangement of the kind at once (its worked-out fields, and its Starts and Ends as days), so each run records how many it changed, with `audit: true`, even when it stops part way.
- **A date that doesn't exist is refused** on a schedule: its start and end, the date it starts from on a calendar, On real dates, its references, Add to calendar's from and until, and a change of hands' moment. "2027-02-30" or a 13th month says the date doesn't exist, rather than tripping the server or running over a stretch nobody chose. Times on a pattern, an occasion and a holiday rule have to read like 15:00.
- **No more "Nights each need Structure 1.89.6"**: Tasks needs Structure 1.89.12, so where Structure refuses a kind of schedule's fields, **Needs a look** now gives Structure's reason instead of blaming its version.

**Fixed**
- **Forgetting a kind's setup** (an admin action no screen uses yet) checks the kind is one the admin may change, and never forgets Tasks' own type's setup. The quick capture type and a kind's name in that action are checked for length.
- **A schedule's type** is taken only from the type field's own choices (a name every object answers to, such as "constructor", is ignored).

**Upgrade notes**
- Run `npx tasks update`. No schema change. At the hardened or strict security tier, saving a kind of schedule asks for the emailed code once.

Verified: `check:templates`, `conformance:check`, `type-check` and the build pass; 452 runtime tests pass (new: dates that don't exist and a time it can't read refused across the schedule routes; forgetting a kind's setup limited as above; Structure's own reason where it refuses the fields). Rendered into a fresh copy of the app it runs in (starter v2.16.12, Structure v1.89.12, Tasks v1.22.39 installed): both halves type-check with no errors (the step-up middleware included), and the styling audit passes. Not yet done: a click-through in the running app.

## v1.22.36 — 2026-11-15

**Faster: a lighter first load, screens that don't blank, and calendars and schedules that read less.** From a speed audit; the findings and what's left are on the [Roadmap](/modules/tasks/roadmap/#speed-audit-2026-11-15).

**Changed**
- **A lighter first load.** The calendar, timeline and schedule tabs, widgets and cards, the Tasks tab, the Steps and Energy widgets and the Today dashboard widget now download only where one shows, each with its own small loading state. Measured in a copy of the app it runs in: Tasks' part of the first download fell from about 65 KB to about 17 KB compressed, and the app's whole first download by 56 KB.
- **Nothing blanks while the next part loads.** A schedule's On real dates, the calendar's nights column and year, and the task list, board and timeline when a filter changes keep what's on screen until the next answer is in, as the calendar's month already did.
- **Calendars read less, and at once.** Side by side reads its rows together rather than one after another. A month with a schedule on it no longer works out the calendar's own day colours only to replace them, and reads its days, its schedules and their changes of hands together. A stretch of days reads its entry once rather than once a page.
- **Schedules ask Structure less.** Who can be chosen, and their colours, are read together, each entry once, with types kept for a few seconds as the rest of Tasks does.
- **Smaller savings.** Each day's entries are worked out once for a whole month or list rather than for each day; date and time wording reuses its formatters; a schedule planner's references are looked up by date rather than searched for each day; saving a task no longer fetches it again; the admin page can start downloading ahead of a click.

**For developers**
- Registrations: lazy components in a local `Suspense` with `LoadingState` (Structure's entry page puts none around a tab or widget); the timeline slot and the Today widget lazy as they are (their hosts bring a boundary); the admin page registers `preload`.
- `eventsByDay(events, from, to)` in the kit's `model.ts`, used by `MonthCalendar` and `AgendaCalendar`; a test checks it agrees with `eventsOn` day by day.
- `cachedTypeFor` exported from the views service and used by the schedules; saving a schedule setup clears the views' caches too.
- `loadItems` takes the caller's `anchor`.

**Upgrade notes**
- Run `npx tasks update`. No schema change.

Verified: `check:templates`, `conformance:check`, `type-check` and the build pass; 446 runtime tests pass. Rendered into a fresh copy of the app it runs in (starter v2.16.12, Structure v1.89.10, Tasks v1.22.35 installed): both halves type-check with no errors, the styling audit passes, and the app builds.

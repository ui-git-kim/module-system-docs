The starter's markup carries structure only ([Rule 7](/getting-started/llm-rules/#7-template-components-use-structure--semantic-tokens-only)), so a look reaches it through **hooks**: a `data-slot` naming a part, a `data-*-part` marker inside a larger block, and state attributes such as `data-active`. This page lists the hooks in `frontend/src` outside `components/ui/*` (shadcn's own primitives carry their own `data-slot`s). A Style module rule, a Style snippet's `slot`, or an app's own CSS can target any of them.

Checked against the code for v2.16.9.

<Aside type="caution" title="Hook names are an interface">
Apps' snippets and the Style module's rules depend on these names. Renaming or removing one is a breaking change for those apps, so a change here goes in the changelog.
</Aside>

**Foundation** in the tables below means the starter's own `foundation.slots` entry gives the hook a default look; see [the starter's style entries](#the-starters-style-entries) for the variables that retune it. Every other hook is unstyled by the starter: it is there for a theme to use.

## DataTable

`data-slot` marks the table's main parts and `data-table-part` its smaller ones. The [DataTable](/starter-template/data-table/) page describes the parts; the Style module's catalogue styles several of them.

| Hook | Marks | Foundation |
|------|-------|-----------|
| `data-slot="data-table"`, with `data-density` | The whole table | No |
| `data-slot="data-table-frame"`, `-toolbar`, `-pagination` | The frame, the toolbar, the pager | No |
| `data-slot="data-table-row-actions"`, with `data-intent` | The row's action menu (and a destructive action's intent) | No |
| `data-slot="data-table-status"` (with `data-selected`, `data-intent`), `data-table-status-error` | The status bar and its error line | No |
| `data-table-part="column-header"`, with `data-sorted` and `data-align` | A sortable column header | Its offset only: `--data-table-sort-offset` |
| `data-table-part` = `search`, `view-options`, `reset-columns`, `density`, `primary-action`, `filter`, `more-filters` (with `data-active`), `copy` (with `data-copied`), `confirm`, `skeleton-row`, `error-state`, `retry`, `truncate`, `expanded-row`, `missing`, `person`, `link`, `id`, `progress` (with `data-state` / `data-value`) | The toolbar controls, the loading and error states, and the cell kinds | No |
| Row `data-state="selected"`, `data-depth`; status Badge `data-status`; cell Avatar `data-size` | Row selection and nesting; a status cell's value | No |

## The starter's style entries

The starter registers two entries in the [`styleRegistry`](/starter-template/registries/#style-registry), both at `order: 10`, so the Style module (and anything at the default 50) wins on a conflict. Every value is a CSS variable with a fallback to the app's shadcn or Tailwind token, inside `@layer components` and `:where()`, so a utility on the element or any later rule wins without `!important`.

| Entry | Styles |
|-------|--------|
| `foundation.slots` | The [UI typography roles](/starter-template/typography/) (`.ui-*`, behind `<Heading>` / `<Text>`) and the hooks marked **Foundation** above |
| `admin.stat-value` | `[data-slot="admin-stat-value"]` |

Either can be switched off through the [style overrides](/starter-template/style-system/#admin-overrides) (`AppSettings.styleOverrides`).

### Retune variables

Set these in `globals.css`, or let the Style module set them. Each falls back to the value in brackets.

| Variable | Retunes | Default |
|----------|---------|---------|
| `--ui-scale-base`, `--ui-<role>-scale`, `--ui-<role>-size` / `-weight` / `-leading` / `-tracking` / `-transform` / `-font`, `--ui-titles-*` | The typography roles | See [Typography](/starter-template/typography/#retuning--never-inline) |
| `--widget-stat-size`, `-leading`, `-weight` | `widget-stat-value` | `--text-2xl`, `--leading-tight`, semibold |
| `--plan-name-size`, `-weight` | `plan-name` | `--text-lg`, semibold |
| `--admin-stat-size`, `-leading`, `-weight` | `admin-stat-value` | `--text-2xl`, `--leading-tight`, semibold |
| `--toolbar-badge-size`, `-weight`, `-bg`, `-foreground` | `header-toolbar-badge` | `0.6875rem`, medium, `--destructive`, then `--destructive-foreground` or `--primary-foreground` |
| `--divider-dashed-color` | The dashed divider | `--border` |
| `--data-table-sort-offset` | How far a sort header's button is pulled out, so its label lines up with the cells | `-0.75rem` |
| `--auth-wordmark-font`, `-size`, `-weight` | `auth-wordmark` | `--font-heading`, `--text-xl`, semibold |
| `--nav-trigger-active-bg` | A top-bar trigger holding the current page | `--muted` at 50% |
| `--nav-topbar-offset` | The scroll padding under the sticky top bar | `3rem` |

## Caveats

- **Override changes re-render `useStyleRegistry()` since v2.16.9.** Before, only registering, updating or removing an entry did, so a toggle row reading `styleRegistry.isEnabled(id)` stayed stale until something else re-rendered it.
- **`resetThemeVariables()` also removes the style registry's tokens.** The registry writes its tokens through `applyThemeVariables()`, so a reset strips them until the registry next re-applies (any register, update or override change). See [Theme Utilities](/starter-template/theme/#resetting-to-defaults).
- **`--typeset-*` can't be set from `:root`.** `typeset.css` declares every `--typeset-*` on `.typeset` itself, so set them on `.typeset` or a preset class.
- **Tokens a `theme.cssVariables` filter adds are never cleared.** The registry clears the tokens that fall out of its own merge, not extra ones a filter injected.
- **The starter ships no toggle UI for style entries.** It stores and applies the overrides; the Style module's admin page is one UI that changes them.
- **`components:sync` takes the components to install from `.module-state.json`** (each enabled module's `installedShadcnComponents`), plus the starter's baseline on a restyle. See [the sync](/starter-template/style-system/#reinstall-flow-terminal-only-for-now).

The create script (`create-app.ps1` on Windows, `create-app.sh` on macOS/Linux) sets up a new app interactively. This guide explains each prompt.

---

## Before You Start

Have these ready from the [Neon Console](https://console.neon.tech):

1. **Connection snippet** - Your project → **Connect** (top of the dashboard), with **Connection pooling** on → copy the `.env` (or Prisma) snippet, or just the connection string
2. **Auth URL** - Your project → **Auth** (Enable Auth first if it is off) → **Configuration** tab → copy the **Base URL**

:::tip[Credentials are optional]
You can skip the database and auth prompts during setup. The script creates placeholder comments in `.env` files that you can fill in later.
:::

## If the Folder Already Exists

If the target folder already exists, the script offers three choices before doing anything:

```
Directory 'C:\Users\you\ReactApps\my-saas-app' already exists.

  [O] Overwrite - Delete and recreate from scratch
  [U] Update    - Open the folder and use template:update instead
  [C] Cancel

Choose (O/U/C):
```

- **Overwrite** deletes the directory and recreates it. Before deleting, the script reads the previous `backend/.env` and offers to reuse the prior configuration (see below).
- **Update** prints the `npm run template:update` instructions for updating the existing app, then exits.
- **Cancel** exits without changes.

On **Overwrite**, the database, auth, and port prompts each show the previous value and offer to reuse it:

- `Reuse previous database config? (Y/n)` - reuses the prior `DATABASE_URL` / `DIRECT_DATABASE_URL`
- `Reuse previous auth URL? (Y/n)` - reuses the prior `NEON_AUTH_URL`
- The previous `PORT` becomes the default backend port

The script creates the app in a sibling folder to the template by default. Press Enter to accept, or specify a different path.

## Step 3: Database URLs

The script asks you to paste the connection snippet from Neon:

```
Database Setup (Neon)
Get this from the Neon Console (https://console.neon.tech):
  your project -> Connect (top of the dashboard) -> keep Connection pooling on
  -> copy the .env (or Prisma) snippet, or just the connection string

Paste the whole snippet (its comments and blank lines are fine). It looks like:
DATABASE_URL="postgresql://...@ep-xxx-pooler.../neondb?sslmode=require..."
DATABASE_URL_UNPOOLED="postgresql://...@ep-xxx.../neondb?sslmode=require..."
(An older snippet with the second line commented out with # works too. So does
a lone connection string: the other URL is derived from it.)

Or press Enter now to skip (you'll need to configure .env manually later)

Paste your Neon snippet, then press Enter twice:
```

### Getting the Neon Snippet

<Steps>
1. Go to [Neon Console](https://console.neon.tech)
2. Select your project
3. Click **Connect** at the top of the dashboard
4. Make sure **Connection pooling** is on (the default)
5. Copy the snippet, or just the connection string
6. Paste it into the terminal
7. Press Enter **twice** to finish
</Steps>

:::note[Two empty lines end the paste]
Since v2.14.2 one empty line inside the paste doesn't end it, because Neon's snippet can have a blank line between its blocks (before, the rest of the paste answered the next prompts). Two empty lines in a row, or the end of input, finish it. An empty **first** line skips the step.
:::

The script automatically extracts both URLs:
- **Pooled URL** (with `-pooler`) - for app queries
- **Direct URL** (without `-pooler`) - for migrations

It accepts any of Neon's shapes, one per line: `DATABASE_URL=` and `DATABASE_URL_UNPOOLED=` lines (quoted or bare, with or without a leading `#`), or any line holding a `postgres://` / `postgresql://` string, such as a bare connection string or a `psql '...'` command. A string with `-pooler` in it is the pooled URL; any other is the direct one. If you paste only one URL, the script derives the other: it removes `-pooler` to get the direct URL, or adds it after the endpoint id (`@ep-xxx.<region>` becomes `@ep-xxx-pooler.<region>`) to get the pooled one, and says which it derived (`Derived direct URL from pooled URL` or `Derived pooled URL from direct URL`).

```
Parsed URLs:
  Pooled:  ...ep-xxx-pooler.ap-southeast-2...
  Direct:  ...ep-xxx.ap-southeast-2...
```

### Skipping Database Setup

Press Enter without pasting anything to skip. You'll need to:
1. Open `backend/.env` after setup
2. Uncomment and fill in `DATABASE_URL` and `DIRECT_DATABASE_URL`
3. Run `cd backend && node ../scripts/prisma-migrate-safe.mjs --init --name init`

## Step 4: Auth URL

```
Neon Auth Setup
Get this from the Neon Console: your project -> Auth (the Better Auth page;
  Enable Auth first if it is off) -> Configuration tab -> copy the Base URL
Example: https://ep-xxx.neonauth.<region>.aws.neon.tech/neondb/auth

Or press Enter to skip (you'll need to configure .env manually later)
Enter your NEON_AUTH_URL:
```

Get this from your Neon project's Auth page (the **Base URL** on the **Configuration** tab). It's used for JWT token validation: the backend fetches its signing keys from it and, since v2.14.2, checks each token's issuer and audience against it. It must be an `https://` URL; the backend refuses to start on plain `http://` except for `localhost`, `127.0.0.1` or `[::1]`. Paste the Base URL, not Neon's `jwks_url`.

### Skipping Auth Setup

Press Enter to skip. You'll need to add `NEON_AUTH_URL` to both:
- `frontend/.env` as `VITE_NEON_AUTH_URL`
- `backend/.env` as `NEON_AUTH_URL`

---

## Step 5: Backend Port

```
Backend Port
Choose a unique port for this app's API server
Enter backend port (default: 3100):
```

Choose a unique port for this app's backend API. The default is 3100, but if you have multiple apps running, use different ports (3101, 3102, etc.).

The answer ends up in `PORT=` and `VITE_API_URL=`, so since v2.14.2 it must be digits only, from 1 to 65535. Anything else prints `"<input>" is not a port number (1-65535) - using <default>` and uses the default.

The frontend port is handled automatically by Vite - it will use the next available port if 5173 is taken.

---

## Step 6: Prisma Schema Mode

```
Prisma Schema Mode
How should your database schema be organised?
  1. Single file (default) - All models in prisma/schema.prisma
  2. Multi-file - Separate .prisma files in prisma/schema/ directory
     (Recommended if you plan to install modules)
Enter choice (1/2, default: 1):
```

Choose how your database schema is organised. **Single file** (the default) keeps all models in `prisma/schema.prisma`. **Multi-file** splits models across separate `.prisma` files in a `prisma/schema/` directory - recommended if you plan to install modules, since each module can own its own schema file.

---

## Step 7: Vector Database (pgvector)

```
Vector Database (pgvector)
Enables AI embeddings and similarity search via pgvector
Adds the pgvector extension and a starter Embedding model
Enable vector database? (y/N):
```

Defaults to **No**. Answer `y` to enable AI embeddings and similarity search: the script adds the `pgvector` extension to your database and a starter `Embedding` model to the schema.

## Step 8: App Remote (Optional)

```
App Repository (Optional)
If you've created a GitHub repo for your app, enter the URL.
Or press Enter to skip (you can publish via VS Code later)
Example: https://github.com/yourusername/my-app
Enter your app's git remote URL:
```

If you've created a GitHub/GitLab repo for your app, enter the URL here. Otherwise, skip and set it up later via VS Code's "Publish Branch" feature.

```
  Backend port: 3100
  Schema:       Single file (prisma/schema.prisma)
  Vectors:      No
  Database:     Configured
  Auth:         Configured
  App remote:   None (local only)

Proceed? (Y/n):
```

Review the settings and press Enter (or `Y`) to proceed, or `n` to cancel.

The **Schema** line shows `Multi-file (prisma/schema/)` when you chose multi-file, and **Vectors** shows `Enabled (pgvector)` when enabled. If you skipped the database or auth prompts, their status reads `Manual setup required` instead of `Configured`.

## What Happens Next

The script runs in six labelled phases (`[1/6]` … `[6/6]`): clone, install dependencies, shadcn, env files, database, initial commit. Along the way it:

1. **Clones the template** with full git history (`[1/6]`)
2. **Sets up remotes** - `template-upstream` for updates, pull-only (push disabled, so your app can't be pushed into the template)
3. **Removes template-only files** (`create-app.ps1`, `create-app.sh`, `create-app.bat`) and the template's `.claude/` folder
4. **Removes the docs git submodule** - apps don't need the shared module-system docs
5. **Swaps in the app CLAUDE.md** - renames the bundled `CLAUDE.app.md` over the template's `CLAUDE.md`
6. **Updates package.json** with your app name (lowercase letters, digits and hyphens only)
7. **Installs all dependencies** (root, frontend, backend) from the template's one install list, `scripts/install-all.mjs` (`[2/6]`)
8. **Sets up shadcn/ui** and adds the template components listed in `scripts/shadcn-baseline.json` (`[3/6]`)
9. **Prompts for the security tier** (standard / hardened / strict, default hardened), then **creates .env files** with your credentials (or placeholders) — including a generated local field-encryption key so hardened/strict boot clean without KMS (`[4/6]`). On macOS/Linux both files are owner-only (`0600`) because they hold secrets. Windows has no such permission bit: the files inherit the output folder's access rules, so on a shared machine keep your apps under your user profile.
10. **Runs Prisma generate** to create the database client (if configured) (`[5/6]`)
11. **Runs Prisma migrate** to set up database tables (if configured)
12. **Offers AWS KMS field-encryption setup** (optional) - prompts `Set up AWS KMS now? (y/N)`; if yes, runs `node scripts/setup-kms.mjs` (also available later as `npm run security:setup-kms`) to move field-encryption key custody to AWS KMS
13. **Creates an initial commit** (`[6/6]`)

## Environment Files Written

The `[4/6]` phase writes two `.env` files. Keys with a value are written live; the rest are written commented as placeholders for you to fill in later.

**`frontend/.env`**

| Key | Value |
|-----|-------|
| `VITE_NEON_AUTH_URL` | Your auth URL (commented if skipped) |
| `VITE_API_URL` | `http://localhost:<backend-port>` |
| `VITE_APP_NAME` | Your app name |

**`backend/.env`**

| Key | Value |
|-----|-------|
| `DATABASE_URL` / `DIRECT_DATABASE_URL` | Pooled and direct URLs (commented if skipped; the placeholders end in `?sslmode=require&channel_binding=require`, as Neon's strings do) |
| `DATABASE_ADAPTER` | `neon` |
| `NEON_AUTH_URL` | Your auth URL (commented if skipped) |
| `PORT` / `NODE_ENV` / `FRONTEND_URL` | Server config |
| `SECURITY_PROFILE` | Your chosen tier (default `hardened`) |
| `SECURITY_KEY_PROVIDER` | `env` (move to KMS via the prompt below or `security:setup-kms`) |
| `SECURITY_ENCRYPTION_KEY` | Generated (base64, 32 bytes) — local field-encryption master key |
| `SECURITY_EDGE` | `none` |

The backend file also ships **commented** placeholders for the optional security knobs: `AWS_REGION`, `SECURITY_KMS_KEY_ID`, `SECURITY_KMS_WRAPPED_DEK`, `SECURITY_KMS_PER_TENANT`, `SECURITY_POSTURE_ENFORCE`, `SECURITY_ADMIN_ALLOW_ENV_WRITE`, `SECURITY_AUDIT_SINK`, and `SECURITY_AUDIT_RETENTION_DAYS`. See [Configuration](/starter-template/configuration/) for what each does.

Since v2.13.1 it also writes **commented** lines, with the defaults shown, for the API rate limits (`RATE_LIMIT_WINDOW_MS`, `RATE_LIMIT_MAX`, `RATE_LIMIT_USER_MAX`) and the database idle timeout (`DB_POOL_IDLE_TIMEOUT_MS`). Since v2.14.2 it adds commented `DB_CONNECT_TIMEOUT_MS=10000` and `DB_POOL_MAX=10` (see [Connection limits and timeouts](/starter-template/database/#connection-limits-and-timeouts)), and an empty commented `DATABASE_URL_UNPOOLED=` under the direct URL: Neon's own name for it, read only when `DIRECT_DATABASE_URL` is unset. Leave them commented to use the defaults. See [Rate limits](/starter-template/configuration/#rate-limits).

When you skip the auth prompt, the commented `VITE_NEON_AUTH_URL` / `NEON_AUTH_URL` placeholders now use the endpoint-id form Neon's URLs have, `https://ep-xxx.neonauth.region.aws.neon.tech/neondb/auth` (v2.14.2).

There are no Neon Auth admin keys any more (`NEON_AUTH_PROJECT_ID` / `NEON_AUTH_SECRET_KEY` were dropped in v2.13.0, because nothing read them). Removing a user's Neon Auth login when their account is deleted is wired in code instead — see [The Neon Auth identity](/starter-template/security-feature/#the-neon-auth-identity-closing-the-gap).

Alongside those, create-app also writes **commented** placeholders for the optional integrations — Sentry error tracking (`VITE_SENTRY_*` in `frontend/.env`; `SENTRY_*` in `backend/.env`), email sending (`EMAIL_PROVIDER`, `EMAIL_FROM`, and the provider keys), and background jobs (`JOBS_RUNNER`) — all unset by default. The `JOBS_RUNNER` comment notes that pg-boss keeps a Neon compute from scaling to zero (v2.14.2). See the [Email](/starter-template/email-feature/) and [Jobs](/starter-template/jobs-feature/) feature pages for details.

## Troubleshooting

### "Prisma migrate failed"

Check your `DATABASE_URL` and `DIRECT_DATABASE_URL` are correct. The pooled URL won't work for migrations - make sure you have the direct URL (without `-pooler`).

### "shadcn init failed"

You can run this manually later. The `init` step is interactive - **choose Radix when asked for the component library**. Then install the template's baseline components from the app root; the list lives in one file, `scripts/shadcn-baseline.json` (see [shadcn baseline](/starter-template/scripts/#shadcn-baseline)):
```bash
cd frontend
npx shadcn@latest init
cd ..
node scripts/shadcn-baseline.mjs add
```

The same command fixes a later **"shadcn components failed"** warning. Use `node scripts/shadcn-baseline.mjs add --missing` to install only the ones you don't have yet.

### Script exits unexpectedly

The script keeps the window open on errors. Check the error message and verify your inputs.

### Can't parse Neon snippet

The script prints `Could not parse a database URL from what you pasted` when no line held a `postgres://` or `postgresql://` value. Copy the snippet (or the connection string) from the Neon Console's **Connect** dialog again and paste it whole, then press Enter twice. If you skip the step, fill in `DATABASE_URL` and `DIRECT_DATABASE_URL` in `backend/.env` by hand.

## Git Structure After Setup

Your new app has:

| Remote | Points To | Push? |
|--------|-----------|-------|
| `template-upstream` | Local template folder | No (disabled) |
| `origin` | Your app repo (if provided) | Yes |

```bash
git remote add origin https://github.com/you/your-app.git
git push -u origin main
```

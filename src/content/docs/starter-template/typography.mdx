Typography in the template has one job: **be consistent with whatever shadcn preset the app was initialised with, everywhere, without any file hard-coding a font size.** This page is the firm rule set — for template code and for every module.

## The problem it solves

shadcn's theming owns colour, radius, surfaces, and font *faces* (`--font-sans`, `--font-heading`, `--font-mono`). It deliberately ships **no typographic size scale** — headings are left to you. Tailwind's Preflight then resets every `<h1>`–`<h6>` to inherit body size and weight. So a bare heading in markup renders *flat*, indistinguishable from body text.

At the same time, the [structure-only styling policy](/getting-started/llm-rules/#7-template-components-use-structure--semantic-tokens-only) forbids `text-2xl font-semibold` in template or module markup — because a hard-coded size fights every design system the code lands in.

The resolution: shadcn's own components already carry the theme's type voice (`CardTitle`, `Label`, `Badge`, `TableHead`, …). The only gap is **standalone** text with no shadcn primitive — page titles, section headings, standalone labels and captions. The template fills exactly that gap with a thin primitive and a set of semantic roles, **scaled to your shadcn tokens**.

## The rule (decision tree)

<Steps>

1. **Is the text part of a shadcn primitive?** Use the primitive's own title / description / label (`CardTitle`, `DialogTitle`, `CardDescription`, `Label`, `Badge`, …). It already carries the theme voice. **Never restyle it.**

2. **Is it a standalone heading / label / caption / eyebrow?** Use the `<Heading>` / `<Text>` primitives from `@/components/typography`. Never a bare `<h1>` and never `text-2xl font-semibold`.

3. **Is it prose / markdown / streamed content?** Wrap the container in [`.typeset`](/starter-template/style-system/#typography-typeset).

4. **Is it component-level emphasis on a bespoke element** (a stat value, a wordmark)? Add a `data-slot` and style it in a [Style Registry](/starter-template/style-system/) entry — like the foundation's `widget-stat-value`.

</Steps>

<Aside type="danger" title="Never">
No `text-*` / `font-*` / `tracking-*` size utilities and no bare `<h1>`–`<h6>` in template or module markup. That is the whole point — a hard-coded scale drifts across apps and fights the theme.
</Aside>

## The primitives

Import from `@/components/typography`. Both are structure-only wrappers: they render a semantic element and apply **one** `.ui-*` role class. All values live in the foundation typography roles (below).

### `<Heading>`

```tsx
import { Heading } from '@/components/typography';

<Heading level={1}>Billing</Heading>                       // <h1 class="ui-title">
<Heading level={2}>Payment methods</Heading>              // <h2 class="ui-heading">
<Heading level={3} variant="section">Invoices</Heading>   // <h3 class="ui-heading">  ← tag ≠ size
<Heading level={1} variant="display">Welcome</Heading>    // <h1 class="ui-display">
```

- **`level` (1–4, required)** → the rendered `<hN>` tag. Keeps the document outline valid for accessibility.
- **`variant` (optional)** → the visual role, defaulting from `level` (`1→page`, `2→section`, `3/4→subsection`). Set it to decouple size from semantics — e.g. an `<h3>` in the outline that should *read* as a section title.

### `<Text>`

```tsx
import { Text } from '@/components/typography';

<Text>Standard running copy.</Text>                         // <p class="ui-body">
<Text variant="caption">Last updated 3 days ago.</Text>     // <p class="ui-caption">  (muted)
<Text variant="overline">Danger zone</Text>                 // <span class="ui-overline">  (muted, uppercase)
<Text variant="label" as="label" htmlFor="x">Name</Text>    // standalone label, not a shadcn <Label>
<Text muted>Dimmed body copy.</Text>                        // adds the muted-foreground token
```

- **`variant`** — `body` (default), `label`, `caption`, `overline`.
- **`as`** — override the element (`caption` on a `<span>`, `overline` on an `<h2>`, …).
- **`muted`** — force the `muted-foreground` token (`caption`/`overline` are already muted by role).

<Aside type="note" title="Not for shadcn primitive text">
`<Text variant="label">` is for a **standalone** label with no form control of its own. For a real form field, use shadcn's `<Label>` — it carries the theme voice and the `peer`/`data-slot` wiring the primitives can't. Same for `CardDescription`, `Badge`, etc.
</Aside>

## The roles

Each role is a `.ui-*` class defined in `config/foundation-style.registration.ts`. Every value defaults to the app's shadcn/Tailwind token, so the scale **tracks the preset the app was initialised with** — with a literal fallback if a token isn't emitted.

Heading **sizes are relative** — an anchor (`--ui-scale-base`, defaulting to the CardTitle tier `--text-lg`) times the role's multiplier — so the ladder scales with whatever shadcn config is active. The small roles sit on the shadcn body scale.

| Role | Class | Default element | Size | Face / weight | Typical use |
|------|-------|-----------------|------|---------------|-------------|
| Display | `.ui-display` | `<h1>` | base × 2 | heading · 700 | Hero / marketing title |
| Page title | `.ui-title` | `<h1>` | base × 1.65 | heading · 600 | Page top (`PageHeader`) |
| Section heading | `.ui-heading` | `<h2>`/`<h3>` | base × 1.35 | heading · 600 | Section / card-group heading |
| Subheading | `.ui-subheading` | `<h3>`/`<h4>` | base × 1.15 | heading · 600 | Sub-section heading |
| Body | `.ui-body` | `<p>` | `--text-sm` | body · 400 | Short running copy in chrome |
| Label | `.ui-label` | `<span>` | `--text-sm` | body · 500 | Standalone labels, toolbar text |
| Caption | `.ui-caption` | `<p>` | `--text-sm` | body · 400 · **muted** | Helper text, hints, timestamps |
| Overline | `.ui-overline` | `<span>` | `--text-xs` | body · 600 · **muted · uppercase · tracked** | Eyebrows, group labels |

<Aside type="tip" title="Relative to your card title">
`base` = `--ui-scale-base`, which defaults to `var(--text-lg, 1.125rem)` — the tier shadcn's `CardTitle` sits on. So `.ui-title` resolves to `calc(var(--ui-scale-base) * var(--ui-title-scale, 1.65))` on the `--font-heading` face — a page title is ~1.65× your card titles, and if your config puts card titles on a different step you repoint one anchor and the whole ladder follows. No fixed sizes to chase per theme.
</Aside>

## Retuning — never inline

You never edit markup to change type. Retune **app-wide** from `:root` (in your `globals.css`) or via a [style module](/starter-template/style-system/)'s `tokens`:

```css
:root {
  /* Move the whole heading ladder — the anchor is the CardTitle tier. */
  --ui-scale-base: var(--text-lg);

  /* Resize one role by its multiplier — e.g. section headings at 1.5× the card. */
  --ui-heading-scale: 1.5;

  /* Or pin an absolute size (escape hatch — wins over the multiplier). */
  --ui-title-size: var(--text-3xl);

  /* Other properties are their own tokens. */
  --ui-title-tracking: 0em;
}
```

Tokens per role: **`--ui-scale-base`** (the shared anchor — the CardTitle tier, `--text-lg`), **`--ui-<role>-scale`** (its multiplier — heading defaults `display 2 / title 1.65 / heading 1.35 / subheading 1.15`), and **`--ui-<role>-size` / `-weight` / `-leading` / `-tracking`** (plus `-font` on headings, `-color` on caption/overline). Setting `--ui-<role>-size` pins an absolute size and overrides the multiplier for that role.

<Aside type="note" title="Style module (later)">
Deep, admin-toggleable typography theming belongs in a style module, which contributes these tokens through the Style Registry. The template only ships the mechanism and sensible defaults; it does not build the theming UI.
</Aside>

## Why it composes cleanly

The `.ui-*` rules ship inside `@layer components` and are `:where()`-guarded (zero specificity). Tailwind v4 declares the layer order `theme, base, components, utilities`, so the roles:

- **beat Preflight** (`base` layer) — headings are no longer flat;
- **lose to a Tailwind utility** on the element (`utilities` layer) — `<Heading level={1} className="text-xl">` still wins, no `!important` needed;
- **lose to any app or style-module rule** — zero specificity means a plain selector overrides them.

The real retune surface, though, is the tokens above — they work regardless of the cascade.

## Relationship to Typeset

They are siblings, not rivals:

| | Typeset (`.typeset`) | Foundation roles (`.ui-*`) |
|---|---|---|
| **For** | Flowing prose, markdown, chat, streamed content | Discrete UI chrome — one element at a time |
| **Applied to** | A container; styles its descendants | The element itself, via `<Heading>` / `<Text>` |
| **Owned by** | The app (`typeset.css`, regenerated per app) | The template (`foundation-style.registration.ts`, propagates on update) |
| **Shares** | `--font-heading`, the base scale — so both read as one design | ← |

Use Typeset for a blog post or an AI response; use the roles for the page title above it.

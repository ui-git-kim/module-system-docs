The colour picker is a shared component library at `@/components/colour-picker` that all modules use when they need colour selection. It ships two components that share a single **value contract**, so a value picked in one is valid in the other:

- **`ColourPicker`** — the comprehensive picker: a trigger button that opens a popover with a free-text value input, the shadcn semantic theme tokens, and the full Tailwind palette (hue overview → per-shade grid).
- **`QuickColourPicker`** — a lightweight inline row of swatch chips for the common case where a popover and a full palette are overkill.

<Aside type="note" title="Two pickers, one contract">
Both emit and accept the same value shape (see [The value contract](#the-value-contract)), so you can start with `QuickColourPicker` and swap to `ColourPicker` later without changing how the value is stored or applied.
</Aside>

---

## Quick Start

```tsx
import { useState } from 'react';
import { ColourPicker, QuickColourPicker } from '@/components/colour-picker';

function AccentField() {
  const [colour, setColour] = useState('');

  return (
    <>
      {/* Comprehensive: tokens + full palette + free-text, in a popover */}
      <ColourPicker value={colour} onChange={setColour} label="Accent" />

      {/* Quick: an inline row of theme-token swatches */}
      <QuickColourPicker value={colour} onChange={setColour} label="Accent" />
    </>
  );
}
```

## The value contract

A colour value is a **string** that is one of three shapes. Consumers store the string and decide how to apply it:

| Shape | Example | How to apply it |
|-------|---------|-----------------|
| shadcn **token** name | `"primary"`, `"destructive"` | `bg-primary`, or `var(--primary)` |
| Tailwind **hue-shade** | `"red-500"`, `"slate-950"` | `bg-red-500`, or `var(--color-red-500)` |
| **raw CSS** value | `"#ff0000"`, `"oklch(0.6 0.2 20)"`, `"var(--brand)"` | inline `style`, or as-is |

<Aside type="caution" title="Tailwind v4 palette variables">
Tailwind v4 exposes the palette as `--color-<hue>-<shade>` variables (e.g. `--color-red-500`) — **not** `--red-500`. The picker's `resolveColourPreview` helper maps `hue-shade` values to the correct `--color-*` variable so swatch previews match the app's real palette. Use it if you render your own preview from a stored value.
</Aside>

## `ColourPicker`

The comprehensive picker. A trigger button shows the current selection; clicking it opens a popover with three ways to choose:

1. **Free-text value** — type any token name, `hue-shade`, or CSS value.
2. **Theme** — the shadcn semantic tokens (`THEME_TOKENS`).
3. **Palette** — the full Tailwind palette: pick a hue, then a shade.

```tsx
<ColourPicker value={colour} onChange={setColour} label="Accent" />
```

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `value` | `string` | — | Currently selected value (see the value contract) |
| `onChange` | `(value: string) => void` | — | Called when a colour is selected, typed, or cleared (`''`) |
| `label` | `string` | — | Optional label rendered above the trigger |
| `className` | `string` | — | Additional class names for the trigger button |

Requires the shadcn `Popover`, `Button`, `Input`, and `Label` primitives (all shipped by `create-app` — `popover` was added to the baseline in v2.5.10).

## `QuickColourPicker`

A lightweight inline row of swatch chips, built on the shadcn `ToggleGroup` primitive (radio-like semantics, themable data-slots). Defaults to the theme's accent-ish tokens (`QUICK_COLOURS`), so it is theme-aware out of the box.

```tsx
{/* Default swatches (theme tokens) */}
<QuickColourPicker value={colour} onChange={setColour} label="Label colour" />

{/* Custom swatches + clear-on-reclick */}
<QuickColourPicker
  value={colour}
  onChange={setColour}
  colours={[
    { label: 'Ocean', value: '#0ea5e9' },
    { label: 'Rose', value: 'rose-500' },
    { label: 'Brand', value: 'primary' },
  ]}
  allowClear
/>
```

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `value` | `string` | — | Currently selected value |
| `onChange` | `(value: string) => void` | — | Called with the new value (or `''` when cleared) |
| `label` | `string` | — | Optional label rendered above the row |
| `colours` | `ColourOption[]` | `QUICK_COLOURS` | Swatches to offer |
| `allowClear` | `boolean` | `false` | Clicking the active swatch clears the selection |
| `disabled` | `boolean` | `false` | Disable the whole picker |
| `className` | `string` | — | Additional class names for the wrapper |

Each `ColourOption` is `{ label, value, preview? }`. `preview` overrides the swatch colour; when omitted it is derived from `value` via `resolveColourPreview`.

---

## `resolveColourPreview`

Turns a stored value into a CSS colour for a swatch/preview. Both pickers use it, so their previews agree — reach for it when you render your own preview from a saved value.

```tsx
import { resolveColourPreview } from '@/components/colour-picker';

resolveColourPreview('primary');    // "var(--primary, #888888)"
resolveColourPreview('red-500');    // "var(--color-red-500, #888888)"
resolveColourPreview('#ff0000');    // "#ff0000"
resolveColourPreview('oklch(0.6 0.2 20)'); // "oklch(0.6 0.2 20)"
resolveColourPreview('');           // "#888888"  (fallback)

<div style={{ backgroundColor: resolveColourPreview(saved) }} />
```

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `value` | `string \| undefined` | — | Stored colour value |
| `fallback` | `string` | `'#888888'` | Used when `value` is empty or its CSS variable is unset |

## Constants

| Constant | Type | Description |
|----------|------|-------------|
| `THEME_TOKENS` | `ColourOption[]` | The shadcn semantic tokens (primary, secondary, accent, muted, destructive, card, popover, background, foreground, border) |
| `QUICK_COLOURS` | `ColourOption[]` | Default `QuickColourPicker` swatches (the accent-ish theme tokens) |
| `TAILWIND_HUES` | `readonly string[]` | The 22 Tailwind palette hue names |
| `SHADE_STOPS` | `readonly string[]` | The Tailwind shade stops (`50`–`950`) |
| `HUE_PREVIEW_COLOURS` | `Record<TailwindHue, string>` | Static representative hex per hue for the hue-overview swatches |

## Styling

Both components follow the [structure-only styling policy](/starter-template/style-system/) — layout and shadcn semantic tokens only. Swatch backgrounds are the one exception: a swatch renders an **arbitrary runtime colour** that no theme class can express, so it uses an annotated inline `style={{ backgroundColor }}`. `QuickColourPicker`'s selected-swatch check mark uses the sanctioned contrast-marker exception (a `text-white` + functional drop-shadow over an unknown colour). Downstream apps re-theme the surrounding chrome through their own theme; they never need to fight a hardcoded colour here.

---

## Relationship to `AvatarColorPicker`

The user feature's [`AvatarColorPicker`](/starter-template/user-feature/) is a **separate, avatar-specific** control: it stores raw hex, offers the browser's native colour input for arbitrary values, and ships contrast helpers (`getContrastColor`, `getDefaultAvatarColor`). Use the shared colour picker for **design-token / palette** selection; use `AvatarColorPicker` for the avatar background. Consolidating the two is [tracked on the roadmap](/starter-template/roadmap/).

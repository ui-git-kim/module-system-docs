## User Types

### UserRole

```typescript
// backend/src/features/user/user.types.ts
```

### UserProfile

The complete user record returned from the API.

```typescript
interface UserProfile {
  id: string;                    // Neon Auth user ID (UUID)
  email: string;
  role: UserRole;
  name: string | null;
  avatarUrl: string | null;
  bio: string | null;
  preferences: UserPreferences;
  createdAt: Date;
  updatedAt: Date;
}
```

### UserPreferences

Stored as JSON in the database. Extensible by modules.

```typescript
interface UserPreferences {
  // Appearance
  theme?: 'light' | 'dark' | 'system';

  // Locale
  timezone?: string;     // IANA timezone (e.g., 'America/New_York')
  language?: string;     // Language code (e.g., 'en-US')

  // Avatar
  avatarColor?: string;  // Hex color (e.g., '#3b82f6')

  // Dashboard
  dashboardWidgets?: DashboardWidgetPreference[];

  // Email Notifications
  emailSecurityAlerts?: boolean;
  emailProductUpdates?: boolean;
  emailWeeklyDigest?: boolean;
  emailMarketing?: boolean;

  // Feature modules add their preferences here
}
```

### DashboardWidgetPreference

User preference for a dashboard widget (stored in `UserPreferences.dashboardWidgets`).

```typescript
interface DashboardWidgetPreference {
  id: string;
  visible: boolean;
  order?: number;
  size?: string;
}
```

## Zod Validation Schemas

### UpdateProfileSchema

```typescript
const UpdateProfileSchema = z.object({
  name: z.string().max(255).optional(),
  bio: z.string().max(5000).optional(),
  avatarUrl: z.string()
    .max(AVATAR_URL_MAX_LENGTH)   // 512 KB (v2.13.0); avatars are downscaled to 256px before upload
    .refine(/* URL or base64 image */)
    .optional(),
}).strict();
```

### UpdatePreferencesSchema

```typescript
const UpdatePreferencesSchema = z.object({
  theme: z.enum(['light', 'dark', 'system']).optional(),
  timezone: z.string().max(100).optional(),
  language: z.string().max(20).optional(),
  avatarColor: z.string().regex(/^#[0-9a-fA-F]{6}$/).optional(),
  dashboardWidgets: z.array(z.object({
    id: z.string().max(100),
    visible: z.boolean(),
    order: z.number().int().min(0).max(100).optional(),
    size: z.string().max(10).optional(),
  })).max(50).optional(),
  emailSecurityAlerts: z.boolean().optional(),
  emailProductUpdates: z.boolean().optional(),
  emailWeeklyDigest: z.boolean().optional(),
  emailMarketing: z.boolean().optional(),
})
  // Module-registered keys pass through, each value at most 4 KB of JSON
  .catchall(ModulePreferenceValueSchema)
  // At most 100 keys per update; key names at most 100 characters
  .superRefine(/* key count + key length */);
```

Since v2.13.0 the stored preferences are also capped as a whole: an update that would grow them past 200 keys or 64 KB is rejected with a 400 (an update that shrinks an oversized blob still works). A device token can't change `emailSecurityAlerts`.

### Express Request Extension

Available in all backend route handlers after `requireAuth` middleware.

```typescript
declare global {
  namespace Express {
    interface Request {
      user?: {
        id: string;         // Neon Auth user ID (JWT 'sub' claim)
        email: string;      // User's email (JWT 'email' claim)
        role?: UserRole;    // Populated by requireAdmin/requireRole/attachRole
        tenantId?: string;  // Isolation key for data scoping (RLS + owned()); set by requireAuth, equals id in solo apps
        authMethod?: 'jwt' | 'device'; // Web session or device token; requireWebSession / requireStepUp refuse 'device'
      };
    }
  }
}
```

## Error Types

### AppError

Base class for all operational errors.

```typescript
class AppError extends Error {
  public readonly statusCode: number;
  public readonly isOperational: boolean;
  public readonly code?: string;  // v2.13.0 — machine-readable reason, e.g. 'step_up_required'
  constructor(message: string, statusCode?: number, isOperational?: boolean, code?: string);
}
```

### Error Response

Failed requests are answered with JSON of this shape (a description, not an exported type):

```typescript
interface ErrorResponse {
  error: string;               // The message (a generic one for unexpected errors in production)
  code?: string;               // v2.13.0 — only for client-safe errors that carry one
  details?: Record<string, string[]>; // Validation failures: field → messages (validate middleware)
  retryAfterSeconds?: number;  // Rate-limit errors only
  stack?: string;              // Development only
}
```

The `code` lets the frontend react without reading the message. Codes the template sends:

| `code` | Status | Meaning |
|--------|--------|---------|
| `step_up_required` | 403 | Needs a fresh emailed code ([step-up](/starter-template/security-feature/#step-up-re-verification-sensitive-actions)) |
| `step_up_invalid_code` | 400 | The code was wrong or expired |
| `step_up_email_unavailable` | 503 | The code couldn't be emailed in production (usually no email provider). 400 if the account has no email address |
| `web_session_required` | 403 | A device token tried an action that needs a web session |
| `account_deletion_pending` | 403 | The account's deletion hasn't finished ([details](/starter-template/security-feature/#when-a-deletion-doesnt-finish)) |
| `account_deletion_incomplete` | 503 | This deletion run didn't finish; retrying is safe |

On the frontend, show a failed call with `getApiErrorMessage(err, fallback)` from `@/lib/api`. It returns the server's `error` (with any validation `details` folded in), or `fallback` when the response has no usable message.

### Error Subclasses

| Class | Status Code | Default Message |
|-------|-------------|-----------------|
| `BadRequestError` | 400 | `Bad request` |
| `UnauthorizedError` | 401 | `Unauthorized` |
| `ForbiddenError` | 403 | `Forbidden` |
| `NotFoundError` | 404 | `Not found` |
| `ConflictError` | 409 | `Conflict` |
| `TooManyRequestsError` | 429 | `Too many requests` |
| `InternalError` | 500 | `Internal server error` |
| `ServiceUnavailableError` | 503 | `Service temporarily unavailable` |

`TooManyRequestsError` has an additional `retryAfterSeconds` property. `UnauthorizedError`, `ForbiddenError` and `ServiceUnavailableError` take an optional second argument, the `code` (v2.13.0):

```typescript
throw new ForbiddenError('This account is being deleted', 'account_deletion_pending');
```

## Security Types

Exported from the backend security barrel (`features/security/index.js`). Added in v2.13.0.

### Step-up

Returned by `POST /api/v1/auth/step-up/start` and `/verify`. See [Step-up re-verification](/starter-template/security-feature/#step-up-re-verification-sensitive-actions).

```typescript
interface StepUpChallenge {
  challengeId: string;
  expiresAt: string;   // ISO time; the code lasts 5 minutes
  sentTo: string;      // Masked recipient, e.g. "k***@example.com"
}

interface StepUpGrant {
  grant: string;       // Sent back in the X-Step-Up-Grant header
  expiresAt: string;
  expiresIn: number;   // Seconds left (the browser times it on its own clock)
}
```

The frontend declares the same two shapes in `features/auth/services/step-up.service.ts`.

### Data export

The personal-data export handler contract. See [Personal-data export](/starter-template/security-feature/#personal-data-export).

```typescript
interface DataExportSubject {
  tenantId: string;    // Isolation key (== userId in solo apps)
  userId: string;
  email?: string;
}

interface DataExportContext {
  subject: DataExportSubject;
  at: Date;            // One capture time for the whole export
}

interface DataExportHandler {
  id: string;          // Unique; also this handler's key in the export
  moduleId: string;
  description?: string;
  run(ctx: DataExportContext): Promise<unknown>; // JSON-serialisable; never secrets or hashes
}

interface DataExportCollection {   // Returned by collectDataExport()
  data: Record<string, unknown>;   // Handler output, keyed by handler id
  handlers: number;                // How many handlers ran
  failed: Array<{ handlerId: string; moduleId: string }>;
}
```

## Environment Variables Schema

Backend environment validated with Zod on startup:

```typescript
const envSchema = z.object({
  // Database
  DATABASE_URL: z.string().min(1),
  DIRECT_DATABASE_URL: z.string().optional(),
  DATABASE_ADAPTER: z.enum(['neon', 'pg']).default('neon'),
  DEBUG_PRISMA: z.string().default('false').transform((val) => val === 'true'),  // -> boolean
  DB_QUERY_TIMEOUT: z.coerce.number().default(10000),

  // Auth
  NEON_AUTH_URL: z.string().url(),

  // Server
  PORT: z.coerce.number().default(3100),
  NODE_ENV: z.enum(['development', 'production', 'test']).default('development'),
  FRONTEND_URL: z.string().url().default('http://localhost:5173'),
  SHUTDOWN_TIMEOUT: z.coerce.number().default(10000),
  REQUEST_TIMEOUT: z.coerce.number().default(30000),  // per-request timeout (Slowloris guard); 0 disables
  TRUST_PROXY_HOPS: z.coerce.number().int().min(0).default(1),  // Express `trust proxy` hop count

  // Rate limiting (global API limiter)
  RATE_LIMIT_WINDOW_MS: z.coerce.number().default(15 * 60 * 1000),  // 900000 = 15 min
  RATE_LIMIT_MAX: z.coerce.number().default(300),

  // Security tier + per-knob overrides (see features/security/security.config.ts)
  SECURITY_PROFILE: z.enum(['standard', 'hardened', 'strict']).default('hardened'),
  SECURITY_MFA_REQUIRED: z.enum(['true', 'false']).optional().transform(/* -> boolean | undefined */),
  SECURITY_FIELD_ENCRYPTION: z.enum(['true', 'false']).optional().transform(/* -> boolean | undefined */),
  SECURITY_SESSION_STEP_UP: z.enum(['true', 'false']).optional().transform(/* -> boolean | undefined */),  // emailed code before sensitive actions (requireStepUp); on at hardened/strict (v2.13.0)
  SECURITY_AUDIT_MODE: z.enum(['activity', 'compliance']).optional(),
  SECURITY_KEY_PROVIDER: z.enum(['env', 'kms']).optional(),
  SECURITY_KMS_PER_TENANT: z.enum(['true', 'false']).optional().transform(/* -> boolean | undefined */),  // per-tenant KMS data keys + crypto-shred (v1.64.0)
  SECURITY_AUDIT_SINK: z.enum(['memory', 'database']).optional(),
  SECURITY_AUDIT_RETENTION_DAYS: z.coerce.number().optional(),
  SECURITY_DATA_RESIDENCY: z.string().optional(),
  SECURITY_JURISDICTION: z.string().optional(),
  SECURITY_EDGE: z.enum(['cloudflare', 'none']).optional(),  // declared CDN/WAF edge
  SECURITY_POSTURE_ENFORCE: z.enum(['true', 'false']).optional().transform(/* -> boolean | undefined */),
  SECURITY_ADMIN_ALLOW_ENV_WRITE: z.enum(['true', 'false']).optional().transform(/* -> boolean | undefined */),
  SECURITY_ENCRYPTION_KEY: z.string().optional(),  // base64, 32 bytes — only for `env` key provider

  // Logging
  LOG_LEVEL: z.enum(['fatal', 'error', 'warn', 'info', 'debug', 'trace']).default('info'),
});
```

## Filter & Action Types

### Filter Types

```typescript
// Sync filter callback
type FilterCallback<T = unknown, C = unknown> = (value: T, context: C) => T;

// Async filter callback (backend only)
type AsyncFilterCallback<T = unknown, C = unknown> = (value: T, context: C) => T | Promise<T>;

interface RegisteredFilter<T = unknown, C = unknown> {
  id: string;
  callback: FilterCallback<T, C>;
  order: number;
}
```

### Action Types

```typescript
type ActionCallback<C = unknown> = (context: C) => void | Promise<void>;

interface RegisteredAction<C = unknown> {
  id: string;
  callback: ActionCallback<C>;
  order: number;
  async: boolean;
}
```

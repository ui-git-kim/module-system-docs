Each module grew its own words for the same things, and that made the system hard to follow. This page is the one list. If a word is here, use it the way it is defined here: on screens, in docs, in code comments and in conversation.

The examples use a made-up law firm app. **Matter** and **Person** are node types, "Citizen v Citizen" is a Matter, and John Citizen is a Person.

## How this page works

- **One thing, one word.** A shared word never gets a second meaning. If your module's word clashes with one here, raise it with Kim before adding anything.
- **Shared words go in the first list.** They belong to the whole system, not to one module.
- **A module's own words go under that module's heading.** Add a heading for your module if it has none.
- **Keep each entry short:** the word in bold, one to three plain sentences, and a link to the page that explains it in depth.
- **When a word is replaced,** add the old word to [Words we no longer use](#words-we-no-longer-use) with what to say instead.

## Shared words

Settled by Kim on 2026-11-28.

**Node type**: a kind of thing an app keeps, such as Matter or Person. An admin sets up node types in Structure. Where it can't be mistaken for anything else, a screen may shorten it to **type** (Tasks' screens say "an entry type", "a task type"). See [Structure](/modules/structure/).

**Node**: one entry of a node type. John Citizen is a node of the node type Person. Everything the system keeps is a node.

**Entry**: the same as a node. The two words are interchangeable (Kim, 2026-11-28): use whichever reads better for the people using a screen. Tasks' screens say entry.

**Connection**: a link between two nodes. A connection says what it means, such as "extracted from". The graph is built by connections and by nothing else.

**Connection type**: the kind of a connection, which is what gives it its meaning.

**Graph**: all the nodes and the connections between them.

**Primary scope node type**: the one node type that keeps an app's work apart. In the example it is Matter, so what belongs to one Matter is never mixed with another. An app has one primary scope node type only. See [Sections and Isolation](/modules/structure/sections-and-isolation/).

**Isolated to the primary scope**: a node that belongs to one node of the primary scope node type, and is kept apart from the rest. John Citizen is isolated to "Citizen v Citizen". This is a fact of its own. It is not a connection, and it is not described as one.

**Isolated node type**: a node type whose nodes are each isolated to the primary scope. Person is one: every Person belongs to one Matter. Kim leans to this word; "scoped node type" is the other one in use.

**Global node type**: a node type whose nodes the whole app uses, such as a list of courts. Its nodes are isolated to nothing.

## Words we no longer use

| Do not say | Say |
|---|---|
| record, item (for one node) | node, or entry |
| section type, and "isolated type" when it means the one type that keeps work apart | primary scope node type |
| scoped type, scoped node type | isolated node type |
| shared type, shared node type | global node type |
| parent, child, under, inside, top level, tree, hierarchy | Say what the connection means, or which node of the primary scope node type the node is isolated to |

A node does not sit inside another node. Two nodes are related by a connection that says what the relation is.

## Not yet settled

These still have more than one word in use. Do not pick one yourself; they are Kim's to settle.

- **One node of the primary scope node type, together with what is isolated to it.** Structure's screens say "scope". Structure's docs and code say "section" and "space". Cognitive Pipeline's screens and docs say "section". AI Core says "space" (its "space wall"). Each of the three words already means something else in the starter: "space" is a user's own private area (see the next list), "section" is a block of a settings or admin page, and "scope" is a provider's own name for a permission in the connections code.
- **A node that is isolated to nothing.** Structure says "unassigned". Cognitive Pipeline says "no section".

Found in the starter template on 2026-11-28, and also Kim's to settle:

- **A link to an outside service.** The starter says "connection" (its Connections admin page, `connections.use()`, most of its docs) for one person's link to an account at Google or Microsoft 365. That clashes with the shared word **Connection**. Its table is named `ServiceConnection`, so "service connection" in full is one way out.
- **A user's own private area.** The starter says "space": its `Space` table, the [Product Model](/getting-started/product-model/) page, and it asks modules to use the word on screens. Structure's code and AI Core use "space" for the first item above. One word, two meanings.
- **How strongly an app is locked down** (standard, hardened or strict). The starter's screens say "security level", its docs say "security tier", and its code and settings say "security profile".
- **The person who runs an app** (puts it online, holds its accounts with outside providers, sets it up). The starter's docs say "app owner" and "operator". The Product Model page also says "operator" for a person using the app.
- **One thing a module uses a service for, which a person switches on or off for a connected account** (such as "Calendar sync"). The starter's docs and code say "use". Its screens say "feature", which is also the starter's word for one area of its own code (the auth feature, the connections feature).
- **"Record" in the starter's security words.** Its Security page and docs say "record integrity" and "record hold", where a record is any row an app keeps. "Record" is retired for one node.
- **A line in a list, when the line is not a node.** The starter says "entry" for a line of a service's activity list and of a changelog. **Entry** is a shared word for a node.
- **The step-by-step set-up panel.** Its component and the newer pages say "setup guide". A few older pages say "wizard".

## Starter Template

The foundation's own words, which every module builds on. See [Starter Template](/starter-template/).

**Starter**: the foundation every app is made from and updated from. Also written "starter template". It is not an app by itself.

**App**: one product made from the starter, with its own database and its own web address.

**Module**: an add-on installed into an app that brings one area of work, such as Structure or Tasks. See [Modules](/modules/).

**Registry**: a list the starter keeps that modules add to, such as the sidebar's menu or the settings pages. A module registers with a registry instead of changing the starter's files. See [Registries](/starter-template/registries/).

**Registry entry**: one thing registered in a registry. Say "registry entry" in full, so it is not taken for an entry (a node).

**Hook**: a named moment a module can listen for. An **action hook** tells a module that something happened. A **filter hook** lets it change a value on the way through. See [Hooks](/starter-template/hooks/).

**User**: someone signed in to an app.

**Admin**: a user with the admin role, who can open the Admin area and change how the app is set up.

**Tenant**: the code's name (`tenantId`) for whose data something is. It is never shown on a screen. See [Product Model](/getting-started/product-model/).

**Background job**: work the backend does later, not while a person waits. Say "background job" in full, so it is not taken for a Cognitive Pipeline job. See [Jobs](/starter-template/jobs-feature/).

**Step-up**: asking a signed-in user to prove it is them again, with a code sent by email, before a sensitive change is saved.

**Template update**: bringing a newer version of the starter into an app. See [Updating](/starter-template/updating/).

**Node.js**: the program the backend and the scripts run on. Write "Node.js" in full, so it is not taken for a node in the graph.

**Service**: an outside product a user can connect to the app, such as Google or Microsoft 365. See [Connections](/starter-template/connections/).

**Service connection**: one user's link to one account at a service, with the access they agreed to. It is not a connection between two nodes.

**Connected account**: the account at the service that a service connection is for, shown by its email address or name.

**Permission**: a named thing a service connection may do, said in plain words, such as "See and edit your calendars".

Today the starter's own data (users, notifications, service connections, settings) is kept in ordinary tables, not as nodes in the graph.

A clash still to clear: the starter's screens, docs and code say plain "connection" for a service connection in many places. See [Not yet settled](#not-yet-settled).

## Cognitive Pipeline

The module's own words. See [Cognitive Pipeline](/modules/cognitive-pipeline/).

**Pipeline**: what happens to content from the moment it arrives until its nodes and connections are in the graph. Each source has its own pipeline, drawn on a canvas by an admin.

**Pipeline node**: one box on the pipeline canvas, such as Upload, Split or AI Op. It does one job and is set up on the box itself. Always say "pipeline node" in full, so it is not taken for a node in the graph. Today a pipeline node is kept in its source's settings, not in the graph.

**AI Op node**: a pipeline node that runs whichever AI Core operation is set on it. See [AI Core](/modules/ai-core/).

**Source**: a kind of content an admin has set up, such as "Court Document", with its own pipeline.

**Job**: one run of a source's pipeline over one piece of content. It keeps the status, the result and any error.

**Mapping**: the setting on a source that says which node type a piece of content becomes and which of its fields are filled.

**Unit**: one piece a document is split into, such as one message of a conversation. Each unit is a node with an "extracted from" connection to its document.

**Uploaded to**: the connection from a document's node to the node it was uploaded on. It says where the document was put, not what it is about, and it is not made when that node is the document's scope itself.

**Suggestion**: something the engine noticed that a person may want to act on, such as two nodes that look like the same person. Suggestions wait in an inbox.

**Engine**: cognitive-db, which is bundled with the module. It reads content and works out the nodes and connections in it. See [cognitive-db](/cognitive-db/).

A clash still to clear: this module's screens and its engine say "isolated node type" for the primary scope node type. That use is going; see the module [roadmap](/modules/cognitive-pipeline/roadmap/).
